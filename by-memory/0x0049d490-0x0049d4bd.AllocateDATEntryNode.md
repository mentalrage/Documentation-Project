# 0x0049d490-0x0049d4bd AllocateDATEntryNode

## Status

- Disposition: non-emitting old-MSVC/Dinkumware list-node allocation lowering for typed `EntryMap` sentinel/value nodes.
- Entity kind: compiler/template support body, not an authored helper.
- Owner/emitter/source route: none. [UID:000004][_DATFileMgr](by-class/_DATFileMgr.md) owns the typed map declaration that generates this behavior.

## Range And Behavior

Live IDA MCP session `80de0a67` reports `0x0049d490-0x0049d4bd` as a small node allocator/sentinel initializer. It allocates `DATEntryNode` storage and either initializes explicit `m_next`/`m_prev` links or self-links the node when called with null link arguments. The public manager constructor uses this helper for the resolver sentinel, and `CreateDATEntryNode` uses it for per-entry nodes.

## Historical Source Reconstruction Notes

An earlier reconstruction treated the body as a file-local helper because it has no `this` field route. Complete typed-container analysis supersedes that source claim: this is list-node/sentinel allocation lowering generated by `EntryMap` construction and insertion.
