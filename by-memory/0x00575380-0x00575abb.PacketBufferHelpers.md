## Evidence

- Live IDA MCP confirms all listed function starts and end addresses on 2026-06-04.
- Live IDA MCP xref counts show the common helpers are shared broadly: `sub_575380` has 1114 direct code refs from 178 caller functions, `sub_575480` has 372 refs from 96 caller functions, and `sub_5754C0` has 226 refs from 70 caller functions.
- Live decompilation confirms `sub_5753C0` stores the high/middle/low bytes of a 24-bit-style value, `sub_575420` writes an eight-byte big-endian value plus trailing zero, and `sub_5754F0` reconstructs an eight-byte big-endian value.
- Live decompilation confirms `sub_575730` and `sub_575790` read big-endian values from `base + *cursor` and advance the caller cursor by two and four bytes respectively.
- Live decompilation confirms `sub_575580` is an adjacent network utility: it calls `WideCharToMultiByte`, `gethostbyname`, and copies four address bytes through local string/storage helpers.
- Live decompilation confirms `sub_575970` is the two-byte length variant of the wide-string write path, but live xrefs report no direct code refs.
- No helper in this cluster requires a `Socket*` or `CashShopRequest*` receiver, so source ownership should be a utility module.

## Ownership Decision

Attach the packet-buffer helper family to [UID:0000M8][PacketBuffer](by-file/PacketBuffer.md). Do not migrate it into `Socket.cpp` merely because the address cluster sits between `CashShopRequest::GetConnectionStatus` and `Socket::NoOpVirtualHook`.

The by-memory span is a coverage island, not a promise of one contiguous original source block. The embedded `std::_Narrow_char_traits<char,int>::to_char_type` helper remains non-owned runtime code, and the hostname/address helper may have been a nearby network utility rather than a scalar packet-field routine. Keeping those caveats in this page prevents overclaiming while still documenting the exact bytes.
