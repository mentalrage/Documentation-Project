## Behavior

Both constructor paths resolve localized text id `155`, call the alert/dialog initializer, construct the direct `Singleton<ReconnectDialog>` base, install three `ReconnectDialog` vtable views at `+0x00/+0xa0/+0xa4`, and call `0x005540a0`. The observed writes to [UID:0004SR][0x0067ab58-0x0067ab5c.g_pReconnectDialog](by-memory/0x0067ab58-0x0067ab5c.g_pReconnectDialog.md) are compiler-inlined base publication, not source-authored assignments.

`InitiateReconnect` marks the reconnecting state when application/session globals are valid, clears byte `this+0x270`, sends a reconnect request using the saved server address/port fields, and starts a 10000 ms timeout through the timer-handler view at `this+0xa4`.

The byte-stream helper reads bytes from a packet buffer span at `a2+0x0c/+0x10` and advances state byte `this+0x1d0` through ESC/command/terminal marker handling. When the state reaches the complete reconnect branch, it calls packet/session cleanup helpers and starts a shorter 3000 ms timer on `this+0x04`.

`OnButtonClick` has two important paths. The reconnect path closes active UI state, sends the literal `baram`, calls [UID:0001HW][0x00574d40-0x00574e44.QueueClientVersionStatusPacket](by-memory/0x00574d40-0x00574e44.QueueClientVersionStatusPacket.md) `SendPositionUpdate`, and marks EPF/session state when needed. The cancel path cleans packet state and creates a replacement `ConnectionClosedDialog` either inline or through the alternate constructor.

`OnReconnectTimeout` clears the reconnecting packet/session state, conditionally disconnects/reset packet state, deletes any existing connection-closed alert, and constructs a new `ConnectionClosedDialog` through `0x00553cc0`.
