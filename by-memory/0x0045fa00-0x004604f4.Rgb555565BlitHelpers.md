## Pixel Format Notes

- RGB555 helpers use green mask `0x03e0` and combined red/blue mask `0x7c1f`.
- RGB555 half-blend paths use `0x3def` to average without cross-channel carry.
- RGB555 transparent-shadow copy treats source value `1` as a special half-bright destination shadow sentinel.
- RGB565 transparent-shadow copy uses `0x7bef`, the corresponding half-bright RGB565 mask.
- Alpha weights are five-bit weights in the `0..32` range; `16` is the exact 50 percent case.

[UID:00028W][0x0067a7f0-0x0067a830.MmxBlendWeightScratchData](by-memory/0x0067a7f0-0x0067a830.MmxBlendWeightScratchData.md) records the binary writable scratch qword pairs used by the RGB555 weighted block helpers in this island. `BlendTransparentRgb555Blocks` at `0x0045fff0` writes and then loads `qword_67A7F0` and `qword_67A7F8`; `BlendRgb555Blocks` at `0x00460120` writes and then loads `qword_67A800` and `qword_67A808`. Future C++ for these helpers should prefer local source/inverse weight-vector temporaries or inline-assembly operands rather than requiring global `qword_67A7F0` through `qword_67A808` declarations, while preserving the binary scratch/xref facts on [UID:00028W][0x0067a7f0-0x0067a830.MmxBlendWeightScratchData](by-memory/0x0067a7f0-0x0067a830.MmxBlendWeightScratchData.md).

For `BlitTransparentShadow565` at `0x00460370-0x0046040f`, the four-pixel bulk path calls [UID:000208][0x00460940-0x004609d3.BlitTransparentShadow565MmxBlocks](by-memory/0x00460940-0x004609d3.BlitTransparentShadow565MmxBlocks.md) at `0x00460399`. The caller computes `width / 4` blocks, dispatches the MMX helper for those qword groups, advances the source and destination pointers past `blocks * 8` bytes, and then runs the scalar tail. The scalar tail and UID000208 share the same RGB565 transparent-shadow contract: source word `0` preserves destination, source word `1` writes a half-bright destination shadow using the RGB565 mask, and all other source words copy through. UID000208 is now independently emit-ready as a SoftwareBlend16-owned first-draft MSVC x86 inline-assembly helper; this caller page remains the row/scalar-wrapper context and does not take direct ownership of the block helper.

For this split, the RGB555 block-helper children use formal source-level four-pixel loops rather than pasted Hex-Rays temporaries or standalone global scratch declarations. That source form preserves the proven masks, weights, transparent skips, sentinel handling, row stepping, and in-place writes while following the accepted SoftwareBlend16 local-mask/local-weight policy from UID0000YF, UID000208, and UID00028W.
