## Interpretation

The surface/presentation initializer at `0x00558840` builds two lookup-table root pointers immediately after the pixel-format flags and immediately before the callback table at [UID:0001PI][0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable](by-memory/0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable.md). The software render callbacks then read both roots when applying byte alpha values to packed 16-bit color channels.

These are external render-module globals owned next to the callback table, not globals owned by any individual pane that happens to draw through the callbacks. `ScreenPane::~ScreenPane()` in another translation unit directly frees them, so file-static linkage would be incompatible with the observed cross-file source route. The table contents remain best described functionally: the first root is used for 5-bit channels, and the second covers the middle channel, including RGB565's 6-bit green channel.

## Evidence

B011's 2026-07-08 UID00029U pass observed zero bytes instead; the UID00023U focused pass independently reconfirmed all eight bytes are zero and resolved the conflict in favor of zero initialization.
