## Interpretation

The surface/presentation initializer at `0x00558840` builds two lookup-table root pointers immediately after the pixel-format flags and immediately before the callback table at [UID:0001PI][0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable](by-memory/0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable.md). The software render callbacks then read both roots when applying byte alpha values to packed 16-bit color channels.

These should be reconstructed as render-module globals owned next to the callback table, not as globals owned by any individual pane that happens to draw through the callbacks. The table contents are still best described functionally rather than with final source names: the first root is used for 5-bit channels, and the second root covers the middle channel, including RGB565's 6-bit green channel.

## Evidence

- Live IDA bytes for `0x0069b3d8-0x0069b3e0` are `ff ff ff ff ff ff ff ff`, matching two pointer-sized storage slots in the data image.
- Live IDA reports 12 direct references to `0x0069b3d8` and 11 direct references to `0x0069b3dc`. The preceding pixel-format flag block at `0x0069b3d4-0x0069b3d8` has its own flag references, while `0x0069b3e0` begins the separate callback-table global.
- The initializer at `0x00558840` stores the first table root at `0x00558c95`, reads it back at `0x00558caa` and `0x00558cf7`, stores the second table root at `0x00558d24`, then reads it back at `0x00558d5a` and `0x00558da8`. The second pixel-format flag at `0x0069b3d5` is tested at `0x00558d2a` while the second table family is being filled.
- 2026-06-07 A001 live IDA recheck confirms the initializer/function boundary at `0x00558840-0x00558f63`, compatibility callback consumers in `0x004bdcc0-0x004bdf3e`, RGB565 consumers in `0x004c3a50-0x004c3ce1`, and helper reads in `0x00556a60-0x00556cd4`.
- Compatibility callback consumers read both roots at paired sites such as `0x004bde35`/`0x004bde4c`, `0x004be04a`/`0x004be065`, and `0x004bedf9`/`0x004bede3`.
- RGB565 callback consumers read both roots at paired sites such as `0x004c3bc6`/`0x004c3bd6`/`0x004c3bf7`, `0x004c3dfc`/`0x004c3e0b`, and `0x004c4733`/`0x004c4738`.
- Additional render-helper reads at `0x00556ab6`, `0x00556acf`, `0x00556aec`, and `0x00556b05` use the same two roots, confirming this is shared render lookup-table state rather than callback-local storage.
- [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md) already records these lookup tables as nearby globals constructed by the callback-table initializer.

## Assignment Decision

Assign to [UID:0000OC][Surface](by-file/Surface.md). This child is `85/91`, the direct file parent is now `88/85`, and by-structure assignment is justified because the pointer pair is shared surface render state built by the surface initializer and consumed by multiple software-render callback families. Do not assign this page to [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md): that global documents the callback table at `0x0069b3e0-0x0069b410`, while this pointer pair occupies the immediately preceding range.
