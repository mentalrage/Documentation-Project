# 0x0069b3d8-0x0069b3e0 Surface Alpha Lookup Table Pointers

## Status

- Disposition: reconstructable NexusTK render globals.
- Entity kind: render lookup-table pointer globals.
- Confidence: strong for address, initializer, and callback consumers; medium for final table names.
- Proposed owner: [UID:0000OC][Surface](by-file/Surface.md) / [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md).

## Layout

| Address | IDA name | Role |
| --- | --- | --- |
| `0x0069b3d8-0x0069b3dc` | `dword_69B3D8` | Lookup-table pointer used by software alpha/blend/render callbacks. |
| `0x0069b3dc-0x0069b3e0` | `dword_69B3DC` | Companion lookup-table pointer used by the same callback families. |

## Raw Data

```text
0x0069b3d8: ff ff ff ff ff ff ff ff
```

## Interpretation

The surface initializer allocates or builds two lookup tables immediately before the callback table at [UID:0001PI][0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable](by-memory/0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable.md). The selected software render callbacks then read these globals for blend/alpha/color conversion operations.

These should be reconstructed as render-module globals owned next to the callback table, not as globals owned by any individual pane that happens to draw through the callbacks.

## Evidence

- IDA MCP data xrefs show both globals written by `sub_558840`, the surface/presentation initializer.
- `dword_69B3D8` is read by compatibility and RGB565 callback families including `0x004bdcc0`, `0x004bdf40`, `0x004bede0`, `0x004c3a50`, `0x004c3cf0`, and `0x004c4730`.
- `dword_69B3DC` is read by the same callback families, with xrefs including `0x004bde4c`, `0x004be065`, `0x004bede3`, `0x004c3bc6`, `0x004c3dfc`, and `0x004c4733`.
- [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md) already records these lookup tables as nearby globals constructed by the callback-table initializer.
