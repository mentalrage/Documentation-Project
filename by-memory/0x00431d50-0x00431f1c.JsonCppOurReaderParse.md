# JsonCpp OurReader Parse Front End

## Status

- Address range: `0x00431d50-0x00431f1c`
- Entity kind: statically linked third-party JsonCpp parser method
- Confidence: strong for JsonCpp ownership; high for `OurReader::parse` role
- Evidence basis: IDA MCP `xrefs_to` and `decompile` on 2026-05-25 plus official JsonCpp source-history comparison. `wave3.py` was not executed.

## Function Role

IDA models this as `sub_431D50`, size `0x1cc`. It is the second parser family's `OurReader::parse`-style front end. The immediately preceding [UID:0000X6][0x00430092-0x00431d50.JsonCppWriterTailAndOurReaderPrelude](by-memory/0x00430092-0x00431d50.JsonCppWriterTailAndOurReaderPrelude.md) now documents the `OurFeatures::all`/`OurReader::OurReader` setup code that leads into this parse front end. The function:

- initializes parser input begin/end/current pointers;
- clears stored comments/errors and resets parser state;
- calls the adjacent value parser at `0x00432f10`;
- reads one additional token after the document value;
- reports `Extra non-whitespace after JSON value.` when `failIfExtra` is set and the trailing token is neither `tokenError` nor `tokenEndOfStream`;
- attaches collected comments to the parsed root when requested;
- enforces `strictRoot` by requiring the parsed root to be an array or object.

## Evidence

- String `Extra non-whitespace after JSON value.` at `0x0060e6d4` has its only current IDA xref from `0x00431e25` inside this function.
- The value parser call goes to `0x00432f10`, the entry documented in [UID:0000X8][0x00432e10-0x004345ee.JsonCppSecondParserIsland](by-memory/0x00432e10-0x004345ee.JsonCppSecondParserIsland.md).
- The strict-root failure string `A valid JSON document must be either an array or an object value.` is emitted later in the same function after the root type check.
- The local token enum values align with JsonCpp `OurReader::TokenType`: `tokenEndOfStream = 0` and `tokenError = 16`.
- IDA reports the function body as `0x00431d50-0x00431f1c`; bytes `0x00431f1c-0x00431f20` are `0xcc` alignment padding before the next helper at `0x00431f20`.

## Version Matching Notes

This function is a useful discriminator inside the `1.7.x` JsonCpp family:

- The binary's fail-if-extra branch is equivalent to `features_.failIfExtra_ && token.type_ != tokenError && token.type_ != tokenEndOfStream`.
- Upstream JsonCpp commit `126bdc2` changed that branch to include `features_.strictRoot_ || token.type_ != tokenError`.
- The binary does not include that `strictRoot` term in the fail-if-extra branch, so this function predates `126bdc2` and rejects official release tag `1.7.5` and newer for the observed reader source.

Combined with [UID:0000WY][0x00424630-0x00428b4b.JsonCppValueCore](by-memory/0x00424630-0x00428b4b.JsonCppValueCore.md), which matches the `Value::nullSingleton()` static-object change from upstream commit `b299d3581f4dc670734f1fe1a34fce1282337802`, the current best source snapshot is the official `b299d358` commit between tags `1.7.4` and `1.7.5`.
