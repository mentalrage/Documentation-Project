## Behavior

`DLPalette::LoadFromFile` returns `void`. It constructs one automatic `DATFile` object, opens the caller's read-only wide resource path, passes the object through the `File` stream interface to the adjacent `DLPalette::LoadFromStream`, explicitly closes it on the normal path, and then leaves scope so the destructor runs.

`DATFile::Open` is a throwing `void` operation. A failed DAT entry lookup constructs and throws `FileError`; therefore there is no Boolean Open result to test. If `Open` or `LoadFromStream` throws, compiler-generated EH cleanup destroys the local and the explicit `Close` call is not reached. There is no hand-authored local catch, translation, fallback, retry, or logging path.

`DATFile::Close` returns `bool`, but this wrapper ignores the result. No instruction tests, stores, normalizes, or returns that value, and the later destructor is also `void`. Residual EAX state after helper calls is incidental ABI state rather than a source return contract.
