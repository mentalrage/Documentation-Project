# 0x00525be0-0x00525dbb Midi Stream Callback

## Status

- Confidence: strong for behavior and source family.
- Entity kind: WinMM callback function.
- Proposed owner: [UID:0000LD][MidiPlayer](by-file/MidiPlayer.md)
- Related state: [UID:0000T9][MidiPlayerWinMMState](by-global/MidiPlayerWinMMState.md)

## Behavior

This is the callback passed to `midiStreamOpen` by [UID:0001CE][0x00525920-0x00525b0d.MidiStreamOpenAndPrimeBuffers](by-memory/0x00525920-0x00525b0d.MidiStreamOpenAndPrimeBuffers.md).

IDA MCP decompilation shows two main message paths:

- Message `969`: buffer-return/completion handling. It increments the pending-return counter, advances stop/reset state when both prepared buffers have returned, optionally calls [UID:0001CF][0x00525b10-0x0052664b.MidiPlayerAndWinMMHelpers](by-memory/0x00525b10-0x0052664b.MidiPlayerAndWinMMHelpers.md), signals the "Wait For Buffer Return" event, and queues the next stream buffer when playback is active.
- Message `970`: MIDI short-message handling for controller 7 volume events. It updates per-channel volume state and forwards scaled volume through `midiOutShortMsg` when the stream is running.

On refill, the callback reads the next MIDI chunk through [UID:00023C][0x005271b0-0x005277bb.MidiSMFLoadAndStreamFillHelpers](by-memory/0x005271b0-0x005277bb.MidiSMFLoadAndStreamFillHelpers.md), writes `dwBytesRecorded`, submits the header with `midiStreamOut`, rotates the two-buffer index, and releases MIDI document resources through [UID:0001CI][0x005270e0-0x005271a3.MidiDocumentRelease](by-memory/0x005270e0-0x005271a3.MidiDocumentRelease.md) on error/end paths.
