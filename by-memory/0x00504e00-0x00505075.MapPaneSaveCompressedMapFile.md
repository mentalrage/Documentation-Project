## Behavior

This method writes the current `MapPane` tile buffer as a compressed local map-cache file. If the tile buffer pointer is absent, the method skips filesystem work and immediately refreshes the monster image-library cache state through [UID:0001PN][0x0069b440-0x0069b444.g_pMonsterImageLib](by-memory/0x0069b440-0x0069b444.g_pMonsterImageLib.md).

When tile storage exists, the method resolves the user's Documents folder with `SHGetFolderPathW`, creates `NexusTK` and `NexusTK\Maps` beneath it, accepts `ERROR_ALREADY_EXISTS` (`183`) for both directory-creation calls, then formats `TK%06d.cmp` with unsigned 16-bit `m_mapId`. It opens the path through `g_pfnWideOpenFile` / `_wfopen` in write-binary mode, writes exactly four `CMAP` bytes with no NUL, writes `m_mapWidth` and `m_mapHeight` as two-byte little-endian fields, and computes raw input as `sizeof(MapPaneTileRecord) * m_mapWidth * m_mapHeight`.

The local `_AUTOBUF<unsigned char>` is resized to the exact 32-bit capacity formula `rawBytes * 11 / 10 + 12`; the binary does not call `compressBound`. Lowercase zlib `compress` receives the AUTOBUF storage, an in/out `uLongf` length, `m_tileBuffer`, and raw size. Its status is ignored, and the mutated compressed length becomes the payload `_fwrite` count. After `_fclose`, the ordinary path frees/nulls `m_tileBuffer`, destroys/releases the local compressed buffer, and only then calls `MonsterImageLib::ClearLoadedData`.

The save helper is paired with [UID:0002QJ][0x00504b90-0x00504df1.MapPaneLoadCompressedMapFile](by-memory/0x00504b90-0x00504df1.MapPaneLoadCompressedMapFile.md). The load side expects the same path family, `CMAP` signature, width/height header, and zlib-compressed `6 * width * height` payload.
