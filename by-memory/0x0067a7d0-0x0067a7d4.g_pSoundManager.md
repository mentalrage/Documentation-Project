# 0x0067a7d0-0x0067a7d4 g_pSoundManager

## Summary

- Address range: `0x0067a7d0-0x0067a7d4`
- Entity kind: global pointer
- Proposed name: `g_pSoundManager`
- Disposition: reconstructable NexusTK global data
- Confidence: strong for address, owner class, and singleton role

This four-byte zero-initialized global stores the active `SoundManager` singleton pointer. It is set by the `SoundManager` constructor, cleared by destructor paths, and used throughout UI, pane, video, Bink, Miles, and packet/hotkey code to play effects, control music, and query DirectSound/Miles state.

## Evidence

- IDA MCP reports four zero-initialized `.data` bytes at `0x0067a7d0` and 117 direct data xrefs.
- `SoundManager::SoundManager` at `0x00579a30` writes `dword_67A7D0 = this` before installing the `SoundManager` vtable and initializing Miles/DAT-backed audio state.
- `SoundManager` destructor paths at `0x00579cb0` and `0x0057bb30` clear `dword_67A7D0 = 0`.
- Callers such as `MiniMapDialog::MiniMapDialog`, `Application` cleanup/startup paths, `SoundStatusPane`, `VideoPlayerPane`, `LivingObjectPane` hotkey handling, and many UI controls use this pointer for sample playback, music volume/mode, or DirectSound/Miles bridge access.
- Existing docs already identify `0x0067a7d0` as `g_pSoundManager` in [UID:0001I8][0x005797b0-0x0057bc58.SoundManager](by-memory/0x005797b0-0x0057bc58.SoundManager.md), [UID:0000NV][SoundManager](by-file/SoundManager.md), and [UID:0000NX][SoundStatusPane](by-file/SoundStatusPane.md).

## Reconstruction Notes

Declare this singleton in the audio module with the `SoundManager` implementation. It should be initialized by normal zero-initialized global storage and assigned/cleared in the constructor/destructor bodies.
