## Evidence Notes

- IDA MCP lookup on 2026-05-25 reports function sizes `0x22`, `0x1d`, `0xb`, and `0xb` for the four starts in this page.
- IDA decompilation of `0x00549b00` and `0x00549b30` shows only message-byte checks and the adjusted call `sub_544690(this - 160)`.
- IDA xrefs show handler vtable data references at `0x00622084`, `0x00622088`, `0x00622120`, and `0x00622124`; thunk vtable references are at `0x0062211c` and `0x0062214c`.
- The thunk pair is compiler-generated vtable glue and is recorded in [UID:0000VN][-ignored](by-memory/-ignored.md). The handler bodies are handwritten project behavior and should stay documented under `PictureViewPane`.
- 2026-06-04 live IDA MCP recheck confirms exact bounds: `0x00549b00-0x00549b22`, `0x00549b30-0x00549b4d`, `0x00549b4d-0x00549b58`, and `0x00549b58-0x00549b63`; the scalar deleting destructor target is `0x00549b70-0x00549bc5`.
- The first handler reads `message[4]`, accepts codes `3` or `6`, adjusts `ecx` by `-0xa0`, calls `0x00544690`, and returns handled. The second accepts code `8`, performs the same `-0xa0` adjustment and close-helper call, and returns handled.
- The adjacent thunks subtract `0xa0` and `0xa4` respectively before jumping to `0x00549b70`, proving they are destructor vtable glue rather than separate handwritten close logic.
