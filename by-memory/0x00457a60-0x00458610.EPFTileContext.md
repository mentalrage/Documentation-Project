## Evidence

- Wave3 `inspect class EPFTileContext --method-limit 20` reports five included methods, no memory conflicts, and owner file `class_EPFTileContext.cpp`.
- Wave3 summary describes the class as a shared tile-image context holding decoded EPF/EPD pixel buffers, bounds metadata, and an optional cached run-length mask.
- Generated source shows a consistent 0x28-byte layout with pixel mode, two buffer pointers, row stride, bounds, mask size, and mask pointer.
- `BuildRleMask8` and `BuildRleMask16` encode each row into zero/nonzero runs, terminating each row with a zero byte.
- 2026-05-27 IDA MCP confirms `sub_458500` ends at `0x00458557`, `0x00458557-0x00458560` is `0xcc` alignment, `sub_458560` is `0x00458560-0x00458585`, `0x00458585-0x00458590` is `0xcc` alignment, and `sub_458590` is `0x00458590-0x00458610`.
- IDA xrefs show `0x00458560` is called by shared image decode wrappers at `0x004d06f2`, `0x004d079a`, `0x004d0991`, `0x004d0c42`, `0x004d0d7d`, and `0x004d0f29`; `0x00458590` is called from raw light-image generation code at `0x004df70c` and `0x004df7aa`.

## Ownership Decision

This range belongs in `render/EPFTileContext.cpp`. It should not be grouped into DAT archive parsing. It sits downstream of DAT-backed EPF/EPD payload lookup and upstream of pane/image-library drawing code.
