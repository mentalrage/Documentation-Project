## Behavior

The context is a compact 0x28-byte render-support record. Live Hex-Rays consistently accesses it as:

```text
+0x00  mode/control dword
+0x04  primary pixel buffer
+0x08  auxiliary pixel buffer
+0x0c  row stride
+0x10  bounds.left
+0x14  bounds.top
+0x18  bounds.right
+0x1c  bounds.bottom
+0x20  encoded mask byte count
+0x24  encoded mask buffer
```

The first dword selects several behavior branches. `sub_457AB0` treats zero as the word-pixel mask path and nonzero as the byte-pixel path; `sub_458430`/`sub_458490` set it to zero for 16-bit allocations, while `sub_4583D0` and `sub_457A60` set it to one for byte-sized contexts. The final source field name remains provisional.

The mask builders free any existing encoded mask, scan each row, emit zero/nonzero runs, set bit `0x80` on nonzero runs, cap run length at `127`, and terminate each row with a zero byte. Both builders use a 100000-byte stack scratch buffer before allocating the exact encoded size and copying it into `+0x24`.

The deep-copy helpers preserve the whole context header, then allocate fresh primary, auxiliary, and mask buffers when the corresponding source pointers are non-null. `sub_457E00` chooses byte or word copy sizes from the first dword; the unpromoted `0x00457f30` body always uses the word-sized primary/auxiliary copy calculation and has no direct start xrefs in the current IDB.

The middle allocation helpers are important coverage additions:

- `sub_457FF0` creates a half-size decimated context by halving left/top and width/height and sampling every other source pixel/row.
- `sub_458260` is a similar word-pixel half-size decimator with no live direct callers.
- `sub_4583D0`, `sub_458430`, and `sub_458490` are common reset-and-allocate helpers used by image decoders to prepare byte, word, or word-plus-auxiliary buffers.
