## Allocation Behavior

For `count <= 0x7e07e0`, the product is retained. A zero product returns null without allocation. A nonzero product below `0x1000` calls throwing `operator new` for the exact logical byte count and returns its pointer directly.

Logical sizes at or above `0x1000` use the aligned path. The helper requests logical bytes plus `0x23` / 35, saturates the request to `UINT_MAX` if that addition wraps, calls throwing `operator new`, aligns `(raw + 35)` upward to a 32-byte boundary, stores the raw pointer in `aligned[-1]`, and returns the aligned pointer. Count 8 is the first ordinary count whose `8 * 0x208 = 4160` logical bytes select the large path.

If `count > 0x7e07e0`, this helper does not call the vector-too-long routine. It sets logical bytes to `UINT_MAX` and continues through the large allocation path. UID0003X6/UID0003X9 perform their own vector-size checks before calling this allocator. This distinction supersedes older wording that the allocator itself caps or reports vector length.

Although the linked `operator new` is throwing, the generated body includes a post-call null check on the large path; a null result reaches `_invalid_parameter_noinfo_noreturn`. That route terminates and is distinct from ordinary allocation exceptions.
