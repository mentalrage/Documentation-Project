## Signature And Parameters

The accepted source-level shape is the libcurl write callback ABI: `static size_t CurlWriteCallback(char *contents, size_t size, size_t nmemb, void *userData)`. In this 32-bit binary IDA's `int`/`void **` rendering is register-width compatible with `size_t` and a `void *` user pointer; the source-facing type should not carry the IDA label or pointer-to-pointer decompiler artifact.

| Parameter | Observed role |
| --- | --- |
| `Src` / source pointer | Incoming NUL-terminated text chunk. The function scans it manually with a byte loop equivalent to `strlen`, so embedded NUL bytes would truncate the append. |
| `elementSize` | First multiplicand returned to libcurl; not used for append length. |
| `elementCount` | Second multiplicand returned to libcurl; not used for append length. |
| `userData` / IDA `buffer` | Pointer to a `std::string` response buffer. The binary proof is the MSVC/Dinkumware 24-byte small-string layout: inline bytes begin at offset `+0x00`, length is at `+0x10`, and capacity is at `+0x14`. |

## Behavior Notes

- Uses `strlen(source)` for the incoming append length, not the `elementSize * elementCount` byte count.
- The formal C++ intentionally uses `responseText->append(contents)`, which preserves the observed NUL-terminated append behavior. It must not be rewritten as binary-safe `append(contents, size * nmemb)`.
- Treats the callback user data as a `std::string *`; the offset evidence is the MSVC/Dinkumware small-string layout, not a separate project-owned custom string class.
- Reads the current string length from buffer offset `+0x10` and capacity from `+0x14`.
- Uses inline storage when capacity is below `0x10`; otherwise uses the heap pointer at offset `+0x00`.
- Grows capacity with `(requiredLength | 0x0f)` plus the half-capacity growth check used by nearby string helpers.
- In the no-growth path, updates length, selects inline storage or the heap pointer, copies the incoming bytes with `memmove_0`, writes the trailing NUL, and returns `elementSize * elementCount`.
- In the growth path, checks for signed 31-bit overflow against `0x7fffffff`, allocates `newCapacity + 1`, stores the new length and capacity, copies the old bytes and the new chunk, writes a trailing NUL, then publishes the new heap pointer.
- Old inline contents are copied from the object itself when previous capacity is below `0x10`. Old heap contents are copied from `buffer[0]` when previous capacity is at least `0x10`.
- When freeing an old heap allocation whose recorded capacity plus NUL is at least `0x1000`, the function uses the preceding allocator header dword and validates the header distance is at most `0x1f`; otherwise it calls `_invalid_parameter_noinfo_noreturn`.
- The only persistent state touched is the caller-provided small-string buffer. The callback does not read or write StartupWindow fields or globals directly; ownership comes from the two callback setup xrefs in `RunUpdateCheck`.
