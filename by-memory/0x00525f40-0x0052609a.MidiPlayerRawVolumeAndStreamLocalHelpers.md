## Behavior Notes

`ApplyMidiVolume` intentionally computes outgoing controller values from the old global `g_midiVolumeScale` and stores the incoming argument only after all 16 channel sends succeed. This unusual order is binary-confirmed and must not be rewritten to use the new argument inside the loop.

The event helper intentionally calls `g_pfnCreateEventW` instead of the `CreateEventW` import directly. Older target/generated wording that used direct `CreateEventW` was behavior-equivalent, but the current bytes and Wide API dispatch docs make the dispatch slot the more accurate source shape.

The helper is emitted as `static void __stdcall ApplyMidiVolume(unsigned int volumeScale)` because IDA reports `void __stdcall(int)`, the body returns with `retn 4`, and raw callers do not clean the argument. Older wording that treated it as an ordinary static helper is superseded.
