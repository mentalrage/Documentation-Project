## Behavior

`DATIndexVector::InsertNode` inserts a newly linked intrusive node into the bucket range selected by a four-byte FNV-1a key hash. The helper returns both the resulting node pointer and an inserted/duplicate flag through the caller-provided result object.

Important behavior from live Hex-Rays:

- Hashes exactly four bytes from the incoming key pointer with FNV-1a seed `0x811c9dc5`, multiplies by `16777619` after each byte, and masks with the vector field at object offset `+0x18`.
- Reads the bucket table pointer at object offset `+0x0c`, using two pointer slots per bucket: first at `bucket + 0x00` and last at `bucket + 0x04`.
- Uses the intrusive list sentinel at object offset `+0x04` and node links at `node + 0x00/+0x04`.
- Scans the selected bucket range backward from the bucket tail toward the bucket head looking for an existing node with the same 32-bit key at `node + 0x08`.
- On duplicate, unlinks the new node from the intrusive list, decrements the owning count at object offset `+0x08`, frees the new node through `sub_5C7526`, returns the existing node, and sets the inserted flag to `false`.
- On a new key, moves the new node before the scan point when needed, repairs neighboring `next`/`prev` links, and updates the bucket first/last pointers.
- After insertion, compares `nodeCount / bucketCount` against the float max-load field at object offset `+0x00`. If the load factor is too high, it grows the bucket count by `*8` below `0x200` buckets, otherwise by `*2` below `0x1fffffff`, calls [UID:0000WW][0x00423b00-0x00423c3d.DATIndexVectorResizeAndFill](by-memory/0x00423b00-0x00423c3d.DATIndexVectorResizeAndFill.md), and reinserts existing nodes through the self-call at `0x004572c2`.
- On success, returns the inserted node and sets the inserted flag to `true`.
