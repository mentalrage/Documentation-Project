## Range Summary

IDA does not currently model the starts in this span as functions, but disassembly shows function-shaped LodePNG code and the neighboring modeled function at `0x00444be0` is also LodePNG color-mode support.

| Range | Provisional source match | Evidence |
| --- | --- | --- |
| `0x00444740-0x00444af0` | `lodepng_error_text(unsigned code)` | Switch over error codes `0..94`, returning LodePNG/PNG/zlib diagnostic strings. The jump table lives inside this raw span at `0x00444a70`. |
| `0x00444af0-0x00444b13` | `lodepng_decompress_settings_init`-style zero initializer | Clears four dwords at `+0x00`, `+0x04`, `+0x08`, and `+0x0c`, matching the 20160501 `LodePNGDecompressSettings` fields. |
| `0x00444b20-0x00444b66` | `lodepng_compress_settings_init` | Writes defaults `btype=2`, `use_lz77=1`, `windowsize=0x800`, `minmatch=3`, `nicematch=0x80`, `lazymatching=1`, and null custom callbacks/context. |
| `0x00444b70-0x00444baf` | `lodepng_color_mode_init` | Writes color type `6`, bit depth `8`, clears palette/palette size, and clears transparent color-key fields. |
| `0x00444bb0-0x00444be0` | `lodepng_palette_clear` | Frees the palette pointer at `+0x08`, then clears palette pointer and palette size. |

The next modeled IDA function is `0x00444be0-0x00444c6d`, which matches `lodepng_color_mode_copy`: it clears/copies a color-mode struct, allocates `0x400` bytes when the source has a palette, copies `palettesize * 4` bytes, and returns error `0x53` on allocation failure.

## Boundary Notes

- The span ends at `0x00444be0`, where IDA resumes modeled LodePNG helper functions.
