# 0x004d1f30-0x004d2697 - ObjectStatusBlob Parsers

## Status

- Confidence: strong for exact function starts/ranges, caller families, callee set, parser byte counts, and global references; medium for final field names and source file path.
- Primary class: [UID:00009S][ObjectStatusBlob](by-class/ObjectStatusBlob.md)
- Proposed source file: [UID:0000M6][ObjectStatusBlob](by-file/ObjectStatusBlob.md)
- Evidence basis: `simroot_v2` metadata/source, older missing-ref report, and IDA MCP boundary/caller checks on 2026-05-24.

## Anchors

| Address range | Proposed method | Notes |
| --- | --- | --- |
| `0x004d1f30-0x004d1f99` | `ParseTaggedStatus` | Reads a status mode byte; mode `0` delegates to full status parsing, modes `1`/`2` read compact appearance data, other modes fail with `0`. |
| `0x004d1fa0-0x004d2637` | `ParseFullStatus` | Parses the full 43-byte status payload and normalizes title, palette, profile, equipment, object-type, and effect/status fields. |
| `0x004d2640-0x004d2697` | `ParsePartialStatus` | Parses reduced five-byte direction/posture/appearance state. |

## Caller Evidence

- IDA MCP 2026-06-01 `xrefs_to` confirms `ParseTaggedStatus` has broad direct callers in object-image/map/profile/look flows, including `0x00517dfd`, repeated caller sites in `0x00517f30`, `0x005198e0`, `0x0051b880`, `0x0051ca40`, `0x0051db40`, and object-dialog/image paths from `0x0054caf0` through `0x00553610`.
- IDA MCP 2026-06-01 `xrefs_to` confirms `ParseFullStatus` is called by `ParseTaggedStatus` at `0x004d1f8d`, map/object handlers at `0x0050fba3` and `0x00513354`, object-image/profile preview paths at `0x0056949b`, `0x00569540`, `0x005721e7`, and `0x00572294`, plus `UserLookPane` at `0x0059f8dc`.
- IDA MCP 2026-06-01 `xrefs_to` confirms `ParsePartialStatus` is called by the reduced-update caller family at `0x0050fbbc`, `0x0051336d`, `0x005694b1`, `0x0056956b`, `0x005721f9`, `0x005722b4`, and `0x0059f901`.

## IDA Evidence

- IDA MCP 2026-06-01 `lookup_funcs` confirms exact function sizes: `sub_4D1F30` is `0x69` bytes, `sub_4D1FA0` is `0x697` bytes, and `sub_4D2640` is `0x57` bytes. `0x004d1f99`, `0x004d2637`, and `0x004d2697` are not function starts.
- IDA MCP 2026-06-01 decompilation confirms `ParseTaggedStatus` switches on the first input byte: mode `0` calls `ParseFullStatus(input + 1)` and returns that result plus one, modes `1` and `2` set the blob mode, read a 16-bit appearance id from `input + 1`, read one byte from `input + 3`, and return `4`; other modes return `0`.
- IDA MCP 2026-06-01 decompilation confirms `ParseFullStatus` initializes mode `0`, default category/state values, reads a 43-byte payload, resolves title metadata when the title id is nonzero, remaps palette bits through the appearance remap table, normalizes special body/object ids, handles sentinel `0xffff` title/equipment states, and returns `43`.
- IDA MCP 2026-06-01 decompilation confirms `ParsePartialStatus` initializes compact mode `1`, default state `11`, byte `0x50`, reads two leading bytes, a 16-bit appearance id from `input + 2`, one byte from `input + 4`, and returns `5`.
- IDA MCP 2026-06-01 `callees` confirms byte/word readers at `0x00575470` and `0x00575480` are shared by all three parsers; `ParseFullStatus` additionally calls string helpers at `0x00421310`/`0x00421590`, formatter `0x0041b9b0`, metadata/table lookup `0x00523120`, and a wide string conversion helper.
- IDA MCP 2026-06-01 global/string review confirms the full parser references `byte_66DA97` for display-mode gating, `dword_69B410` for the metadata manager/table root, `dword_67A760` for appearance remap state, wide format string `"%d"` at `0x00610660`, and metadata/table text starting with `RidableAnimals` at `0x0061c2c4`.
- IDA MCP 2026-06-01 raw-byte audit confirms both internal gaps are pure alignment: `0x004d1f99-0x004d1fa0` contains seven `0xcc` bytes and `0x004d2637-0x004d2640` contains nine `0xcc` bytes.

## Boundary Notes

- This parser family is a shared object appearance/status structure. Do not reattach it to old `MenuCommandRecord` or one-dialog projections.
- Generated source repeats `ObjectStatusBlobFields` local declarations across methods; normalize that into one header/source definition during migration.
- Global dependencies include `g_displayMode`, `g_pAppearanceRemapTable`, `g_pMetaMan`, and `kStatusTitleMetaTableName`.
- `RECONSTRUCTABLE` is true because these are project-owned parser methods for [UID:00009S][ObjectStatusBlob](by-class/ObjectStatusBlob.md). `AUTOGEN_PARENT_UID` remains blank because [UID:0000M6][ObjectStatusBlob](by-file/ObjectStatusBlob.md) does not yet have a projected path in the validator registry.
- Leave `RECONSTRUCTION_CPP` blank until the 68-byte field layout and title/equipment member names are final-source quality.
