## IDA Evidence

- IDA MCP 2026-06-05 `lookup_funcs` confirms exact function sizes: `sub_4D1F30` is `0x69` bytes, `sub_4D1FA0` is `0x697` bytes, and `sub_4D2640` is `0x57` bytes. `0x004d1f99`, `0x004d2637`, and `0x004d2697` are not function starts.
- IDA MCP 2026-06-05 decompilation confirms `ParseTaggedStatus` switches on the first input byte: mode `0` calls `ParseFullStatus(input + 1)` and returns that result plus one, modes `1` and `2` set the blob mode, read a 16-bit appearance id from `input + 1`, read one byte from `input + 3`, and return `4`; other modes return `0`.
- IDA MCP 2026-06-05 decompilation confirms `ParseFullStatus` initializes mode `0`, default category/state values, reads a 43-byte payload, resolves title metadata when the title id is nonzero, remaps palette bits through the appearance remap table, normalizes special body/object ids, handles sentinel `0xffff` title/equipment states, writes offsets through `+64`, and returns `43`.
- IDA MCP 2026-06-05 decompilation confirms `ParsePartialStatus` initializes compact mode `1`, default state `11`, byte `0x50`, reads two leading bytes, a 16-bit appearance id from `input + 2`, one byte from `input + 4`, and returns `5`.
- IDA MCP 2026-06-05 `callees` confirms byte/word readers at `0x00575470` and `0x00575480` are shared by all three parsers; `ParseFullStatus` additionally calls string helpers at `0x00421310`/`0x00421590`, formatter `0x0041b9b0`, metadata/table lookup `0x00523120`, and a wide string conversion helper.
- IDA MCP 2026-06-05 global/string review confirms the full parser references `byte_66DA97` for display-mode gating, `dword_69B410` for the metadata manager/table root, `dword_67A760` for appearance remap state, wide format string `"%d"` at `0x00610660`, and metadata/table text starting with `RidableAnimals` at `0x0061c2c4`.
