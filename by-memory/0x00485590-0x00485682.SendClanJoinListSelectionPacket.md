## Behavior

`ClanStatusPane::SendClanJoinListSelectionPacket(const wchar_t *selectedClanName)` accepts a borrowed wide string from the selected clan join-list row, computes its character length, writes packet header `{ 0x4b, 2, 1 }`, converts the wide string to CP_ACP bytes with `WideCharToMultiByte`, stores the converted byte length, appends the converted payload, and sends `convertedLength + 4` bytes through [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md) using [UID:0000Q5][g_packetSender](by-global/g_packetSender.md) / [UID:0001P0][0x0067a7ec-0x0067a7f0.g_packetSender](by-memory/0x0067a7ec-0x0067a7f0.g_packetSender.md). The body does not dereference `this`, but both callers set `ECX = g_pClanStatusPane`, matching the accepted subtype-6 packet helper pattern on [UID:00021K][0x00485960-0x00485abe.ClanEnlistListRefreshAndSelectionPacketHelpers](by-memory/0x00485960-0x00485abe.ClanEnlistListRefreshAndSelectionPacketHelpers.md).

Packet layout:

| Offset | Sent? | Contents |
| --- | --- | --- |
| `0` | yes | opcode `0x4b`, Clan outbound request/action packet family |
| `1` | yes | subtype `2`, join-list family |
| `2` | yes | action `1`, selected join-list row/clan-name submission |
| `3` | yes | converted multibyte payload byte length |
| `4..(4+length-1)` | yes | CP_ACP converted selected-row/clan-name bytes |
| `4+length` | no | local packet terminator/scratch byte excluded from `QueueAndSendPacket` length |

The stack packet buffer writes a zero byte at offset `convertedLength + 4` after the payload, but the queued length is exactly `convertedLength + 4`, so that local terminator/padding byte is not sent.

Range checks fail through `___report_rangecheckfailure` if the converted string reaches `0x100` bytes or if the final packet length reaches `0x80` bytes.

IDA disassembly computes the wide-character count manually and passes the sign-extended low byte (`movsx eax, bl`) as `cchWideChar` to `WideCharToMultiByte`. Treat this as real legacy signed-byte behavior, not a decompiler artifact: it likely reflects source storing the wide count in a `char`/low-byte variable because the protocol uses one-byte string lengths. The first-draft C++ intentionally preserves this edge case rather than replacing it with a full `wcslen`/`-1` conversion.
