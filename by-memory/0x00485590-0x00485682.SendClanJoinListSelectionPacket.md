## Behavior

The helper accepts a wide string from the selected clan-list row, computes its character length, writes packet header `{ 0x4b, 2, 1 }`, converts the wide string to a multibyte string with `WideCharToMultiByte`, stores the converted byte length, appends the converted payload, and sends `convertedLength + 4` bytes through [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md) using `dword_67A7EC`.

Packet layout:

| Offset | Contents |
| --- | --- |
| `0` | opcode `0x4b` |
| `1` | subtype `2` |
| `2` | action `1` |
| `3` | converted string byte length |
| `4..(4+length-1)` | converted selected-row text bytes |

The stack packet buffer writes a zero byte at offset `convertedLength + 4` after the payload, but the queued length is exactly `convertedLength + 4`, so that local terminator/padding byte is not sent.

Range checks fail through `___report_rangecheckfailure` if the converted string reaches `0x100` bytes or if the final packet length reaches `0x80` bytes.

IDA disassembly computes the wide-character count manually and passes the sign-extended low byte (`movsx eax, bl`) as `cchWideChar` to `WideCharToMultiByte`; keep this width caveat in mind until final source signatures and length policy are audited across the clan packet helper family.
