## Behavior

IDA decompilation on 2026-06-01:

```c
int __stdcall sub_4D15D0(void **Block)
{
  sub_516030();
  if ( Block[2] )
    sub_516170(Block[2]);
  return sub_516170(Block);
}
```

The helper initializes/obtains the memory manager, frees the owned payload pointer at `block + 0x08` when present, then frees the outer block. Existing generated names describe this as destroying an owned image block; IDA confirms that the helper is shared by destructors that own image/frame resources.

Live disassembly on 2026-06-06 shows the exact control flow:

- call `0x00516030` once and keep the returned memory-manager/context pointer in `esi`;
- load the input block pointer into `edi`;
- test `*(block + 0x08)`;
- when the nested payload pointer is non-null, call `0x00516170` with that nested pointer using the same context pointer in `ecx`;
- always call `0x00516170` on the outer block pointer;
- return with `ret 4`.
