# 0x004db010-0x004db0f7 MonsterImageLib Destructor

## Status

- Confidence: strong for body boundaries, cleanup order, parent ownership, vtable/singleton refs, and scalar-deleting destructor parity; medium for final field names.

## Behavior

This is the ordinary non-deleting destructor for `MonsterImageLib`. The scalar deleting destructor at `0x004e6750-0x004e6860` repeats the same cleanup sequence and then optionally calls `operator delete`.

Cleanup sequence:

1. Restore the [UID:0001Y7][MonsterImageLibVtable](by-type/by-vtable/MonsterImageLibVtable.md) at `this + 0x00`.
2. Call `MonsterImageLib::ClearLoadedData` at `0x004dc2e0`.
3. Destroy and free the 0x0c-byte [UID:0001VC][MonsterImageEntry](by-type/by-struct/MonsterImageEntry.md) vector at object offset `+0x04`.
4. Destroy the two embedded [UID:00003K][DATIndexVector](by-class/DATIndexVector.md)-style cache tables at object offsets `+0x3c` and `+0x1c`.
5. Free the archive-offset vector at object offsets `+0x10`, `+0x14`, and `+0x18`, then zero those fields.
6. Tail-call the base `LObject` cleanup at `0x004f4a90`.
7. Clear [UID:0000RR][g_pMonsterImageLib](by-global/g_pMonsterImageLib.md) at `0x0069b440`.
