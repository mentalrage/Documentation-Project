## Ownership Analysis

Best owner: [UID:0000IE][Config](by-file/Config.md). The helper is not a `Config::` method because callers pass it as a function pointer and it receives one entry record, not the `Config` object. It still belongs to the `Config.cpp` source family because the entry record is the private storage type built by `Config::Config`, destroyed by the Config/RegistryConfig cleanup paths, and documented with [UID:000032][ConfigEntryBlock](by-class/ConfigEntryBlock.md).

Rejected owner: [UID:0000N4][RegistryConfig](by-file/RegistryConfig.md). RegistryConfig consumes the entry storage through inherited config behavior, but IDA shows the initializer is first anchored by the base Config constructor and by the shared server-select parsing path, not by registry persistence.

Rejected owner: the `sub_4F6D80` server-select/session handler. It uses the helper for temporary records, but that is a consumer edge to a shared config-entry helper rather than source ownership.
