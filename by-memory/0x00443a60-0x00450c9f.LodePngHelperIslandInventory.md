# LodePNG Helper Island Inventory `0x00443a60-0x00450c9f`

## Status

- Disposition: bundled third-party library code, provisional span
- Proposed owner: [UID:0000KW][LodePNG](by-file/LodePNG.md)
- Confidence: strong that the anchors are LodePNG; strong that the old `0x00450ca0-0x00456031` tail is not wholly LodePNG.
- Evidence basis: read-only IDA MCP `py_eval`, `lookup_funcs`, `strings`, `xrefs_to`, and `disasm` checks on 2026-05-24 and 2026-05-25. `wave3.py` was not executed for this pass.

## Summary

IDA-modeled function inventory shows a dense helper island starting before the known encode front end at `0x00443c80` and continuing through the local helper at `0x00450b60-0x00450c9f`. The direct IDA callgraph rooted at `0x00443c80`, `0x00443db0`, `0x00443e40`, and `0x004466b0` reaches 73 modeled helper functions through `0x00450b5e`; a follow-up caller pass shows `0x00450b60-0x00450c9f` is still called from LodePNG-local/raw helpers.

The older provisional `0x00443a60-0x00456031` span was too wide. `0x00450ca0` is already documented as [UID:0000XK][0x00450ca0-0x0045381b.MiniMapDialog](by-memory/0x00450ca0-0x0045381b.MiniMapDialog.md), and `0x00453df0-0x004563b5` is already documented as [UID:0000XO][0x00453df0-0x004563b5.MiniMapRendererAndControls](by-memory/0x00453df0-0x004563b5.MiniMapRendererAndControls.md). Several functions in the old tail also have direct callers from product UI, metadata, audio/vector, and menu code, so they must not be folded into `third_party/lodepng.cpp`.

Do not move this island into screenshot, DAT/archive, or generic render source just because the visible project-facing caller is screenshot PNG output.

## Raw Boundary Caveat

IDA `lookup_funcs` reports `0x00444740`, `0x00444af0`, `0x00444b20`, `0x00444b70`, and `0x00444bb0` as `Not a function`.

Disassembly still shows function-shaped code:

- `0x00444740`: switch over roughly 95 LodePNG error codes returning PNG/zlib/LodePNG error strings.
- `0x00444932` and `0x00444939`: switch cases returning `LODEPNG_COMPILE_ZLIB` and `LodePNGEncoderSettings.filter_strategy` error text.
- `0x00444af0`: clears four dwords in a small decompression-settings/default record.
- `0x00444b20`: initializes compression settings such as method/window/filter defaults.
- `0x00444b70`: initializes output color defaults including color type `6` and bit depth `8`.
- `0x00444bb0`: frees/resets palette heap storage before the next modeled function at `0x00444be0`.

This is a Wave3/IDA boundary issue, not evidence that the bytes are data-only or project-owned code.

## Excluded Old Tail

The old provisional tail `0x00450ca0-0x00456031` is now excluded from the LodePNG island. IDA MCP and existing docs identify this region as MiniMap and shared support code:

- `0x00450ca0-0x0045381b`: [UID:0000XK][0x00450ca0-0x0045381b.MiniMapDialog](by-memory/0x00450ca0-0x0045381b.MiniMapDialog.md).
- `0x00453df0-0x004563b5`: [UID:0000XO][0x00453df0-0x004563b5.MiniMapRendererAndControls](by-memory/0x00453df0-0x004563b5.MiniMapRendererAndControls.md).
- External caller sweep examples: `0x004536e0` is used by mail/help/static-text style paths, `0x00453740` is used by [UID:000088][MetaMan](by-class/MetaMan.md), `0x00455060` and related helpers are used by MiniMap plus menu/status UI vector cleanup paths, and `0x00455b40` is used by menu-variety and user-status pane cleanup paths.

This correction means LodePNG should be treated as a bounded library island ending at `0x00450c9f`, while the following MiniMap/control helper islands retain their existing file-level owners.

## String Evidence

IDA string and xref checks tie the island to LodePNG:

- `LodePNG` at `0x0060f538` is referenced from `0x004466b0`.
- Version string `20160501` at `0x0060f4c0` is referenced through a text-chunk data pointer at `0x0066d000`, matching the obtained upstream `20160501` source's optional LodePNG identifier chunk path.
- `must provide custom zlib function pointer if LODEPNG_COMPILE_ZLIB is not defined` is referenced from the raw switch body around `0x00444932`.
- `invalid filter strategy given for LodePNGEncoderSettings.filter_strategy` is referenced from the raw switch body around `0x00444939`.
- RTTI-ish strings `.?AULodePNGState@@` and `.?AVState@lodepng@@` exist near `0x00674248` and `0x00674264`.

## Source-Structure Decision

Keep `0x00443a60-0x00450c9f` as the current `third_party/lodepng.cpp` helper-island candidate. Source comparison now shows the visible PNG file helpers at `0x00443db0` and `0x00443e40` are stock LodePNG public APIs, so they should not be moved to [UID:0000K4][ImageWriters](by-file/ImageWriters.md).

Before final source migration, split this inventory into exact per-function LodePNG names where possible and keep the MiniMap/control ranges starting at `0x00450ca0` outside the LodePNG module.
