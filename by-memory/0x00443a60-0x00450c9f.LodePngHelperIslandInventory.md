## Raw Boundary Caveat

IDA `lookup_funcs` reports `0x00444740`, `0x00444af0`, `0x00444b20`, `0x00444b70`, and `0x00444bb0` as `Not a function`.

Live IDA MCP lookup on 2026-06-05 reconfirmed those raw starts as not IDA-modeled functions. Byte sampling at the same starts still begins with normal function prologues, while `0x00444be0`, `0x004460f0`, `0x004466b0`, `0x00448520`, `0x00450030`, and `0x00450b60` remain modeled functions inside the island.

Disassembly still shows function-shaped code:

- `0x00444740`: switch over roughly 95 LodePNG error codes returning PNG/zlib/LodePNG error strings.
- `0x00444932` and `0x00444939`: switch cases returning `LODEPNG_COMPILE_ZLIB` and `LodePNGEncoderSettings.filter_strategy` error text.
- `0x00444af0`: clears four dwords in a small decompression-settings/default record.
- `0x00444b20`: initializes compression settings such as method/window/filter defaults.
- `0x00444b70`: initializes output color defaults including color type `6` and bit depth `8`.
- `0x00444bb0`: frees/resets palette heap storage before the next modeled function at `0x00444be0`.

This is a Wave3/IDA boundary issue, not evidence that the bytes are data-only or project-owned code.
