# 0x0067a938-0x0067a940 ApplicationLifecycleFlags

## Summary

- Address range: `0x0067a938-0x0067a940`
- Entity kind: application lifecycle flags
- Proposed name: `ApplicationLifecycleFlags`
- Disposition: reconstructable NexusTK global data
- Confidence: strong for ownership and roles, medium for final enum names

This pair of dwords stores the process-level Application phase code and the exact four-byte windowed-versus-exclusive display-mode state used by initialization, activation, input/window dispatch, ScreenPane presentation, and DirectDraw restoration paths.

## Layout

| Range | Provisional source name | Provisional role |
| --- | --- | --- |
| `0x0067a938-0x0067a93c` | `ApplicationPhaseState` | Application phase/state code written by initialization and startup-mode transitions. |
| `0x0067a93c-0x0067a940` | `g_isWindowedDisplayMode` | Four-byte state derived from registry `DisplayMode`: nonzero selects `DDSCL_NORMAL` windowed presentation, while zero selects exclusive display mode and `BltFast`. |

## Evidence

- Live IDA MCP on 2026-06-14 (`a001_goal2_class_batch`, `NexusTK.exe`) rechecked the exact eight-byte span as zero-initialized writable `.data` storage and confirmed five direct refs to the phase/state dword: `Application::Initialize` at `0x004639d0` writes phase value `1`, startup-mode helpers at `0x004f6700` and `0x00504110` write phase values `2` and `3`, another startup/teardown-adjacent helper at `0x004f6490` writes phase value `4`, and diagnostic code at `0x004ab870` reads the current phase.
- The display-mode dword has initialization refs at `0x004639d0`, a helper at `0x00465d30`, window/input dispatch at `0x00465f20`, activation/deactivation handlers at `0x004669c0` and `0x00466a70`, plus UI/server-side readers in the `0x004a8b40`, `0x004fb2d0`, `0x00556a60`, `0x00557470`, `0x005576a0`, `0x00558840`, and `0x005595d0` families.
- B005's 2026-06-23 [UID:00039R][0x005576a0-0x00557810.SurfaceDirectDrawRestoreMaintenance](by-memory/0x005576a0-0x00557810.SurfaceDirectDrawRestoreMaintenance.md) implementation names the `0x005576a0` reader family as `ScreenPane::RestoreDirectDrawState()`. It tests this dword as part of exclusive display-mode restoration; [UID:0003A4][0x005595d0-0x00559a0f.BlitSurfaceToDisplay](by-memory/0x005595d0-0x00559a0f.BlitSurfaceToDisplay.md) gives the decisive polarity by selecting windowed paths when nonzero and exclusive `BltFast` when zero.
- The 2026-06-14 xref pass reports `0x0067a938` with five xrefs and `0x0067a93c` with eighteen xrefs, all as data references into the two static dwords. The live bytes are eight zero bytes, matching zero-initialized writable runtime state rather than a constant table.
- Current decompilation of `Application::Initialize` at `0x004639d0` assigns the phase value and derives `0x0067a93c` from registry `DisplayMode`: accepted value `1` enters `DDSCL_NORMAL`/windowed setup, while zero uses exclusive cooperative level and display mode. The old `ApplicationActiveGate` description conflated those display semantics with general lifecycle activity and is superseded.
- Existing Application lifecycle documentation ties the same initialization, shutdown, diagnostics, and message-dispatch families to the process-level app shell, supporting the [UID:0000HG][Application](by-file/Application.md) parent attachment.
