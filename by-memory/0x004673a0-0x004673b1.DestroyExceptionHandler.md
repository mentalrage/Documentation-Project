The range is half-open. IDA MCP `lookup_funcs` reports size `0x11`; `0x004673b1` is not inside a function.

## Behavior

Final C++ reconstruction should prefer the source-level delete form:

```cpp
delete g_pCrashTarget;
```

The compiler-level behavior is:

```cpp
if (g_pCrashTarget != nullptr) {
    g_pCrashTarget->ScalarDeletingDestructor(1);
}
```

IDA's decompiler leaves an uninitialized `result` return when the global is null. That is a decompiler artifact of this tiny helper and should not be modeled as meaningful source behavior.

The helper does not clear [UID:0000QN][g_pCrashTarget](by-global/g_pCrashTarget.md) after deleting it; callers that need a null assignment must do that separately.

## Ownership Decision

Document this as cleanup glue around the active crash handler, not as normal exception-filter teardown. The [UID:0000J8][ExceptionHandler](by-file/ExceptionHandler.md) class and [UID:0000QN][g_pCrashTarget](by-global/g_pCrashTarget.md) remain owned by `platform/ExceptionHandler.cpp`; final source reconstruction can keep this helper local to application/resource-failure cleanup if later naming evidence supports that.
