## IDA MCP Evidence

Checked on 2026-05-25 and 2026-05-26:

- `lookup_funcs` reports `0x00530c78` and `0x00530c83` as real functions with size `0xb`.
- `decompile 0x00530c78` forwards to `0x00530c90` after subtracting `160` bytes from `this`.
- `decompile 0x00530c83` forwards to `0x00530c90` after subtracting `164` bytes from `this`.
- `xrefs_to` reports vtable/data refs at `0x00620234` and `0x00620264`.
- `xrefs_to 0x00530c90` includes code refs from both thunks and the scalar deleting destructor vtable data ref at `0x6201d4`.
- `callers 0x00530c90` reports no ordinary caller list even though the thunk code xrefs exist, matching vtable-only destructor dispatch.
- IDA's temporary `boost::exception` type in decompiler output is type pollution; the target is the documented `NumberInputDialog` scalar deleting destructor.
- 2026-06-06 IDA MCP reconfirms both thunk functions as size `0xb`, with bytes `81 e9 a0 00 00 00 e9 0d 00 00 00` and `81 e9 a4 00 00 00 e9 02 00 00 00`.
- 2026-06-06 xrefs reconfirm vtable data refs at `0x00620234` and `0x00620264`, plus code refs from `0x00530c7e` and `0x00530c89` into `0x00530c90`.
- 2026-06-06 boundary bytes show only two `0xcc` bytes at `0x00530c8e-0x00530c90` before the scalar deleting destructor.

## Ownership Decision

These are compiler/vtable support thunks for `NumberInputDialog`, not source-level feature methods. They should be recognized as reviewed compiler glue rather than left as bad/missing generated data or reconstructed as handwritten methods.

The scalar deleting destructor at `0x00530c90-0x00530cf7` remains reconstructable; only these `this`-adjusting wrappers are excluded from source reconstruction.
