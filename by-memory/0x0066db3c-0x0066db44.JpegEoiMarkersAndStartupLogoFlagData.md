# 0x0066db3c-0x0066db44 JPEG EOI Markers And Startup Logo Flag Data

## Summary

- Address range: `0x0066db3c-0x0066db44`
- Entity kind: mixed small initialized data
- Disposition: reconstructable project data with adjacent-owner caveat
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong for bytes, xrefs, and immediate consumers; medium for final source-file grouping because image decode, JPEG screenshot, and startup-logo code all receive adjacent declarations.

This eight-byte island contains two `FF D9` JPEG End Of Image marker pairs used as two-byte fallback buffers, followed by the startup-logo Bink midpoint-restart flag byte at `0x0066db42`. The bytes are adjacent rather than one coherent source object, so preserve the range as a small mixed-data island until the final linker/source declaration order is known.

## Reconstruction Notes

- Do not collapse this range into `HourPane` solely because it follows [UID:00027K][0x0066db04-0x0066db3c.HourPaneFrameTable](by-memory/0x0066db04-0x0066db3c.HourPaneFrameTable.md). No xrefs tie these bytes to `HourPane`.
- The `FF D9` pairs should be documented as JPEG EOI marker fallback storage, not generic short strings.
- Final source may express this range as separate file-local declarations in different compilation units that the linker placed adjacently:

```cpp
static unsigned char g_jpegDecodeFakeEoi[2] = { 0xFF, 0xD9 };
static unsigned char g_jpegScreenshotFakeEoi[2] = { 0xFF, 0xD9 };
static bool g_restartStartupLogoBinkAtMidpoint = true;
```

- Keep the first marker with image decode/JPEG source-manager support, the second marker with screenshot JPEG writer callbacks, and the flag with startup-logo Bink playback state. This page is the address-level bridge documenting why those source declarations share an eight-byte binary neighborhood. The markers are written as non-`const` above because the observed bytes live in writable `.data`; no direct writes to the marker bytes have been found.
- The final build does not need these exact addresses, but it does need equivalent source declarations and initialized values so the JPEG callback and startup-logo behavior are preserved.
