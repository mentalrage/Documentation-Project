# 0x00421480-0x004214bb ScrollPane Family Scalar Deleting Destructor

## Status

- Address range: `0x00421480-0x004214bb`
- Entity kind: method / shared scalar deleting destructor
- Proposed owner: shared `ScrollPane` / `FittingRoomScrollPane` family, with reuse by ranking and inventory scroll panes
- Disposition: source-declared/generated-binary support for multiple scroll-pane classes
- Rebuild handling: compiler-generated deleting-destructor wrapper caused by class declarations and base destructor calls
- Confidence: strong for behavior and vtable reuse; medium for final canonical source owner.

## Behavior

This is a compact scalar deleting destructor body for scroll-pane-like classes whose own destructor body does not add class-specific teardown beyond the shared pane-base destructor. It calls `0x00544580` for the base pane cleanup and conditionally calls `0x004f4ac0` to free the object when the MSVC deleting-destructor flags request deletion.

Unlike [UID:0002DX][0x00421410-0x00421477.FittingRoomListPaneScalarDeletingDestructor](by-memory/0x00421410-0x00421477.FittingRoomListPaneScalarDeletingDestructor.md), this body does not restore class-specific vtables or release an owned scroll child. It is referenced by several scroll-pane vtables and secondary-base adjustor thunks.

## Raw Code Evidence

IDA MCP decompilation on 2026-05-30 shows the whole body:

- `sub_544580(this)`;
- if `(flags & 1) != 0` and `(flags & 4) == 0`, call `sub_4F4AC0(this)`;
- return `this`.

IDA data references include `0x0060dc88`, `0x00610a4c`, `0x00623d5c`, `0x00623e94`, `0x00623f1c`, `0x00623fa4`, `0x0062402c`, and `0x006240b4`. Fitting-room secondary/tertiary vtable thunks at `0x004213f8` and `0x00421403` also forward here.
