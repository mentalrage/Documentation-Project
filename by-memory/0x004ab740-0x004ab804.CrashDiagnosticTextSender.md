## Behavior

This helper sends a short diagnostic text record through the normal packet-send path. IDA decompilation shows it:

- gets the MemoryMan singleton/context through [UID:0001BC][0x00516030-0x00516036.GetMemoryMan](by-memory/0x00516030-0x00516036.GetMemoryMan.md) before building the stack packet buffer;
- measures the input ANSI text with `strlen`;
- accepts only byte lengths `1..0xFFF` / `1..4095` and rejects the empty string plus any string of length `0x1000` / `4096` or greater; it does not truncate overlong strings;
- writes packet fields opcode `0x42` / ASCII `B`, subtype `1`, a two-byte big-endian length, the raw ANSI source bytes, and a trailing zero byte;
- sends exactly `length + 5` bytes from the stack buffer through [UID:0000Q5][g_packetSender](by-global/g_packetSender.md).

The accepted payload shape is:

| Offset | Source-facing writer | Meaning |
| --- | --- | --- |
| `0` | `PacketBufferWriteUInt8(0x42, packet)` | Crash/diagnostic packet opcode. |
| `1` | `PacketBufferWriteUInt8(1, packet + 1)` | Diagnostic text subtype. |
| `2..3` | `PacketBufferWriteUInt16BE(length, packet + 2)` | ANSI payload byte length, excluding trailing zero. |

Empty strings are rejected because the unsigned `length - 1` test fails. Accepted strings therefore have byte length `1..0xFFF`, and the queued packet length is `length + 5`.
