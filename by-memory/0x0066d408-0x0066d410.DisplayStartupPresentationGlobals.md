# 0x0066d408-0x0066d410 Display Startup Presentation Globals

## Summary

- Address range: `0x0066d408-0x0066d410`
- Entity kind: initialized writable global data
- Disposition: reconstructable project data
- Rebuild handling: `source-declared/generated-binary`
- Direct parent decision: [UID:0000HG][Application](by-file/Application.md)

This exact child covers the two display startup globals at the front of the former mixed [UID:000275][0x0066d408-0x0066d414.DisplayStartupAndPasswordGuardGlobals](by-memory/0x0066d408-0x0066d414.DisplayStartupAndPasswordGuardGlobals.md) aggregate. ## Evidence

- Prior IDA-backed target documentation records bytes at `0x0066d408` as `00 04 00 00 01 00 00 00`, matching the two initialized dwords in this child.
- Prior IDA xrefs to `xRight` are `0x00463da7` and `0x004642f3` in `Application::Initialize` (`0x004639d0`). The documented write path clamps the configured width, aligns it with `and eax, 0FFFFFFFCh`, then stores the result.
- Prior IDA xrefs to `dword_66D40C` are `0x00463dbe`, `0x00463dde`, and `0x005597b4`. The first two are in `Application::Initialize` and implement default/validated startup selection; `0x005597b4` is a consumer read in `BlitSurfaceToDisplay` inside the SurfacePresentation aggregate.
- The [UID:0002H0][0x004639d0-0x00464a52.ApplicationInitialize](by-memory/0x004639d0-0x00464a52.ApplicationInitialize.md) page documents display configuration as an `Application::Initialize` startup phase: reads `DisplayMode`, `WindowWidth`, and `DrawType`, clamps/aligns windowed width, and validates `DrawType` values `1..3`.
