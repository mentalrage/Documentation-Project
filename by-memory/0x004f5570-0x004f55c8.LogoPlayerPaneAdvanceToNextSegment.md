# 0x004f5570-0x004f55c8 LogoPlayerPane Advance To Next Segment

## Status

- Disposition: reconstructable NexusTK project code.
- Entity kind: member method.
- Rebuild handling: source-authored `LogoPlayerPane` method.
- Owner class: [UID:00007H][LogoPlayerPane](by-class/LogoPlayerPane.md).
- Parent aggregate: [UID:00019D][0x004f53b0-0x004f570c.LogoPlayerPane](by-memory/0x004f53b0-0x004f570c.LogoPlayerPane.md).

## Behavior

`LogoPlayerPane::AdvanceToNextSegment()` handles user-requested advancement from the first startup movie segment to the next segment. It checks the one-shot guard `m_hasRequestedSegmentAdvance` at `LogoPlayerPane +0x110` and inherited Bink playback progress through `VideoPlayerPane::m_binkHandle` at `+0xfc`; if the pane is still eligible to advance, it computes the second segment pointer from the embedded AUTOBUF base plus the saved first-segment size, marks the guard, and calls the inherited protected `VideoPlayerPane::OpenBinkVideo(const void *segmentData, unsigned int segmentSize)` helper at `0x005c0110`.

The second segment pointer is `m_movieData.m_data + 4 + m_firstSegmentSize`, where the AUTOBUF payload pointer is read from `+0x104` and the first segment size from `+0x114`. The remaining byte count passed to `OpenBinkVideo` is `m_movieData.m_count - m_firstSegmentSize - 4`, with the loaded payload count read from `+0x108`. The first four bytes of the payload are the first Bink segment size, matching the segmented startup-logo media contract documented by [UID:0001RN][startup-logo-media](by-resource/startup-logo-media.md).

If the second segment opens, the raw body tail-jumps through primary vtable slot `+0x48`; both `LogoPlayerPane` and `VideoPlayerPane` vtables point that slot at `0x005c01f0`, now modeled as inherited `VideoPlayerPane::StartPlayback()`. If opening fails, it tail-jumps to [UID:0001EA][0x00544460-0x00545086.PaneCore](by-memory/0x00544460-0x00545086.PaneCore.md)'s `0x00544690` mark-for-deletion helper. The guard is set before the open attempt, so a failed skip still prevents repeated reopen attempts.

## Source-Quality Decisions

- Use `LogoPlayerPane::AdvanceToNextSegment()` as the source-facing method name. `SkipToNextSegment` describes the key/mouse caller policy, but this body owns the transition, open failure handling, and playback restart.
- Use `m_hasRequestedSegmentAdvance` for `+0x110`. `m_hasAdvancedToNextSegment` is weaker because the byte is set before `OpenBinkVideo`; failed opens still consume the attempt.
- Use `m_firstSegmentSize` for `+0x114`, `m_movieData.m_data` for `+0x104`, and `m_movieData.m_count` for `+0x108`. The constructor reads the first payload dword into `+0x114`, opens `m_movieData.m_data + 4`, and this target opens `m_movieData.m_data + 4 + m_firstSegmentSize`.
- Model `BINK +0x0c` as `FrameNum` / current frame. [UID:00022U][0x004f5ae0-0x004f5b1e.TryAdvanceStartupLogoBinkSegment](by-memory/0x004f5ae0-0x004f5b1e.TryAdvanceStartupLogoBinkSegment.md) compares the same field against half of `BINK +0x08`, and `VideoPlayerPane::OnIdle` compares it against `BINK +0x08`, supporting `BINK +0x08` as `Frames` / total frame count.
- Model vtable slot `+0x48` as inherited `VideoPlayerPane::StartPlayback()`. The `LogoPlayerPane` primary slot at `0x0061d060` and `VideoPlayerPane` primary slot at `0x00631094` both point to `0x005c01f0`, which sets active/playback bytes and calls the pane refresh slot.
- Keep `0x005c0110` as protected `VideoPlayerPane::OpenBinkVideo(const void *segmentData, unsigned int segmentSize)`. The second argument is retained because both known callers pass a size even though the recovered helper body does not consume it before `BinkOpen`.
