# 0x0069bec4-0x0069bec8 g_browserControlKeyCallback

## Status

- Disposition: reconstructable global-data callback pointer / browser consumer alias.
- Entity kind: function-pointer-like callback storage.
- Proposed owner: unresolved app/transport callback storage; browser is a consumer, but transport/network refs dominate.
- Global doc: [UID:0000PT][g_browserControlKeyCallback](by-global/g_browserControlKeyCallback.md)
- Confidence: strong for address, size, and callback role; medium for final owner/name.

## Storage

`0x0069bec4-0x0069bec8` is the four-byte `.data` item IDA names `dword_69BEC4`.

Generated browser sources name it `g_browserControlKeyCallback` or `g_pTransportCallback` depending on context. Browser code uses it for Tab/Escape forwarding, but the wider xref set argues against browser-owned storage.

## Evidence

- IDA MCP `py_eval` reports the data item at `0x0069bec4` as `dword_69BEC4`, size `4`, in `.data`.
- IDA reports 17 direct xrefs.
- 2026-05-26 IDA `py_eval` recheck confirms the initial value is `0xffffffff`. Xrefs include one modeled startup/setup write at `0x0041a474`, two raw writes at `0x005997ae` and `0x005999e4`, browser calls at `0x0046f0e6` and `0x0046f34d`, and transport/socket calls in `0x005747e0`, `0x005749e0`, `0x00575e60`, `0x00576660`, `0x00576d90`, and `0x005795a0`.
- Browser refs are limited to `0x0046f0e6` in `BrowserThread::RunMessageLoop` and `0x0046f34d` in `BrowserControlPaneOld::HandleBrowserMessage`.
- Non-browser refs include startup/setup `0x0041a474`, transport/network-family refs `0x0057498c`, `0x005749a5`, `0x005749bf`, `0x00574a79`, `0x00574a93`, `0x00576033`, `0x005767f5`, `0x00576b57`, `0x00576e15`, `0x00576eba`, `0x00579640`, `0x0057965a`, `0x005997ae`, and `0x005999e4`.

## Disposition

Keep this outside browser ownership. Browser docs should link here as a consumer note, not as proof that `Browser.cpp` declares the storage. The storage should be reconstructed as an app/transport callback once the startup/raw writer sites are named.
