## Split Decision

This physical range is intentionally retained as a reviewed split/index page because it mixes reward-container source semantics lowered into compiler/STL helper bodies with compiler/header formatting support. The reward vector children belong to `RankingRewardInfoDialog`, while fixed-`0x100` UID0003X8 has ranking paint, screenshot JPG/BMP/PNG, and user-list callers but no project owner/emitter. Its exact local-options/`___stdio_common_vswprintf_s` body and secure array-overload source shape classify it as non-emitting MSVC/UCRT support. No direct final C++ should be emitted from this aggregate.

The final C++ for the reward children should model:

```c++
struct RankingRewardItem {
    wchar_t name[256];
    int quantity;
    unsigned short iconId;
    unsigned char paletteIndex;
    unsigned char reserved_207;
};

struct RankingRewardEntry {

    wchar_t rankEndText[8];
```

Natural four-byte alignment inserts the two bytes at `+0x222..+0x223`, preserving `items` at `+0x224` and `sizeof(RankingRewardEntry) == 0x230` without an explicit member. The accepted source container is `std::vector`: UID0000BP emits both vector aliases, UID0001ZF emits `items.push_back(item)`, and UID0001ZH emits `m_rewardEntries.push_back(entry)`. UID0003X6 and UID0003X7 carry formal covered-by markers instead of duplicate growth C++, and UID0003X9 now carries the matching formal covered-by marker instead of a standalone copy-constructor body. Its exact empty/allocation/contiguous-copy/publication/failure behavior is compiler/STL lowering regenerated from the same UID0001ZH outer append and implicit entry copy. UID0003X8's non-emitting compiler/UCRT classification is unchanged; the `0x0045ef20` formatting wrapper remains outside reward-container source despite physical adjacency.
