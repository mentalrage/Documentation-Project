Decoded behavior:

1. Load signed 32-bit `recordIndex` from `[ebp+8]`.
2. Return without side effects when `recordIndex < 0`.
3. Compare `recordIndex` against `m_movementHistoryCapacity` at `this+0x13eb18`.
4. Return without side effects when `recordIndex >= m_movementHistoryCapacity`.
5. Load `m_movementHistoryRecords` from `this+0x13eb14`.
6. Compute `recordIndex * 0x10` by doubling `edx` and using scaled addressing `edx*8`.
7. Store zero only to `records[recordIndex].active`.
8. Return `void` with `ret 4`.

This helper has no record-pointer null guard. Capacity zero rejects every nonnegative index; a negative capacity also rejects every nonnegative index because the comparison is signed. The two known callers pass a widened low-seven-bit packet byte, but the helper itself accepts a signed dword and explicitly rejects negative values, so `int recordIndex` is the correct source-facing parameter type.
