## Behavior

This helper parses one JsonCpp item object into a 0xc0-byte fitting-room category entry. The caller allocates the entry, preinitializes the category id and part-vector triplet, then calls this parser for each JSON array element in one item-shop category.

Confirmed parsed field names include:

- `name`
- `tile`
- `color`
- `items`
- `part`
- `gender`

The function starts by defaulting the item name path to `None`, then performs repeated JsonCpp field lookups and copies values into the entry. If the parsed name remains exactly `None`, the helper frees the temporary string and returns `false` without inserting the entry. Otherwise it copies the name into the entry buffer, parses the top-level tile/color fields, and then builds a nested vector of per-part records under the entry tail. The small per-part record lookup helper at [UID:0002E5][0x00421fe0-0x0042201c.FittingRoomCatalogEntryPartLookup](by-memory/0x00421fe0-0x0042201c.FittingRoomCatalogEntryPartLookup.md) reads those records as 6-byte elements.

The 2026-06-05 A003 live IDA disassembly pass and 2026-06-18 B001 source-quality reanalysis confirm these destination offsets inside the caller-allocated `0xc0` byte entry:

- `entry + 0x00`: `FittingRoomCatalogCategory category` / `uint32_t categoryId`, written by the caller before this parser runs.
- `entry + 0x04`: `bool enabled` or `bool valid`, set to `1` at function entry. The descriptive `enabled`/`valid` spelling is preferred over stronger UI terms until consumers prove selection semantics.
- `entry + 0x05`: reserved/pad byte; no parser assignment is known and the byte keeps the following 16-bit tile aligned.
- `entry + 0x06`: `int16_t tile` / `tileId`. The source operation is `tile = rawTile - 0x4000`; older unsigned-view wording that described this as adding `0xc000` was the same 16-bit result but not the best source expression.
- `entry + 0x08`: `uint8_t color`, parsed from JSON `color` with default `-1`.
- `entry + 0x09`: reserved/pad byte; no parser assignment is known.
- `entry + 0x0a`: `wchar_t name[0x50]`, written with `_wcscpy_s(..., 0x50, ...)` after the JsonCpp `name` lookup and ANSI-to-wide conversion.
- `entry + 0xaa..+0xb3`: reserved/padding gap between the 80-WCHAR name buffer and part-vector triplet.
- `entry + 0xb4/+0xb8/+0xbc`: `FittingRoomCatalogPartRecord *partsBegin/partsEnd/partsCapacity` for nested 6-byte part records.

Each accepted nested part record stores the `part` byte, a 16-bit tile value, color byte, and gender byte before appending the 6-byte record. `part == 0xf5` and `gender == 0xff` are reject sentinels that terminate the parse with `false`.
