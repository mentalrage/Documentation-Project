# 0x0066d000-0x0066d408 LodePNG Mutable Data Tables

## Summary

- Address range: `0x0066d000-0x0066d408`
- Entity kind: initialized writable third-party data
- Disposition: reconstructable third-party static-embed data
- Rebuild handling: `source-declared/generated-binary` via the LodePNG static embed
- Confidence: very strong for LodePNG ownership and the CRC-32 table identity; medium-high for exact stock helper names that consume it

This `.data` span is writable data used by the statically embedded LodePNG code. It is not NexusTK handwritten source, but it is reconstructable because the rebuilt executable must contain equivalent LodePNG static-embed data. Rebuild from the obtained LodePNG source/header files and let the compiler/linker lay out equivalent mutable data.

## Evidence

- IDA data xrefs show `off_66D000` read at `0x00446e40` inside the LodePNG helper island, where it is passed with the `"LodePNG"` label.
- IDA data xrefs show `dword_66D008` read at `0x004465de`, `0x004473ee`, and `0x0044b024`, all inside the documented LodePNG code range.
- The first dword points at `0x0060f4c0`, documented with the LodePNG read-only data and version string.
- IDA MCP `py_eval` on 2026-06-07 rechecked `0x0066d000 -> 0x0060f4c0` (`a20160501`), the zero separator at `0x0066d004`, the table xrefs at `0x004465de`, `0x00447164`, `0x004471c1`, `0x004473ee`, `0x00447451`, and `0x0044b024`, and the successor `xRight` boundary at `0x0066d408`.
