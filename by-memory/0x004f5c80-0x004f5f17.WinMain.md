# 0x004f5c80-0x004f5f17 WinMain

## Scope

## Behavior

This is the real client startup body reached after the VC CRT startup wrapper. It:

- stack-constructs the application shell through `Application__Constructor` at `0x00463310`;
- writes the `BaramApp` primary and secondary vtables onto that stack object;
- allocates a `MiniMapVersionManager` object and calls `MiniMapVersionManager::LoadHashFile`;
- allocates a `StartupWindow`, calls `StartupWindow::RunUpdateCheck`, then destroys the startup window through its vtable;
- launches `NexusUpdater.exe` through `ShellExecuteExA` when the StartupWindow out byte requests the updater path;
- otherwise runs `Application::Startup`, `Application::RunMessageLoop`, and `Application::Shutdown`;
- on the updater or abort-startup path, deletes `g_pDATFileMgr` when live and requests application exit before destroying the stack application object;
- catches thrown `Error *` objects, copies/formats the wide error text, hides the main window, restores display and keyboard state, shows `MessageBoxW`, deletes the caught error object, and returns through the same application-destruction tail.
- causes compiler EH cleanup child [UID:0004R1][0x004f66b0-0x004f66b5.WinMainBaramAppCleanupThunk](by-memory/0x004f66b0-0x004f66b5.WinMainBaramAppCleanupThunk.md) for the stack `BaramApp app(...)`; that out-of-line thunk is compiler support, not another handwritten WinMain helper.

The `0x004f5e95-0x004f5f16` tail is not a StartupWindow virtual-message path. It is the source-level body of a `catch (Error *error)` handler described by WinMain's EH metadata.
