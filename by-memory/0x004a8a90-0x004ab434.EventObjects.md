# 0x004a8a90-0x004ab434 Event Objects

## Scope

- Range: `0x004a8a90-0x004ab434`
- Entity kind: class aggregate / base event object methods
- Current Wave3 owner: `Event`
- Disposition: reconstructable project code

## Covered Methods

- `0x004a8a90-0x004a8aaf` `Event::Event`
- `0x004a8ab0-0x004a8abe` `Event::~Event`
- `0x004ab3f0-0x004ab434` `Event::ScalarDeletingDestructor`

## Evidence

- IDA MCP confirms all three function boundaries.
- Direct callers include application event adapter paths and other event construction/destruction paths.
- Wave3 reports this as the base event object for the event dispatch system.

## Reconstruction Notes

- Keep the base `Event` near [UID:0000J7][EventDispatcher](by-file/EventDispatcher.md) until subclasses are mapped. A small [UID:0000J6][Event](by-file/Event.md) file remains a plausible original split.
- The wide gap between destructor and deleting destructor is not a single function; the filename records the known Event-owned method span, not ownership of every byte in the gap.
- [UID:00004N][EventHandler](by-class/EventHandler.md) sits immediately before this range at `0x004a8970-0x004a8a83`; keep it separate from `Event` because handlers receive events while `Event` is the payload object.
- The adjacent `EventMan` class and event factory helpers are now documented separately at [UID:00014C][0x004a8b40-0x004ab476.EventMan](by-memory/0x004a8b40-0x004ab476.EventMan.md).
