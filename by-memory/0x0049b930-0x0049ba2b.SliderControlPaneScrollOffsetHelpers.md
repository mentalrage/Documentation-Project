## Behavior

The four helpers all operate on the same inherited `ControlPane` 16-bit range fields:

- `this+0xfa`: inherited `m_rangeCurrent`, current scroll/selection offset, byte offset 250 decimal (Verified with int_convert.py).
- `this+0xfc`: inherited `m_rangeEnd`, maximum/limit offset, byte offset 252 decimal (Verified with int_convert.py).
- vtable slot `+0x20`: refresh/invalidate after changing the offset, byte offset 32 decimal (Verified with int_convert.py).

Each body is `0x3b` bytes / 59 decimal (Verified with int_convert.py). The decrement helpers saturate at zero before the upper-limit clamp. The increment helpers use the same lower-bound guard before adding either one or `0x0a` / 10 decimal (Verified with int_convert.py), then clamp the stored value to `this+0xfc`.

The caller at `0x00497780` maps keyboard messages `0x80`/`0x81` (128/129 decimal; Verified with int_convert.py) to the one-step decrement helper, `0x82`/`0x83` (130/131 decimal; Verified with int_convert.py) to the one-step increment helper, `0x93` (147 decimal; Verified with int_convert.py) to the ten-step decrement helper, and `0x94` (148 decimal; Verified with int_convert.py) to the ten-step increment helper. [UID:0000DB][SliderControlPane](by-class/SliderControlPane.md) documents `0x00497780-0x00497818` as `SliderControlPane::HandleKeyOrTextEvent`.

The caller at `0x00497c60` maps hit/drag result cases `13`, `14`, `16`, and `17` to the same four helpers.
