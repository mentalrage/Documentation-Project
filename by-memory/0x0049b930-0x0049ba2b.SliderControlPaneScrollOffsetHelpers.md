## Behavior

The four helpers all operate on the same 16-bit fields:

- `this+0xfa`: current scroll/selection offset, byte offset 250 decimal (Verified with int_convert.py).
- `this+0xfc`: maximum/limit offset, byte offset 252 decimal (Verified with int_convert.py).
- vtable slot `+0x20`: refresh/invalidate after changing the offset, byte offset 32 decimal (Verified with int_convert.py).

Each body is `0x3b` bytes / 59 decimal (Verified with int_convert.py). The decrement helpers saturate at zero before the upper-limit clamp. The increment helpers use the same lower-bound guard before adding either one or `0x0a` / 10 decimal (Verified with int_convert.py), then clamp the stored value to `this+0xfc`.

The caller at `0x00497780` maps keyboard messages `0x80`/`0x81` (128/129 decimal; Verified with int_convert.py) to the one-step decrement helper, `0x82`/`0x83` (130/131 decimal; Verified with int_convert.py) to the one-step increment helper, `0x93` (147 decimal; Verified with int_convert.py) to the ten-step decrement helper, and `0x94` (148 decimal; Verified with int_convert.py) to the ten-step increment helper. [UID:0000DB][SliderControlPane](by-class/SliderControlPane.md) documents `0x00497780-0x00497817` as `SliderControlPane::OnKey`.

The caller at `0x00497c60` maps hit/drag result cases `13`, `14`, `16`, and `17` to the same four helpers. The legacy [UID:000118][0x00494b50-0x00499e30.ButtonChoiceControlCore](by-memory/0x00494b50-0x00499e30.ButtonChoiceControlCore.md) notes that `0x00497886-0x00497c60` remains a non-padding gap in the button/choice neighborhood, and the older trace report names `0x00497c60` as `ProcessScrollInput` called by `SliderControlPane::OnMouseEvent`, `SliderControlPane::OnTimerTick`, and a fitting-room parent-scroll drag path.
