# 0x0069b3d4-0x0069b3d8 Surface Pixel Format Flags

## Status

- Disposition: reconstructable NexusTK render globals.
- Entity kind: render mode / pixel-format flag bytes plus reserved bytes.
- Confidence: strong for addresses and use sites; medium for final flag names.
- Proposed owner: [UID:0000OC][Surface](by-file/Surface.md) / [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md).

## Layout

| Address | IDA name | Role |
| --- | --- | --- |
| `0x0069b3d4` | `byte_69B3D4` | DirectDraw/surface pixel-format mode flag used by presentation conversion paths. |
| `0x0069b3d5` | `byte_69B3D5` | Compatibility/RGB565-style pixel-format flag used by image decode, screenshot, and render paths. |
| `0x0069b3d6-0x0069b3d8` | none | Reserved/alignment bytes; no direct IDA xrefs found. |

## Raw Data

```text
0x0069b3d4: ff ff ff ff
```

## Interpretation

The surface initialization path at [UID:0001G6][0x00557140-0x00559aef.SurfacePresentation](by-memory/0x00557140-0x00559aef.SurfacePresentation.md) sets these flags while selecting software render callbacks. `byte_69B3D5` is the broad consumer-facing flag: decoded EPF tiles, screenshot/proof capture, and pixel conversion helpers check it before choosing compatibility conversion logic.

Keep the final names provisional until the render mode pass has separated DirectDraw surface-format detection, RGB555/RGB565 selection, and screenshot conversion behavior.

## Evidence

- IDA MCP data xrefs show writes to `byte_69B3D4` and `byte_69B3D5` from `sub_558840`, the surface/presentation initializer.
- [UID:0001PI][0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable](by-memory/0x0069b3e0-0x0069b410.SurfaceRenderCallbackTable.md) already records that the same initializer sets these flags while installing render callback families.
- [UID:000200][0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels](by-memory/0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels.md) checks `byte_69B3D5` before applying compatibility pixel conversion.
- IDA MCP data xrefs show `byte_69B3D5` used by screenshot/render helpers including `0x004efbc0`, `0x00557aa0`, `0x00557e80`, and `0x005c02a0`.
