## Interpretation

The out-of-line [UID:00039V][0x00558690-0x0055883d.InitializeSurfaceRenderCallbacks](by-memory/0x00558690-0x0055883d.InitializeSurfaceRenderCallbacks.md) and its complete semantic inline copy in [UID:00039W][0x00558840-0x00558f63.SurfaceMinimapRenderInitializer](by-memory/0x00558840-0x00558f63.SurfaceMinimapRenderInitializer.md) set these flags while selecting software render callbacks. The byte at `0x0069b3d4` is `g_surfaceUses32BitPresentation`: each initializer sets it only for the 32-bit display branch, clears it for the 24-bit and 16-bit branches, and [UID:0003A4][0x005595d0-0x00559a0f.BlitSurfaceToDisplay](by-memory/0x005595d0-0x00559a0f.BlitSurfaceToDisplay.md) reads it at `0x0055960e` before locking the source and ScreenPane `m_offscreenSurface`. That path divides source/destination pitches by 2/4, iterates with unsigned 16-bit counters, and expands each RGB565 word as `((pixel & 0xf800) << 8) | ((pixel & 0x07e0) << 5) | ((pixel & 0x001f) << 3)` without low-bit replication or alpha. The converted surface is then presented only through the windowed DrawType paths. The byte at `0x0069b3d5` is best documented as `g_surfaceUsesRgb565Pixels`: decoded EPF tiles, screenshot/proof capture, alpha lookup, palette logic, callback-family selection, and pixel conversion helpers check it before choosing RGB565-capable handling or RGB555/compatibility conversion. If the DirectDraw query fails or reports an unsupported bit depth, neither flag is rewritten; the callback-family fallback uses the prior value of `g_surfaceUsesRgb565Pixels`.

Keep the exact final symbol spelling provisional. The B005 [UID:000200][0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels](by-memory/0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels.md) pass rejects broader names such as `g_newRenderingMode`, `g_highColorMode`, and `g_is32BitMode` for `0x0069b3d5` because the observed polarity is specifically RGB565-capable pixel handling rather than an overall product mode or bit-depth flag. `g_is32BitMode` is also wrong for `0x0069b3d5` because 16-bit RGB565 sets that flag.
