# 0x0067a7c8-0x0067a7cc g_pConfig

## Status

- Address range: `0x0067a7c8-0x0067a7cc`
- Entity kind: global pointer
- Proposed name: `g_pConfig`
- Disposition: reconstructable NexusTK global data
- Parent: [UID:0000IE][Config](by-file/Config.md)
- Confidence: strong for address, lifecycle, owner, and broad config-object role

This four-byte zero-initialized global stores the active configuration object pointer. Live IDA evidence shows that the base `Config` constructor publishes the pointer, startup promotes the object to the `RegistryConfig` runtime layout, and teardown paths clear the slot before object destruction completes.

## Layout

| Range | Current IDA name | Role |
| --- | --- | --- |
| `0x0067a7c8-0x0067a7cc` | `dword_67A7C8` | Process-global configuration object pointer used through base `Config` storage and derived `RegistryConfig` fields. |

## Evidence

- 2026-06-05 live IDA MCP inspection reports four zero-initialized `.data` bytes at `0x0067a7c8`, 433 direct data xrefs, and five direct writes.
- `0x0048e550-0x0048e77a` is the base `Config` constructor path. It stores `this` into `dword_67A7C8` at `0x0048e592`, has a defensive null clear at `0x0048e599`, installs the `Config` vtable, zeroes the fixed config tables, constructs 32 config-entry records, and initializes list/string buffers.
- Startup code at `0x004639d0` allocates the large config object, calls the base constructor, installs the `RegistryConfig` vtable, then calls the load-or-initialize path through `dword_67A7C8` at `0x0046414e`.
- Teardown clears are explicit: the base destructor clears at `0x0048e83a`, the tiny clear helper at `0x00493ef0` writes zero, and the deleting destructor clears at `0x004940de` before conditional free.
- Representative consumers span MiniMapDialog setup (`0x00450ca0`, `0x004518b0`, `0x00451a10`, `0x00451c90`), startup and cleanup (`0x004639d0`, `0x00464a60`), activation/deactivation (`0x004669c0`, `0x00466a70`), and UI/profile/network/audio/packet helpers including `0x0047ff80`, `0x004946c0`, `0x0049dfd0`, `0x004f6700`, `0x004f9280`, and `0x004fad00`.
- [UID:0000IE][Config](by-file/Config.md) is the best parent because it owns the process-global configuration pointer. [UID:0000N4][RegistryConfig](by-file/RegistryConfig.md) and [UID:0000BW][RegistryConfig](by-class/RegistryConfig.md) document the derived runtime layout used after startup vtable promotion.
