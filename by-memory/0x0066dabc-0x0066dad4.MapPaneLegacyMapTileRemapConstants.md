# 0x0066dabc-0x0066dad4 MapPane Legacy Map Tile Remap Constants

## Summary

- Address range: `0x0066dabc-0x0066dad4`.
- Entity kind: initialized MapPane file-level remap constants.
- Disposition: reconstructable source-declared data.
- Source owner and emitter: [UID:0000L3][MapPane](by-file/MapPane.md).
- Consumer: `0x0050c120`, inferred `MapPane::GetLegacyAwareMapTileLayerIds(int tileX, int tileY, MapTileLayerIds *out)`.
- Confidence: very strong for owner, xrefs, behavior, and first-draft C++; lower for original field and symbol spelling.

The six constants are live MapPane map-tile record id remap thresholds. They are not coordinate min/max constants. The helper reads map coordinates, but the comparisons are against tile/resource ids loaded from a six-byte tile-layer record.

Decimals are verified with `int_convert.py`. `Primary` and `Overlay` are high-probability descriptive names for the first and third 16-bit words in the map tile-layer record. If map-file support docs recover canonical field names, update these names to match.

## Consumer Behavior

Best source-facing helper name:

```text
MapPane::GetLegacyAwareMapTileLayerIds(int tileX, int tileY, MapTileLayerIds *out)
```

Acceptable shorter aliases are `MapPane::GetMapTileLayerIds`, `MapPane::GetTileRenderIds`, or `MapPane::GetTileRecordForDraw`.

Behavior recovered by B002:

- Receiver `ecx` is `MapPane *`.
- Stack arguments are output pointer, tile X/column, and tile Y/row; the function returns the output pointer and cleans `0x0c` stack bytes.
- It bounds-checks coordinates against `MapPane +0x3f4` and `MapPane +0x3f6`.
- It reads `MapPane +0x3f8` as the tile buffer.
- It indexes a six-byte record, copies a dword from record `+0x00`, and copies a word from record `+0x04`.
- If [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md) / `byte_66DA97` equals `1`, it returns the record unchanged.
- In legacy/non-EPF mode, the first tile word is remapped if it falls inside `0x7992..0x79c1`; the signed add immediate is `0xfb51`. Values above `0x74e2` outside that band clamp to zero.
- In legacy/non-EPF mode, the third tile word is remapped if it falls inside `0x380a..0x3822`; the signed add immediate is `0xfe85`. Values above `0x368e` outside that band clamp to zero.
- Out-of-bounds coordinates produce a zero/blank output record.

## Xrefs And Callers

- Direct reads of all six addresses occur only inside `0x0050c120`.
- Direct call sites to the helper are `0x00505544`, `0x0050555c`, `0x0050c07c`, `0x0050c3b4`, `0x0050d95f`, and `0x0050f178`.
- Caller `0x00505430` uses nearby tile-layer ids while deciding movement/object transition behavior.
- Caller `0x0050c040` is a tile-span/visible-region helper loop.
- Caller `0x0050c370` is the tile draw helper; call site `0x0050c3b4` retrieves a remapped tile id before calling `MapTileImageLib::DrawTile` at `0x004d1a20`. This caller was missing from older inventories.
- Caller `0x0050d8e0` is a map/tile render path that draws visible cells and calls nearby tile-rect helper `0x0050c240`.
- Caller `0x0050f130` is a static-object tile-region refresh path using the map-tile layer id while reconciling static object panes.

## Rejected Alternatives

- Coordinate clamp names: rejected because the constants compare against tile/resource ids read from `m_tileBuffer`, not against input coordinates.
- MapTileImageLib ownership: rejected for this exact group because only the MapPane helper reads the addresses. MapTileImageLib consumes the already-remapped id through `DrawTile`.
- `g_useEpfAssets` ownership: rejected as direct owner. The flag gates the branch, but the constants belong to the source that performs the remap.
- Class fields: rejected because the constants are static `.data` values, not fields read through `this`.

## First-Draft C++ Notes

The first-draft C++ intentionally uses writable file-static `short` declarations, not `static const`, because the original storage lives in writable `.data` and live code loads through memory. Do not use `word_66DABC`-style names in final source. These constants should sit near the tile-record lookup helper in `MapPane.cpp`, not near the MapTileImageLib draw routine.
