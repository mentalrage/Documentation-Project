## Behavior

This method updates enabled/disabled state for the exchange controls based on local and remote offer/ready/money flags. It is the control-state callback reached from the dialog's selected-control refresh path and internal state changes.

The method obtains controls through the inherited `DialogPane` control manager at `this+0x1fc`:

- Control id `1`: confirm/ready/OK button.
- Control id `2`: add item button.
- Control id `3`: cancel button.
- Control id `6`: local money edit control.

It builds a three-bit state from the packed ExchangeDialog bytes:

- `this+0x270`: local offer/ready-request state, emitted as `m_localOfferPending`, contributes bit `4`.
- `this+0x271`: local ready-confirmed state, emitted as `m_localReadyConfirmed`, contributes bit `2`.
- `this+0x272`: peer/remote ready-confirmed state, emitted as `m_peerReadyConfirmed`, contributes bit `1`.
- `this+0x278`: amount-decrease/confirm-lock flag, emitted as `m_amountDecreasePending`, gates only changes to control id `1`.

State cases:

| State | Meaning | Control updates |
| --- | --- | --- |
| `0` | Neither side ready and no local offer pending. | If `+0x278 == 0`, enable id `1`; enable ids `3`, `2`, and `6`. |
| `1` | Peer ready only. | If `+0x278 == 0`, enable id `1`; enable id `3`; disable ids `2` and `6`. |
| `2`, `4`, `5` | Local ready/pending states that block local edit/add. | If `+0x278 == 0`, disable id `1`; enable id `3`; disable ids `2` and `6`. |
| `3`, `6`, `7`, default | Already-complete or unsupported combination. | No state changes. |
