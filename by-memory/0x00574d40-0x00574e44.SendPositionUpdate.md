## Behavior

This helper builds an 8-byte position/status upload and posts it to the shared request queue as request code `8`.

Observed packet layout from IDA decompilation:

| Offset | Value |
| --- | --- |
| `0` | Zero. |
| `1..2` | Player X coordinate, big-endian. |
| `3` | Constant `0xc5`. |
| `4..5` | Player Y coordinate, big-endian. |
| `6` | `byte_66DA97`, generated as high-resolution/EPF-mode state in nearby docs. |
| `7` | Zero terminator/padding byte. |

The helper clears `byte_69ba60` before building the packet. Current generated source names this as `g_cashShopRequestPending`.

If the config byte at `g_pConfig + 2693368` is nonzero, the helper subtracts `(rand() < 0x1fff)` from the X coordinate before serialization. Treat the generated `useStablePosition` field name as provisional; the machine code implements a one-step optional X-coordinate jitter, not a plain stable-position read.

Before queuing the send, the helper checks `this + 240206`, the same send-disabled byte used by [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md) and [UID:0001HV][0x00574d00-0x00574d3f.SendRawDataRaw](by-memory/0x00574d00-0x00574d3f.SendRawDataRaw.md). When sending is allowed, it allocates 8 bytes, copies the first 7 packet bytes, writes the final zero byte, and calls `0x00596960` as the shared dispatch primitive.
