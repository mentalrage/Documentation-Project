## Behavior

`ReadRemaining` accepts a destination object with `_AUTOBUF<unsigned char>`-like layout, frees its current data pointer, computes the number of bytes from the current file position to the cached file size, allocates a replacement data buffer, stores the replacement pointer and size, then reads the remaining bytes through the `StdioFile` virtual `Read` slot.

| Step | Observed behavior |
| --- | --- |
| Destination access | The explicit argument is used as a three-word object: `+0x00` vtable/type head, `+0x04` data pointer, and `+0x08` size/count. This matches [UID:0001WN][AUTOBUF_unsigned_char](by-type/by-template/AUTOBUF_unsigned_char.md). |
| Initial free | Calls `j_j_j___free_base(*(void **)(dest + 4))`. The destination pointer is not nulled. |
| Remaining count | Calls the virtual slot at `this->vtable + 0x14`, documented as `Tell` / `GetPosition`, then computes `this[2] - position`. `this[2]` is the cached file size at object offset `+0x08`. |
| Duplicate free | Calls `j_j_j___free_base(*(void **)(dest + 4))` a second time before allocation, still without clearing the pointer. Existing callers pass freshly constructed or null-buffer destinations, but the binary behavior is a duplicate free if a non-null owned pointer reaches this method. |
| Allocation | Calls the allocation wrapper at `0x005c7790` with the computed remaining byte count, then stores the returned pointer at `dest + 4` and the count at `dest + 8`. |
| Read | Calls the virtual slot at `this->vtable + 0x20`, documented as `Read(buffer, count)`, and returns that virtual call result. |

No range check is visible for negative `cachedSize - position`, no allocation-failure branch is visible, and the helper does not verify that the final read count equals the requested remaining count.
