## Timer Evidence

IDA MCP checks on 2026-05-24 confirm that `0x0053a900`, `0x0053b700`, `0x0053b830`, `0x0053bf40`, and `0x0053bf80` use the process scheduler through [UID:0001K9][0x00597610-0x00597645.TimerHandlerWrappers](by-memory/0x00597610-0x00597645.TimerHandlerWrappers.md) and `TimerMgr::ScheduleTimer` at `0x00597910`. These calls drive sprite config refresh, direction-change delay, frame animation, and movement/forward-step timer messages.

The active generated `class_LivingObjectPane.cpp` names `0x00597610` and `0x00597630` as `SoundManager::CancelTimer` and `SoundManager::CancelPendingTimersExceptEvent`. That is stale generated ownership. The wrapper bodies forward through [UID:0000SI][g_pTimerMgr](by-global/g_pTimerMgr.md), and caller evidence is broad/non-audio, so this memory cluster should document `LivingObjectPane` as a timer owner/consumer rather than as an audio caller.
