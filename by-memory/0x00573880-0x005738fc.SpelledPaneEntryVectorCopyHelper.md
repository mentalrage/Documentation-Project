# 0x00573880-0x005738fc SpelledPane Entry Vector Copy Helper

## Status

- Disposition: non-emitting compiler/template helper for `SpelledPane` entry-vector storage.
- Entity kind: vector element copy/construct helper.
- Proposed owner context: [UID:0000DK][SpelledPane](by-class/SpelledPane.md) entry storage, but this helper itself is not source-facing handwritten UI behavior.
- Parent aggregate: [UID:000240][0x00573570-0x0057399e.LookGroupSpelledDestructorVectorHelpers](by-memory/0x00573570-0x0057399e.LookGroupSpelledDestructorVectorHelpers.md).
- Rebuild handling: compiler/linker-generated helper emitted from source-level vector/list operations; do not hand-port as standalone C++.

## Behavior

This helper copies 12-byte entry-vector records from `[a1, a2)` into the destination sequence beginning at `a3`. For each record it calls `0x00582a90` for the first pointer-like field, copies the `+4` dword, copies the `+8` dword, advances both source and destination by 12 bytes, and returns the final destination pointer.

## Evidence

- 2026-06-11 live IDA MCP `decompile` shows `sub_573880(int a1, int a2, int a3)` looping until `i == a2`, calling `0x00582a90((void **)a3, (const void **)i)`, copying fields at `+4` and `+8`, incrementing the source by 12, and advancing the destination by 12.
- 2026-06-11 live IDA MCP `py_eval` confirmed exact modeled bounds `0x00573880-0x005738fc`, direct callers only at `0x00573151` and `0x00573162` inside `sub_572FD0`, and `0x005738fc-0x00573900` as `0xcc` padding.
