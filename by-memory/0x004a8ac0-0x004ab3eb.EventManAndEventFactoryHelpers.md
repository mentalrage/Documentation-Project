## Aggregate C++ Decision

The formal `RECONSTRUCTION_CPP` block intentionally remains blank for this aggregate. This is a target-specific split-first decision, not a reconstruction failure:

- The range contains many exact source functions rather than one function or one class method.
- It spans base `Event` predicate helpers, `EventMan` methods including the IME/candidate band, free packet factories, the EventMan/application notification post helper, a retained duplicate no-direct-xref helper band, and the `0x004ab3e0` EH/unwind singleton-clear helper.

## Event Payload Field Direction

The aggregate should stop using generic "event-record helper" wording without field context. [UID:00004L][Event](by-class/Event.md) now carries the accepted exact-size union declaration:

- `Event::m_type` is an unsigned byte at `+0x04`, defaulted/reset to `kEventNone` (`0xff`). Unsigned classifier opcodes prove the type.
- The aligned payload union begins at `+0x08`, is `0x108` bytes, and preserves exact `sizeof(Event) == 0x110`.
- Pointer/mouse: x `+0x08`, y `+0x0c`, modifiers `+0x10`, detail/wheel `+0x14`, message time `+0x18`.
- Key: translated key `+0x08`, modifier `+0x10a`, message time `+0x10c`.
- Text/live composition: input/subtype `+0x08`, length/text `+0x09/+0x0a`, UTF-16 storage through `+0x109`, modifier `+0x10a`, message time `+0x10c`.
- IME result: length `+0x09`, 129-word storage at `+0x0a-+0x10b`, message time `+0x10c`.
- IME open: integer state `+0x08`, message time `+0x10c`.
- Candidate: list pointer `+0x08`, selected row `+0x0c`, message time `+0x10c`.
- Packet: kind byte `+0x08`, transferred data pointer `+0x0c`, size `+0x10`; EventDispatcher frees the data pointer after type-18 dispatch, so `+0x08` is not overclaimed as the sole ownership bit.
- Application notification: channel `+0x08`, `LObject *` payload `+0x0c`; Main_WndProc releases the payload after dispatch.

The historical blanket `m_tickCount +0x10c` statement is superseded because pointer/mouse message time is at `+0x18`. Exact original spellings remain inferred, but the accepted names and overlays are source-ready and no longer a UID00014B blocker.
