## Dispatch And Queue Flow

- `TimerHandler` construction/destruction/wrapper functions form the public owner-facing edge: objects schedule callbacks, unregister all pending timers, cancel an event id, or cancel all except one event id through `g_pTimerMgr`.
- `TimerMgr::TimerMgr` initializes the singleton/static manager, embedded queue state, timer period/tick state, and first due-tick cache. The destructor path reverses that lifecycle by ending the multimedia timer period, destroying queued records, clearing `g_pTimerMgr`, and running base cleanup.
- `TimerMgr::DispatchDueTimers` is the scheduler pump used by the application helper/message-loop path. It pulls due `ScheduledTimerEvent` records in sorted order, removes them from the embedded queue, and dispatches the owner callback through the `TimerHandler` virtual callback slot.
- `TimerMgr::ScheduleTimer`, the removal helpers, and `TimerMgrFindQueuedTimerDueTick` are scheduler-facing methods over the embedded queue. The tail helpers under [UID:0001KA][0x00597dc0-0x005986da.TimerMgrQueueHelpers](by-memory/0x00597dc0-0x005986da.TimerMgrQueueHelpers.md) provide the ring queue reverse/rotate/grow/splice/insert mechanics and timer tick refresh.
