- [UID:0001J1][0x00582500-0x00583206.LObjectStringConstructionAndCow](by-memory/0x00582500-0x00583206.LObjectStringConstructionAndCow.md) records that `AllocateAnsiBuffer` / `AllocateWideBuffer` use these small-buffer pool globals when capacities fit fixed-size buckets.
- IDA decompilation of `0x00582e30` selects records such as `byte_69BB44` for a 512-sized bucket and falls back to heap allocation for larger buffers.
- [UID:0000TM][StringBufferSentinelsAndPools](by-global/StringBufferSentinelsAndPools.md) records the exact four-ref pattern for each pool: one static constructor, one allocation helper, one release helper, and one cleanup wrapper. It also links these eight storage records to [UID:0001VK][PoolAllocatorLayout](by-type/by-struct/PoolAllocatorLayout.md).

The exact per-record ranges are documented in the layout table above for future split work if the project later wants one page per `PoolAllocator` instance.
