# String Buffer Pool Static Storage

## Summary

- Address range: `0x0069bacc-0x0069bc0c`
- Entity kind: static object storage cluster
- Disposition: reconstructable string/pool support data
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong for string-buffer pool ownership; medium for exact source type names

This range contains eight 40-byte static-storage records used by the ref-counted ANSI/UTF-16 string buffer allocator for small pooled capacities.

## Evidence

- IDA MCP reports each item as a 40-byte byte object: `byte_69BACC`, `byte_69BAF4`, `byte_69BB1C`, `byte_69BB44`, `byte_69BB6C`, `byte_69BB94`, `byte_69BBBC`, and `byte_69BBE4`.
- Each record has constructor/setup refs from the `0x0041a1a7-0x0041a267` static initialization cluster and cleanup refs from the `0x0060c3c0-0x0060c430` static cleanup wrappers.
- [UID:0001J1][0x00582500-0x00583206.LObjectStringConstructionAndCow](by-memory/0x00582500-0x00583206.LObjectStringConstructionAndCow.md) records that `AllocateAnsiBuffer` / `AllocateWideBuffer` use these small-buffer pool globals when capacities fit fixed-size buckets.
- IDA decompilation of `0x00582e30` selects records such as `byte_69BB44` for a 512-sized bucket and falls back to heap allocation for larger buffers.

## Rebuild Notes

Model this as typed static storage owned by the string-buffer/pool allocator source. The rebuilt binary should produce the storage from declarations and constructors rather than hand-copying the `0xff` initial bytes.
