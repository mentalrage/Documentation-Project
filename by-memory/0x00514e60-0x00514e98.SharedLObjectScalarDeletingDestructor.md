## Behavior

The body is a compact scalar-deleting destructor wrapper:

- `ecx` is the object pointer, saved in `esi`.
- It first calls `0x004f4a90`, the non-deleting `LObject` cleanup body.
- It reads the delete flags from `[ebp+8]`.
- If bit `0` is clear, it returns the object pointer without freeing.
- If bit `0` is set and bit `2` is clear, it calls `0x004f4ac0` to free the object storage, then returns the original pointer.
- If bit `2` is set, it takes the guard/no-op path through `0x0041b6a0` and returns without calling the delete wrapper.

## Classification Decision

Keep this page `RECONSTRUCTABLE:FALSE`. The body is a shared MSVC scalar deleting-destructor adapter:

- it calls only the inherited `LObject` cleanup at `0x004f4a90`;
- it has no class-specific vtable restore or field/resource teardown;

- it is reached by vtable data slots only, with no ordinary direct callers; and
- it is folded across system-message marker classes and stack dialog-creator helper classes.

The source reconstruction should express the four owner class declarations and their destructor/vtable relationships. This standalone wrapper should regenerate from those declarations or be compiler-folded during the rebuild; it should not be attached to a single class/file parent or emitted as handwritten C++.
