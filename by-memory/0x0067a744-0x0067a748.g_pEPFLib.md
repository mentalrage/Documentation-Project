# 0x0067a744-0x0067a748 g_pEPFLib

## Status

- Entity kind: global data pointer
- Current aliases: `g_pEPFLib`, `DAT_0067a744`, IDA `dword_67A744`
- Proposed owner: [UID:0000K2][ImageLib](by-file/ImageLib.md)
- Disposition: reconstructable project global
- Evidence basis: IDA MCP `xrefs_to`, IDA MCP disassembly of `0x004cffb0`, and generated `class_ImageLib.cpp` / `class_ResourceLayoutTable.cpp`.

## Storage And Lifetime

This four-byte global stores the process-wide EPF/EPD image/layout registry pointer. The object it points to is anchored by [UID:0001US][ImageLibLayout](by-type/by-struct/ImageLibLayout.md) and [UID:0001XR][ImageLibVtable](by-type/by-vtable/ImageLibVtable.md). It owns a [UID:000079][List](by-class/List.md) at offset `+0x0c`; that list contains 44-byte [UID:0001VT][ResourceLayoutNameRecord](by-type/by-struct/ResourceLayoutNameRecord.md) rows.

Observed writes:

- `0x004cffef`: `ImageLib::ImageLib` stores `this` into `dword_67A744`.
- `0x004cfff6`: constructor nulls the global if the adjusted object pointer path is null.
- `0x004d00fa`: `ImageLib` destructor cleanup path clears or updates the same storage.
- `0x004e652c`: scalar deleting destructor cleanup path clears the same storage.

IDA MCP xrefs on 2026-05-24 showed many additional data reads from UI panes, image libraries, and resource helpers. Those reads are consumers, not owners.

## Ownership Decision

The global belongs with [UID:0000K2][ImageLib](by-file/ImageLib.md), not with a pane or asset-specific image library. The recovered `ResourceLayoutTable` methods use this pointer as their object, but `ImageLib::ImageLib` owns initialization and `ImageLib` destruction owns shutdown.

The registry store is not a separate proven class. IDA MCP follow-up shows `ImageLib::ImageLib` constructs it with `List::List(44, 10)`, so `ResourceLayoutStore` should remain a provisional alias over the generic `List`.

Keep the final C++ type open until the `ImageLib` / `ResourceLayoutTable` class boundary is resolved. Current best source-level declaration is:

```cpp
extern ImageLib* g_pEPFLib;
```

with a note that callers currently use a `ResourceLayoutTable`-style API on the same object.
