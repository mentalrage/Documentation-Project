## Behavior

The method accepts target map coordinates plus a viewport-offset pair. When the final flag is set, it ignores the supplied offset pair and reads the active local-player viewport position through [UID:0002RW][0x005a2de0-0x005a2dfb.LivingObjectPaneGetViewportPosition](by-memory/0x005a2de0-0x005a2dfb.LivingObjectPaneGetViewportPosition.md). The local-object create/update caller is the only modeled caller that passes this flag set. The packet-dispatch, UserPane, movement-correction, and unmodeled code-reference callers pass the flag clear and supply the offset pair directly.

After selecting the offset pair, the method validates both target coordinates against the stored map dimensions and validates the offset pair against the visible viewport extents. Invalid coordinates return without side effects.

The valid path recalculates the MapPane pixel origin from [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md) and [UID:0000T7][MapTilePixelDimensions](by-global/MapTilePixelDimensions.md). Current-layout mode stores negative tile-width/tile-height offsets; the alternate layout stores `14 - tileWidth` and `12 - tileHeight`. It then builds a rectangle covering `(viewportWidth + 1) * tileWidth` by `(viewportHeight + 1) * tileHeight`, stores it through [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md) and [UID:0001FW][0x00554680-0x00554b38.RegionAndMotionRect](by-memory/0x00554680-0x00554b38.RegionAndMotionRect.md), and invokes the MapPane bounds/update virtual slot with the pane-local bounds object.

The tile origin fields are then set to `targetX - offsetX` and `targetY - offsetY`. The method passes those deltas to the larger ObjectList scan/update helper documented under [UID:00023F][0x00532f70-0x0053728e.ObjectListExtendedTypeLookupHelpers](by-memory/0x00532f70-0x0053728e.ObjectListExtendedTypeLookupHelpers.md), redraws the visible tile cache through the MapPane draw helper in [UID:0001AT][0x00506970-0x0050e320.MapPaneInputPacketRenderCore](by-memory/0x00506970-0x0050e320.MapPaneInputPacketRenderCore.md), computes a clamped visible tile rectangle, and calculates a 16-bit checksum over that range using [UID:00027N][0x0066db4c-0x0066dd50.MapPaneChecksumLookupTable](by-memory/0x0066db4c-0x0066dd50.MapPaneChecksumLookupTable.md).

The method sends an opcode `0x05` position packet through [UID:0001P0][0x0067a7ec-0x0067a7f0.g_packetSender](by-memory/0x0067a7ec-0x0067a7f0.g_packetSender.md) and [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md). After sending, it computes a wider object refresh rectangle and calls the nearby MapPane/ObjectList reconciliation helper at `0x0050f130`, which removes or creates object panes when visible-tile object ids no longer match the current [UID:00009Q][ObjectList](by-class/ObjectList.md) contents.

One caveat remains: the packet delta bytes are formed from the helper-populated old-position pair minus the newly clamped visible origin. In the flag-clear call pattern, the live disassembly uses the supplied offset pair for validation and tile-origin math, but does not visibly initialize the old-position packet pair in this callee before the two byte writers. All known flag-clear callers still execute the send path, so final source reconstruction needs caller/ABI cleanup before naming those delta fields with high confidence.
