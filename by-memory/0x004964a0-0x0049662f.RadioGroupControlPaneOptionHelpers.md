## Single-Option Paint Helper Evidence

The raw body at `0x004964e0` has the clearest behavior:

- Stack arguments are used as option index (`[ebp+0x08]`), source text/string pointer (`[ebp+0x0c]`), and option rectangle pointer (`[ebp+0x10]`).
- It constructs or initializes a local image/tile context with a call to `0x00457a60`.
- It compares the selected value at `this+0x10c` against the option index. If equal, the frame-state base becomes `2`; otherwise it starts at `0`.
- It checks control enabled/active byte `this+0x101`, combines that bit with the selected-state base, and dispatches through the four-entry jump table. The cases choose frame ids `2`, `1`, `3`, and `0`.
- It computes radio-button image bounds from the option rectangle, using the vertical midpoint and small offsets around the 16-byte option rectangle.
- It chooses a radio-button EPF string by testing global byte `0x0066da97`: false pushes string `0x00618750` (`"RBUTTON.EPF"`), true pushes pointer/global `0x00618768`.
- It pushes string `0x00618784` (`"RBUTTON.PAL"`), then calls `0x004d02f0` and `0x004b9980` in the EPF/palette render path.
- It calls `0x004b9680` after computing a text color/style value from enabled state. The enabled-state branch maps to `0x80` or `0x88`.
- It scans the wide text argument for a terminating zero word, computes a character count, and calls `0x004bad70`, the documented `DrawTextInRect` family helper, with the computed label rectangle.
