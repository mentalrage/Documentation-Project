## Evidence Notes

- IDA MCP decompilation confirms the constructor writes `dword_67A7CC = this` and stores constructor width/height into word offsets `137` and `138`.
- IDA MCP decompilation confirms the destructor clears `dword_67A7CC = 0`.
- 2026-05-28 IDA MCP boundary recheck confirms the prior end address missed the final byte of the `OnFrameTick` tail jump; padding starts at `0x00557132`.
- IDA MCP callers for `0x00556ce0` include repeated `Application::Startup` layer setup calls plus map/world-map creation paths. Callers for `0x00556d20` include `Application::Shutdown`, MapPane cleanup paths, and screen-message handling.
- IDA MCP decompilation shows both `0x00556ce0` and `0x00556d20` operate on the screen object's layer-list field at offset `0x10c`, not on map tile/object state.
- The `CursorManager` getters at `0x00557450` and `0x00557460` read those same width/height offsets, so the [UID:0000QP][g_pCursorManager](by-global/g_pCursorManager.md) generated alias should be treated as a [UID:0000S7][g_pScreenPane](by-global/g_pScreenPane.md) typed view for now.
- 2026-05-26 IDA MCP confirms `ScreenPane::ScreenPane` still has one startup caller at `0x004645ea`, while the exact global storage page records 145 refs to `0x0067a7cc`.
