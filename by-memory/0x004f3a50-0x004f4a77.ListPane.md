## Range Summary

This range is the reusable `ListPane` implementation. It starts with construction over [UID:0000CF][ScrollablePane](by-class/ScrollablePane.md), includes shared item-list and selection helpers, implements scroll metric virtuals, handles input and painting, and ends with destructor/thunk material.

## Evidence

- IDA MCP `lookup_funcs` confirms all mapped starts above except `0x004f4820`. Querying `0x004f4820` returns `Not a function`, so the disabled generated missing method there is stale or misbounded data.
- IDA MCP decompilation of `0x004f3bd0`, `0x004f3c50`, `0x004f3dc0`, `0x004f3e20`, and `0x004f3f00` shows they read the same `ListPane` offsets: primary list `+0x130`, selected index `+0x134`, selection list `+0x138`, mode byte `+0x13c`, dimensions `+0x140/+0x144`, and drag byte `+0x149`.
- 2026-05-26 IDA `py_eval` recheck confirms `0x004f3e20-0x004f3e74` has 14 xrefs and no `SelectionState` names/RTTI, while `ListPane` vtables and RTTI exist.
- Caller evidence is broad. Examples include board/article functions, chat-color functions, clan list functions, exchange item dialogs, item/spell menu lists, server-select, phone-book, and user-list routines. This breadth rules out board-only or chat-only ownership.
- `0x004f3c00`, `0x004f3c50`, and `0x004f3d60` call `0x0055e990`, matching scroll/viewport synchronization after list mutation.
- `0x004f4190` calls mouse capture/release through the event manager and uses `HitTestItem`/`EnsureItemVisible`; `0x004f4300` calls the navigation helpers; `0x004f43e0` dispatches item drawing through a virtual row-draw slot.

## Disposition

Reconstructable project code. Treat the full range as `ListPane.cpp` reusable UI-control infrastructure. Derived feature files should call or override this behavior but should not own the shared helper bodies.
