## Behavior

1. Reads the incoming active-part byte parameter. The source-facing signature uses `ScrollVolumePart part`, while the binary reads the low byte of the first stack argument.
2. If the part is the thumb (`2`, `kScrollVolumePartThumb`), refreshes highlight state for the thumb path: invalidates the previous non-`0xff` highlighted part, invalidates the new thumb rectangle, and stores `2` to `this+0x103`.
3. For the thumb path, computes the thumb rectangle through `0x00565010` and stores the mouse-to-thumb offset point at `this+0x108` through `0x004b7c30`.
   The first-draft `InitPointPair(&m_thumbDragOffset, mouseY - rect.top, mouseX - rect.left)` stores the vertical/top drag offset in the first component and the horizontal/left drag offset in the second/+4 component; [UID:0001H5][0x00565360-0x00565488.ScrollVolumePaneNotifyValueChange](by-memory/0x00565360-0x00565488.ScrollVolumePaneNotifyValueChange.md) consumes the second/+4 component while computing the horizontal volume value.
4. Stores the incoming active part to `this+0x104`.
5. Calls [UID:0001H4][0x005652a0-0x00565360.ScrollVolumePaneCommitInteraction](by-memory/0x005652a0-0x00565360.ScrollVolumePaneCommitInteraction.md) so the interaction state is immediately reconciled with the current cursor position.
6. Starts the timer/update view through `this+0xa4` by calling `0x005975e0` with interval `0xc8`.
7. Returns with `retn 0Ch`, matching the three incoming interaction arguments observed in the raw calling shape.
