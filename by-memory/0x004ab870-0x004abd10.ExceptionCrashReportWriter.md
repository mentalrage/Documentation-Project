# 0x004ab870-0x004abd10 ExceptionCrashReportWriter

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: crash report writer
- Likely source module: [UID:0000J8][ExceptionHandler](by-file/ExceptionHandler.md)
- Confidence: strong for behavior and source-family ownership.

## Behavior

This helper writes the main `BCrash.nfo` report for an unhandled exception. IDA decompilation shows it:

- builds the output path as `<client-directory>\BCrash.nfo`;
- opens the report in text mode;
- writes the client version line with the major/minor version helpers;
- resolves the exception fault address to module/logical-address text through [UID:00014I][0x004abfa0-0x004ac035.ExceptionLogicalAddressHelper](by-memory/0x004abfa0-0x004ac035.ExceptionLogicalAddressHelper.md);
- formats the exception code through [UID:00014H][0x004abd10-0x004abe4a.ExceptionCodeStringHelper](by-memory/0x004abd10-0x004abe4a.ExceptionCodeStringHelper.md);
- writes exception code, fault address, x86 register state, segment registers, flags, elapsed time, phase, and the observed `565` byte;
- attempts to load `IMAGEHLP.DLL`, resolves `SymInitialize`, `SymCleanup`, `StackWalk`, `SymFunctionTableAccess`, `SymGetModuleBase`, and `SymGetSymFromAddr`, then emits a symbol-aware stack walk through [UID:00014J][0x004ac230-0x004ac4cb.ImageHlpStackWalkHelper](by-memory/0x004ac230-0x004ac4cb.ImageHlpStackWalkHelper.md);
- falls back to an EBP frame-chain walk when ImageHlp setup is unavailable.

## Evidence

- IDA MCP confirms the function at `0x004ab870` with size `0x4a0`, ending at `0x004abd10`.
- IDA caller evidence shows the only direct caller is [UID:00014F][0x004ab830-0x004ab86f.TopLevelExceptionFilter](by-memory/0x004ab830-0x004ab86f.TopLevelExceptionFilter.md) at `0x004ab858`.
- IDA callee evidence includes report formatting, version helpers, module-path helpers, `WideCharToMultiByte`, ImageHlp symbol APIs loaded by name, and the local helpers documented in this range.
- Active `simroot_v2/class_ExceptionHandler.cpp` omits this function, so source reconstruction must not infer the class only had constructor/destructor behavior.

## Ownership Notes

The helper stores resolved ImageHlp function pointers in the `ExceptionHandler` object while writing the report. It should remain with `platform/ExceptionHandler.cpp` unless later source-order or naming evidence proves a separate crash-diagnostics utility file.
