# JsonCpp Legacy Reader Raw Lexical Helpers `0x0042acdf-0x0042ae90`

## Status

- Disposition: ignored for NexusTK source reconstruction.
- Entity kind: raw/unmodeled third-party JsonCpp lexer helper code plus alignment padding.
- Likely owner: [UID:0000KI][JsonCpp](by-file/JsonCpp.md), legacy `Json::Reader` lexical support.
- Reconstructability decision: `RECONSTRUCTABLE:FALSE`; product-owned code should call JsonCpp parser APIs, not emit these raw third-party scanner helpers as NexusTK source.
- Confidence: strong for JsonCpp ownership and non-product disposition; medium for final per-function names because IDA has not modeled these as functions.

## Range Role

This range sits between the [UID:0000X0][0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds](by-memory/0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds.md) and the first modeled [UID:0000X2][0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland](by-memory/0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland.md). IDA does not currently create function objects or external caller xrefs for the code starts in this span, but the local disassembly matches JsonCpp legacy `Json::Reader` lexical-helper behavior.

The observed helpers advance `current_`/`end_`-style pointers, scan C-style comments, C++-style comments, double-quoted strings, and numeric tokens, then return boolean scanner success where the upstream helper does.

## Evidence

- 2026-06-04 live IDA MCP neighbor scan reports `sub_42AB40` ending at `0x0042acdf` and the next modeled function `sub_42AE90` starting at `0x0042ae90`; the only modeled neighbors in the local window are `sub_42AAF0`, `sub_42AB40`, and `sub_42AE90`.
- The same scan reports no function objects at `0x0042ace0`, `0x0042ad30`, `0x0042ad70`, or `0x0042adb0`, and no xrefs to those raw helper starts.
- Live IDA byte/disassembly audit shows the span is executable code separated by `0xcc` alignment, not empty padding.
- `0x0042ace0-0x0042ad27` reads cursor/end fields at offsets `+0x48` and `+0x44`, scans until `'*'` followed by `'/'`, advances the cursor, and returns whether the closing slash was consumed.
- `0x0042ad30-0x0042ad66` reads the same cursor/end fields, scans until LF or CR, consumes optional CRLF, stores the advanced cursor, and returns true.
- `0x0042ad70-0x0042ada3` scans through backslash escapes until a closing double quote, advances the cursor, and returns whether the quote terminator was found.
- `0x0042adb0-0x0042ae88` scans decimal digits, optional fractional digits after `.`, and optional exponent digits after `e`/`E` with `+`/`-`, while updating the cursor field.
- IDA caller checks for the raw helper starts currently return no external callers. Treat that as an IDA modeling caveat, not product ownership evidence.
