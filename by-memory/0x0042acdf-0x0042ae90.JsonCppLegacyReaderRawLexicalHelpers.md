B005's 2026-06-23 MCP-backed [UID:0000X0][0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds](by-memory/0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds.md) recheck tightens the predecessor boundary: `sub_42AB40` ends exactly at `0x0042acdf` and now maps to legacy `Json::Reader::readComment()` with inlined C-style/C++-style comment scanner and `addComment` behavior. ## Evidence

- 2026-06-16 B001 live IDA MCP neighbor scan reports `sub_42AB40` ending at `0x0042acdf` and the next modeled function `sub_42AE90` starting at `0x0042ae90`; the local function inventory around the gap does not include starts at `0x0042ace0`, `0x0042ad30`, `0x0042ad70`, or `0x0042adb0`.
- 2026-06-23 B005 current MCP session `80de0a67` reclassifies the predecessor `0x0042ab40-0x0042acdf` as legacy `Json::Reader::readComment()` rather than a placeholder parser helper. The predecessor decompile distinguishes `/*...*/` and `//...` comments, records comments through `lastValueEnd_` / `commentsBefore_`, and calls the same JsonCpp comment machinery; this confirms the one-byte `0xcc` boundary at `0x0042acdf-0x0042ace0` before this raw-helper parent.
- The same recheck reports no xrefs to those four raw helper starts. Adjacent `sub_42AE90` does have code xrefs, so the negative xref result is specific to the raw helpers.
- Live IDA byte/disassembly audit shows the span is executable code separated by `0xcc` alignment, not empty padding.
- `0x0042ace0-0x0042ad27` reads cursor/end fields at offsets `+0x48` and `+0x44`, scans until `'*'` followed by `'/'`, advances the cursor, and returns whether the closing slash was consumed.
- `0x0042ad30-0x0042ad66` reads the same cursor/end fields, scans until LF or CR, consumes optional CRLF, stores the advanced cursor, and returns true.
- `0x0042ad70-0x0042ada3` scans through backslash escapes until a closing double quote, advances the cursor, and returns whether the quote terminator was found.
- `0x0042adb0-0x0042ae88` scans decimal digits, optional fractional digits after `.`, and optional exponent digits after `e`/`E` with `+`/`-`, while updating the cursor field.
- Raw PE VA/RVA pointer and `.text` rel32 call/jump scans found no hits to the four raw helper starts. Active modeled parser paths inline equivalent scanner logic in `sub_42A770` and `sub_42AB40`.

Keep this parent with [UID:0000KI][JsonCpp](by-file/JsonCpp.md) as third-party JsonCpp reader support and leave it non-emitting.
