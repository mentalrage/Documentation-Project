## Behavior

The wrapper receives `this` in `ecx` and deleting-destructor flags at `[ebp+8]`. It calls [UID:00003S][DialogInSession](by-class/DialogInSession.md) non-deleting destructor `0x004a1450` first, then checks the flags:

- `(flags & 1) == 0`: return `this` without freeing storage.
- `(flags & 1) != 0 && (flags & 4) == 0`: call [UID:000197][0x004f4ac0-0x004f4b00.OperatorDeleteWrapper](by-memory/0x004f4ac0-0x004f4b00.OperatorDeleteWrapper.md) at `0x004f4ac0` on `this`, then return `this`.
- `(flags & 1) != 0 && (flags & 4) != 0`: push object size `0x5368` / 21352 bytes (Verified with `int_convert.py`), push `this`, call the one-byte MSVC guard-check no-op at `0x0041b6a0`, clean the two pushed arguments with `add esp, 8`, and return `this`.

The `flags & 4` branch is compiler/runtime ABI support for an alternate sized/vector-delete flag state in this build, not source-authored cleanup. The current binary does not free object storage on that branch.

Current generated source labels the base cleanup as `ArticleDialog::~ArticleDialog()`. That is owner pollution: IDA xrefs show sibling deleting-destructor wrappers for `ArticleDialog`, `ArticleListDialog`, `BulletinDialog`, and predefined article dialogs all call the same [UID:00003S][DialogInSession](by-class/DialogInSession.md) non-deleting destructor at `0x004a1450`. IDA decompilation also currently types `this` as `boost::exception *`; that is a decompiler type leak and should not be carried into source reconstruction.
