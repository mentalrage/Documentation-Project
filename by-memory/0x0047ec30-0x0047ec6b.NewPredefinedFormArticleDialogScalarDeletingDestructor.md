## Behavior

IDA MCP decompilation on 2026-05-26 shows this wrapper calls `0x004a1450`, checks the scalar deleting destructor flags, returns immediately when bit `0` is clear or bit `2` is set, and otherwise calls `0x004f4ac0` before returning `this`.

Current generated source labels the base cleanup as `ArticleDialog::~ArticleDialog()`. That is owner pollution: IDA xrefs show sibling deleting-destructor wrappers for `ArticleDialog`, `ArticleListDialog`, `BulletinDialog`, and predefined article dialogs all call the same [UID:00003S][DialogInSession](by-class/DialogInSession.md) non-deleting destructor at `0x004a1450`.

IDA decompilation also currently types `this` as `boost::exception *`; that is a decompiler type leak and should not be carried into source reconstruction.
