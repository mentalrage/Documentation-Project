## Version Matching Notes

This pass compared the staged `jsoncpp-0.10.6.candidate.zip`, release tags `1.7.0-1.7.7`, and the official `b299d3581f4dc670734f1fe1a34fce1282337802` commit archive.

Observed binary discriminators:

- IDA string `Unable to parse token length` at `0x0060e730` is referenced by `sub_4345F0` at `0x0043463c`. This string is present in JsonCpp `1.7.x` reader source and absent from `0.10.6`.
- IDA string search found no `reader error` string. JsonCpp `0.10.6` contains `throwRuntimeError("reader error")` in `parseFromStream`; the `1.7.x` source path throws the collected error string instead.
- `Json::Value::asCString(): requires stringValue` appears twice in the `1.7.x` `json_value.cpp` line family and once in `0.10.6`; IDA has the string referenced from both `0x00425a10` and `0x0042b120`, which favors the `1.7.x` layout.

Current conclusion: `0.10.6` is no longer an equal candidate for the observed binary. Combined with the value-core and reader discriminators, this writer-builder island fits the current best source snapshot, official upstream commit `b299d3581f4dc670734f1fe1a34fce1282337802`. The extracted candidate has version macro `JSONCPP_VERSION_STRING "1.7.4"` but includes post-`1.7.4` commit behavior, so document it by commit hash rather than release tag.
