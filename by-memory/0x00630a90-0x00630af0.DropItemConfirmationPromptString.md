# 0x00630a90-0x00630af0 Drop Item Confirmation Prompt String

## Range

- Address range: `0x00630a90-0x00630af0`
- Entity kind: UTF-16 prompt string literal.
- Literal: `Are you sure you want to drop this item? (Y/N)`
- Span size: `0x60` / 96 bytes (Verified with int_convert.py).
- Rebuild handling: source-declared/generated-binary string literal emitted by the item-action prompt source.
- Container: [UID:0002YX][0x00630a90-0x00630bd8.UserPaneDropTargetPromptStrings](by-memory/0x00630a90-0x00630bd8.UserPaneDropTargetPromptStrings.md)

## Evidence

Live IDA MCP on 2026-06-12 against session `b001_nexustk` reconfirmed the exact two xrefs to this literal:

| Address | Function | Use |
| --- | --- | --- |
| `0x005b46e1` | `sub_5B45F0` / `DropAllInputPane::OnConfirmInput` | High-slot drop-all branch allocates a confirmation pane and passes `sub_5B7450(..., selectedSlot, 1)` into `sub_5B75D0` with this prompt. |
| `0x005b4a10` | `sub_5B4920` / `DropInputPane::OnSubmit` | High-slot normal-drop branch allocates the same confirmation path with mode byte `0`. |

The same decompile shows lower inventory slots sending direct opcode `0x08` packets, while only high-slot selections use this visible confirmation string. The string ends with a UTF-16 null at `0x00630aee`; `0x00630af0` starts the next prompt string.

## Ownership And Routing

Assigned to [UID:0000KC][ItemActionInputPanes](by-file/ItemActionInputPanes.md). The literal is shared by [UID:000042][DropAllInputPane](by-class/DropAllInputPane.md) and [UID:000044][DropInputPane](by-class/DropInputPane.md), so the direct source owner for the pooled literal is the item-action input-pane source module rather than one of the two class pages. The child clears `86/92`, and the direct file parent clears the strict gate at `90/85`.

Final C++ remains blank because this page documents the emitted literal, not a standalone source object. The prompt should reappear from the drop confirmation helper/callback construction in `ItemActionInputPanes.cpp`.
