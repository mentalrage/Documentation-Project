## Paint And Text Flow

The method copies current Pane bounds, selects draw color zero, and fills the rectangle
through the established Surface `FillRect` callback. It initializes only the four semantic
FontStyleRule fields: foreground `0x8f`, secondary `0x80`, effect `0`, and alignment `0`.
The three bytes after the effect byte are record padding and are not initialized here.

The owned `SimpleUString` supplies the wide text pointer. Initial drawing coordinates are
constructed with `InitPointPair(y, x)`: y is line height plus vertical padding, while x is
horizontal padding. This y-then-x call order follows the accepted Point helper ABI rather
than textual x/y argument order.

CR (`0x0d`), LF (`0x0a`), and tab (`0x09`) enter the same delimiter branch. Tabs therefore
do not encode inline formatting commands. Consecutive delimiters dispatch empty segments,
CRLF dispatches two breaks, and the tail is always dispatched even when empty. Each break
advances y by line height plus `m_lineSpacing` and increments the unsigned rule index.

When the borrowed `m_fontStyle` is non-null and enabled, `GetRule` updates the current rule
when the index is in range; out-of-range lookup preserves the existing fallback or previous
rule. The private `DrawTextLine` helper consumes that rule. Otherwise the method performs a
plain `MoveTo` followed by `DrawWideText` using the same signed-short segment count.
