## Behavior

- Part `0` is the first button; part `4` is the second button.
- Part `1` is the track before the thumb; part `3` is the track after the thumb.
- Part `2` is the thumb itself.
- The function uses scrollbar orientation, `m_scrollSkinIndex` / style table extents, current position, range, drag state, and EPF skin offset to compute output rectangles.
- Vertical and horizontal paths share the same part-id contract, so callers can request scrollbar subrectangles without duplicating orientation-specific geometry.
- `ScrollPane::OnDraw` calls this helper for each drawable scrollbar part, while text-edit scrollbar handlers use the same rectangles for hot/drag/cursor behavior. That caller mix supports generic scrollbar ownership rather than `TextEditPane` ownership.

## Rectangle Formulas

The decompiler's incidental `char`/`int` return is rejected as source shape. The method writes `outRect` and every observed caller ignores the return, so the source method is `void ScrollPane::GetScrollPartRect(ScrollPanePart part, RectBounds *outRect)`.

In EPF mode (`g_useEpfAssets` / `byte_66DA97 == 1`), the method first reads the current cursor through the event manager, asks the pane for its screen offset, returns without writing when the offset is the `(-1000, -1000)` sentinel, and converts the cursor into pane-local coordinates. The local cursor only affects the EPF vertical drag-active branch.

EPF horizontal mode uses `bounds.bottom - bounds.top` as the thumb extent. Part `0` collapses to `right = left`; part `4` collapses to `left = right`. When a thumb is visible, `thumbLeft = bounds.left + m_scrollPosition * (bounds.right - bounds.left - thumbExtent) / m_scrollRange`, and parts `1`, `2`, and `3` split the full bounds at `[thumbLeft, thumbLeft + thumbExtent]`. When no thumb is visible, part `2` returns the interior trimmed by one thumb extent on both horizontal sides and parts `1`/`3` return an empty rectangle through `InitRectBounds(outRect, 0, 0, 0, 0)`.

EPF vertical mode uses `kScrollPanePartExtentBySkin[m_scrollSkinIndex]` / `dword_624144[m_scrollSkinIndex]` as the fixed thumb extent. Part `0` collapses to `bottom = top`; part `4` collapses to `top = bottom`. When the thumb is visible and `m_thumbDragActive` is false, `thumbTop = bounds.top + (bounds.bottom - thumbExtent - bounds.top) * m_scrollPosition / m_scrollRange`. When `m_thumbDragActive` is true, `thumbTop = bounds.top + localCursor.y - m_thumbDragOffset.y`, clamped to `[bounds.top, bounds.bottom - thumbExtent]`. Parts `1`, `2`, and `3` split around `[thumbTop, thumbTop + thumbExtent]`; no-thumb handling mirrors the horizontal case on the vertical axis.

Classic horizontal mode uses `bounds.bottom - bounds.top` as the button/thumb extent. Part `0` returns `[left, left + extent]`; part `4` returns `[right - extent, right]`. When the thumb is visible, `thumbLeft = bounds.left + extent + m_scrollPosition * (bounds.right - bounds.left - 3 * extent) / m_scrollRange`, then part `1` returns `[left + extent, thumbLeft]`, part `2` returns `[thumbLeft, thumbLeft + extent]`, and part `3` returns `[thumbLeft + extent, right - extent]`. Without a visible thumb, part `2` returns the button-trimmed interior and parts `1`/`3` return an empty rectangle.

Classic vertical mode uses `kClassicScrollPanePartExtentBySkin[m_scrollSkinIndex]` / `dword_62415C[m_scrollSkinIndex]` as the fixed button/thumb extent. Part `0` returns `[top, top + extent]`; part `4` returns `[bottom - extent, bottom]`. When the thumb is visible, `thumbTop = bounds.top + extent + m_scrollPosition * (bounds.bottom - bounds.top - 3 * extent) / m_scrollRange`, then part `1` returns `[top + extent, thumbTop]`, part `2` returns `[thumbTop, thumbTop + extent]`, and part `3` returns `[thumbTop + extent, bottom - extent]`. Without a visible thumb, part `2` returns the button-trimmed interior and parts `1`/`3` return an empty rectangle.
