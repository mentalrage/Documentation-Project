# 0x0047ed20-0x0047ed50 ChangeMan Constructor Cleanup

## Status

- Disposition: ignored for handwritten source reconstruction.
- Entity kind: compiler-generated constructor cleanup/unwind fragment.
- Owner class: [UID:00001K][ChangeMan](by-class/ChangeMan.md)
- Related source module: [UID:0000I2][ChangeMan](by-file/ChangeMan.md)
- Confidence: strong.

## Behavior

This byte range is not modeled by IDA as a normal function. It sits immediately after the `ChangeMan` constructor and immediately before the real register method at `0x0047ed50`.

The fragment restores the [UID:0001X7][ChangeManVtable](by-type/by-vtable/ChangeManVtable.md), destroys `this + 0x04` through that object's vtable when the sorted-list member is non-null, clears the member, clears [UID:0000QI][g_pChangeMan](by-global/g_pChangeMan.md), and tail-jumps into the `LObject` destructor at `0x004f4a90`.

This is MSVC partial-construction cleanup materialization for the constructor path. Reconstructed source should express normal C++ construction and destruction; it should not emit this as a handwritten `ChangeMan` method.

## Evidence

- IDA MCP disassembly on 2026-05-26 shows code bytes from `0x0047ed20` through the tail jump at `0x0047ed4a`, with the next modeled function beginning at `0x0047ed50`.
- IDA MCP `xrefs_to 0x00614cd0` reports the vtable store at `0x0047ed26`.
- IDA MCP `xrefs_to 0x0067ab2c` reports the singleton clear write at `0x0047ed3f`.
- The fragment destroys the same `this + 0x04` member as [UID:000103][0x0047ef50-0x0047efae.ChangeManScalarDeletingDestructor](by-memory/0x0047ef50-0x0047efae.ChangeManScalarDeletingDestructor.md), then tail-jumps to the same base destructor helper.

## Replacement

No separate source construct is required. The final `ChangeMan` source should rely on the compiler to generate equivalent unwind cleanup from the constructor, member ownership, base-class destructor, and normal deleting destructor.
