## Function Boundary

IDA MCP `lookup_funcs` on 2026-05-25 reports a real function at `0x004b89a0` with size `0xdf`, ending at `0x004b8a7e`. Live IDA MCP on 2026-06-04 rechecked the same function body and decompiled the helper as a `thiscall` method with two stack arguments.

## Behavior

This is the one-child analogue of [UID:00015X][0x004b8650-0x004b8822.GeneralPurposePanelSwitchActiveTab](by-memory/0x004b8650-0x004b8822.GeneralPurposePanelSwitchActiveTab.md).

Observed flow:

1. Accepts only child index `0`; returns without switching for any index greater than or equal to `1`.
2. If [UID:0000SK][g_pTotemFrame](by-global/g_pTotemFrame.md) is active, marks it for deletion before switching.
3. Finds the old child from `this[activeIndex + 1]` when the previous active index is valid.
4. Stores the new active index at `this[2]`.
5. Collapses and hides the old child when present.
6. Sets the active child bounds to `(832, 376, 1021, 641)`.
7. Adds the child to the current UI layer/root, activates it, shows it with the caller argument, and runs [UID:0000YI][0x004615b0-0x00461657.AboveFrameRefreshHelpers](by-memory/0x004615b0-0x00461657.AboveFrameRefreshHelpers.md), which refresh the dynamic frame-chrome slot after the switch.

## Caller Evidence

IDA `callers` and `xrefs_to` return a single direct caller inside `UserPane::OnServerMessage` at `0x005a771b`. The singleton data xrefs for [UID:0000R1][g_pGeneralPurposePanel2](by-global/g_pGeneralPurposePanel2.md) also show the same user-pane neighborhood consuming the one-child panel shell.

## Ownership Notes

The helper uses the same one-child layout and active-index field initialized by `GeneralPurposePanel2::GeneralPurposePanel2`, so it should be documented as a `GeneralPurposePanel2` method rather than remaining unknown.

Recommended reconstruction owner: `GeneralPurposePanel2::SwitchActiveChild` or `GeneralPurposePanel2::SwitchActiveTab`.

The `0x004615b0` / adjacent creator pair belongs to [UID:0000JL][FrameChrome](by-file/FrameChrome.md). It is a dependency called after the panel switch, not a `GeneralPurposePanel2`-owned helper.

## 2026-06-04 IDA Evidence

- Live decompilation confirms the bounds check `index < 1`; out-of-range indices return without touching the child slot.
- The previous active child is read from `this[activeIndex + 1]` after checking active index `-1`, then hidden/collapsed through calls at virtual offsets `0x40` and helper `0x00544ee0`.
- The active child is read from `this[index + 1]`, receives bounds `(832, 376, 1021, 641)`, and is then passed through virtual calls at offsets `0x2c`, `0x30`, `0x3c`, and `0x48` with `dword_67A740` and `dword_69B368` as layer/context arguments.
- The helper calls [UID:0000YI][0x004615b0-0x00461657.AboveFrameRefreshHelpers](by-memory/0x004615b0-0x00461657.AboveFrameRefreshHelpers.md) before returning.
- Xrefs still show exactly one direct caller, `0x005a771b` inside `0x005a76c0`.
