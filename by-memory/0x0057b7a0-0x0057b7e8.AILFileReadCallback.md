# AIL File Read Callback

## Status And Source Disposition

- Exact half-open range `[0x0057b7a0,0x0057b7e8)`, size `0x48`.
- File-static Miles read callback canonically owned by [UID:0000NV][SoundManager](by-file/SoundManager.md) and inserted through class router [UID:0000DG][SoundManager](by-class/SoundManager.md) at position `550`. This is an output-order route, not class membership: it preserves the physical `520-560` callback sequence after the following stream callback moved into private static SoundManager scope.
- [UID:0004WV][SoundManagerMilesCallbackDeclarations](by-item/SoundManagerMilesCallbackDeclarations.md) owns the sole prototype. This page owns one CPP definition and keeps H blank.

## Exact Behavior And Preserved Weakness

The callback recovers `File *` from the 32-bit Miles handle, obtains `GetSize()` and `GetPosition()`, subtracts them, and interprets the remaining count as unsigned `U32`. When the requested byte count is greater than or equal to that remaining count, it clamps the request to the remainder. It calls `File::Read(buffer, bytes)`, deliberately ignores the actual read result, and returns the clamped request count.

The ignored `Read` return is an observed runtime weakness, not an omission to repair. A short underlying read can therefore be reported to Miles as if the full clamped request succeeded. The unsigned subtraction/comparison must also remain: adding signed underflow guards, EOF validation, or a short-read retry would alter executable behavior.

## Binary Evidence, Xrefs, And Boundaries

- Live evidence reports a modeled `0x48` function and one data xref from `0x0057b587`, the read argument in the four-callback registration sequence.
- The body dispatches File size and position virtual slots, subtracts, performs the unsigned clamp, dispatches File read, discards its return, and returns the local clamped count.
- `[0x0057b793,0x0057b7a0)` is a separate thirteen-byte all-`0xcc` item after seek.
- `[0x0057b7e8,0x0057b7f0)` is a separate eight-byte all-`0xcc` item before the stream callback.
- Both gaps have no name, type, comments, or xrefs and remain alignment rather than authored source.

## Ownership, Naming, And Rejected Alternatives

The sole registration xref places this adapter in SoundManager.cpp. Generic File dispatch makes FileIO a dependency, not the callback owner. A class method is rejected because no SoundManager receiver is passed. Third-party Miles implementation is rejected because the function adapts NexusTK's own File hierarchy to the external SDK ABI.

The descriptive callback and local names are inferred from exact behavior and the accepted sibling pattern. Emitted source intentionally omits raw `sub_57B7A0`, `_DWORD`, and virtual-slot arithmetic.
