# 0x0067adf0-0x0069adf0 WideCharStrGlobalBuffer

## Status

- Entity kind: global-data buffer.
- Disposition: reconstructable NexusTK project global state.
- Rebuild handling: source-declared/generated-binary.
- Likely owner: clan dialog/packet text handling, pending broader text-buffer review.
- Confidence: strong for address, size, and direct user; medium for final owner/name.

## Storage

`0x0067adf0-0x0069adf0` is a 128 KiB global UTF-16 scratch buffer, named `WideCharStr` by IDA. The observed access pattern treats it as `WCHAR[0x10000]`.

Candidate source shape:

```cpp
static wchar_t g_wideTextScratch[0x10000];
```

The final name should be chosen after reviewing whether any non-clan packet handlers use the same scratch buffer.

## Evidence

- IDA MCP byte review shows the entire range is in `.data` and initialized to `0xff`.
- IDA names `0x0067adf0` as `WideCharStr`.
- Decompilation of `0x004877d0` writes converted packet text into `(LPWSTR)(2 * offset + 0x0067adf0)` with a remaining count of `0x10000 - offset`, then terminates `::WideCharStr[v7] = 0`.
- The same function passes `::WideCharStr` and `wcslen(::WideCharStr)` into a text-pane/update helper after converting packet bytes.
- [UID:00021S][0x004877d0-0x00488594.ClanStatusPacketDialogHandlers](by-memory/0x004877d0-0x00488594.ClanStatusPacketDialogHandlers.md) owns the only currently observed direct xrefs.

## Rebuild Notes

This is source-authored mutable storage, not compiler padding. It may be reducible or replaceable by dynamic string storage in a non-address-identical rebuild, but the original binary has a fixed 65536-wide-character global buffer.
