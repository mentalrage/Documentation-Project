# 0x00463970-0x004639c4 Application Destructor

## Scope

- Entity kind: class destructor

## Signature And ABI

- IDA models the body as `void __thiscall sub_463970(int this)`.
- `ecx` is the `Application` object. The IDA `int` type is not a final class type.
- There are no explicit stack arguments and no returned source value.
- The function ends with a tail jump to [UID:0000KV][LObject](by-file/LObject.md) destructor cleanup at `0x004f4a90`.

## Behavior

Destroys the process-level `Application` object after startup/shutdown code has already run. The destructor:

1. Restores the two `Application` vtable slots at object offsets `0x0` and `0x4`.
2. Reads the closeable handle at `Application + 0x24`; if non-null, calls `CloseHandle` and stores `0` back to `Application + 0x24`.
3. Releases the string-like member at `Application + 0x854` through `sub_582B70`.
4. Releases the string-like member at `Application + 0x1c` through `sub_582B70`.
5. Destroys the embedded/default [UID:0001CN][0x00528d60-0x00528e55.MSGHandler](by-memory/0x00528d60-0x00528e55.MSGHandler.md) subobject at `Application + 0x4` through `sub_528D80`.
6. Clears [UID:000294][0x0067ab1c-0x0067ab20.g_pApplication](by-memory/0x0067ab1c-0x0067ab20.g_pApplication.md) / `dword_67AB1C`.
7. Tail-jumps to `LObject::~LObject` at `0x004f4a90`, which restores the base `LObject` vtable.

The body does not call `Application::CleanupResources`; resource-manager and subsystem teardown are handled by the separate cleanup/shutdown methods before this object destructor runs.
