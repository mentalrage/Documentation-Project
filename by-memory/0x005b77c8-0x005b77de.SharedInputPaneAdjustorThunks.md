# 0x005b77c8-0x005b77de SharedInputPaneAdjustorThunks

## Status

- Disposition: ignored for handwritten source reconstruction.
- Entity kind: compiler-generated secondary/tertiary destructor adjustor thunks.
- Current generated ownership: often attached to `TakeOffInputPane` or nearby input-pane classes.
- Real owner model: C++ inheritance/vtable layout shared by `LineInputPane`/`CharInputPane` derivatives.
- Confidence: strong.

## Covered Range

| Range | Current label | Notes |
| --- | --- | --- |
| `0x005b77c8-0x005b77d3` | secondary adjustor thunk | Subtracts `0xa0` from `ecx` and jumps to scalar deleting destructor `0x005b7940`. |
| `0x005b77d3-0x005b77de` | tertiary adjustor thunk | Subtracts `0xa4` from `ecx` and jumps to scalar deleting destructor `0x005b7940`. |

## IDA MCP Evidence

- `disasm 0x005b77c8` shows `sub ecx, 0A0h` followed by `jmp sub_5B7940`.
- `disasm 0x005b77d3` shows `sub ecx, 0A4h` followed by `jmp sub_5B7940`.
- `disasm 0x005b7940` shows the shared scalar deleting destructor wrapper calling `0x004f2010`, then optionally freeing or vector-deleting storage.
- `xrefs_to 0x005b77c8` and `xrefs_to 0x005b77d3` report broad vtable data refs across item, command, spell, and target-input pane tables, including `TakeOffInputPane`, `ChangeItemSlotInputPane`, `Drop*InputPane`, `Give*InputPane`, `ThrowInputPane`, `UseInputPane`, `EatInputPane`, `WieldInputPane`, and `WearInputPane`.

## Reconstruction Decision

Ignore these two functions as compiler-generated layout glue. The final source should model the owning pane classes with normal inheritance and destructors; it should not port these two tiny adjustor wrappers as handwritten methods.

Do not treat the generated `TakeOffInputPane` label as exclusive ownership. The xref set proves the thunks are shared by the broader input-pane vtable block.
