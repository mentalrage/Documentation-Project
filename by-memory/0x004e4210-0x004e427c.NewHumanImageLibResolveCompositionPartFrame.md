## Behavior

`ResolveCompositionPartFrame` resolves a `Part.tbl` frame draw record for the render path.

1. Falls back to descriptor zero when the requested `descriptorIndex` is outside the selected Part.tbl row's descriptor count. The binary deliberately does not add a separate zero-count guard.
2. Selects the 0x20-byte descriptor and the inline 0x10-byte `NewHumanSequenceFrameTable` slot for `motionIndex`.
3. Returns without writing when that slot's `frames` pointer at `+0x0c` is null.
4. Reads the packed 9-byte frame row at `frameIndex`, adds its `recordIndex` to descriptor `drawIndexBase`, and projects the corresponding `FrameDrawRecord` through `g_pEPFLib->LoadFrameDrawRecord`.
5. Adjusts `outRecord->sourceRect` with `RectBounds::Offset(xOffset, yOffset)`.

The formal block uses inferred support names `NewHumanPartEntry`, `NewHumanPartFrameDescriptor`, `NewHumanSequenceFrameTable`, `FrameDrawRecord`, and `ResolveCompositionPartFrame`. These are source-facing names chosen from behavior and local NewHuman layout evidence, not proven original spellings. The older `NewHumanDrawRecord` name is superseded historical shorthand for this same accepted shared 40-byte type.
