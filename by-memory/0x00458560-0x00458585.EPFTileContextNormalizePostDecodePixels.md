## Behavior

This helper finalizes a decoded 16-bit pixel buffer after image-loader code has filled the `EPFTileContext` primary pixel data. If `byte_69B3D5` is clear, it calls the compatibility pixel transform at `0x004bb0e0` over the decoded pixel buffer.

The pixel count is computed from the context bounds:

```text
(0x04) pixelData
(0x10) left
(0x14) top
(0x18) right
(0x1c) bottom
count = (right - left) * (bottom - top)
```

IDA decompiles the body as:

```c
void __thiscall sub_458560(int this)
{
    if (!byte_69B3D5)
        sub_4BB0E0(*(unsigned __int16 **)(this + 4),
                   (*(int *)(this + 24) - *(int *)(this + 16)) *
                   (*(int *)(this + 28) - *(int *)(this + 20)));
}
```

`sub_4BB0E0` iterates `count` 16-bit pixels and rewrites each value as `(pixel & 0x001f) | ((pixel >> 1) & 0x7ff0)`. The exact product-level meaning of `byte_69B3D5` still belongs to the render-mode/global pass, but nearby docs identify it as part of the surface pixel-format mode initialized with the render callback table.

The helper has no alternate branch, no allocation, and no buffer lifetime side effects. If the render-mode byte is already set, it returns without mutating the context.
