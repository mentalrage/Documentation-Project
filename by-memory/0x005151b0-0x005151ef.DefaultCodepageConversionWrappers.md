## Behavior

Both helpers are thin default-codepage conversion wrappers used by the ref-counted string family. They pass code page `0` (`CP_ACP`) and flags `0`, so conversion uses the process default ANSI code page rather than UTF-8 or a resource-specific code page.

`0x005151b0` converts an ANSI byte range into a caller-supplied wide buffer:

```text
MultiByteToWideChar(0, 0, sourceBytes, sourceByteCount, destinationWide, destinationCharCapacity)
```

`0x005151d0` converts a UTF-16 range into a caller-supplied ANSI buffer:

```text
WideCharToMultiByte(0, 0, sourceWide, sourceCharCount, destinationBytes, destinationByteCapacity, NULL, NULL)
```

Neither helper allocates, frees, touches globals, or adds validation; buffer sizing, terminators, and string-header length updates are handled by the `0x00582500+` callers.

## Signature Notes

- IDA decompiles `0x005151b0` as `int __cdecl sub_5151B0(LPWSTR outWide, int outChars, LPCCH inBytes, int inBytesCount)`.
- IDA decompiles `0x005151d0` as `int __cdecl sub_5151D0(LPSTR outBytes, int outBytesCapacity, LPCWCH inWide, int inWideChars)`.
- The return value is the Win32 API conversion count forwarded directly to the caller.
