# 0x005151b0-0x005151ef Default Codepage Conversion Wrappers

## Status

- Disposition: reconstructable utility wrapper code.
- Entity kind: global helper functions.
- Proposed file: [UID:0000OA][StringBase](by-file/StringBase.md) or [UID:0000OB][StringUtil](by-file/StringUtil.md)
- Confidence: strong for function boundaries and behavior; medium for exact original source owner.

## Covered Ranges

| Range | Current IDA name | Proposed role |
| --- | --- | --- |
| `0x005151b0-0x005151cb` | `sub_5151B0` | `MultiByteToWideDefaultCp`: wraps `MultiByteToWideChar(0, 0, ...)`. |
| `0x005151d0-0x005151ef` | `sub_5151D0` | `WideCharToMultiByteDefaultCp`: wraps `WideCharToMultiByte(0, 0, ...)`. |

## Behavior

Both helpers are thin default-codepage conversion wrappers used by the ref-counted string family. The first converts an ANSI byte range into a caller-supplied wide buffer. The second converts a UTF-16 range into a caller-supplied ANSI buffer.

## Evidence

- IDA MCP reports real functions at `0x005151b0-0x005151cb` and `0x005151d0-0x005151ef`.
- IDA decompilation shows direct calls to `MultiByteToWideChar(0, 0, ...)` and `WideCharToMultiByte(0, 0, ..., 0, 0)`.
- Xrefs to `0x005151b0` come from string constructors/converters at `0x00582500` and `0x00582830`.
- Xrefs to `0x005151d0` come from string conversion helpers at `0x005825a0`, `0x00582680`, and `0x00582770`.
- Historical Wave2 notes already named these helpers `MultiByteToWideDefaultCp_5151B0` and `WideCharToMultiByteDefaultCp_5151D0`.

## Reconstruction Notes

Keep these near `StringBase`/`StringUtil`, not with the following MD5 helper island. They are adjacent to [UID:0001B6][0x005151f0-0x00515f48.MD5HashHelpers](by-memory/0x005151f0-0x00515f48.MD5HashHelpers.md) only by layout.
