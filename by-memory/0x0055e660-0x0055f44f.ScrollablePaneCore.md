## Behavior Summary

This cluster implements the active `ScrollablePane` body around owned horizontal and vertical [UID:0000CM][ScrollPane](by-class/ScrollPane.md) children. The constructor creates a horizontal `ScrollPane(1)` and vertical `ScrollPane(0)`, initializes content/viewport rectangle state, and the in-cluster cleanup body deletes the owned scrollbar children before base teardown. The separate [UID:0001H6][0x005654ec-0x00565608.ScrollablePaneVirtualDefaults](by-memory/0x005654ec-0x00565608.ScrollablePaneVirtualDefaults.md) island covers later scalar deleting destructor/default virtual support. The layout path toggles scrollbar visibility, computes high/low-resolution scrollbar bounds, shrinks the content rectangle around enabled bars, and calls the internal `0x0055f250-0x0055f44f` viewport recompute helper.

The `0x0055e7e0-0x0055e83c` helper is source-facing inferred `ScrollablePane::SetSkinIndex(unsigned short)`, not a scroll-range setter. It visits both owned children, compares and writes each child's `m_scrollSkinIndex` word at `+0xf8`, and invokes the child change callback only on change. The [UID:0002EO][0x0047efb0-0x0047f1ce.ChattingPaneConstructor](by-memory/0x0047efb0-0x0047f1ce.ChattingPaneConstructor.md) call with literal `1` immediately after `SyncScrollbars()` is a derived-class caller and does not transfer ownership from `ScrollablePane`.

The adjacent `[0x0055e840,0x0055e897)` body is source-facing `ScrollablePane::SetScrollbarsVisible(bool)`. It preserves horizontal-child then vertical-child order and independent null checks. UID0000CM declares inline `ScrollPane::SetScrollStyle(unsigned char)`, whose exact changed-value compare, one-byte `m_scrollStyle +0xfa` store, and virtual `InvalidateRect(&m_visibleBounds)` lowering appears twice in this body. The child inherited bounds are at `+0x44`; no raw offsets, undeclared facade, separate mode, extra include, or duplicate UID00042X CPP body remain in source.

Layer membership and input helpers keep the owned scrollbar children synchronized with the base pane. Add/remove paths attach or detach enabled scrollbar children alongside the base pane. EventHandler secondary pointer/mouse `+0x04` and key/text `+0x08` dispatch give child scrollbars first chance, then recover the complete object and call primary `+0x60` or `+0x64` respectively. The update path temporarily intersects the visible region with the content region while the scroll update hook runs.

Do not document this as one broad `0x0055e660-0x00565608` contiguous class range. The intervening corridor contains mixed `TextEditPane` scrollbar code, and the later default/destructor cluster is already split into its own exact page.
