## Behavior

This helper grows a begin/end/capacity vector of six-byte fitting-room catalog part records and inserts one new record at the requested position. The only live direct caller is the catalog-entry item parser path in [UID:0002E4][0x00421a40-0x00421fd8.FittingRoomCatalogEntryFromJson](by-memory/0x00421a40-0x00421fd8.FittingRoomCatalogEntryFromJson.md), which appends a parsed part record when the current part-vector storage is full.

The vector triplet uses:

- begin pointer at vector slot `0x00`;
- end pointer at vector slot `0x04`;
- capacity pointer at vector slot `0x08`;
- in the active caller, the triplet is the `FittingRoomCatalogEntry` tail at entry offsets `+0xb4`, `+0xb8`, and `+0xbc`;
- fixed element stride of six bytes, copied as one dword plus one word.

On growth, the helper computes the insertion index from the position pointer, computes the current size by dividing pointer deltas by six, rejects the `0x2aaaaaaa` element limit through the vector-too-long helper at `0x00421500`, chooses `max(size + 1, oldCapacity + oldCapacity / 2)` when that growth is safe, allocates `newCapacity * 6` bytes, copies the inserted record into its new slot, copies the pre-insert and post-insert ranges around it, frees the old backing storage with aligned-allocation validation, updates begin/end/capacity, and returns the inserted-record pointer.

The only caller passes the current end pointer as the insertion position, so the observed fitting-room use is append growth. The helper is nevertheless shaped as a general vector insert slow path: it preserves a prefix, writes the new element, then preserves the suffix.
