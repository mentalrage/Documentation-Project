## Summary

This child covers the physical `COMMA.EPF` string. It is a real `.rdata` item, but B001-051 found direct consumers across unrelated source owners, so assigning the physical literal to any one source file would overclaim ownership.

## IDA Evidence

- IDA decodes the literal at `0x006247f0` as `COMMA.EPF`.
- Direct xrefs include SelfLookPane function `0x00567480`, GroupPane function `0x0056ce50`, and UserStatusPane2 function `0x005baf80`.
- These callers route to separate documented file parents: [UID:0000NL][SelfLookPane](by-file/SelfLookPane.md), [UID:0000JS][Group](by-file/Group.md), and [UID:0000P2][UserStatusPane](by-file/UserStatusPane.md).

## NewGroupPane Frame-Zero Lookup Evidence - 2026-08-16

- [UID:0004Z5][0x0056ce50-0x0056da03.NewGroupPaneOnPaint](by-memory/0x0056ce50-0x0056da03.NewGroupPaneOnPaint.md) is one of the literal's three direct consumers. It pushes `L"COMMA.EPF"` at `0x0056cf1b` and calls the EPF lookup at `0x0056cf20` with frame index zero.
- The output is an `EPFTileContext` local that was explicitly initialized before the lookup. The method performs this lookup after all six observed context initializers and before the normal/expanded background rendering branch.
- No later direct method read consumes the lookup output. Human source must nevertheless retain the call because it is a binary-observed resource lookup with possible cache/resource side effects; it must not invent a `DrawNumberString` or other numeric-overlay dependency for the local.
- The same method uses other context locals for background, member bars, and the toggle button, but that stack-liveness detail does not make this pooled UTF-16 item Group-owned. SelfLookPane and UserStatusPane2 remain independent consumers, so `CANONICAL_OWNER:NONE`, `RECONSTRUCTABLE:FALSE`, blank emitter/formal channels, and `85/88` remain correct.
- Historical generic wording that identified only the containing GroupPane function is refined by the exact instruction phase and output disposition above; it is not evidence for a named standalone resource object.

## Rule 26 Claim Details

B001-051 identified this as a linker/resource-pooled literal rather than a source-local declaration. The accepted decision is parent blank and non-emitting because the three consumer families are unrelated source owners in current documentation. SelfLookPane uses it with look rendering, GroupPane uses it from the group drawing/setup path, and UserStatusPane2 uses it for compact-number separator resources.

Rejected routes: do not assign this physical string to SelfLookPane just because it is adjacent to SelfLookPane look resources; do not assign it to Group because `0x0056ce50` is only one consumer; and do not assign it to UserStatusPane merely because the resource also belongs to user-status package evidence. Those are use routes, not proof of one original declaration owner.

## Ownership And Reconstruction

Keep `AUTOGEN_PARENT_UID` blank and `RECONSTRUCTABLE:FALSE`. The xrefs prove shared use, not a single source declaration owner. This page documents the pooled physical literal so the surrounding split is exact without forcing false source ownership.
