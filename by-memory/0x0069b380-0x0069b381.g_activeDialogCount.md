# 0x0069b380-0x0069b381 g_activeDialogCount

## Status

- Disposition: reconstructable source-declared global storage.
- Entity kind: global UI/input gate byte.
- Proposed owner: [UID:0000IT][DialogPane](by-file/DialogPane.md) / shared dialog lifetime state.
- Confidence: strong for address, lifecycle owner, references, and gating behavior; medium-high for exact source declaration because the stored initial value is `0xff`.

## Covered Range

| Range | Role |

| `0x0069b380-0x0069b381` | One-byte active-dialog depth/gate adjusted by `DialogPane` lifetime and read by inventory, spell, and take-off action paths. |

## Interpretation

The byte behaves as a modal/dialog activity gate. Dialog construction increments it at `0x0049d902`, dialog destruction decrements it at `0x0049da31`, and consumers compare it with zero before allowing immediate item, spell, and equipment actions. The initial image byte is `0xff`, so the behavioral name is well supported, but the exact original source type and bias convention remain below the final reconstruction gate.

## Evidence

- Live IDA reports exactly 13 direct references to `0x0069b380`.
- `DialogPane` construction increments the byte at `0x0049d902` after installing the dialog vtable views and initializing layout/control state.
- `DialogPane` destruction decrements the byte at `0x0049da31` before releasing child/control state and tearing down the layout helper.
- Inventory code tests the byte at `0x004ed126`, `0x004ed4e5`, `0x004ed667`, `0x004edce3`, `0x004edd61`, and `0x004ee483` before immediate inventory input/action branches.
- Spell inventory code tests the byte at `0x0057ddae` and `0x0057df37`; the packet helper at `0x0057e633` sends opcode `0x0f` only when the byte is not positive.
- Take-off logic tests the byte at `0x005b27d3` and `0x005b2914`; both packet paths send opcode `0x1f` only when the byte is not positive.
- No live direct refs target `0x0069b381`, keeping the documented range to one byte.
