## Function Role

`VectorGrowMotion` grows the `Motion.tbl` record vector owned by [UID:000092][NewHumanImageLib](by-class/NewHumanImageLib.md). The function inserts one fixed-size `0x42` byte record at the requested position, reallocates when capacity is exhausted, copies records before and after the insertion point, frees the old storage, and returns the inserted record pointer.

This is a source-adjacent helper for the new-human image library, not a method on the unrelated runtime [UID:00008R][Motion](by-class/Motion.md) class.

## Observed Shape

```text
MotionEntryVector
  +0x00 begin
  +0x04 end
  +0x08 capacity

MotionEntry size: `0x42` bytes, 66 decimal bytes (Verified with int_convert.py)
```

The capacity growth follows the MSVC vector pattern of `oldCapacity + oldCapacity / 2`, clamped up to the requested count. Large allocations use aligned storage with the raw allocation pointer stored immediately before the aligned pointer.

## Detailed Behavior

| Phase | Evidence |
| --- | --- |
| Compute insertion index | IDA decompile computes `(insertPos - begin) / 0x42` from the vector and insert-position arguments. |
| Compute current size | Computes `(end - begin) / 0x42`; if size reaches `0x3e0f83e`, 65075262 decimal (Verified with int_convert.py), it calls `0x00421500` as the length-error path. |
| Choose new capacity | Reads capacity pointer, derives `(capacity - begin) / 0x42`, grows by half, and clamps upward to `size + 1`. |
| Allocate new storage | For allocations below `0x1000`, 4096 decimal bytes (Verified with int_convert.py), calls `operator new(size)`. For larger allocations, allocates `size + 0x23`, 35 decimal bytes (Verified with int_convert.py), aligns the returned pointer to `0x20`, 32 decimal bytes (Verified with int_convert.py), and stores the raw allocation pointer at `aligned[-4]`. |
| Copy inserted record | Copies four 16-byte chunks from the source record and then the final 16-bit word at record offset `+0x40`, proving a `0x42`-byte, 66 decimal byte (Verified with int_convert.py) element. |
| Preserve existing records | If inserting at end, `memmove`s the entire prefix. Otherwise, `memmove`s the prefix before the insertion point and the suffix after the insertion point to `newInsert + 0x42`. |
| Free old storage | If the old allocation is non-null, frees it directly when the allocation size is under `0x1000`; otherwise validates the stored raw pointer before freeing. |
| Publish vector pointers | Stores new begin, new end as `newBegin + 0x42 * (oldSize + 1)`, and new capacity as `newBegin + 0x42 * newCapacity`; returns the inserted element pointer. |
