        AIL_close_stream(m_stream);

    m_digitalDriver = AIL_open_digital_driver(sampleRate, 16, 2, 1);

## Detailed Behavior

`SoundManager::ReinitializeAudioDriver` is the Miles Sound System startup/restart bridge. Existing SoundManager file and audio-subsystem docs show it shuts down and restarts Miles state, sets the redistributable/runtime directory, opens the digital driver, configures the DirectSound HWND, registers the file-callback family through `AIL_set_file_callbacks`, and allocates the sample handles used by sound-effect playback.

B009's 2026-06-19 [UID:0003ZJ][0x0057b3f0-0x0057b48d.SoundManagerRotateReusableSampleSlotRaw](by-memory/0x0057b3f0-0x0057b48d.SoundManagerRotateReusableSampleSlotRaw.md) pass pins the exact sample-slot allocation window in this initializer. After `0x0057b59b` registers AIL file callbacks, `0x0057b5a1` pushes `0x40`, `0x0057b5a3` loads `this+0x48` into the slot-array cursor, `0x0057b5b0` clears the 64-byte array through a memset-like helper, and `0x0057b5be-0x0057b5d4` loops eight times calling `mss32.dll!_AIL_allocate_sample_handle@4` through `0x0060d5cc`, storing each returned `HSAMPLE` at the current slot dword 0 before advancing by stride 8. This initializer produces the handles later consumed by live [UID:0001I9][0x0057a260-0x0057a88e.SoundManagerPlaybackControls](by-memory/0x0057a260-0x0057a88e.SoundManagerPlaybackControls.md) and raw no-entry [UID:0003ZJ][0x0057b3f0-0x0057b48d.SoundManagerRotateReusableSampleSlotRaw](by-memory/0x0057b3f0-0x0057b48d.SoundManagerRotateReusableSampleSlotRaw.md); it does not call, fall through into, or absorb the raw helper, which is separated from this page by `0x0057b48d-0x0057b490` three `0xcc` bytes.

The callback family is project-owned glue, not Miles runtime code. The open callback [UID:0000TU][0x0057b630-0x0057b72b.AILFileOpenCallback](by-memory/0x0057b630-0x0057b72b.AILFileOpenCallback.md) converts the incoming ANSI path, probes the DAT archive through [UID:0000T0][HasDATEntry_49C700](by-global/HasDATEntry_49C700.md), falls back to loose-file existence through [UID:0000V6][PathExistsViaStat_00582460](by-item/PathExistsViaStat_00582460.md), constructs either [UID:00003G][DATFile](by-class/DATFile.md) or [UID:0000E6][StdioFile](by-class/StdioFile.md), then calls the selected reader's virtual `Open` slot before returning the handle to Miles.

The close, seek, and read callbacks keep the same `File` API bridge. The close callback destroys the selected file object when Miles is done with it. The seek callback forwards to the virtual seek operation and returns the current position. The read callback clamps the requested byte count to the remaining size before forwarding to the virtual read slot, protecting Miles stream reads from over-running the selected DAT/loose-file object.
