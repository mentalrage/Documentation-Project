# MSVC STL Iostream Template Support

## Address Range

- `0x004361b0-0x00439df9`
- Entity kind: runtime / third-party template support.
- Disposition: ignored for NexusTK-owned reconstruction.
- Rebuild handling: `compiler/linker-generated` plus `third-party/runtime`.

## Summary

This range is a dense support island of MSVC/Dinkumware STL, iostream, locale, exception, string, and map/set template helpers. Many callers are JsonCpp value/writer/parser helpers, but the code is not NexusTK feature logic and should not become a product source module.

The rebuilt project should express the source-level JsonCpp and NexusTK uses of `std::string`, `std::map`, `std::set`, streams, and exceptions. Equivalent helper code should come from the selected compiler/runtime and template instantiation, not from hand-ported decompiler output.

## Source-Owner Policy

Ranked routing decision:

1. Keep `CANONICAL_OWNER:NONE` with `RECONSTRUCTABLE:FALSE`. This is a runtime/compiler-template support island, not a product source unit.
2. [UID:0001QE][client_libraries](by-meta/client_libraries.md) is procurement/context only. It should explain the compatible MSVC-era CRT/STL/Dinkumware requirement, but it is not a canonical emitter for this by-memory page.
3. [UID:0000KI][JsonCpp](by-file/JsonCpp.md) ownership is rejected. JsonCpp is the heaviest nearby source consumer, but the diagnostic strings, broad runtime caller spread, and standard-library helper shapes prove the range is not JsonCpp-authored source.
4. [UID:0000XA][0x00439e00-0x00439ea3.DequeDestroy](by-memory/0x00439e00-0x00439ea3.DequeDestroy.md) and adjacent project ownership are rejected because `DequeDestroy` begins only after seven bytes of padding at `0x00439e00`.
5. Product modules such as MiniMap/LodePNG-facing callers are rejected. Later product/library callers consume shared helpers but do not own helper source.
6. Per-family source splits are not useful for source emission today. They would produce more non-emitting runtime helper pages with the same compiler-template policy.

## No-Code Proof

Do not add first-draft C++ or no-op stubs for this target. The range is filled with standard-library/vendor helpers for iostream state/sentry handling, locale exception handling, `std::string`, `std::map`, `std::set`, tree/copy helpers, and exception/string support. Its diagnostic strings are compiler/runtime strings, and the broad caller spread crosses JsonCpp, later support islands, and product/library users. The source rebuild action belongs at caller sites: use `std::string`, `std::map`, `std::set`, streams, exceptions, and staged JsonCpp source normally, then let the selected MSVC-era compiler/runtime generate equivalent helper code. Hand-porting decompiler output here would create non-source library implementation code and pin the rebuild to raw compiler helper shapes.
