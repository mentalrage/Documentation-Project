# MSVC STL Iostream Template Support

## Address Range

- `0x004361b0-0x00439df9`
- Entity kind: runtime / third-party template support.
- Disposition: ignored for NexusTK-owned reconstruction.
- Rebuild handling: `compiler/linker-generated` plus `third-party/runtime`.

## Summary

This range is a dense support island of MSVC/Dinkumware STL, iostream, locale, exception, string, and map/set template helpers. Many callers are JsonCpp value/writer/parser helpers, but the code is not NexusTK feature logic and should not become a product source module.

The rebuilt project should express the source-level JsonCpp and NexusTK uses of `std::string`, `std::map`, `std::set`, streams, and exceptions. Equivalent helper code should come from the selected compiler/runtime and template instantiation, not from hand-ported decompiler output.

## Evidence

- Live IDA MCP audit on 2026-06-04 against `NexusTK.exe` (`md5 4247e04e20b65d6414c7238aa8ff5515`, image base `0x00400000`) reports 63 modeled functions from `sub_4361B0` at `0x004361b0-0x00436256` through `sub_439CF0` at `0x00439cf0-0x00439df9`.
- Start boundary is closed by live neighbor and byte checks: `sub_436010` ends at `0x00436177`, bytes `0x004361ae-0x004361b0` are `cc cc`, and `sub_4361B0` begins at `0x004361b0`.
- End boundary is closed by live neighbor and byte checks: `sub_439CF0` ends at `0x00439df9`, bytes `0x00439df9-0x00439e00` are seven `0xcc` bytes, and `sub_439E00` begins the next documented project-code range at `0x00439e00`.
- Live string-xref audit confirms standard-library diagnostics inside the island: `ios_base::badbit set`, `ios_base::failbit set`, and `ios_base::eofbit set` are each referenced by five helper functions (`sub_436340`, `sub_436630`, `sub_436DD0`, `sub_4385C0`, `sub_438AE0`); `map/set<T> too long` is referenced from `sub_437E40` and `sub_437FA0`; `bad locale name` is referenced from `sub_439650`.

- Live xrefs report 371 external code references into function starts in this island. Samples include JsonCpp value/writer/parser and adjacent support callers at `0x00427310`, `0x00428720`, `0x00428940`, `0x00425010`, `0x00430ae0`, `0x00431080`, `0x00431130`, `0x004354b0`, `0x004358c0`, `0x00435e10`, and `0x00436010`, consistent with shared Dinkumware template/runtime support rather than one NexusTK-owned source module.
