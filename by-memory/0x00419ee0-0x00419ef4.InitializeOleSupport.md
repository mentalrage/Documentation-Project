## Behavior

`0x00419ee0` initializes OLE for the process by calling `OleInitialize(0)`, then registers the paired OLE teardown thunk at `0x0060c0f0` with `_atexit`.

The registered shutdown thunk writes the anonymous `AutoInit` vtable pointer into the static object slot `off_66D42C`, then tail-jumps to `OleUninitialize`. The vtable is documented by [UID:0001X0][AutoInitVtable](by-type/by-vtable/AutoInitVtable.md), and the static object slot is documented by [UID:000277][0x0066d42c-0x0066d430.AutoInitStaticObjectVptr](by-memory/0x0066d42c-0x0066d430.AutoInitStaticObjectVptr.md).

This is important source-policy evidence for [UID:00000Q][AutoInit](by-class/AutoInit.md), but the exact helper is not a source-callable project function. Current MCP evidence shows no ordinary callers and one startup-table data xref. The source-level reconstruction should declare the AutoInit/OLE lifetime object or equivalent platform startup policy, not a raw helper named after this startup-table body.
