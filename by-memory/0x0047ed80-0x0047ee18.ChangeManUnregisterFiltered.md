## Behavior

`ChangeMan::UnregisterFiltered` removes registrations for one owner, optionally narrowing by listener and message filter. It lower-bounds the sorted list by owner pointer, scans forward while the owner still matches, and removes matching entries through the list vtable remove-at slot.

Match behavior:

| Filter | Match rule |
| --- | --- |
| listener pointer | `0` is a wildcard, otherwise must match entry offset `0x04`. |
| scope byte | `1` is an all-message wildcard. |
| message type | when scope byte is `0`, message type must match entry offset `0x0c`. |

After a removal, the method decrements the current index and cached count before continuing, which prevents skipped entries after compaction.

## Raw Code Evidence

IDA raw disassembly on 2026-05-30 confirms the loop mechanics that are easy to lose in decompiler output:

- `0x0047ed98` calls `sub_4F3780(m_changeList, &key)` to find the owner lower-bound.
- `0x0047eda5` reads the current list count from `m_changeList + 0x0c`.
- `0x0047edbb` calls the list vtable slot `+0x10` to fetch the current entry.
- `0x0047edc1-0x0047edc3` breaks when `entry.owner != owner`.
- `0x0047edc5-0x0047edd4` implements listener wildcard matching: null listener matches all, otherwise the listener must equal `entry.listener`.
- `0x0047edd4-0x0047edee` implements scope/message matching: scope byte `1` matches all messages, scope byte `0` matches only `entry.messageType == messageType`, and other scope values fail.
- `0x0047edfa-0x0047ee06` calls list vtable slot `+0x1c` with `(index, 1)`, then decrements both index and cached count before the loop increment.

## C++ Reconstruction Candidate

```cpp
void ChangeMan::Unregister(void *owner, ChangeListener *listener, int messageType, bool allMessages)
{
    ChangeManEntry key;
    key.owner = owner;

    int index = m_changeList->LowerBound(&key);
    int count = m_changeList->Count();
    if (index < 0 || index >= count)
        return;

    for (; index < count; ++index) {
        ChangeManEntry *entry = m_changeList->At(index);
        if (entry->owner != owner)
            break;

        bool listenerMatches = (listener == nullptr || entry->listener == listener);
        bool messageMatches = (allMessages == true) ||
            (!allMessages && entry->messageType == messageType);

        if (listenerMatches && messageMatches) {
            m_changeList->RemoveAt(index, true);
            --index;
            --count;
        }
    }
}
```

The `allMessages` name is provisional; IDA only proves the byte semantics (`1` wildcard, `0` message-type filtered).
