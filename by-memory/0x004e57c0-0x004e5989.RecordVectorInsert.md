## Behavior Details

- Treats `this` as a three-pointer vector header over `0x28` / 40-byte records: begin pointer, end pointer, and capacity-end pointer.
- Computes insertion index from `position - begin` and current size/capacity from the vector triplet, all divided by `40`.
- Throws through [UID:0002E1][0x00421500-0x0042151a.MsvcVectorThrowHelpers](by-memory/0x00421500-0x0042151a.MsvcVectorThrowHelpers.md) when the vector reaches `107374182` elements, matching the MSVC `vector<T> too long` path rather than target-local feature code.
- Uses a capacity-plus-half growth rule with a clamp to at least `size + 1`, then allocates `newCapacity * 40` bytes through `operator new(uint)`.
- Uses MSVC-style large-allocation handling for blocks of at least `0x1000` bytes: request `size + 0x23`, align the usable pointer to 32 bytes, and store the raw allocation pointer in the preceding dword for later validation/free.
- Copies the inserted 40-byte record as two 16-byte lanes plus one 8-byte tail.
- If inserting at the old end, the old range relocation is inline in this helper. If inserting before the old end, it calls [UID:0004DO][0x004e6ff0-0x004e7026.FrameDrawRecordUninitializedCopyCompilerSupport](by-memory/0x004e6ff0-0x004e7026.FrameDrawRecordUninitializedCopyCompilerSupport.md) twice: `[oldBegin,position)` to `newBegin`, then `[position,oldEnd)` to `newBegin + insertionOffset + 40`.
- Frees old storage through `sub_5C7526`, the broad runtime free wrapper, with the same large-allocation header validation before freeing aligned storage.
- [UID:00017R][0x004dfd10-0x004e4d79.NewHumanImageLibLocalMethodCluster](by-memory/0x004dfd10-0x004e4d79.NewHumanImageLibLocalMethodCluster.md) performs the source-level fast append inline when capacity remains and calls this helper only for the grow/relocate slow path. - The inserted record and relocated elements are copied shallowly as two 16-byte lanes plus one 8-byte tail. There is no element constructor, destructor, copy hook, validation, or per-element cleanup; pointer members remain borrowed values.
- UID0004DO's output-iterator return is ignored. Actual old/new ranges are disjoint. The private range-copy loop is forward-only and not a general overlap-safe `memmove`.
