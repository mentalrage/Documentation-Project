# 0x00575cb0-0x00575d83 Packet Nonce Initialization

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: global packet transform helper
- Current Wave3 owner: recovered global `InitializePacketNonce`
- Likely source module: [UID:0000M9][PacketTransform](by-file/PacketTransform.md)
- Shared state: [UID:0000TG][PacketTransformGlobals](by-global/PacketTransformGlobals.md)
- Confidence: strong for behavior, medium for exact original file owner.

## Covered Range

| Range | Current name | Notes |
| --- | --- | --- |
| `0x00575cb0-0x00575d83` | `InitializePacketNonce` | Derives alternate XOR/key bytes from the process argument/key buffer and copies them into repeated transform table slots. |

IDA MCP confirms `0x00575cb0` as a function start with size `0xd3`.

## Behavior

The helper:

- Reads `g_packetXorAlternateSize` at `0x0066fe50`.
- Uses `nonceHighLow`, `nonceMiddle`, and `g_processArgList` at `0x0069ba58` to fill `g_packetNonceScratch` at `0x0069ba4c`.
- Terminates the scratch bytes with zero.
- Copies the scratch sequence four times into `g_packetXorTableAlternate` at `0x0069ba94`.
- Calls range-check failure if the key size exceeds the scratch-table expectation.

## Ownership Decision

This helper is packet/protocol transform code, not feature code and not scalar packet-buffer formatting. It is close to `Socket` because `Socket::TransformFramePayload` and `Socket::BuildEncryptedPacket` consume the alternate transform table. It should be reconstructed with [UID:0000M9][PacketTransform](by-file/PacketTransform.md), while the Socket encode/decode methods remain Socket-owned.

Current reconstruction should document it as packet protocol support and avoid attaching it to feature modules.

## Open Questions

- Whether the original source grouped nonce/key initialization in a separate packet encryption/protocol file or as a private helper section inside `Socket.cpp`.
- Confirm exact sizes and declarations for `g_packetNonceScratch`, `g_packetXorTableAlternate`, and `g_processArgList`.
