## Behavior

The helper is the alternate packet-key derivation routine used immediately before inbound or outbound payload XOR. It:

- Calls `sub_516030`, which IDA decompiles as returning `dword_69B4FC`; the value is kept in `ebx` and passed as `ecx` for the later copy-helper calls.
- Reads `g_packetXorAlternateSize` / IDA `Size` at `0x0066fe50`; the initialized dword is `9`.
- Reads `g_processArgList` / IDA `ArgList` at `0x0069ba58`, the 1024-byte key/process buffer prepared by the string-key helper and Socket lifetime code.
- Computes an index for each output byte as `(nonceBase + i * step) % 1024`, where the initial `step` is `nonceMiddle * nonceMiddle` and the step is incremented by `3` after each emitted byte.
- Writes the selected key/process byte into `g_packetNonceScratch` / `byte_69BA4C`.
- Enforces the scratch/table limit with a range-check failure when the size is `>= 12`; otherwise writes a zero terminator at `byte_69BA4C[size]`.
- Copies the scratch bytes into four consecutive `g_packetXorTableAlternate` windows at `0x0069ba94`, `0x0069ba94 + size`, `0x0069ba94 + 2 * size`, and `0x0069ba94 + 3 * size`.

IDA decompilation on 2026-06-01:

```c
void *__stdcall sub_575CB0(unsigned __int16 a1, unsigned __int8 a2)
{
  size_t size = Size;
  int i = 0;

  sub_516030();
  if ((int)Size > 0) {
    char *key = ArgList;
    int step = a2 * a2;
    do {
      int index = (a1 + i * step) % 1024;
      step += 3;
      byte_69BA4C[i++] = key[index];
    } while (i < (int)size);
  }
  if (size >= 0xC)
    __report_rangecheckfailure(i);
  byte_69BA4C[size] = 0;
  sub_516220(&unk_69BA94, byte_69BA4C, size);
  sub_516220((char *)&unk_69BA94 + Size, byte_69BA4C, Size);
  sub_516220((void *)(2 * Size + 0x69BA94), byte_69BA4C, Size);
  return sub_516220((char *)&unk_69BA94 + 3 * Size, byte_69BA4C, Size);
}
```

The decompiler's return type is an artifact of tail-returning the final `memmove` wrapper; callers ignore the return value.

## Ownership Decision

This helper is packet/protocol transform code, not feature code and not scalar packet-buffer formatting. It is close to `Socket` because `Socket::TransformFramePayload` and `Socket::BuildEncryptedPacket` call it and consume the alternate transform table. It should be reconstructed with [UID:0000M9][PacketTransform](by-file/PacketTransform.md), while the Socket encode/decode methods remain Socket-owned.

Current reconstruction should document it as packet protocol support and avoid attaching it to feature modules. The parent attachment to `PacketTransform` is now safe for autogen grouping, but the source-facing helper prototype and transform-global names are still provisional.
