# 0x0069ae18-0x0069af20 KeyboardStateGlobals

## Status

- Entity kind: global-data buffer and companion flags.
- Disposition: reconstructable NexusTK project global state.
- Rebuild handling: source-declared/generated-binary.
- Likely owner: application event/input dispatch module.
- Confidence: strong for address use and keyboard-state role; medium for final source names.

## Covered Data

| Address | Current IDA name | Role |
| --- | --- | --- |
| `0x0069ae18-0x0069af18` | `KeyState` | 256-byte buffer passed to `GetKeyboardState`. |
| `0x0069aea9` | `byte_69AEA9` | One byte inside `KeyState`; bit 0 is sampled into `dword_69AF18`. |
| `0x0069af18` | `dword_69AF18` | Cached low-bit state from the keyboard buffer. |
| `0x0069af1c` | `dword_69AF1C` | Event/input dispatch pointer or context used by shortcut-handling paths. |

## Behavior

The application/event-dispatch code snapshots Win32 keyboard state into `KeyState`, watches the low bit of `KeyState[0x91]`, and uses `dword_69AF18` / `dword_69AF1C` while handling keyboard shortcuts and dispatch-side input state.

Candidate source shape:

```cpp
static BYTE g_keyState[256];
static int g_cachedKeyStateBit;
static void* g_keyboardDispatchContext;
```

Do not lock final names until the owner module and the meaning of `dword_69AF1C` are confirmed from its non-keyboard consumers.

## Evidence

- IDA MCP byte review shows the entire range is in `.data` and initially filled with `0xff`.
- `0x004a6a80` calls `GetKeyboardState(&KeyState)` and assigns `dword_69AF18 = byte_69AEA9 & 1`.
- `0x004a7130` calls `GetKeyboardState(&KeyState)`, compares the same cached bit state, probes `GetAsyncKeyState(VK_LSHIFT)` and `GetAsyncKeyState(VK_CONTROL)`, and uses `dword_69AF1C` while dispatching the shortcut branch.
- Additional xrefs to `dword_69AF1C` appear in input/UI helper paths at `0x004cfe60`, `0x004cfec0`, `0x004cff50`, `0x004f6490`, and `0x004f7660`.
