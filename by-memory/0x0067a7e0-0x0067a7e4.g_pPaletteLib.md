# 0x0067a7e0-0x0067a7e4 g_pPaletteLib

## Summary

- Address range: `0x0067a7e0-0x0067a7e4`
- Entity kind: global pointer
- Proposed name: `g_pPaletteLib`
- Disposition: reconstructable NexusTK global data
- Confidence: strong for address, owner class, and singleton role

This four-byte zero-initialized `.data` slot stores the process-wide `PaletteLib` singleton pointer. Rendering, image, map, tile, UI, and palette-filter paths load it before resolving current, named, slot, and transformed palettes.

## Evidence

- IDA MCP reports four zero-initialized bytes at `0x0067a7e0` and 83 direct data xrefs.

- `PaletteLib::~PaletteLib` at `0x00543af0` clears `dword_67A7E0 = 0`.
- The constructor-unwind cleanup helper at `0x005443a0` also clears `dword_67A7E0`; existing docs treat it as unwind support rather than normal handwritten source flow.
- Existing class/global/file docs already identify this slot as [UID:0000RW][g_pPaletteLib](by-global/g_pPaletteLib.md) and tie its owner to [UID:0000A1][PaletteLib](by-class/PaletteLib.md) / [UID:0000MB][PaletteLib](by-file/PaletteLib.md).

## Reconstruction Notes

Declare the storage with the palette manager source family. It should be zero-initialized by the runtime and assigned/cleared by `PaletteLib` construction and destruction. Do not move it to DAT archive code; the palettes are DAT-backed resources, but this global owns render palette policy.
