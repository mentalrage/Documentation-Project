## Behavior

This is the startup constructor for the light-image singleton. It initializes the base `LObject`, writes [UID:0000RD][g_pLightObjImageLib](by-global/g_pLightObjImageLib.md), installs the [UID:0001XY][LightObjImageLibVtable](by-type/by-vtable/LightObjImageLibVtable.md), initializes the embedded `ProtectedArray<LightInfo>` at `this + 0x04`, seeds the fallback [UID:0001UW][LightInfo](by-type/by-struct/LightInfo.md) record at `this + 0x14`, opens `LIGHT.TBL`, and builds generated radial mask frames for each valid light table record.

The table reader first reads the record count, reallocates the entry array to `count * 0x1c` bytes when needed, then reads each record as four integers followed by two floats. For entries with positive X/Y radii, it allocates an `IntAlphaSurface` frame sized `(2 * radiusX + 1)` by `(2 * radiusY + 1)`, clears it, reads the frame center, and calls the radial mask helper with brightness converted through `int(brightness * 32.0f + 0.5f)` plus the second float as the blend/falloff input.

The `LIGHT.TBL` row schema is now source-bounded as `tableId`, `innerRadius`, `radiusX`, `radiusY`, `brightness`, `blendScale`, and `generatedFrame`. The former `lightSource` label for row `+0x04` is rejected because constructor dataflow passes that field to `IntAlphaSurface::FillEllipticGradient` as the `innerRadius` argument after the generated frame center has already been computed from the frame dimensions.

The constructor preserves existing rows with `memmove` before freeing the old entry buffer when resizing, matching a protected-array resize/grow implementation rather than a pure one-shot allocation. It intentionally omits source-level vtable writes, security-cookie checks, and exception cleanup chunk jumps from first-draft C++; those are compiler output.
