## Behavior Summary

The helper takes the `MainMenuPane` owner pointer plus mouse `x` and `y` coordinates. It reads the menu item count byte at `this + 0xf9`; if the count is non-positive, it returns `-1`. Otherwise it loops from index `0` through `count - 1`, computes the same menu item rectangle family used by [UID:00019M][0x004f8b90-0x004f8c07.ComputeMenuItemRect](by-memory/0x004f8b90-0x004f8c07.ComputeMenuItemRect.md), and returns the first index whose rectangle contains the coordinate.

| Layout branch | Coordinates |
| --- | --- |
| `byte_66DA97 == 1` | left `781`, top `493 + 41 * index`, right `972`, bottom `532 + 41 * index` |
| legacy branch | left `467`, top `299 + 30 * index`, right `640`, bottom `329 + 30 * index` |

Each loop iteration builds a local four-dword rectangle with `sub_4B7C50`, calls `sub_4B7E80(mouseX, mouseY, rect)`, and returns the current index on the first positive containment result. If no item matches, it returns `-1`.

This is the missing body behind the generated `HitTestMenuItem` prototype in `source-3/simroot_v2/class_MainMenuPane.cpp`, but the behavior above is based on IDA/Ghidra evidence rather than generated source authority.
