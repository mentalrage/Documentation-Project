## Behavior

The helper copy-constructs a destination three-pointer vector header from a source three-pointer vector header:

| Offset | Destination field | Source field | Meaning |
| --- | --- | --- | --- |
| `+0x00` | `dst.begin` | `src.begin` | First pointer slot in storage. |
| `+0x04` | `dst.end` | `src.end` | One-past-last occupied pointer slot. |
| `+0x08` | `dst.capacityEnd` | `src.capacityEnd` | One-past-last allocated pointer slot. |

Register and argument roles:

- `ECX` / saved `EBX` is the destination vector header.
- `[EBP+8]` / saved `EDI` is the source vector header pointer.
- Element width is 4 bytes.
- `count = (src.end - src.begin) >> 2`.
- `byteCount = src.end - src.begin`.
- Maximum count is `0x3fffffff`; values above that threshold branch to the vector-too-long helper so `count * 4` cannot overflow the unsigned 32-bit byte count.

Normal behavior:

1. Zeroes destination `begin`, `end`, and `capacityEnd`.
2. Computes the source element count from the source byte span.
3. If the source is empty, returns the zeroed destination.
4. If the source count is too large, calls [UID:0002E1][0x00421500-0x0042151a.MsvcVectorThrowHelpers](by-memory/0x00421500-0x0042151a.MsvcVectorThrowHelpers.md), specifically the vector-too-long path.
5. Allocates `count * 4` bytes through [UID:0002E2][0x00421520-0x00421584.AllocateAlignedDwordArray](by-memory/0x00421520-0x00421584.AllocateAlignedDwordArray.md).
6. Sets destination `begin` and `end` to the allocated storage, then sets destination `capacityEnd = begin + count`.
7. Copies the source pointer span to the destination with `memmove` at `0x005c9b30`.
8. Updates destination `end = begin + byteCount`.
9. Returns the destination header in `EAX` and uses `ret 4`.

The element size is dword-width, but current source-quality interpretation is pointer slots rather than scalar `uint32_t` values because confirmed callers copy entry pointer vectors and the project route is pointer-vector copy/construct. Do not rename this back to older `UInt32Vector_421290` style labels; those labels only proved 4-byte width, not unsigned integer value semantics.
