# JsonCpp Value Core `0x00424630-0x00428b4b`

## Status

- Confidence: strong for JsonCpp ownership; high for current upstream snapshot candidate, medium-low for per-function names.
- Proposed owner: [UID:0000KI][JsonCpp](by-file/JsonCpp.md)
- Disposition: third-party static library code; exclude from NexusTK product source modules.
- Evidence basis: read-only IDA MCP function-list, lookup, caller/callee, string, decompile, and string-xref checks on 2026-05-25. `wave3.py` was not executed for this pass.

## Range Role

This range is the current JsonCpp value/object helper core immediately after the fitting-room UI/control code and before the separate mixed JsonCpp/CRT support island. It includes exception/value construction helpers, value copy/destroy paths, type checks, object/member lookup, array access, array sizing, comments, and member-name enumeration helpers used by the parser islands and by fitting-room item-shop catalog code.

The range starts at `0x00424630`, where IDA-modeled JsonCpp exception/runtime-error helpers begin. The small raw helper island immediately before it is tracked separately as [UID:0000WX][0x00424600-0x00424629.JsonCppPreExceptionFlagInitializers](by-memory/0x00424600-0x00424629.JsonCppPreExceptionFlagInitializers.md). The range ends at `0x00428b4b`; the following [UID:0000WZ][0x00428b4b-0x004298f0.JsonCppValuePathIteratorAndCrtNumericSupport](by-memory/0x00428b4b-0x004298f0.JsonCppValuePathIteratorAndCrtNumericSupport.md) page now owns the adjacent `__crt_strtox::big_integer`, `Json::Value::setComment()`, `Json::Path`, and iterator-support island.

IDA also assigns an out-of-line cleanup tail chunk at [UID:0001ZU][0x00439eb0-0x00439ed5.JsonCppValueCoreEhCleanupChunk](by-memory/0x00439eb0-0x00439ed5.JsonCppValueCoreEhCleanupChunk.md) to `sub_427310`. That chunk is documented separately because it is physically separated from the primary `JsonCppValueCore` range by unrelated Deque and runtime-support code.

## Version Matching Notes

This range now provides the strongest non-reader evidence for the current JsonCpp source snapshot:

- Tags `1.7.0-1.7.2` do not have `Value::nullSingleton()`.
- Tags `1.7.3-1.7.4` have `Value::nullSingleton()`, but implement it as a static pointer initialized with `new Value`; the binary's `0x00424850` instead initializes a static object and registers an `atexit` destructor.
- Upstream commit `b299d3581f4dc670734f1fe1a34fce1282337802` changes `nullSingleton()` to that static-object form, matching `0x00424850`.
- The next relevant upstream value change, commit `7e0571b444497ad9a0a8547d76a06ef426c7116e`, changes the default `stringValue` constructor to point at a static empty string. The binary's `0x00424c90` still assigns a null string pointer, so the observed source is before that commit.

Together with [UID:0000X7][0x00431d50-0x00431f1c.JsonCppOurReaderParse](by-memory/0x00431d50-0x00431f1c.JsonCppOurReaderParse.md) and [UID:0000X9][0x004345f0-0x00434887.JsonCppNumberTokenParseHelper](by-memory/0x004345f0-0x00434887.JsonCppNumberTokenParseHelper.md), this favors official upstream commit `b299d3581f4dc670734f1fe1a34fce1282337802` as the current best source snapshot.

## Ownership Decision

Keep `0x00424630-0x00428b4b` with [UID:0000KI][JsonCpp](by-file/JsonCpp.md) and `third_party/jsoncpp/`. It is third-party parse/value support, not fitting-room, downloader, or cash-shop product code.

Do not include the adjacent fitting-room UI/control functions at `0x00424020-0x004245f5`, and do not automatically include the CRT numeric-conversion helper beginning at `0x00428b50`.
