## Evidence

- `0x0041a479-0x0041a488` loads `GetLocaleInfoW` and `SetFileAttributesW` and stores them to `dword_69BEC8` and `dword_69BECC`.
- `0x005997b4-0x005997c6` and `0x005999e9-0x005999f8` contain generated/raw UniAPI-region writes for the same two slots.
- Direct call consumers include `call dword_69BEC8` at `0x004e8cd7` and `call dword_69BECC` at `0x0050acc3`.

## Reconstruction Notes

Declare these as part of the platform API dispatch table, not as owner-local globals in the UI or file modules that call through them. A rebuilt executable should initialize them from the real Win32 wide APIs on NT-family Windows and leave any ANSI/fallback behavior with the same platform compatibility layer as [UID:0000WD][0x0041a280-0x0041a4a8.WideApiDispatchInit](by-memory/0x0041a280-0x0041a4a8.WideApiDispatchInit.md).
