# 0x0046fcb0-0x0046ff50 Browser Legacy Host WndProc

## Scope

- Entity kind: browser host window procedure plus compiler switch table.
- Direct owner: [UID:0000HV][Browser](by-file/Browser.md).
- Parent inventory: [UID:0000ZF][0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers](by-memory/0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers.md).

The modeled function `0x0046fcb0-0x0046fe47` is the registered legacy browser-host `WndProc` helper. The source-facing name `BrowserLegacyHostWndProc` is descriptive and inferred, not original-symbol proof, but it distinguishes this callback from [UID:00020V][0x0046a630-0x0046a6ea.BrowserWindowHostWndProc](by-memory/0x0046a630-0x0046a6ea.BrowserWindowHostWndProc.md) and the retained raw clone [UID:00020W][0x0046a760-0x0046a855.BrowserRawWindowProcClone](by-memory/0x0046a760-0x0046a855.BrowserRawWindowProcClone.md). - It handles `WM_PAINT` with `BeginPaint`/`EndPaint`.
- It handles keyboard messages `WM_KEYDOWN`, `WM_KEYUP`, `WM_SYSKEYDOWN`, and `WM_SYSKEYUP`, queries browser COM interfaces, forwards accelerator messages, special-cases Tab/Escape/F4-style keys, and otherwise falls back through PlatformApi `g_pfnDefWindowProcW` at `0x0069be50`.
- The helper is a file-level/static browser callback rather than a direct class method because its entry signature is the Win32 window-procedure shape and ownership is established by BrowserThread host registration, not by a class vtable slot.

## B010 2026-06-19 Source-Quality Reanalysis

B010 reanalysis keeps the owner/emitter route at [UID:0000HV][Browser](by-file/Browser.md) and resolves the remaining source-quality blockers enough for first-draft C++ under `NexusTK/browser/Browser.cpp`. The callback is registered by [UID:00032W][0x00470a00-0x00470dc9.BrowserThreadInitializeBrowserHost](by-memory/0x00470a00-0x00470dc9.BrowserThreadInitializeBrowserHost.md), but it is not a `BrowserThread` method: the entry signature is `LRESULT CALLBACK(HWND, UINT, WPARAM, LPARAM)` and the body retrieves the Browser object from window user data or the temporary construction bridge. It is also not a `Browser` class method even though it reads Browser fields, because Win32 window-class registration requires a free/static procedure. It is not the active `BrowserWindow` WndProc at `0x0046a630`, and it is not the no-route raw clone at `0x0046a760`.

The host pointer type is now strong for this path: `BrowserThread +0x68` is the legacy [UID:000013][Browser](by-class/Browser.md) object, `BrowserThread::InitializeBrowserHost` publishes that pointer through `g_pCurrentBrowserHost`, and this WndProc then treats the recovered pointer as a Browser object. The draft uses the current Browser field names `m_hWnd` for offset `+0x14` and `m_webBrowser` for offset `+0x18`; the exact static interface type for `m_webBrowser` remains a Browser layout/header cleanup item, but behavior supports an OLE/WebBrowser control pointer that can be queried for `IOleInPlaceActiveObject` and `IOleObject`.

The fallback dispatch pointer at `0x0069be50` is not Browser storage. Existing PlatformApi evidence identifies that address as [UID:0000TQ][WideApiDispatchTable](by-global/WideApiDispatchTable.md) slot `g_pfnDefWindowProcW`, initialized by [UID:0000WD][0x0041a280-0x0041a4a8.WideApiDispatchInit](by-memory/0x0041a280-0x0041a4a8.WideApiDispatchInit.md). This page should therefore describe the default path as `g_pfnDefWindowProcW(hwnd, message, wParam, lParam)`.

### Keyboard And COM Behavior

- The keyboard path queries `IID_IOleInPlaceActiveObject` (`0x006315c0`) from the Browser WebBrowser/OLE object and uses vtable slot `+0x14`, matching `IOleInPlaceActiveObject::TranslateAccelerator(MSG *)`.

- The binary writes only `message`, `wParam`, and `lParam` into the local `MSG`-shaped block before `TranslateAccelerator`; it does not prove stores to `MSG.hwnd`, `time`, or `pt`. ### Rejected Alternatives

- Do not move this page to `BrowserThread`: the thread method registers the callback but the callback body is not a method and does not receive `BrowserThread this`.
- Do not move it to `Browser` class ownership: the body uses Browser state, but the entry point is a Win32 callback.
- Do not merge it with [UID:00020V][0x0046a630-0x0046a6ea.BrowserWindowHostWndProc](by-memory/0x0046a630-0x0046a6ea.BrowserWindowHostWndProc.md) or [UID:00020W][0x0046a760-0x0046a855.BrowserRawWindowProcClone](by-memory/0x0046a760-0x0046a855.BrowserRawWindowProcClone.md); those cover a separate registered BrowserWindow host callback and a retained no-route clone.
- Do not treat `g_pfnDefWindowProcW` as Browser-owned storage; PlatformApi owns the dispatch slot and Browser is only a consumer.
- Do not split the switch tables into standalone source items; they are compiler data local to this callback.
