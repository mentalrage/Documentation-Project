## Behavior

Lazy-loads a named resource layout if needed, retrieves the selected [UID:0000VB][ResourceLayoutEntry](by-item/ResourceLayoutEntry.md), and copies only its 16-byte rectangle into the caller's output rectangle.

IDA MCP decompilation on 2026-05-31 shows:

- same `FindResourceIndex` then `LoadResourceIndex` fallback pattern as `LookupLayoutEntry`;
- registry row lookup through [UID:000079][List](by-class/List.md) vtable slot `+0x10`;
- negative or out-of-range frame indexes reset the output rectangle through `0x004b7c50`;
- valid indexes copy the first 16 bytes of the selected 24-byte entry.
- the function returns the output rectangle pointer, but all current evidence treats the important effect as mutating the caller-provided rectangle.

2026-06-06 A008 live IDA decompilation and disassembly refine the exact flow:

- `sub_4D17C0(this, resourceName)` returns a slot index or `-1`; the `-1` path calls [UID:0002KO][0x004d0120-0x004d02e5.ResourceLayoutTableLoadResourceIndex](by-memory/0x004d0120-0x004d02e5.ResourceLayoutTableLoadResourceIndex.md).
- The method then calls the registry list vtable slot `+0x10` on `this+0x0c` using the slot index returned by the lookup/load pair.
- It rejects negative indexes with `test edx, edx` / `js`, then rejects indexes greater than or equal to the 16-bit count at name-record offset `+0x20`.
- For valid indexes, it loads the entry array pointer at name-record offset `+0x28`, computes `entryBase + 24 * frameIndex`, and copies the 16-byte rectangle prefix with `movups`.
- If validation fails, it calls [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md) helper `0x004b7c50(outRect, 0, 0, 0, 0)`.
