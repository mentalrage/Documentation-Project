# 0x0066fe50-0x00670258 PacketTransform Alternate Size And LUT

## Summary

- Address range: `0x0066fe50-0x00670258`
- Entity kind: initialized packet-transform globals
- Disposition: reconstructable project data
- Rebuild handling: source-declared/global protocol state
- Confidence: strong for address, owner, and initial values

This range contains the alternate packet transform size dword and a 256-entry dword lookup table used by the socket packet transform helpers.

## Layout

| Range | Current IDA name | Proposed role | Initial value |
| --- | --- | --- | --- |
| `0x0066fe50-0x0066fe54` | `Size` | `g_packetXorAlternateSize` | `9` |
| `0x0066fe54-0x0066fe58` | unnamed | alignment/unused dword inside packet-transform state | `0` |
| `0x0066fe58-0x00670258` | `dword_66FE58` | `g_packetTransformLut` | 256 dwords, each initialized to a repeated byte value from `0x00` through `0xff`. |

## Evidence

- [UID:0000TG][PacketTransformGlobals](by-global/PacketTransformGlobals.md) already identifies `0x0066fe50` and `0x0066fe58` as packet transform globals.
- IDA MCP xrefs to `0x0066fe50` include `0x00575cbb`, `0x00575d28`, `0x00575d41`, `0x00575d5b`, and `0x00578c0e` in the packet nonce/transform neighborhood.
- IDA MCP xrefs to `0x0066fe58` include `0x0057615f` in [UID:0001I1][0x00575d90-0x005796c7.SocketTransportCore](by-memory/0x00575d90-0x005796c7.SocketTransportCore.md) and `0x00576fee` in the socket transport cluster.
- Raw range summary: size `1032`, head bytes `09 00 00 00 00 00 00 00 00 00 00 00 01 01 01 01`, tail bytes `fc fc fc fc fd fd fd fd fe fe fe fe ff ff ff ff`.
- IDA currently under-sizes the LUT type in some views; the observed writer and initializer prove 256 dword-oriented entries.

## Reconstruction Notes

Keep this with [UID:0000M9][PacketTransform](by-file/PacketTransform.md) or a private packet-transform section of [UID:0000NS][Socket](by-file/Socket.md). Do not migrate it as generic packet-buffer storage; the dword table is consumed by the encryption/transform helpers.
