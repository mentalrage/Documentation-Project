void InputMan::TrackInputTarget(int targetId, bool active)
{
    HWND appWindow = GetApplicationWindow();
    if (targetId == 0) {
        g_pfnPostMessageW(appWindow, kInputManContextMessage,
                          active ? 1 : 0, 0);
        m_inputTargetList->RemoveAll();
        return;
    }

    int oldCount = m_inputTargetList->GetCount();
    int foundIndex = -1;
    int *targets = static_cast<int *>(m_inputTargetList->GetData());
    for (int i = 0; i < oldCount; ++i) {
        if (targets[i] == targetId) {
            foundIndex = i;
            break;
        }
    }

    if (active) {
        if (foundIndex < 0) {
            m_inputTargetList->Append(1, &targetId);
        }
    } else if (foundIndex >= 0) {
        m_inputTargetList->RemoveAt(foundIndex, 1);
    }

    int newCount = m_inputTargetList->GetCount();
    if (oldCount == 0 && newCount != 0) {
        g_pfnPostMessageW(appWindow, kInputManContextMessage, 1, 0);
    } else if (oldCount != 0 && newCount == 0) {
        g_pfnPostMessageW(appWindow, kInputManContextMessage, 0, 0);
    }
}

## Message Routing Notes

- `HandleWindowMessage` has one application caller at `0x00465fad` and returns a handled flag while writing `*resultOut` for messages consumed by the IME bridge.
- `0x51` recreates the owned IME context and associates it with the main window when an app context is present.
- `0x102` dispatches character input through the event layer when bit `0x20000000` is not set.
- `0x10d`, `0x10e`, and `0x10f` dispatch IME composition start/end/result/composition-string events. The `0x10f` path uses `0x004e9510` for `GCS_RESULTSTR`/`GCS_COMPSTR`-style text copies.
- `0x282` handles IME notifications: subcommand `2` is swallowed, `3`/`5` build visible candidate-list strings from `CANDIDATELIST` page-start/page-size data, `4` emits a candidate-close event, and `8` emits open-status through `ImmGetOpenStatus`. The candidate-list branch defaults zero page size to `9`, appends visible candidate strings through `0x004e9710`, computes selected row as `dwSelection - pageStart`, and calls Event factory `0x004a9e50` for Event type `15`.
- `0x281` forwards through `dword_69BE50` only when the stored IME property flags do not contain `0x20000`.
- The custom `0x401` message associates or detaches the owned IME context, matching the state-change notification sent by `TrackInputTarget`.

The receiver-bearing event methods at `0x004a97e0-0x004a9f00` remain owned by [UID:0000J6][Event](by-file/Event.md) through [UID:00004O][EventMan](by-class/EventMan.md): `DispatchCharEvent`, `DispatchImeOpenStatusEvent`, `DispatchCompositionTextEvent`, `DispatchCompositionStartEvent`, `DispatchCompositionResultEvent`, `DispatchCompositionEndEvent`, `DispatchCandidateListEvent`, and `DispatchCandidateCloseEvent`. Call sites load `g_pEventMan` into ECX; historical free-factory prototypes are superseded. `InputMan::HandleWindowMessage` calls these methods but does not absorb their bodies.

The `dword_69BE*` calls in this island are PlatformApi wide-dispatch entries initialized by [UID:0000WD][0x0041a280-0x0041a4a8.WideApiDispatchInit](by-memory/0x0041a280-0x0041a4a8.WideApiDispatchInit.md): `dword_69BE50` is `g_pfnDefWindowProcW`, `dword_69BE90` is `g_pfnPostMessageW`, `dword_69BEBC` is `g_pfnImmGetCompositionStringW`, `dword_69BEC0` is `g_pfnImmGetCandidateListW`, and `dword_69BEC8` is `g_pfnGetLocaleInfoW`.
