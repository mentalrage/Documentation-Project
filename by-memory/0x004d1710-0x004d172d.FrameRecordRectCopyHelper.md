The body starts with a normal stack-frame prologue, performs a single 16-byte SIMD copy, returns with `ret 0x0c`, and is followed by three `0xcc` alignment bytes before `ResourceLayoutTableGetFrameSize` starts at `0x004d1730`.

## Behavior

The helper copies the first 16 bytes of a selected 24-byte frame record to a caller-provided output buffer:

- reads the frame index from the second stack argument;
- computes `index * 24` with `lea ecx, [eax+eax*2]` followed by scaled addressing;
- reads the frame-record array pointer from table offset `+0x08`;
- loads the record's first 16 bytes with `movups`;
- writes the 16 bytes to the output pointer from the third stack argument;
- performs no local bounds check, so callers must have already validated the frame index.

The copied 16-byte block is the same bounds/rectangle block used by the adjacent ImageFrameTable record projection helpers.
