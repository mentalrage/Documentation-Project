# 0x0069ba38-0x0069ba3c g_pVoteMenuPane

## Status

- Disposition: reconstructable NexusTK global-data pointer.
- Entity kind: process singleton pointer / alias correction point.
- Proposed owner: [UID:0000P6][VoteMenuPane](by-file/VoteMenuPane.md).
- Global doc: [UID:0000SP][g_pVoteMenuPane](by-global/g_pVoteMenuPane.md)
- Confidence: strong for address, size, and owner correction.

## Storage

`0x0069ba38-0x0069ba3c` is the four-byte `.data` storage used by the active [UID:0000FX][VoteMenuPane](by-class/VoteMenuPane.md) singleton pointer.

Active generated `RightButtonMenuPane` output can mislabel this same address as `g_pBulletinSession`. Treat that as generated owner/name pollution: this storage is the vote-popup singleton, not the bulletin session singleton.

## Evidence

- IDA MCP `py_eval` reports the data item at `0x0069ba38` as `dword_69BA38`, size `4`, in `.data`.
- Vote popup lifecycle refs:
  - `0x005558f8`: raw `VoteMenuPane` constructor stores `this`.
  - `0x0055599d`: `VoteMenuPane` non-deleting destructor clears the pointer.
  - `0x00556374`: `VoteMenuPane` scalar deleting destructor clears the pointer.
- Right-click menu reads:
  - `0x00554ca5`, `0x00554ee8`, `0x00554f1a`, `0x00554f93`, and `0x005552a3` read/check the active vote popup from [UID:0000N7][RightButtonMenuPane](by-file/RightButtonMenuPane.md) paths.
- 2026-05-26 recheck: IDA MCP `py_eval` still reports `dword_69BA38`, item size `4`, segment `.data`; the adjacent `.data` words are separate items at `0x0069ba34` and `0x0069ba3c`.

## Disposition

Own this storage with `ui/menu/VoteMenuPane.cpp`. `RightButtonMenuPane.cpp` may read it to dismiss or coordinate with the vote popup, but those reads do not make the storage a bulletin-session or right-button-menu global.
