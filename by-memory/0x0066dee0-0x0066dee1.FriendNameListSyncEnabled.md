# 0x0066dee0-0x0066dee1 - Friend Name-List Sync Enabled Flag

## Status

- Confidence: strong for address, observed use, and current source-facing name.
- Entity kind: global-data bool backed by one byte at `0x0066dee0`.
- Current Wave3 id: `g_friendNameListSyncEnabled`.
- Former aliases: `byte_66DEE0`, `g_isCashShopEnabled`.
- Related global: [UID:0000PG][byte_66DEE0](by-global/byte_66DEE0.md).

## Behavior

This byte gates friend/name-list upload behavior.

- Inbound map opcode `0x6a` reads one payload byte and writes this global to `payloadByte != 0`.
- When the byte is nonzero, the opcode handler immediately calls [UID:0001HX][0x00574e50-0x0057536b.BuildAndSendInventoryData](by-memory/0x00574e50-0x0057536b.BuildAndSendInventoryData.md), which builds outbound opcode `0x77` from the 20 configured friend/name-list slots.
- [UID:00005J][FriendListDialog](by-class/FriendListDialog.md) writes the same 20 slots back into config, then reads this byte; if nonzero, it sends the updated opcode `0x77` payload.

The old generated `g_isCashShopEnabled` name was misleading. Current evidence ties the byte to social/name-list sync, not cash-shop feature enablement.

## Evidence Notes

- 2026-05-25 IDA MCP `xrefs_to 0x0066dee0` reports:
  - `0x00508aff` inside `MapPane::HandlePacket`, a write in inbound opcode `0x6a`.
  - `0x0051439c` inside a raw/unmodeled duplicate handler that reads a packet byte and sends the same opcode `0x77` upload when nonzero.
  - `0x0053f8dc` inside `FriendListDialog::OnOkButton`, a read before calling [UID:0001HX][0x00574e50-0x0057536b.BuildAndSendInventoryData](by-memory/0x00574e50-0x0057536b.BuildAndSendInventoryData.md).
- Current `simroot_v2/class_FriendListDialog.cpp` defines `bool g_friendNameListSyncEnabled`.
- Current `simroot_v2/class_MapPane.cpp` declares `extern bool g_friendNameListSyncEnabled` and updates it from inbound opcode `0x6a`.

## Source Placement

The byte is written by map/server packet handling and read by social UI. Keep it documented as protocol/social state for now. Do not move it into cash-shop ownership just because the outbound upload helper currently lives in [UID:0000I0][CashShopRequest](by-file/CashShopRequest.md).
