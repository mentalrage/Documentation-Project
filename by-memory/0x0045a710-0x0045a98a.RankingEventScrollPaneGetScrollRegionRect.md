## Behavior

This helper computes a scrollbar part rectangle into an output `RECT`-like four-integer buffer. The part argument uses the same codes as the hit-test and mouse-handler logic:

| Part | Source-facing value | Meaning |
| --- | --- | --- |
| `0` | `kRankingScrollPartLeading` | leading/end-cap edge |
| `1` | `kRankingScrollPartPageBeforeThumb` | track/page region before the thumb |
| `2` | `kRankingScrollPartThumb` | thumb or center track when no thumb exists |
| `3` | `kRankingScrollPartPageAfterThumb` | track/page region after the thumb |
| `4` | `kRankingScrollPartTrailing` | trailing/end-cap edge |

It supports both orientations:

- orientation `0`: vertical scrollbar geometry with source-facing `kRankingScrollThumbSpan = 0x26` / 38 pixel thumb height;
- nonzero orientation: horizontal scrollbar geometry where the current control height becomes the thumb width.

When scrolling is enabled and the max position is positive, the thumb position is derived from the current position and max range. In vertical mode, active dragging instead uses the current mouse position adjusted by the drag anchor (`this + 0x108`) and clamps the thumb top inside the available track. For parts `1` and `3` when no scrollable range exists, the helper returns an empty rectangle through `0x004b7c50`.

The complete output contract includes several non-defensive edge cases that the first draft preserves:

- cursor and screen origin are fetched before the orientation split; if both origin components are exactly `-1000`, the method returns without writing `outRect`;
- both cursor coordinates are localized in canonical y/x order, although this target consumes only local y for the vertical drag path;
- nonzero orientation intentionally ignores `m_thumbDragActive` and uses proportional horizontal geometry;
- enabled/range-positive unknown part values copy full bounds before returning, while disabled/no-range unknown values leave `outRect` untouched;
- leading/trailing values are collapsed zero-area edges, not fixed-size arrow rectangles;
- the vertical drag clamp applies the lower-bound check before the `bottom - 38` upper-bound check, preserving the observed result even for a pathologically short control.
