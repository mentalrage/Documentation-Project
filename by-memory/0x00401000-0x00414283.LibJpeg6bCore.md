# IJG libjpeg 6b Core `0x00401000-0x00414283`

## Status

- Confidence: strong for IJG libjpeg 6b identity and several source-file anchors; medium for full internal helper split.
- Proposed owner: [UID:0000KN][LibJPEG](by-file/LibJPEG.md)
- Disposition: third-party static library code; exclude from NexusTK product source modules.
- Evidence basis: Wave3 read-only prewave range scan and read-only IDA MCP decompilation/disassembly/string/data checks on 2026-05-25.

## Range Role

This range is the current bounded code-island candidate for the statically linked Independent JPEG Group library. It covers the JPEG error manager, marker/codec helpers, memory manager, color/DCT/IDCT helpers, and related support routines compiled into the executable before the zlib island.

The range ends at `0x00414283`, the end of the final DCT/float helper currently preceding non-JPEG glue. `0x00414290-0x004142b5` is excluded: IDA names `0x00414290` as the `_AIL_shutdown@0` import thunk and `0x004142a0` as an `atexit` wrapper that jumps to Miles shutdown. [UID:0000W3][0x004142c0-0x00419e56.ZlibCore](by-memory/0x004142c0-0x00419e56.ZlibCore.md) starts at `0x004142c0`.

## Evidence

- Wave3 `list prewave-function --range 0x00401000 0x0041429f --limit 5` reports an unclassified prewave gap with 320 functions, starting at `0x00401000`.
- Wave3 `list prewave-function --range 0x00401000 0x0041429f --offset 315 --limit 10` shows the late functions `0x00413990`, `0x004139d0`, `0x00413dd0`, `0x00414020`, and an excluded `_AIL_shutdown@0` thunk at `0x00414290`.
- IDA decompilation of `0x00401000` stores callback pointers and assigns `off_631660` as the JPEG message table.
- IDA data inspection of `0x00631660-0x00631840` finds 121 consecutive pointers to canonical IJG diagnostics, including `Bogus Huffman table definition`, `Wrong JPEG library version: library is %d, caller expects %d`, `Corrupt JPEG data: bad Huffman code`, and `Premature end of JPEG file`.
- Source comparison against the obtained official `jpegsrc.v6b.tar.gz` maps the product decode path to stock `jpeg_CreateDecompress`, `jpeg_read_header`, `jpeg_start_decompress`, `jpeg_read_scanlines`, `jpeg_finish_decompress`, and `jpeg_destroy_decompress` in `jdapimin.c`/`jdapistd.c`.
- Source comparison maps the retained JPEG screenshot path to stock `jpeg_CreateCompress`, `jpeg_stdio_dest`, `jpeg_set_defaults`, `jpeg_start_compress`, `jpeg_write_scanlines`, `jpeg_finish_compress`, and `jpeg_destroy_compress` in `jcapimin.c`/`jcapistd.c`/`jcparam.c`/`jdatadst.c`.
- Source comparison maps `0x00401b00-0x004038c7` to stock `jdmarker.c`, including `jpeg_resync_to_restart`, `read_markers`, `jinit_marker_reader`, SOF/SOS/DHT/DQT parsing, and APP/COM marker processors.
- Source comparison maps `0x004049c0-0x00404a5c` to `jcomapi.c`, `0x00404a60-0x0040505b` to `jdinput.c`, and `0x00405c80-0x004063c8` to `jdmaster.c`.
- Source comparison maps `0x004063d0-0x0040649b` to `jutils.c`, `0x004064a0-0x00406d8c` to `jcmarker.c`, and `0x00406d90-0x00406e46` to `jcinit.c`.
- IDA decompilation of `0x00405060` installs JPEG memory-manager callbacks and calls `getenv("JPEGMEM")`.
- IDA decompilation of `0x00406e50-0x00406ed1` matches `jmemnobs.c`, the no-backing-store backend that wraps CRT `malloc`/`free` and has no temp-file storage behavior.
- IDA disassembly of `0x00414290` is a one-instruction jump through `__imp__AIL_shutdown@0`, and `0x004142a0` registers an `atexit` callback that jumps to that thunk. These are Miles runtime glue, not libjpeg.
- IDA disassembly of `0x004142c0` immediately references zlib string `1.1.4`, matching the existing [UID:0000W3][0x004142c0-0x00419e56.ZlibCore](by-memory/0x004142c0-0x00419e56.ZlibCore.md) boundary.
- A previous provisional code neighborhood `0x00469640-0x00470dc9` is rejected for LibJPEG ownership: IDA decompiles `0x00469640` and `0x00470a00` as BrowserWindow/WebBrowser COM code with window creation, OLE, and browser vtables.

## Ownership Decision

Keep `0x00401000-0x00414283` with [UID:0000KN][LibJPEG](by-file/LibJPEG.md) and the proposed `third_party/libjpeg/` source folder. Product image/resource modules may call into the library, but IJG internals should not be attached to render, DAT, browser, startup, or UI files.

Recommended Wave3 follow-up after source comparison:

```powershell
python E:\NTK\GhidraBridge\source-3\wave3.py classify memory-segment 0x00401000 0x00414283 library --reason "statically linked IJG libjpeg 6b; see by-memory/0x00401000-0x00414283.LibJpeg6bCore.md"
```

Do not include `0x00414290-0x004142b5` in that classification; it is Miles shutdown glue.

## Open Questions

- Exact mapping from the remaining internal helper functions to IJG `jpeg-6b` source files such as Huffman helpers, color conversion, sampling, coefficient controllers, quantizers, and DCT/IDCT modules.
- Whether `0x00414283-0x0041428f` is only padding or contains recoverable data/alignment that Wave3 should account for separately.
- Whether the raw JPG screenshot path at `0x00557840-0x00557a95` is reachable through an indirect callback or is retained legacy code.
- Whether the shipped build omitted encoder-side IJG files or compiled a decoder-focused subset.
