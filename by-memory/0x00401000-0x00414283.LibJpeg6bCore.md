## Source Placement And No-Code Proof

The final rebuild should compile or statically embed the official IJG source under `NexusTK/third_party/libjpeg/`, with provenance tracked by [UID:0001QY][README](by-meta/obtained_thirdparty_files/static_embeds/README.md). Parent [UID:0000VP] is not a source file and should not emit. Source-bearing by-memory children should use validator inline import directives for exact staged `third_party_embeds/libjpeg/...` source files and needed headers, which lets generated-output tooling route to the official source without copying upstream bodies into documentation.

This parent is therefore `RECONSTRUCTABLE:FALSE` with blank `EMITTER_UIDS` and blank formal C++. The source-bearing child pages remain `RECONSTRUCTABLE:TRUE` with [UID:0000KN][LibJPEG](by-file/LibJPEG.md) as owner/emitter because they identify concrete third-party source files that the generated reconstruction should stage through validator inline import directives.

## Rejected Alternatives

- Keep [UID:0000VP] as `RECONSTRUCTABLE:TRUE` with `EMITTER_UIDS:0000KN`: rejected because the page is an overlap aggregate and would duplicate child/source-file ownership.
- Paste Hex-Rays C++ or upstream C bodies into the parent: rejected because official static embed files are the source of record and this page is not a source unit.
- Treat the high `0x00406ed1-0x00414283` leaf as unresolved entropy/DCT work: rejected by current MCP initializer/xref evidence and staged IJG source comparison.
- Assign high-range helpers to image loaders, screenshot capture, render, or DAT code: rejected because product modules call public libjpeg APIs while IJG internals remain with [UID:0000KN][LibJPEG](by-file/LibJPEG.md).
- Include `_AIL_shutdown@0` at `0x00414290` or the atexit glue at `0x004142a0`: rejected by live byte/function evidence and existing zlib/Miles boundary docs.
- Revive the old `0x00469640-0x00470dc9` LibJPEG hypothesis: rejected because IDA decompiles that neighborhood as BrowserWindow/WebBrowser COM code.
