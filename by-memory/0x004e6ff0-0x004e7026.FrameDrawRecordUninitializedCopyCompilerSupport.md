The two callers load the vector header in `ECX`, while this body never reads `ECX`. The loop is forward-only. It is valid for the observed disjoint old/new vector storage and for forward overlap where destination precedes source, but it is not a general `memmove`: destination-after-source overlap can overwrite unread bytes. No overlap test or reverse path exists.
