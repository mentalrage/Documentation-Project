## Behavior Notes

The `0x00546bc0` body configures a new flying parcel or letter animation:

- It branches on `byte_66DA97`, the current unresolved name for the layout/rendering-mode selector used by other UI panes.
- In the `byte_66DA97 == 1` path it triggers `0x0057a5c0` with `(200, 100)`, clears or removes the helper at `+0x100` through `0x00556ce0`, initializes the payload fields, builds a rectangle using coordinates around `0x276..0x2eb`, invalidates/updates pane state, bumps offset `+0xac` by `0x1e`, and schedules a `100` ms timer.
- In the other rendering path it builds a smaller sprite rectangle from the first argument, using a fallback rectangle when the value is greater than `4`, then schedules a `10` ms timer.
- Both paths update the same fields and call the same pane virtual slots before scheduling the timer against the tertiary handler object at `this + 0xa4`.

The child layout is consistent with [UID:0001VI][ParcelNotificationPaneLayouts](by-type/by-struct/ParcelNotificationPaneLayouts.md): `+0xf8` is the animation tick, `+0xf9..+0xfb` are the payload bytes later forwarded by `AnimateStep`, `+0xfc` selects parcel versus letter drawing, and `+0x100` is the owned helper pointer.
