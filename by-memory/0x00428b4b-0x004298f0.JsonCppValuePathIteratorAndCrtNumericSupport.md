# 0x00428b4b-0x004298f0 JsonCpp Value/Path/Iterator and CRT Numeric Support

## Status

- Disposition: ignored for NexusTK source reconstruction
- Entity kind: third-party JsonCpp value/comment/path/iterator support plus adjacent CRT `__crt_strtox` numeric helper fragments
- Likely owner: [UID:0000KI][JsonCpp](by-file/JsonCpp.md) and MSVC CRT support

- Confidence: strong for non-product ownership; medium for final per-function upstream names.

## Range Role

This range bridges the earlier [UID:0000WY][0x00424630-0x00428b4b.JsonCppValueCore](by-memory/0x00424630-0x00428b4b.JsonCppValueCore.md) and the [UID:0000X0][0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds](by-memory/0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds.md). It contains a small CRT `__crt_strtox::big_integer` helper pair followed by JsonCpp value comment, path, and iterator support. It is third-party/runtime code, not fitting-room or cash-shop product logic.

## Evidence

- 2026-06-04 live IDA MCP function inventory reports 15 modeled functions in `0x00428b4b-0x004298f0`, from `??0big_integer@__crt_strtox@@QAE@XZ` at `0x00428b50-0x00428b59` through `unknown_libname_3` at `0x00429890-0x004298a6`.
- The same inventory found no external product-code xrefs into those 15 modeled starts; observed refs are internal/support refs or data refs.
- Neighbor scan confirms this page is physically bounded by `sub_428940` ending at `0x00428b4b` and the next JsonCpp document parse front end `sub_4298F0` starting at `0x004298f0`.
- IDA MCP decompilation of `0x00428b50` identifies the first modeled function as `__crt_strtox::big_integer::big_integer`, confirming the CRT numeric-conversion fragment.
- IDA MCP decompilation of `0x00428b70` references `assert json failed` and `in Json::Value::setComment(): Comments must start with /`, then copies the supplied comment text. String xrefs place those diagnostics at `0x00428bf3` and `0x00428c2c` inside `sub_428B70`.
- IDA MCP decompilation of `0x00428d70` and `0x00429090` shows path-syntax processing over `[`, `%`, `.`, decimal digits, and `std::string`-style temporaries. This matches JsonCpp `Json::Path` / `PathArgument` support rather than product logic.
- IDA MCP decompilation of `0x00429830` references `ConstIterator to Iterator should never be allowed.`, a JsonCpp iterator diagnostic at `0x0060e83c` with an xref from `0x0042985b`.
- Live raw disassembly confirms `0x004298b0` and `0x004298d0` are still not IDA function starts; they are small copy/flag helper bodies, followed by `0xcc` alignment at `0x004298e6-0x004298f0`.
- Direct product-code ownership belongs at the call sites that consume JsonCpp parse/value APIs. This support island is reached through JsonCpp value/path/iterator internals and remains third-party/runtime support.
