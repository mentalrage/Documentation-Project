# 0x00471110-0x00471141 CRT Wide Vsnprintf Wrapper

## Scope

- Range: `0x00471110-0x00471141`
- Entity kind: CRT/helper wrapper
- Current IDA name: `sub_471110`
- Disposition: ignored for NexusTK source reconstruction
- Confidence: strong for CRT wide-format wrapper identity
- Rebuild handling: `third-party/runtime`; this should be supplied by the CRT/toolchain rather than hand-authored NexusTK source.

This wrapper forwards wide-format arguments through the local stdio option accessor and `__stdio_common_vsnwprintf_s`. It is runtime/CRT support glue, not product logic.

## Evidence

- IDA MCP reports `sub_471110` at `0x00471110-0x00471141`.
- IDA MCP disassembly shows a direct call to `sub_41B9A0`, then `__stdio_common_vsnwprintf_s`, matching the CRT stdio common wrapper pattern already documented in [UID:0000WO][0x0041b9a0-0x0041b9de.CrtStdioCommonSprintfGlue](by-memory/0x0041b9a0-0x0041b9de.CrtStdioCommonSprintfGlue.md).
- The wrapper does not inspect browser or bulletin-session state despite its placement between the browser and bulletin code islands.
- Live IDA MCP refresh on 2026-06-15 reconfirmed `sub_471110` size `0x31`, `0x00471141` as non-function padding, and successor `sub_471150` at `0x00471150`.
- The 2026-06-15 `disasm` refresh showed the full 19-instruction wrapper: builds a varargs pointer, passes null locale, forwards the buffer/count/max/format arguments, calls `sub_41B9A0`, pushes the returned stdio option pair, calls `___stdio_common_vsnwprintf_s`, and returns `-1` for negative results via `cmovs`.
- The 2026-06-15 `decompile` refresh matched the same signature shape: `int sub_471110(wchar_t *Buffer, size_t BufferCount, size_t MaxCount, wchar_t *Format, ...)`, `va_start`, `sub_41B9A0()`, `__stdio_common_vsnwprintf_s`, and negative-result normalization to `-1`.
- `xref_query` on 2026-06-15 found only two direct callers to this wrapper, from `sub_470A00+0xa1` and `sub_4A6430+0x25`; neither changes the runtime/CRT ownership decision.
- Byte read from `0x00471110` confirms `0x00471141-0x00471150` is `0xcc` alignment padding before the next modeled function.
