## Behavior

This function is the `ThreadMan` worker loop. It waits up to 500 ms for queued Win32 messages, drains messages with `PeekMessage(..., PM_REMOVE)`, and handles message ids `0x0464` through `0x0468`.

The message handlers mutate 20-byte [UID:0001WB][ThreadManWatchRecord](by-type/by-struct/ThreadManWatchRecord.md) entries in `ThreadManLayout::watchList`. Registration creates a record, removal deletes a record, and the other messages update watchdog state by either the watched thread pointer or the cached identity at record offset `0x08`.

When no debugger is present, the timeout path scans the watch list. It arms unarmed records with `timeGetTime() + 10000`; if an armed record remains overdue past the extended grace window, it formats `Possibly dead thread 0x%p` and calls `FatalAppExitW`.

The raw wrappers immediately before this function at [UID:0001K1][0x00596d20-0x00596e0b.ThreadManRawMessageWrappers](by-memory/0x00596d20-0x00596e0b.ThreadManRawMessageWrappers.md) post the same message ids to the manager thread id stored at `ThreadMan + 0x0c`.
