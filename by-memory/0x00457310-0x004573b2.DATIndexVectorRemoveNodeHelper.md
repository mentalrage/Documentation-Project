# 0x00457310-0x004573b2 DATIndexVector RemoveNode Helper

## Status

- Entity kind: private class-owned cleanup/helper
- Current Wave3 owner: not emitted as an active `DATIndexVector` method in `class_DATIndexVector.cpp`
- Proposed owner: [UID:00003K][DATIndexVector](by-class/DATIndexVector.md)
- Proposed file: [UID:0000IP][DATIndexVector](by-file/DATIndexVector.md)
- Function boundary: IDA MCP `lookup_funcs` reports `sub_457310` size `0xa3`.
- Evidence basis: IDA MCP decompilation/caller/xref/disassembly checks on 2026-05-24 and 2026-05-25, plus `simroot_v2/class_DATIndexVector.cpp` comparison.

## Behavior

The helper hashes the node key with the same four-byte FNV-1a bucket selection used by `InsertNode` and `FindNodeByKey`. It updates the selected bucket's first/last entries if the removed node is on a boundary, unlinks the node from the intrusive list, decrements the owning count, frees the node, and returns the next node through the caller-provided out parameter.

## Caller Evidence

IDA MCP `callers` showed only one caller:

- `0x00457100`: [UID:0000XS][0x00457100-0x0045730e.DATIndexVectorInsertNode](by-memory/0x00457100-0x0045730e.DATIndexVectorInsertNode.md), at `0x00457301`.

The `0x00457301` call is in the post-return EH/unwind cleanup block inside `sub_457100`, not in the normal straight-line `InsertNode` decompilation. Current placement decision: keep it with `DATIndexVector.cpp` as private exception-cleanup support, not as a public `Erase`/`Remove` API.
