# 0x0066dd60-0x0066dd78 Image Extension Pointer Table

## Summary

- Address range: `0x0066dd60-0x0066dd78`
- Entity kind: initialized pointer table plus trailing padding
- Disposition: reconstructable project data
- Rebuild handling: `source-declared static table`
- Confidence: strong for pointer targets and consumer; medium for final source owner

This range contains a five-entry pointer table for image sidecar/extension strings, followed by four zero bytes before the day/night float table.

## Layout

| Address | Current IDA name | Pointer target | Notes |
| --- | --- | --- | --- |
| `0x0066dd60` | `off_66DD60` | `0x0061e964` wide `bmp` | First extension string. |
| `0x0066dd64` | pointer | `0x0061e96c` wide `pcx` | Second extension string. |
| `0x0066dd68` | pointer | `0x0061e974` wide `jpg` | Third extension string. |
| `0x0066dd6c` | pointer | `0x0061e97c` wide `jpeg` | Fourth extension string. |
| `0x0066dd70` | pointer | `0x0061e988` wide `pnm` | Fifth extension string. |
| `0x0066dd74-0x0066dd78` | zero bytes | none | Alignment before the float table. |

## Evidence

- IDA pointer inspection resolves the table targets to the five wide image extension strings `bmp`, `pcx`, `jpg`, `jpeg`, and `pnm`.
- IDA xref at `0x005064d0` lands inside `sub_5063E0`, which is documented as `ProfileSidecarRefresh`.
- Existing profile-storage docs record this same sidecar search set under `Documents\\NexusTK\\users`.

## Reconstruction Notes

- Keep this as a named extension list in profile/image sidecar support.
- Do not duplicate the string literals in unrelated image writer code unless a later caller proves the table is shared more broadly.
