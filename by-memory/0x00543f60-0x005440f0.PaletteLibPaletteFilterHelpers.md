## Evidence Notes

- IDA `lookup_funcs` reports `sub_543F60` at `0x00543f60-0x00543f70` and `sub_543F80` at `0x00543f80-0x005440f0`; `0x00543f70` and `0x005440f0` are not IDA function starts.
- IDA callers load `g_pPaletteLib` (`0x0067a7e0`) into `ecx` immediately before calling these helper functions.
- `0x00543f60` has four code refs from map render/tile-update paths: `0x005096e7` and `0x0050a277` in `sub_5094B0`, plus `0x0050d94f` and `0x0050d99f` in `sub_50D8E0`.
- `0x00543f80` has two code refs from map render paths: `0x00509595` in `sub_5094B0` and `0x0050a918` in `sub_50A8B0`.
- `0x00543f60` has no callees; `0x00543f80` calls only `dword_69B408` (`0x0069b408`) directly.
- Decompilation for `0x00543f80` caches the float weight at `+0x75c`, converts it to an integer strength `(weight * 32.0) + 0.5`, calls `dword_69B408` to transform base/super palette entries, then walks the 25 runtime slot lists and skips slot `11`.
- Runtime source-list and destination-list pairs are read from the 25-entry list-pointer banks around `this+0x690`; each non-slot-11 runtime palette entry rewrites 255 16-bit colors beginning at entry offset `+0x2e`.
- Earlier docs attached these functions to `ScreenPanePaletteState_543D30`; that is incorrect for current IDA evidence because every caller uses the `PaletteLib` singleton pointer as `this`.

## Ownership Decision

Promote these helpers into the `PaletteLib`/`render/Palette.cpp` family. They are runtime palette-filter state and derived-table updates used by map rendering, not screen palette-bank reset helpers. The raw getter should stay documented with the same helper group until a direct xref or source-quality final name is recovered.

## Reconstruction Notes

- Reconstructable as `PaletteLib` behavior, but leave C++ blank until the layout pass settles final names for `+0x758`, `+0x75c`, the base/super palette arrays, and the 25 source/runtime slot-list banks.
- Preserve the change guard in the table updater: it returns without rebuilding when the incoming float equals the cached `+0x75c` value under the observed `ucomiss`/`lahf` branch sequence.
- Slot `11` is intentionally skipped while rebuilding runtime slot palettes; do not treat this as an off-by-one until the slot table names are final.
