# JsonCpp Valid Reader Keys `0x004417e0-0x00441d24`

## Status

- Confidence: strong for JsonCpp ownership and upstream function role.
- Proposed owner: [UID:0000KI][JsonCpp](by-file/JsonCpp.md)
- Disposition: third-party static library code; exclude from NexusTK product source modules.
- Evidence basis: read-only IDA MCP lookup, caller/callee, string, string-xref, and decompile checks on 2026-05-25 plus staged JsonCpp commit `b299d3581f4dc670734f1fe1a34fce1282337802` source comparison. `wave3.py` was not executed for this pass.

## Range Role

This function is the JsonCpp `getValidReaderKeys(std::set<JSONCPP_STRING>*)` helper from `src/lib_json/json_reader.cpp`. It clears and repopulates the valid-key set used by `CharReaderBuilder::validate`, not the default settings map.

## Key Anchors

| Range | IDA name | Observed role |
| --- | --- | --- |
| `0x004417e0-0x00441d24` | `sub_4417E0` | Clears a string set and inserts reader setting keys: `collectComments`, `allowComments`, `strictRoot`, `allowDroppedNullPlaceholders`, `allowNumericKeys`, `allowSingleQuotes`, `stackLimit`, `failIfExtra`, `rejectDupKeys`, and `allowSpecialFloats`. |

## Evidence

- IDA string xrefs from this function target the JsonCpp settings string block at `0x0060e75c-0x0060e7f8`.
- IDA caller checks show a direct caller from `0x0042d7f0`, inside the [UID:0000X2][0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland](by-memory/0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland.md). In the staged source, this is the call from `CharReaderBuilder::validate` into `getValidReaderKeys`.
- IDA decompilation shows this function clearing the set before inserting only key names. The values/defaults are installed by the separate `CharReaderBuilder::setDefaults` source function, not by this helper.
- The staged `b299d3581f4dc670734f1fe1a34fce1282337802` source contains the same `getValidReaderKeys` key list in `src/lib_json/json_reader.cpp`.

## Ownership Decision

Keep `0x004417e0-0x00441d24` with [UID:0000KI][JsonCpp](by-file/JsonCpp.md) and `third_party/jsoncpp/`. It should not be attached to product modules that only consume parsed JSON.
