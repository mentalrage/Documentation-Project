# 0x0069b45c-0x0069b480 StartupLogoBinkPlaybackGlobals

## Summary

This `.data` span stores the state used by the standalone startup-logo Bink playback loop and its midpoint/restart helper. The main helper loads `LOGO.PAK` or `LOGO.PAD` into an in-memory buffer, opens the first Bink segment from `buffer + 4`, creates a Bink buffer for the client window, installs a temporary window procedure, pumps frames/messages, restores the old procedure, closes the Bink handle, optionally invokes a teardown callback object, and frees the payload buffer. The adjacent restart helper can close the current Bink handle and reopen the next in-memory segment from the stored payload pointer.

## Playback Setup And Loop

The playback setup in `0x004f5710-0x004f59c6` stores the client window handle at `0x004f5746`, selects the startup logo media file, reads it into an automatic byte buffer, and interprets the first dword as the first segment size.

After loading the payload:

1. `0x004f57d4` reads the first segment size from the payload header.
2. `0x004f57de` advances the first segment pointer to `buffer + 4`.
3. `0x004f57e4` stores `buffer + 4 + firstSegmentSize` in `0x0069b474` as the next-segment pointer.
4. `0x004f57f2` stores `payloadSize - firstSegmentSize - 4` in `0x0069b478`.
5. `0x004f5809-0x004f5817` opens the first Bink stream with flags `0x04080000` and stores the handle at `0x0069b45c`.
6. `0x004f5821-0x004f582d` opens the Bink buffer for the stored window and stores that handle at `0x0069b460`.
7. `0x004f585d-0x004f586a` installs the temporary window procedure on the stored window handle.
8. `0x004f5885` sets the playback loop flag byte to `1`.

The frame loop waits for Bink readiness, draws a frame, locks the Bink buffer, copies the frame to the buffer, unlocks, queries dirty rectangles, blits to the window, checks whether the current frame reached the final frame, and advances to the next frame. When the stream reaches its end, `0x004f594c` clears the loop flag byte, and `0x004f5958` exits the loop when the flag is zero.

Cleanup restores the old window procedure with the stored window handle at `0x004f596a`, closes the active Bink stream at `0x004f5976`, then reads `0x0069b470` at `0x004f5982`. If that object slot is non-null, the code uses compiler-lowered deleting-slot semantics with flag `1`; source-level C++ should model it as `delete g_startupLogoBinkTeardownCallback`, not as a completion `Invoke()` call.
