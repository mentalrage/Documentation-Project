## Behavior

Ensures the queue slot pointer array has capacity for the requested number of additional entries. It doubles capacity until enough open slots exist and the capacity is at least eight, allocates a new pointer array, preserves the wrapped ring layout around the current start index, zeroes newly opened holes, frees the previous slot array with MSVC aligned-allocation validation, then updates the queue pointer and capacity.

This function reallocates the slot pointer array, not the 20-byte scheduled-event records themselves.

B015 source-quality reanalysis prefers source-facing name `EnsureCapacityForInsert(unsigned int additionalCount)` because both raw callers are insert-side capacity checks at `0x005984ac` and `0x005985a6`.

Observed queue fields match [UID:0001WD][TimerMgrLayout](by-type/by-struct/TimerMgrLayout.md): `this[1]` is the slot pointer array, `this[2]` is slot capacity, `this[3]` is logical start index, and `this[4]` is the current entry count used by neighboring helpers. This helper mainly mutates `slotEntries` and `slotCapacity`; it preserves logical start/count while opening zeroed holes around the ring.

Growth and allocation details:

- Starts from current capacity, or `1` when capacity is zero.
- Doubles until `(newCapacity - oldCapacity) >= requestedAdditionalSlots` and `newCapacity >= 8`.
- Checks the capacity/byte-size overflow paths before allocation.
- Allocates `4 * newCapacity` bytes for small arrays.
- For byte counts at or above `0x1000`, allocates `size + 0x23`, aligns the returned slot pointer to a 32-byte boundary, and stores the raw allocation pointer at `aligned[-1]`.
- Copies the old tail range beginning at `startIndex`, copies the old head range, and zeroes the newly opened holes with `memset`.
- Frees the old slot array through the same large-allocation validation path, including the `raw-pointer slack <= 0x1f` check before freeing the saved raw pointer.
