# 0x004a1600-0x004a1b5e DIBitmap And PCX Loaders

## Status

- Confidence: strong for range membership.
- Covered class: [UID:00003V][DIBitmap](by-class/DIBitmap.md)
- Likely source files: [UID:0000IV][DIBitmap](by-file/DIBitmap.md) and [UID:0000K3][ImageLoaders](by-file/ImageLoaders.md)
- Confirmed layout: [UID:0001U6][DIBitmapLayout](by-type/by-struct/DIBitmapLayout.md)

## Functions

| Range | Function | Notes |
| --- | --- | --- |
| `0x004a1600-0x004a1738` | `DIBitmap::DIBitmap` | Builds a 16-bit top-down DIB section with aligned scanlines. |
| `0x004a1740-0x004a17ac` | `DIBitmap` destructor/accessor cluster | Raw non-deleting destructor body, pixel/HBITMAP accessors, guarded width/height accessors, and guarded aligned-width accessor. |
| `0x004a17b0-0x004a18a8` | `LoadPcxImage` | Converts an ANSI path, opens a DAT/file-buffer object, and forwards raw PCX bytes to the factory. |
| `0x004a18b0-0x004a1b0c` | `CreateDIBitmapFromPcxBuffer` | Calls the PCX decoder, constructs `DIBitmap`, copies decoded rows, and frees temporary pixels. |
| `0x004a1b10-0x004a1b5e` | `DIBitmap::ScalarDeletingDestructor` | Deletes the GDI bitmap handle and optional object storage. |

## Evidence Notes

- This is a tight local code cluster, with the two PCX helpers placed between the `DIBitmap` constructor and destructor.
- IDA MCP confirms `LoadPcxImage` is called by the startup window PCX notice path and calls `CreateDIBitmapFromPcxBuffer`.
- IDA MCP confirms `CreateDIBitmapFromPcxBuffer` calls the standalone decoder at `0x00549410`.
- IDA MCP confirms the `0x004a1740-0x004a17ac` DIBitmap method gap is real code, even though active `class_DIBitmap.cpp` currently omits it.
- IDA MCP/raw bytes on 2026-05-27 confirm the aggregate ends at `0x004a1b5e`: `lookup_funcs 0x004a1b5d` maps to `sub_4A1B10` size `0x4e`, and the `retn 4` at `0x004a1b5b` occupies bytes through `0x004a1b5d`.
- IDA-confirmed DIBitmap field use in this range only requires fields through `+0x38`: embedded `BITMAPINFOHEADER`, `HBITMAP`, DIB bits pointer, and requested dimensions. Current simroot metadata's larger/noisy layout is a Wave3 data caveat.
