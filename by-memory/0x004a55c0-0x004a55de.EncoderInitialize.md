## Behavior

Attaches a caller-owned output buffer, stores capacity, resets the write cursor to zero, and marks the encoder valid/writable. It is not a constructor-like method: [UID:00013C][0x004a4e70-0x004a4e94.EncoderConstructor](by-memory/0x004a4e70-0x004a4e94.EncoderConstructor.md) installs the vtable, clears cursor fields, and initializes the packed byte-order/valid flags. `Initialize` is called after construction and only reattaches a caller buffer for a serialization pass.

`Initialize` deliberately does not write byte `+0x10`. The constructor-default nonzero byte-order flag, or any later caller-selected byte order, remains in effect while the new buffer/cursor/valid state is reset. This matters for [UID:0001JN][0x0058e490-0x0058e691.TextEditPaneSerialization](by-memory/0x0058e490-0x0058e691.TextEditPaneSerialization.md), whose marker dword `0x6b6f6e67` is emitted as bytes `"kong"` under the default big-endian scalar-write setting.

## Source-Facing Signature And Fields

```cpp
void Encoder::Initialize(unsigned char *buffer, int capacity);
```

`void` is the source-correct result even though IDA-style decompilers may leave `capacity` in `eax`: the sole live caller ignores the register result, the function returns with `ret 8`, and the method is a state mutator. `unsigned char *` is stronger than `void *` or `char *` because sibling writers operate on bytes and the caller passes a stack byte buffer. B004 recommends `unsigned int capacity` for the draft source signature because the method stores an advertised writable byte count rather than returning a signed status; sibling writers may still cast the stored capacity for the binary's signed compare shape.

| Offset | Source-facing name | Role |
| --- | --- | --- |
| `+0x04` | `m_outputBuffer` | caller-owned byte buffer; constructor/finalize clear it, this method stores it, writers write through it |
| `+0x08` | `m_capacity` | advertised writable window; sibling writers compare it against `m_writePos + payload + 1`; `m_outputCapacity` and `m_bufferCapacity` remain descriptive aliases |
| `+0x0c` | `m_writePos` | current write cursor reset here and advanced by writer helpers |
| `+0x10` | `m_useBigEndian` | byte-order flag preserved by this method and consumed by scalar writers |

Historical aliases such as `m_buffer`, `m_outputCapacity`, `m_bufferCapacity`, `m_cursor`, and `m_isValid` remain useful prose synonyms in older support docs, but raw `mbr_0x...` names are rejected for source-facing C++.
