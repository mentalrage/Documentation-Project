## Behavior

Copies a rectangle from a raw resource-layout record array into the caller's output rectangle, or zeros the output rectangle when the requested index is greater than or equal to the unsigned record count.

IDA MCP decompilation and disassembly on 2026-06-03 show the helper expects:

- `a1[0]` as an entry count;
- `*((DWORD*)a1 + 2)` as a pointer to 24-byte [UID:0000VB][ResourceLayoutEntry](by-item/ResourceLayoutEntry.md)-like records;
- `a2` as the requested frame index;
- `a3` as the 16-byte output rectangle.

If `a2 >= *a1`, it writes a zero rectangle in the order bottom, top, right, left. Otherwise it computes `entryBase + 24 * a2` and copies the first 16 bytes through `movups`. The assembly uses a signed `jge` after zero-extending the 16-bit count, so negative indexes are not rejected by this helper; current documented callers compute nonnegative overlay indexes before calling it.

Historical B013 source used a file-local `ResourceLayoutRawRecordTable` overlay and `static` linkage. The complete source family proves that overlay is the accepted shared `ArchiveMetadataTable`: `frameCount` supplies the comparison and `records[entryIndex].bounds` supplies the leading 16-byte rectangle from the exact 24-byte row. The formal C++ intentionally tests only `entryIndex < table->frameCount`, with no `entryIndex >= 0` guard, so negative indexes retain the binary-observed copy-path behavior.
