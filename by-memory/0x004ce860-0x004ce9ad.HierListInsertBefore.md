## Behavior

Creates a temporary hierarchy row and inserts it into either the root list or a lazily-created child `HierList`.

The method treats the first argument as an optional parent payload, the second as an optional sibling/reference payload, and the third as the caller payload to copy. It allocates `this->elementSizeWithHierarchyOverhead` bytes with `sub_516050`, clears the child-list pointer at row `+0x04`, then copies `elementSizeWithHierarchyOverhead - 11` payload bytes to row `+0x08`.

When a parent payload is supplied, it resolves the parent node with [UID:0002IK][0x004cec30-0x004ced0f.HierListFindNodeByData](by-memory/0x004cec30-0x004ced0f.HierListFindNodeByData.md). If the parent node has no child list, it allocates 24 bytes, calls the `List` constructor with the same element size and page size `32`, installs the `HierList` vtable, writes the parent node into the child list owner field at `+0x14`, and stores the child list at parent node `+0x04`. The new row's parent pointer at `+0x00` is the found parent node.

When no parent payload is supplied, the target list is either the root list or the owner list returned while resolving the sibling payload. The new row's parent pointer is copied from the root list owner field at `this + 0x14`.

The raw insertion slot is always `resolvedIndex + 1`. With no sibling/reference payload this method uses `-1`, so the root/no-sibling and new-child-list defaults insert at index `0`. With a resolved sibling payload, `FindNodeByData` writes the actual zero-based index, and the virtual slot `+0x14` dispatches to [UID:0002IG][0x004ceb70-0x004ceba9.HierListInsertAt](by-memory/0x004ceb70-0x004ceba9.HierListInsertAt.md) with `count = 1`.

The live tail frees the temporary row with `sub_516170` immediately before returning. That helper returns zero, so the observed binary does not preserve `List::InsertAt`'s destination pointer as a useful return value; callers use the list mutation side effect.
