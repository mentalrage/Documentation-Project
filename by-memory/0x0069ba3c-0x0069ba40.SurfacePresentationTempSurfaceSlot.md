This four-byte slot is a temporary DirectDraw-style surface/object pointer used only by the shared surface presentation initializer at `0x00558840`.

## Evidence

- Live IDA bytes for `0x0069ba3c-0x0069ba40` are `ff ff ff ff`, matching one pointer-sized storage slot initialized to the same sentinel pattern as nearby global slots.
- Live IDA reports exactly four direct references to `0x0069ba3c`, all in the initializer at `0x00558840`: `0x00558a53`, `0x00558a90`, `0x00558aa5`, and `0x00558ae6`.
- At `0x00558a53`, the initializer passes the address of this slot as an out-parameter to a DirectDraw-style vtable call. At `0x00558a90`, it reads the created object pointer back. At `0x00558aa5`, it passes the created pointer to a second vtable call with a value derived from the application object. At `0x00558ae6`, it passes the same pointer while attaching/configuring the presentation object's retained surface field.
- Boundary checks keep the range tight: `0x0069ba38` is the preceding VoteMenuPane singleton pointer with eight unrelated refs, while `0x0069ba40` starts the next mutable packet-transform block with six unrelated refs. `0x0069ba30` has zero direct refs and `0x0069ba34` has five unrelated refs, so `0x0069ba3c-0x0069ba40` is a standalone slot.
- The slot has no direct consumers outside the initializer, which supports treating it as a transient render/presentation helper rather than a UI singleton.
- 2026-06-07 A001 IDA MCP reconfirmed the same boundaries: `dword_69BA3C` is a four-byte `.data` item initialized to `0xffffffff`; the only references are the four `0x00558840-0x00558f63` surface initializer sites listed above; `0x0069ba38` remains the VoteMenuPane singleton and `0x0069ba40` begins packet-transform mutable state.
