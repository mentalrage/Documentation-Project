## Timer Evidence

IDA MCP checks on 2026-05-24 confirm that this local-player extension range also uses the generic [UID:0000F1][TimerMgr](by-class/TimerMgr.md) scheduler:

- `0x005a36f0` initializes walking state, cancels the base animation timer through `0x0053bf80`, then schedules the walk-step timer through `TimerMgr::ScheduleTimer` at `0x00597910`.
- `0x005a3770` starts directional animation, resolves the movement frame delay from sprite resources, then schedules timer event `20` through `0x00597910`.
- `0x005a5a90` (`WarpToPosition`) cancels the walk-step event and event `20` through the generic wrapper at `0x00597610`, then clears effects and refreshes map placement.
- `0x005ab090` and `0x005ab410` movement packet handlers call both `0x00597910` scheduling and the timer-removal helper at `0x00597a10` while reconciling predicted versus server-authoritative movement.

Active generated source may spell some of these calls as `SoundManager::CancelTimer`, but IDA body/caller evidence ties the targets to [UID:0001K9][0x00597610-0x00597645.TimerHandlerWrappers](by-memory/0x00597610-0x00597645.TimerHandlerWrappers.md) and [UID:0000SI][g_pTimerMgr](by-global/g_pTimerMgr.md), not audio ownership.

## Macro/Hotkey Evidence

IDA MCP decompile on 2026-05-25 confirms `ExecuteHotkeyAction` consumes [UID:0001V1][MacroHotkeyRecord](by-type/by-struct/MacroHotkeyRecord.md) rows through state view `g_pConfig + 0x28f2f0 + adjustedIndex * 0x108`: state `1` converts row text to multibyte and sends opcode `14`, state `2` dispatches to `0x005a4530`, and state `3` dispatches to `0x005a3e30`.

The state labels are resolved from the editor source tab: `GeneralPurposePanel` child index `2` is inventory and child index `3` is spell inventory. `IntegrateMacroEditControlPane::OnKeyEvent` writes state `2` / `.usr` `S` when active index is `3`, and state `3` / `.usr` `I` when active index is `2`. The current generated helper names `UseCommandSlot` (`0x005a4530`) and `UseSpellSlot` (`0x005a3e30`) remain source-name candidates, but final cleanup should preserve the state-label evidence rather than deriving labels only from those provisional names.

2026-05-27 IDA follow-up now documents `0x005a3e30-0x005a3ff3` separately as [UID:0001KN][0x005a3e30-0x005a3ff3.UseInventorySlotDispatch](by-memory/0x005a3e30-0x005a3ff3.UseInventorySlotDispatch.md). The helper indexes the player/client-state slot table, can send direct object-action packets through `0x005af580`, or constructs [UID:00006X][ItemWhoInputPane](by-class/ItemWhoInputPane.md) for target selection. This strengthens the inventory/item interpretation of the state `3` path while leaving the paired `0x005a4530` name for later review.
