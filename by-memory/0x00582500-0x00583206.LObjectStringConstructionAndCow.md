## Evidence

- IDA MCP function enumeration confirms all starts in this range and shows the family continues into later `0x00583210+` string helpers.
- Active `class_LObject.cpp` shows Interlocked refcounting, shared empty string sentinels, pooled 64/128/256/512 allocators, and a 12-byte header before the data pointer.
- IDA MCP checks tie the empty string sentinels to `0x00670278` and `0x00670290`, and tie the small-buffer pool globals to `0x0069bacc-0x0069bbe4`.
- `AllocateAnsiBuffer` / `AllocateWideBuffer` call into the [UID:0000MM][PoolAllocator](by-file/PoolAllocator.md) fixed-block pool family for small buckets.
- Caller checks show cross-subsystem users for the string family, including config/profile/storage, folder tree code, patching, and string replacement helpers.

## Ownership Notes

This range is current `LObject` output but should not be treated as proof that the original virtual base object and string class were one C++ type. The generated metadata already warns that the first string field is a data pointer, not the base-object vtable pointer. Current source-structure evidence favors [UID:0000OA][StringBase](by-file/StringBase.md) for this ref-counted string family.
