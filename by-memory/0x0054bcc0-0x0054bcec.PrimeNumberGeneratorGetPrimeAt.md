## Behavior

The raw body:

- reads the signed `index` argument;
- returns `2` when the index is negative;
- otherwise reads the generated-prime count at object offset `+0x18`, which is the old-MSVC implementation size field for native `std::deque<int> m_primes`, not a separate PrimeNumberGenerator scalar;
- clamps indexes past the end to `count - 1`;
- passes `this + 0x08` and the selected index to [UID:0001FC][0x0054c0c0-0x0054c110.DequeElementAddressHelper](by-memory/0x0054c0c0-0x0054c110.DequeElementAddressHelper.md);
- returns the 4-byte integer stored at that deque slot.

This is a small non-virtual public or private accessor over the prime table. Historical `simroot_v2` output did not emit it, but B005's 2026-06-18 raw route scan found that the missing caller/symbol route is a liveness/name cap rather than a source-reconstruction blocker.
