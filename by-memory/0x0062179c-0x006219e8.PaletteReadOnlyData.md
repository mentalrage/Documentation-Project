# 0x0062179c-0x006219e8 Palette Read-Only Data

## Range

- Address range: `0x0062179c-0x006219e8`
- Entity kind: `vtable/string-data`
- Disposition: reconstructable source-declared/generated-binary data.
- Rebuild handling: source class declarations and palette filename literals must be reconstructed; vtables are compiler-emitted.

## Summary

This `.rdata` span contains `DLPalette` and `PaletteLib` vtables plus the palette filename table used by map, tile, body/equipment, monster, item, effect, riding, and accessory resources. It ends before the core `Pane` vtable.

## Observed Contents

| Address | Item | Notes |
|---|---|---|
| `0x0062179c` | `DLPalette` vtable | Download/load palette helper table. |
| `0x006217ac` | `PaletteLib` vtable | Palette library table. |
| `0x006217b8` | `DLPalette` type/name string | IDA string detection confirms the class name literal. |
| `0x006217cc-0x006219d4` | palette filename literals | Includes tile, decoration, weapon, shield, monster, item, effect, riding, arrow, shoes, coat, and other palette names. |

## Evidence

- IDA MCP `py_eval` on 2026-05-28 reports `??_7DLPalette@@6B@` and `??_7PaletteLib@@6B@` in this range.
- Vtable xrefs point to palette executable code at `0x00542bbf`, `0x00542c12`, `0x00542ca6`, `0x00543257`, `0x0054375d`, and `0x00543b20`.
- Palette filename xrefs point into palette library load/setup code around `0x005438f7-0x00543a39`.
- The next named item at `0x006219e8` is `??_7Pane@@6B@`.

## Reconstruction Notes

- Treat the filename table as source-owned palette-library constants, not generic global string data.
- The vtables should be generated from reconstructed `DLPalette` and `PaletteLib` definitions.
