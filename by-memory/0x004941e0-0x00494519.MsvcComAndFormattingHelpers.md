# 0x004941e0-0x00494519 MsvcComAndFormattingHelpers

## Status

- Disposition: ignored for NexusTK-owned reconstruction
- Entity kind: MSVC COM support and CRT formatting helper island
- Rebuild handling: third-party/runtime
- Confidence: strong for function boundaries and runtime/header-helper identity

## Covered Ranges

These functions sit between the registry/config cleanup block and `ConnStatusPane`. They are real executable code, but the bodies match Microsoft COM support and CRT wrapper patterns rather than NexusTK-authored class or gameplay logic.

| Range | Current symbol | Interpretation |
| --- | --- | --- |
| `0x004941e0-0x00494396` | `sub_4941E0` | `_com_ptr_t::CreateInstance`-style helper. Converts an ANSI ProgID/CLSID string to wide text, calls `CLSIDFromString` or `CLSIDFromProgID`, then uses `CoCreateInstance`, `OleRun`, and `QueryInterface`. |
| `0x00494396-0x004943a0` | padding | Ten bytes of `0xcc` alignment before the next helper. |
| `0x004943a0-0x0049443f` | `sub_4943A0` | COM-wrapper helper that calls vtable slot 9, allocates a 12-byte `{payload, aux, refcount}` holder, and stores the returned pointer. |
| `0x0049443f-0x00494440` | padding | One byte of `0xcc` alignment. |
| `0x00494440-0x0049449a` | `sub_494440` | Refcounted BSTR/holder release helper; decrements the holder, frees BSTR/heap auxiliary state, and clears the owner slot. |
| `0x0049449a-0x004944a0` | padding | Six bytes of `0xcc` alignment. |
| `0x004944a0-0x004944c0` | `sub_4944A0` | `_freea`-style helper that frees only buffers with the `0xdddd` heap sentinel at `ptr - 8`. |
| `0x004944c0-0x004944e7` | `sub_4944C0` | Narrow CRT formatting wrapper that gathers locale flags and forwards a `va_list` to the shared formatting backend. |
| `0x004944e7-0x004944f0` | padding | Nine bytes of `0xcc` alignment. |
| `0x004944f0-0x00494519` | `sub_4944F0` / `WideStringScanf_4944F0` | Wide `swscanf` wrapper over `__stdio_common_vswscanf`; used by registry, dialogs, terminal setup, and other parsing code. |

## Evidence

- IDA MCP `lookup_funcs` on 2026-05-27 reports exact starts and sizes: `sub_4941E0` size `0x1b6`, `sub_4943A0` size `0x9f`, `sub_494440` size `0x5a`, `sub_4944A0` size `0x20`, `sub_4944C0` size `0x27`, `sub_4944F0` size `0x29`, followed by `sub_494520` at `0x00494520`.
- IDA MCP decompilation of `0x004941e0` shows `strlen`, `MultiByteToWideChar`, `CLSIDFromString`, `CLSIDFromProgID`, `CoCreateInstance`, `OleRun`, `QueryInterface`, and cleanup through `0x004944a0`, matching MSVC COM smart-pointer support.
- IDA MCP caller checks show the COM helper cluster is called from the command-line/session helper island at [UID:000220][0x0048f400-0x00491b28.RegistryCommandLineParsers](by-memory/0x0048f400-0x00491b28.RegistryCommandLineParsers.md), especially `sub_48FCA0` and `sub_490B10`.

- Direct PE byte review of `E:\NTK\Resources\NexusTK\NexusTK.exe` confirms `0xcc` alignment at `0x004941d6-0x004941e0`, between the helper bodies, and at `0x00494519-0x00494520`.
- The older `by-memory/-report.old.md` entry already classified `0x004944f0` as excluded `WideStringScanf_4944F0` CRT/stdio wrapper code.
