## Behavior

Central lookup API for resource-layout entries. Given a resource name, frame index, and optional [UID:00004I][EPFTileContext](by-class/EPFTileContext.md)-like output pointer, it finds or lazy-loads the resource bucket, bounds-checks the requested entry, and writes pixel/mask pointers and bounds into the tile context.

IDA MCP decompilation on 2026-05-31 shows:

- calls [UID:0002KW][0x004d17c0-0x004d182f.ResourceLayoutTableFindResourceIndex](by-memory/0x004d17c0-0x004d182f.ResourceLayoutTableFindResourceIndex.md) and falls back to [UID:0002KO][0x004d0120-0x004d02e5.ResourceLayoutTableLoadResourceIndex](by-memory/0x004d0120-0x004d02e5.ResourceLayoutTableLoadResourceIndex.md) when the resource is not registered;
- retrieves the 44-byte [UID:0001VT][ResourceLayoutNameRecord](by-type/by-struct/ResourceLayoutNameRecord.md) through the registry [UID:000079][List](by-class/List.md) vtable slot `+0x10`;
- checks `frameIndex` against the record's `entryCount` at `+0x20`;
- maps the selected 24-byte [UID:0000VB][ResourceLayoutEntry](by-item/ResourceLayoutEntry.md) into a tile-context output when present;
- computes encoded-mask size as `nextEntry.pixelData - currentEntry.encodedMaskData`, which depends on the sentinel row installed by `LoadResourceIndex`.

Invalid frame indexes zero the relevant tile-context fields and reset the output rectangle.
