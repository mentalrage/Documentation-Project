## Signature And ABI

IDA currently types the body as `_DWORD *__thiscall sub_465730(_DWORD *this, _DWORD *outPair, _DWORD *inPair)`.

- `ecx` is the `Application` instance.
- `arg_0` is the output two-dword coordinate/extent pair and is also returned in `eax`.
- `arg_4` is the input two-dword coordinate/extent pair.
- The stack epilogue is `retn 8`, so the two explicit pointer arguments are callee-cleaned under the observed `__thiscall` ABI.
- The final source-facing argument type is not proven as a normal Win32 `POINT`: live browser callers pass and consume the pair as slot `0` = vertical/height component and slot `1` = horizontal/width component.

## Behavior

`Application::MapToScreen` maps a two-int coordinate or size pair from the base logical display scale into the current screen/browser-window scale. It is the reciprocal helper for [UID:0002GS][0x00465690-0x0046572d.ApplicationMapFromScreen](by-memory/0x00465690-0x0046572d.ApplicationMapFromScreen.md).

If the current dimensions stored on the `Application` object already match the base display globals, the helper copies the two dwords unchanged from input to output. Otherwise it scales each slot independently and rounds toward nearest positive integer by adding the `0.5f` constant at `0x006104b0` before `cvttss2si` truncation:

- output slot `0` uses the height ratio: `input[0] * currentHeight / g_screenHeight`.
- output slot `1` uses the width ratio: `input[1] * currentWidth / g_screenWidth`.

The helper performs no heap work, no virtual dispatch, no API calls, and no writes except the two output dwords.
