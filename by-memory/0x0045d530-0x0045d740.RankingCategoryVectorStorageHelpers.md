## Purpose

This helper island contains teardown, allocation, and range-copy support for the ranking category collection and its embedded user-entry vectors. It is tightly coupled to the 688-byte `RankingCategoryRecord` layout and 76-byte `RankingUserEntry` layout, but it is not one source-authored method. It is now split into exact children so collection-owned category-record helpers and record-owned user-entry helpers can route through their narrow owners.

### UID0003YR Non-Emitting Outer Vector Teardown Closure

[UID:0003YR][0x0045d530-0x0045d5b5.RankingCategoryRecordVectorDestroy](by-memory/0x0045d530-0x0045d5b5.RankingCategoryRecordVectorDestroy.md) is the exact 133-byte compiler specialization for destroying the collection-owned outer `std::vector<RankingCategoryRecord>`. Its sole incoming code route is the five-byte [UID:0003WQ][0x0045c290-0x0045c295.RankingCategoryCollectionDestructorThunk](by-memory/0x0045c290-0x0045c295.RankingCategoryCollectionDestructorThunk.md), which is itself reached by exactly three construction/destruction lifetime paths. The target walks the half-open record range at exact stride `0x2b0`, calls [UID:0003YT][0x0045d5f0-0x0045d653.RankingUserEntryVectorDestroy](by-memory/0x0045d5f0-0x0045d653.RankingUserEntryVectorDestroy.md) on each record's `+0x258` member, and then releases the outer allocation.

The outer free reproduces the MSVC small/large allocation split. Small allocations pass the computed span and begin pointer directly to the free wrapper. Large allocations recover the raw allocation from the header before `begin`, add the allocator overhead, validate that the header distance is within the accepted bound, and route invalid metadata to `__invalid_parameter_noinfo_noreturn`. Successful teardown clears begin, end, and capacity. The exact body SHA256 is `BD68BC2529D22C1E3F240894411081A291B663A38B45EC1B1130BB149034C24D`; the thunk body SHA256 is `BF61252F1E61B859B1994B42177DBE6C9E3859519FCFEA28A27E51A8FC5F11D4`.

These details are runtime obligations, but they do not establish a hand-authored source helper. The coherent source model is [UID:0000BK][RankingCategoryCollection](by-class/RankingCategoryCollection.md)'s `std::vector<RankingCategoryRecord> m_records` and implicit destructor. UID0003YR therefore remains semantically collection-owned while being `RECONSTRUCTABLE:FALSE`, non-emitting, and blank in both formal code channels. The earlier direct owner/emitter interpretation is retained only as corrected history; semantic ownership does not require duplicate source emission.

### UID0003YT Non-Emitting Teardown Closure

[UID:0003YT][0x0045d5f0-0x0045d653.RankingUserEntryVectorDestroy](by-memory/0x0045d5f0-0x0045d653.RankingUserEntryVectorDestroy.md) is an exact 99-byte compiler/container specialization over the record-owned triplet at `+0x258/+0x25c/+0x260`. A null begin pointer returns. Otherwise, the body derives the capacity allocation span from `(capacity - begin) / 0x4c`, frees small allocations directly, and for spans at least `0x1000` recovers the raw allocation from `begin[-1]`, adds `0x23`, and enforces `(begin - raw - 4) <= 0x1f`. Failure reaches exact runtime callee `__invalid_parameter_noinfo_noreturn`; success calls cdecl free wrapper `sub_5C7526` and clears begin, end, and capacity in order. The absence of an element-destructor loop agrees with the trivial 76-byte `RankingUserEntry` row.

The complete nine-call lifetime set is `0x45bf56`, `0x45c2e8`, `0x45c514`, `0x45c5b6`, `0x45c7ee`, `0x45d0f9`, `0x45d516`, `0x45d548`, and `0x45d5d6`. The first call is the second instruction of an existing `[0x0045bf50,0x0045bf5b)` tail chunk owned by `sub_45C2A0`; `loc_45BF50` adds `0x258` and the next instruction tail-jumps to UID0003YT. The immediately following `[0x0045bf5b,0x0045bf60)` is a separate five-byte `0xcc` data item. The earlier ownerless-tail interpretation is retained only as rejected history.

No data xref and no VA, RVA, or raw-file-offset pointer pattern reaches UID0003YT. Its predecessor `[0x0045d5eb,0x0045d5f0)` and successor `[0x0045d653,0x0045d660)` are separate `0xcc` padding items. These boundaries, the class-owned source cause, and the decompiler-private allocator lowering require blank target CPP/H and blank emitter routing; authored source remains the `std::vector<RankingUserEntry> m_userEntries` declaration and ordinary `RankingCategoryRecord` lifetime. This does not weaken runtime requirements: the rebuilt toolchain must reproduce equivalent 0x4c-stride capacity release, large-allocation validation, free, and triplet clearing.

[UID:0003YS][0x0045d5c0-0x0045d5eb.RankingCategoryRecordRangeDestroyUserEntries](by-memory/0x0045d5c0-0x0045d5eb.RankingCategoryRecordRangeDestroyUserEntries.md) is the exact 43-byte range rollback immediately before UID0003YT.
