# 0x0048f400-0x0048f4cf CommandLineArgumentCounter

## Address Range

`0x0048f400-0x0048f4cf`, ending immediately before the exported start at `0x0048f4d0`.

IDA does not currently model this start as a function, but live IDA disassembly decodes a normal stack-frame prologue at `0x0048f400` and the exported/Ghidra inventory gives the same start and end.

## Behavior

This helper copies the process command line, skips the executable token, tokenizes the remaining wide command line, counts startup arguments, rejects oversized argument lists, and reasserts the startup-ready byte at the caller-supplied application/config state block.

It is the common lightweight argument-count/tokenization primitive used by the larger launcher-mode parsers in this island.

## Evidence

- Legacy Wave2 report records `FUN_0048f400` as `0x0048f400 .. 0x0048f4ce`, with no live Wave2 method/global resolution.
- IDA live disassembly begins with `push ebp`, `mov ebp, esp`, and a `0x828` stack allocation, confirming real code at the exported start rather than padding.
- IDA live disassembly shows calls to `GetCommandLineW`, `_wcscpy_s`, `_wcschr`, and `_wcstok_s`, matching a wide command-line tokenizer.
- The legacy report identifies the only lasting side effect beyond token counting as setting `param_1 + 0x2916ca` to `1`.

## Reconstruction Notes

Keep this as a free helper for startup/launcher parsing unless later xrefs prove a concrete owner. The current `param_1` is the shared application startup-state block used throughout the surrounding connection bootstrap routines.
