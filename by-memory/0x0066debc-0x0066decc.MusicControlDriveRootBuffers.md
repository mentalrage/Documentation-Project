# 0x0066debc-0x0066decc Music Control Drive Root Buffers

## Summary

- Address range: `0x0066debc-0x0066decc`
- Entity kind: mutable drive-root buffers
- Disposition: reconstructable project data
- Rebuild handling: `source-declared static buffers`
- Confidence: strong for `MusicControlDialog` use; medium for exact field split

This range contains small `X:\\` / `X:` drive-root buffers used by `MusicControlDialog` when enumerating CD drives and populating the drive-selection control.

## Layout

| Range | Current IDA name | Initial bytes | Notes |
| --- | --- | --- | --- |
| `0x0066debc-0x0066dec0` | `RootPathName` | `58 3a 5c 00` | ANSI root path buffer initialized to `X:\\`; the drive letter byte is rewritten before `GetDriveTypeA`. |
| `0x0066dec0-0x0066dec8` | `asc_66DEC0` | `58 00 3a 00 00 00 00 00` | Wide/word-oriented `X:` buffer passed to the UI string/control path after the drive letter word is rewritten. |
| `0x0066dec8-0x0066decc` | `aP` / adjacent word | `50 00 00 00` | Adjacent initialized word/dword; no separate direct xref was found in this pass. |

## Evidence

- IDA xrefs at `0x00529304` and `0x00529309` push and rewrite `RootPathName` inside `MusicControlDialog::MusicControlDialog` before calling `GetDriveTypeA`.
- IDA xrefs at `0x0052a061` and `0x0052a066` perform the same `RootPathName` rewrite inside the drive popup population helper.
- IDA xrefs at `0x0052931f`, `0x00529339`, `0x0052a078`, and `0x0052a095` rewrite and pass `asc_66DEC0` while adding drive entries to the dialog control.
- Existing `MusicControlDialog` docs list both constructor drive enumeration and the `0x0052a010-0x0052a120` drive popup helper.
