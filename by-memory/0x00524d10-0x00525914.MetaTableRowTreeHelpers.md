## Data Structures

The helpers establish the current [UID:0001V7][MetaTableRowNode](by-type/by-struct/MetaTableRowNode.md) layout:

- tree links and red-black/sentinel flags at `+0x00..+0x0f`;
- `SimpleUString key` at `+0x10..+0x27`;
- `SimpleUString* valuesBegin`, `valuesEnd`, and `valuesCapacity` at `+0x28`, `+0x2c`, and `+0x30`.

The value vector stores 24-byte `SimpleUString` elements. `0x00524db0` uses the same element size during reallocation and insertion.

2026-06-27 B014 materializer amendment confirms this helper island is best documented as compiler/container support for the materializer's source-facing `std::map<SimpleUString, std::vector<SimpleUString>>`-style `m_rows` member. The target-level source expression is `m_rows[rowKey].push_back(valueText)`: the repeated lower-bound/insert path allocates a row node when needed and then appends to the `valuesBegin`/`valuesEnd`/`valuesCapacity` span with 24-byte `SimpleUString` stride. The raw helper calls remain important documentation evidence, but should not be exposed as hand-written calls in [UID:0001CC][0x00524870-0x00524c55.MetaTableMaterializeRows](by-memory/0x00524870-0x00524c55.MetaTableMaterializeRows.md) formal C++.

2026-05-31 IDA MCP recheck confirms the key layout points: `0x00525850` allocates `0x34` bytes and initializes tree links; `0x00524d10` clears flags at `+0x0c`, copies the key into `+0x10`, and clears the value-vector pointers at `+0x28/+0x2c/+0x30`; `0x00524db0` uses 24-byte value elements; `0x00525610` destroys the vector and key; and `0x005245c0` walks the red-black tree using the sentinel byte at `+0x0d`.

2026-06-03 disassembly confirms `sub_525830` is the tree-header/sentinel allocator used by `MetaTable::MetaTable`: the constructor calls it at `0x00524656`, the helper allocates `0x34` bytes, points the first three links back to itself, and writes word `0x0101` at `+0x0c` for the header/sentinel flags.

2026-06-13 C001 `disasm` confirms the same tree-header allocation sequence directly: `sub_525830` pushes size `0x34`, calls `operator new`, stores the returned pointer into `+0x00/+0x04/+0x08`, writes `0x0101` at `+0x0c`, and returns. `disasm` also confirms `sub_525900` is a tiny cleanup thunk that pushes size `0x34`, passes the block argument to `sub_5C7526`, and returns with `retn 4`.
