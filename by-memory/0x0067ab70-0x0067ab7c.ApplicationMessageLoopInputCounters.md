# 0x0067ab70-0x0067ab7c ApplicationMessageLoopInputCounters

## Summary

- Address range: `0x0067ab70-0x0067ab7c`
- Entity kind: application message-loop counters and input accumulator
- Rebuild handling: source-declared/generated-binary global storage
- Disposition: reconstructable NexusTK application data
- Proposed owner: [UID:0000HG][Application](by-file/Application.md)

This split child covers the two message-loop counters and the mouse-wheel accumulator that belong with the application shell/window procedure. It is separated from the preceding heartbeat helper statics and the following `BackGroundPane` singleton slot because these three dwords are not owned by the dialog, BackPane, or TimerMgr modules.

## Layout

| --- | --- | --- | ---: | --- |
| `0x0067ab70-0x0067ab74` | `dword_67AB70` | `ff ff ff ff` | 3 | Message-loop counter that triggers periodic timer-skew checks. |
| `0x0067ab74-0x0067ab78` | `dword_67AB74` | `ff ff ff ff` | 3 | Message-loop throttle counter that periodically calls `Sleep(1)`. |
| `0x0067ab78-0x0067ab7c` | `dword_67AB78` | `ff ff ff ff` | 3 | Accumulated mouse-wheel delta before normalized event dispatch. |

## Evidence

- Live IDA MCP recheck on 2026-06-07 reported all three dwords initialized as `0xffffffff`.
- [UID:0002H2][0x00464cd0-0x00464e1f.ApplicationRunMessageLoop](by-memory/0x00464cd0-0x00464e1f.ApplicationRunMessageLoop.md) increments `dword_67AB74` at `0x00464cf8`, resets it after `Sleep(1)` at `0x00464d0a`, increments `dword_67AB70` at `0x00464d1a`, calls the heartbeat helper when the count exceeds `1000`, and resets it at `0x00464d2b`.
- `Main_WndProc` at `0x00465f20` uses `dword_67AB78` for `WM_MOUSEWHEEL`: it accumulates wheel delta at `0x004664c3`, waits until the absolute delta reaches `120`, preserves the modulo remainder at `0x004664fb`, and dispatches normalized wheel events through `sub_4A95A0`.
- Boundary check: predecessor `0x0067ab6c` is the heartbeat helper's timer-skew report latch; successor `0x0067ab7c` is the `BackGroundPane` singleton slot.

## Assignment Gate

Assigned to [UID:0000HG][Application](by-file/Application.md). The child clears the gate at `87/90` because the slots are exact and directly written by application message-loop/window-procedure code; the parent is already `86/90`.
