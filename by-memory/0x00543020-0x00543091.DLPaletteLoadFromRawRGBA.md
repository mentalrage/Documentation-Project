# 0x00543020-0x00543091 DLPalette::LoadFromRawRGBA

## Status

- Entity kind: `DLPalette` raw RGBA/BMP palette-loading method.
- Rebuild handling: `source-authored`.
- Intended direct owner/emitter: [UID:00003Z][DLPalette](by-class/DLPalette.md) `DLPalette`.
- Split source: [UID:0001E4][0x00542ac0-0x00543149.DLPaletteMethodCluster](by-memory/0x00542ac0-0x00543149.DLPaletteMethodCluster.md) `DLPaletteMethodCluster` accepted B008 implementation callback.

## Address Range

- Range: `0x00543020-0x00543091`, start inclusive and end exclusive.
- IDA function: `sub_543020`, size `0x71`.
- Predecessor/successor: follows existing [UID:0001E5][0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves](by-memory/0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves.md); followed by `0x00543091-0x005430a0` padding before `LoadFromBitmapPalette`.

## Behavior

`DLPalette::LoadFromRawRGBA` stamps a `DLPalette` header, sets header fields for a 256-entry palette with no entry/remap table, and converts 256 raw four-byte entries into the native mapped-color table through Surface-owned `SurfacePackPixelProc g_pfnPackPixel` at `0x0069b404`. Current BMP decoder evidence treats the source entries as BMP BGRA/RGBQUAD-style data. This four-byte route is not UID0004I4's compressed three-byte `RGBTRIPLE` format, although both call the same red/high, green/middle, blue/low pack callback.

## Raw Evidence

- B008 `decompile 0x00543020` shows `strcpy_s(..., "DLPalette")`, header field writes, a 256-entry loop over four-byte source entries, and callback `unk_69B404`.
- B008 `xrefs_to 0x00543020` found one code xref from the BMP decoder path documented by [UID:0002TM][0x004d09b0-0x004d0a8a.Decode8BitBmpToTileContext](by-memory/0x004d09b0-0x004d0a8a.Decode8BitBmpToTileContext.md).

## Ownership And Source Placement

The receiver and written state are `DLPalette`. The BMP decoder is a caller/producer of source data, not the owner of this loader.

## C++ Disposition
