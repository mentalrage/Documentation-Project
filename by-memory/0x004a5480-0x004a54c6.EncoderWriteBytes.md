## Behavior

Copies a caller-supplied byte span into the attached output buffer when valid and when capacity leaves room for the final terminator. On insufficient capacity, clears the valid/writable flag and performs no partial copy.

[UID:00013J][0x004a55c0-0x004a55de.EncoderInitialize](by-memory/0x004a55c0-0x004a55de.EncoderInitialize.md) is the attach/reset method that establishes `m_outputBuffer`, `m_capacity` / `m_outputCapacity`, and `m_writePos` before this method copies raw spans. It preserves `m_useBigEndian`; this method itself does not use byte order, but the scalar siblings in the same serialization stream do. B004's `Initialize` pass uses the same `m_capacity` and `m_isWritable` draft names this `WriteBytes` body already uses, while retaining the older aliases as descriptive layout synonyms.

Exact behavior:

- If valid/writable byte `+0x11` is zero, returns immediately without touching the buffer or cursor.
- Reads cursor `+0x0c`, computes `required = cursor + byteCount + 1`, and compares capacity `+0x08` against that required value with the signed compare shape seen in IDA/Ghidra.
- The extra byte is reserved for [UID:00013K][0x004a55e0-0x004a5621.EncoderFinalize](by-memory/0x004a55e0-0x004a5621.EncoderFinalize.md), which writes the trailing NUL. `WriteBytes` does not write that terminator itself.
- On overflow, writes zero to valid/writable byte `+0x11`, returns, and does not copy a partial span.
- On success, copies from caller `data` to `m_outputBuffer + m_writePos` through the resolved `GetMemoryMan`/MemoryMan copy-helper pair at `0x00516030`/`0x00516220`, then advances `m_writePos` by `byteCount`.
- The binary does not add null-buffer/source guards, clamping, buffer growth, allocation, or resize behavior.
