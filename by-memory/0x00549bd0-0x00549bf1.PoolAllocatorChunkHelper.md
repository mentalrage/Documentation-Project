# 0x00549bd0-0x00549bf1 PoolAllocator Chunk Helper

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: allocator-private helper function
- Likely owner: [UID:0000MM][PoolAllocator](by-file/PoolAllocator.md)
- Confidence: strong for behavior and owner

## Covered Range

| Range | Working name | Notes |
| --- | --- | --- |
| `0x00549bd0-0x00549bf1` | `AllocatePoolChunk` | Allocates one chunk, prepends it to the allocator chunk list, and returns the new chunk header. |

## Behavior

IDA decompilation shows a `__cdecl` helper with arguments equivalent to:

```cpp
PoolChunkHeader* AllocatePoolChunk(
    PoolChunkHeader** chunkListHead,
    int blocksPerChunk,
    int blockSize);
```

The helper allocates `blocksPerChunk * blockSize + 4` bytes, stores the previous `*chunkListHead` in the first word of the new allocation, updates `*chunkListHead`, and returns the new chunk.

The complementary chunk-list free helper is [UID:00023L][0x00549c00-0x00549c18.PoolAllocatorFreeChunkList](by-memory/0x00549c00-0x00549c18.PoolAllocatorFreeChunkList.md).

## Allocation Contract

| Field or value | Evidence-backed role |
| --- | --- |
| `chunkListHead` | Address of the allocator's `+0x08` chunk-list head, passed by `PoolAllocator::Allocate` before it links new free blocks. |
| `blocksPerChunk` | The fixed per-pool batch count stored by the constructor at allocator offset `+0x04`. |
| `blockSize` | The fixed per-pool block size stored by the constructor at allocator offset `+0x00`. |
| `blocksPerChunk * blockSize + 4` | Total allocation size, including the first dword used as the next-chunk link. |
| return value | Header pointer for the newly allocated chunk; the caller treats bytes after the first dword as the contiguous block payload area. |

## Evidence

- 2026-05-26 IDA MCP `lookup_funcs` reports `sub_549BD0` at `0x00549bd0` with size `0x21`.
- 2026-05-26 IDA MCP decompilation shows the allocation size expression, chunk-list prepend, and return value.
- IDA xrefs show one code caller at `0x004b1450` inside `PoolAllocator::Allocate` (`0x004b1400-0x004b14b7`).
- Active `source-3/simroot_v2/class_PoolAllocator.cpp` includes a synthetic `AllocatePoolChunk` helper, but it is not address-scoped with `NTK_ScopedInstall` and should not be treated as complete ownership metadata.
- [UID:0000MM][PoolAllocator](by-file/PoolAllocator.md) and [UID:0000AM][PoolAllocator](by-class/PoolAllocator.md) now document the allocator layout, `Allocate` caller, non-contiguous helper relationship, and static-pool consumers, giving this helper enough file-owner support for a direct parent attachment.
- The caller/callee relationship is one-way: this helper is only reached from the allocator allocate path, and the matching free helper is only reached from allocator destruction.

## Source-Structure Decision

Keep this helper with [UID:0000MM][PoolAllocator](by-file/PoolAllocator.md). It is not a general allocator API and currently has no callers outside the pool allocator allocate path.

The helper should be rebuilt as a file-local helper or private static utility near `PoolAllocator::Allocate`. It should not become a public allocator method unless later source-shape evidence proves the original declaration exposed chunk management.
