## Behavior

The constructor performs a true deep copy of one `DLPalette` into a newly constructed object:

1. Construct the `LObject` base and install the `DLPalette` vtable at `0x0062179c`.
2. Copy the fixed 32-byte palette header from source `+0x0c` to destination `+0x0c` as two 16-byte blocks.
3. Copy `m_paletteRangeCount` from source `+0x08` to destination `+0x08`.
4. If source `m_paletteRanges` at `+0x04` is non-null, perform checked allocation for `m_paletteRangeCount * 2` bytes, equivalent to `new DLPaletteRange[m_paletteRangeCount]`, then `memmove` exactly `sizeof(DLPaletteRange) * m_paletteRangeCount` bytes.
5. If source `m_paletteRanges` is null, store null in the destination.
6. Copy the fixed 512-byte `m_mappedColors[256]` table from source `+0x2c` to destination `+0x2c`.
7. Return `this` through the constructor ABI and `retn 4`; the source parameter is the sole consumed stack argument.

The two dynamic bytes per record are not an opaque byte buffer. [UID:0004I1][0x00542e60-0x00542f91.DLPaletteLoadFromStream](by-memory/0x00542e60-0x00542f91.DLPaletteLoadFromStream.md), [UID:0001E5][0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves](by-memory/0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves.md), and [UID:000201][0x00458590-0x00458610.EPFTileContextPixelRangeTest](by-memory/0x00458590-0x00458610.EPFTileContextPixelRangeTest.md) establish two inclusive endpoint bytes per logical record. The source-facing reconstruction therefore uses `DLPaletteRange`, `m_paletteRanges`, and `m_paletteRangeCount`.
