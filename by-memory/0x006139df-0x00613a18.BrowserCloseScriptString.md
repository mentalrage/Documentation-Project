# 0x006139df-0x00613a18 Browser Close Script String

## Summary

- Address range: `0x006139df-0x00613a18`
- Entity kind: project string literal / browser callback constant
- Disposition: reconstructable NexusTK project data
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong

This small `.rdata` gap is browser-owned string data. The first byte is the trailing zero terminator after the previous ASCII browser string, followed by the UTF-16 literal `javascript:window.close();` used by a browser control callback.

## Covered Data

| Address range | IDA evidence | Notes |
| --- | --- | --- |
| `0x006139df-0x006139e0` | raw byte `00` | Terminator/alignment byte after the preceding browser string. |
| `0x006139e0-0x00613a18` | IDA splits the UTF-16 string into `aJa_0` (`"ja"`) and `aPtWindowClose` (`"pt:window.close();"`) because of embedded zero bytes; raw bytes spell `javascript:window.close();` in UTF-16LE. | Browser script close-prefix literal. |

## Evidence

- IDA MCP byte review over `0x006139df-0x00613a18` reports raw bytes `00 6a 00 61 ... 3b 00 00 00 00`, which is the UTF-16LE string after the leading terminator.
- IDA xrefs show `0x006139e0` referenced at `0x0046c9a2` inside `sub_46C960`.
- IDA MCP decompilation of `sub_46C960` shows the function checks browser navigation text with `wcsstr(v9, aJa) == v9 || wcsstr(v9, aJa_0) == v9 || wcsstr(v9, aRe) == v9` and cancels/closes browser behavior through `g_activeBrowserPane` state.
