## Packed Clipboard Stream

`0x005951a0` and `0x00595250` form a pair. The serializer writes a byte-string first segment ending with a NUL byte, then optionally appends a four-byte payload length and payload bytes. The importer clears existing state, finds the NUL-terminated first segment, converts that segment with `MultiByteToWideChar(CP_ACP/0)`, and copies any valid trailing payload.

The exact length unit for `m_textLength` remains the only meaningful source-quality caveat:

- `SetText` allocates `length * 2`, supporting a UTF-16 code-unit count during normal in-memory text use.
- `BuildClipboardBlock` copies `m_textLength` bytes into the packed first segment before appending a NUL byte, supporting a byte-oriented serialized clipboard segment.
- Current best inference is that the in-memory class stores UTF-16 text for editor operations, while the packed clipboard helper intentionally treats the serialized first segment as byte-oriented custom clipboard data. The draft C++ preserves that ambiguity with `packedTextBytes = m_textLength` in `BuildClipboardBlock` rather than silently converting the field to only one unit system.
