## Evidence Notes

- IDA MCP `lookup_funcs` reports `0x0059ded0` as "Not a function", while disassembly at that address shows a complete constructor-shaped sequence ending with `retn 0Ch` at `0x0059df24`.
- IDA MCP decompilation of [UID:0002DZ][0x004214c0-0x004214c5.CheckBoxTextControlPaneGetControlType](by-memory/0x004214c0-0x004214c5.CheckBoxTextControlPaneGetControlType.md) returns constant `22`/`0x16`; the exact helper lives outside this `0x0059ded0-0x0059f0a4` range and is linked here only for class completeness.
- The constructor bytes call the base control constructor with argument `8`, store the checked byte at `+0x108`, copy the label into `+0x10a` with a `0x100` wide-character count, and install three `CheckBoxTextControlPane` vtable pointers.
- IDA recognizes `0x0059df30`, `0x0059df50`, `0x0059efeb`, `0x0059eff6`, and `0x0059f050` as separate functions.
- `0x0059ded0` has no direct code xrefs in the current IDB. The observed live construction path in [UID:0000A7][PartySearchEditPane](by-class/PartySearchEditPane.md) allocates `0x30c` bytes and inlines equivalent setup at `0x0059e22f-0x0059e265`.
- `PartySearchEditPane::OnAction` reads and toggles the checked byte at `+0x108` directly, then calls the control's repaint path through the vtable.
- 2026-05-26 IDA MCP vtable dump confirmed `CheckBoxTextControlPane` vtables at `0x0062e99c`, `0x0062ea04`, and `0x0062ea34`. The adjustor thunks in `0x0059efeb-0x0059f001` are now recorded as compiler-generated ignored ranges in [UID:0000VN][-ignored](by-memory/-ignored.md).

## Ownership Decision

Keep this range with reusable UI controls. Physical locality beside [UID:0000OZ][UserListDialogPane](by-file/UserListDialogPane.md) and `PartySearchEditPane` is not enough to move the generic checkbox/text control into `social/UserListDialogPane.cpp`; the layout, vtable, and label-buffer behavior describe a reusable control class.
