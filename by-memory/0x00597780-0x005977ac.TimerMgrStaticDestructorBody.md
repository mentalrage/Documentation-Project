## Boundary Correction

Earlier target/support docs used stale range `0x00597780-0x005977aa`. B002 MCP session `b880584f` corrects the body to `0x00597780-0x005977ac`. The instruction sequence includes the `pop esi` at `0x005977a6` and the tail `jmp sub_4F4A90` at `0x005977a7`; padding begins only at `0x005977ac`.

The body restores the `TimerMgr` vtable, ends the previously selected multimedia timer period with `timeEndPeriod(m_timerPeriod)`, destroys the embedded `TimerMgrTimerQueue`, clears [UID:0000SI][g_pTimerMgr](by-global/g_pTimerMgr.md), and transfers to the base `LObject` cleanup path.

## First-Draft C++ Decision

Formal C++ remains blank for this pass. The destructor semantics are well understood, but the raw order is sensitive: `timeEndPeriod`, embedded queue destruction, singleton clear, then base cleanup. A naive source body with `g_pTimerMgr = 0` inside a normal C++ destructor could produce a different ordering relative to compiler-generated member destruction. Until the `TimerMgr`/`TimerMgrTimerQueue` member-declaration and destructor source shape are settled together, this page should not emit a handwritten destructor body.
