# 0x0049ce50-0x0049d0c2 DATFileResolver InsertOrFindEntry

## Status

- Disposition: non-emitting old-MSVC/Dinkumware `stdext::hash_map` insert, duplicate-removal, and rehash lowering generated by `_DATFileMgr::EntryMap`.
- Owner/emitter/source route: none; the historical `DATFileResolver` method interpretation is superseded.
- Entity kind: compiler/template support body, not an authored resolver method.

## Range And Behavior

Live IDA MCP session `80de0a67` reports two xrefs: `_DATFileMgr::LoadDATFileIndex` at `0x0049ca54` and a recursive rehash call at `0x0049d061`. The resolver hashes each normalized wide name with `hash = ch + 5 * hash`, masks the bucket index with `m_bucketMask`, searches the selected bucket/list range, and returns an existing node with `inserted=false` when a duplicate is found.

For duplicate insertion, the newly created node is unlinked/freed before return. For new insertion, the node is linked into resolver state; the load factor triggers bucket growth by `*8` below `0x200` buckets and by `*2` above that, followed by bucket rebuild/reinsert behavior. Ranges `0x0049d0d0` and `0x0049d4f0` are cleanup/remove helpers reached from this body or EH edges and should not be split as public source APIs.
