## Behavior

The first helper is the MD5 `Encode` shape: it accepts destination bytes, source 32-bit words, and a byte count, then loops over four-byte groups and stores source bytes in little-endian order. The compiler has optimized the endian extraction into byte loads from the source dword array, so the body is mostly pointer stepping rather than explicit shifts.

The second helper is the MD5 `Decode` shape: it accepts destination words, source bytes, and a byte count, then loops over four-byte groups and combines `src[0]`, `src[1]`, `src[2]`, and `src[3]` into one little-endian dword with shift/or operations before storing it.

These helpers match the traditional MD5 `Encode`/`Decode` support functions even though this binary's active MD5 update/final/transform path appears to inline or otherwise avoid direct calls to these starts.
