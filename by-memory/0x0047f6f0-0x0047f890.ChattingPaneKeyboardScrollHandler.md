## Behavior

This method handles chat-display keyboard scrolling. It first checks an input event shape:

- event kind byte at `event + 0x04` must be `8`;
- key/status byte at `event + 0x10a` must be `4`;
- the key code is narrowed from `event + 0x08` using the status byte as the fallback/default.

Only four key-code cases are active in IDA's decompile:

- narrowed key value `0x81` scrolls one line upward, and `0x93` scrolls upward by the page-size virtual at slot `+0x50`;
- narrowed key value `0x83` scrolls one line downward, and `0x94` scrolls downward by the same page-size virtual;
- the upward cases read the current scroll value through `0x0055e950`, clamp at zero, and apply the new range through `0x0055eae0`;
- the downward cases read current and maximum scroll values through `0x0055e950` and `0x0055e910`, clamp at the maximum, and apply the new range through `0x0055eae0`;
- unmatched keys return `false`.

The decompiler shows a secondary-interface pointer adjustment before scroll-helper calls. Source reconstruction should express this as a normal `ChattingPane` input override that forwards to the inherited scroll API, not pointer arithmetic.
