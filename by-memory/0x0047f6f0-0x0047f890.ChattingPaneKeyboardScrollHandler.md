## Behavior

This method handles chat-display keyboard scrolling. It first checks an input event shape:

- event kind byte at `event + 0x04` must be `8`;
- key/status byte at `event + 0x10a` must be `4`;
- key code is narrowed from `event + 0x08` / `event + 0x10a`.

Only four key-code cases are active in IDA's decompile:

- one-step/page-up style cases read the current scroll value through `0x0055e950`, reduce it by either `1` or the pane page size from vtable slot `+0x50`, clamp to zero, and call `0x0055eae0`;
- one-step/page-down style cases read the current and maximum scroll values through `0x0055e950` and `0x0055e910`, increase by either `1` or page size, clamp to max, and call `0x0055eae0`;
- unmatched keys return `false`.

The decompiler shows `this - 40` before scroll-helper calls because this is reached through a secondary vtable view. Source reconstruction should express this as a normal `ChattingPane` input override, not pointer arithmetic.
