## Behavior

This method handles chat-display keyboard scrolling. It first checks an input event shape:

- event kind byte at `event + 0x04` must be `8`;
- key/status byte at `event + 0x10a` must be `4`;
- the key code is narrowed from `event + 0x08` using the status byte as the fallback/default.

Only four key-code cases are active in IDA's decompile:

- narrowed signed key value `-127` / byte `0x81` scrolls one line upward, and `-109` / byte `0x93` scrolls upward by the page-size virtual at slot `+0x50`;
- narrowed signed key value `-125` / byte `0x83` scrolls one line downward, and `-108` / byte `0x94` scrolls downward by the same page-size virtual;
- the upward cases read the current scroll value through `0x0055e950`, clamp at zero, and apply the target through `0x0055eae0`;
- the downward cases read current and maximum scroll values through `0x0055e950` and `0x0055e910`, clamp at the maximum, and apply the target through `0x0055eae0`;
- unmatched keys return `false`.

The narrowed key bytes are not raw Win32 virtual-key constants. Win32 `VK_PRIOR`, `VK_NEXT`, `VK_UP`, and `VK_DOWN` are `0x21`, `0x22`, `0x26`, and `0x28`; this handler instead receives the client input layer's extended/narrowed symbols `0x81`, `0x83`, `0x93`, and `0x94`.

`0x0055e950` is the inherited `ScrollablePane` selected-child current/offset getter, source-facing `GetScrollPosition(axis)`. `0x0055e910` is the selected-child target/range getter, source-facing `GetScrollMax(axis)` / `GetScrollRange(axis)`, with `GetScrollMax` preferred for consistency with adjacent accepted Chatting drafts. Primary-vtable slot `+0x50` is canonically `GetPageSize(axis)`; the older class-local `GetScrollPageStep` spelling is superseded history. `0x0055eae0` is the apply helper, source-facing `ApplyScrollPosition(axis, oldPosition, targetPosition)`: its observed signature is `(__int128 *this, char axis, unsigned short old, unsigned short target)`, it no-ops when `old == target`, updates the child offset at `+0xfe`, calls virtual slot `+0x5c` / `GetScrollDelta` with old before target, and refreshes/clips content/render regions. Older local draft names such as `SetScrollRange` are role aliases for this apply helper, not exact final names.

The decompiler shows a secondary-interface pointer adjustment, equivalent to `this - 0xa0`, before scroll-helper calls. Source reconstruction should express this as a normal `ChattingPane` input override that forwards to inherited `ScrollablePane` methods, not pointer arithmetic.
