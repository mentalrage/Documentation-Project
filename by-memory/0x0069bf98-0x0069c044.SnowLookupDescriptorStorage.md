## Covered Ranges

| Range | Proposed name | Notes |

| `0x0069bf98-0x0069bfe8` | `g_snowLookupTables` | Two 40-byte `SnowPatternDescriptor` records used by `RenderSnowParticles`. |

## Evidence

- IDA MCP `py_eval` confirms refs from `SnowingLayerPane::RenderSnowParticles` at `0x005c20e0` to descriptor fields under `0x0069bf98-0x0069bfe8` and the guard at `0x0069bfe8`.
- IDA MCP `py_eval` confirms refs from `SnowingLayerPane::UpdateAndRenderSnowParticles` at `0x005c1c80` to descriptor fields under `0x0069bff0-0x0069c040` and the guard at `0x0069c040`.
- 2026-05-31 IDA MCP `xrefs_to` confirms direct descriptor/guard refs from `0x005c20e0` and `0x005c1c80`, plus `_Init_thread_*` guard refs in compiler-generated initialization paths.
- 2026-05-31 IDA MCP `decompile` confirms both descriptor sets are initialized by loops over two records, each advancing `10` dwords, matching the 40-byte descriptor layout.
- 2026-05-31 IDA MCP `get_bytes` shows this `.data` storage is initialized to `0xff` bytes before runtime guard/descriptor initialization.
- Current `source-3/simroot_v2/class_SnowingLayerPane.cpp` reconstructs each descriptor as a 40-byte `SnowLookupEntry` and initializes two entries per descriptor set.
- The guarded initialization writes pattern pointers to [UID:0001OO][0x00670784-0x006707d0.SnowPatternByteTables](by-memory/0x00670784-0x006707d0.SnowPatternByteTables.md), frame counts `4` and `3`, and small source rectangles.
