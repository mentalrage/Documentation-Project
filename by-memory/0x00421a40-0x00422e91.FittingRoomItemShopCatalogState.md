# FittingRoom Item-Shop Catalog State `0x00421a40-0x00422e91`

## Status

- Confidence: strong for fitting-room item-shop catalog ownership; medium for exact original source split.
- Proposed owner: [UID:0000JE][FittingRoom](by-file/FittingRoom.md), with [UID:0000KD][ItemCatalog](by-file/ItemCatalog.md) as an optional split.
- Disposition: reconstructable NexusTK product code that consumes third-party [UID:0000KI][JsonCpp](by-file/JsonCpp.md).
- Evidence basis: `simroot_v2` generated source, read-only IDA MCP lookup/caller/callee/string/xref checks on 2026-05-25, and existing fitting-room docs. `wave3.py` was not executed for this pass.

## Range Role

This range owns fitting-room item-shop cache and catalog state, not JsonCpp itself. It constructs and decodes the local `ItemShop.jbn` cache, parses the item-shop document through JsonCpp helpers, loads one named item category at a time, and exposes the embedded [UID:0000KD][ItemCatalog](by-file/ItemCatalog.md) count/lookup API used by the fitting-room list pane.

The product/third-party boundary is:

- product-owned cache, category keys, item-entry parsing, vectors, and lookup storage live in this range;
- JsonCpp document/value parsing helpers such as `0x004298f0`, `0x00429b30`, `0x004278e0`, `0x00427500`, and `0x00426ea0` are library dependencies, not fitting-room-owned code. See [UID:0000WY][0x00424630-0x00428b4b.JsonCppValueCore](by-memory/0x00424630-0x00428b4b.JsonCppValueCore.md) and [UID:0000X0][0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds](by-memory/0x004298f0-0x0042acdf.JsonCppDocumentParseFrontEnds.md).

## JsonCpp Handoff

IDA callee checks show `0x00422740` calls:

- `0x004298f0` to construct the JsonCpp document-like object;
- `0x00429b30` to parse the source buffer into a root value;
- `0x004278e0` to look up the `version` field;
- `0x00425ac0` to extract/copy the parsed version/header value;
- `0x00422ba0` to load category arrays from the parsed root;
- `0x0041b350`, `0x0041b300`, and `0x00425200` to destroy JsonCpp values/documents/paths.

IDA callee checks show `0x00422ba0` calls:

- `0x004278e0` to look up each category field;
- `0x00426ea0` to read the array count;
- `0x00427500` and `0x00425010` to copy each array element value;
- `0x00421a40` to translate each parsed item value into fitting-room item-entry storage;
- fitting-room-owned vector/list helpers at `0x00420de0`, `0x00421290`, `0x00423000`, and `0x00423470`.

## Evidence

- Active `simroot_v2/class_FittingRoomDialogItemState.cpp` emits the constructor, cache load/save, transform, and category loader source in this range.
- IDA MCP confirms modeled function starts and end-exclusive ranges for the normal IDA functions listed in the covered range table.
- IDA MCP byte/head review confirms the raw `0x00422920-0x004229ef` cache-path builder, which IDA decodes as code but has not promoted to a function record.
- IDA MCP byte/head review confirms `0x00422e94-0x00422ec0` is `jpt_422BD7`, the compiler-emitted switch table for `0x00422ba0`.
- IDA MCP caller checks show `0x00422740` is called from the constructor at `0x00422020`, fitting-room dialog command/update code at `0x0041cb70`, and two local file-buffer helpers at `0x004229f0` and `0x00422ec0`.
- IDA MCP caller checks show `0x00422ba0` is called by `0x00422740`, and `0x00421a40` is called by `0x00422ba0`.
- IDA MCP xrefs tie category key strings only to `0x00422ba0`, and tie encode/decode key strings only to `0x00422020`.
- `0x004298f0` and `0x00429b30` are also called by `DownloadCashShopVersion_41AA00`, proving the item-shop version/catalog path shares JsonCpp parsing support.

## Ownership Decision

Keep this range with [UID:0000JE][FittingRoom](by-file/FittingRoom.md) / [UID:000051][FittingRoomDialogItemState](by-class/FittingRoomDialogItemState.md). [UID:0000KD][ItemCatalog](by-file/ItemCatalog.md) may remain a separate small source file if final project layout favors a catalog helper split, but it is embedded fitting-room catalog state rather than a global item database.

Keep JsonCpp helpers under [UID:0000KI][JsonCpp](by-file/JsonCpp.md) / `third_party/jsoncpp/`. Do not migrate `0x004298f0`, `0x00429b30`, `0x004278e0`, `0x00427500`, or `0x00426ea0` into `FittingRoom.cpp` just because this feature consumes them.

## Open Questions

- Whether the final source tree should keep `ItemCatalog.cpp` separate or fold its two lookup methods into `FittingRoom.cpp`.
