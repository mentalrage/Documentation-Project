## B002 Source-Quality Reanalysis

B002's 2026-06-18 report resolves the prior open questions that kept this target at `84/88`:

- Range/split: keep [UID:000168] as one exact source-bearing function. The helper calls are already documented elsewhere, the security-cookie setup/teardown belongs to this compiled body, and the four line dispatches are one coherent frame-drawing operation.
- Owner/source route: choose [UID:00005V][GrafPort](by-class/GrafPort.md) as direct class owner and [UID:0000JR][GrafPort](by-file/GrafPort.md) as generated source file. Reject [UID:0000OC][Surface](by-file/Surface.md), [UID:000167][0x004ba250-0x004ba444.SurfaceSpriteBlitHelper](by-memory/0x004ba250-0x004ba444.SurfaceSpriteBlitHelper.md) adjacency, and pane/feature owners such as `RankingEventListPane`.
- Receiver/signature: `GrafPort::DrawRectFrame(const RectBounds *rect)` is the best current source-facing signature. `ecx` is the receiver, `[ebp+8]` is the single explicit pointer argument, and `ret 4` proves a one-argument `__thiscall` method.
- Rectangle semantics: the input is a four-int `left/top/right/bottom` block. `IntersectRects` and `IsRectEmptyOrInvalid` use a stack copy only to decide visibility; drawing still uses the original caller rectangle. Right/bottom are exclusive bounds, so endpoint deltas subtract one.
- Callback sequence: the helper seeds the draw cursor to `(rect->left, rect->top)` and dispatches four deltas through `dword_69B3E4`: top edge `(right - left - 1, 0)`, right edge `(right - currentX - 1, bottom - currentY - 1)`, bottom edge `(left - currentX, bottom - currentY - 1)`, and left edge `(left - currentX, top - currentY)`. The second through fourth deltas intentionally subtract the live cursor because the line callback advances current draw position.
- Field naming: `this+0x6c` is `m_currentX`, `this+0x68` is `m_currentY`, and `this+0x71` is best named `m_drawEnabled`. Swapping X/Y is rejected by [UID:000162][0x004b95e0-0x004b969f.GrafPortDrawStateAccessors](by-memory/0x004b95e0-0x004b969f.GrafPortDrawStateAccessors.md) and [UID:000165][0x004b9820-0x004ba24a.SurfacePaintHelpers](by-memory/0x004b9820-0x004ba24a.SurfacePaintHelpers.md) `LineTo`.
- Callback naming: `g_pfnDrawLineDelta` / `DrawLineDelta` is a strong descriptive name for `dword_69B3E4`. `DrawRectFrameCallback` is rejected because the same slot is used by `LineTo`; `SurfaceSpriteBlit` naming is rejected because slot `0x0069b3e4` is line-delta, while [UID:000167][0x004ba250-0x004ba444.SurfaceSpriteBlitHelper](by-memory/0x004ba250-0x004ba444.SurfaceSpriteBlitHelper.md) uses sprite/blit slot `0x0069b3e8`.
- Remaining uncertainty: exact original spelling of `RectBounds` versus `RECT`, `m_drawEnabled`, and the line-callback wrapper is not proven. This caps confidence below final-source certainty but does not block owner correction, support updates, score lift, or first-draft C++.
