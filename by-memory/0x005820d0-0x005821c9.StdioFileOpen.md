# 0x005820d0-0x005821c9 StdioFileOpen

## Status

- Confidence: strong for body and file-size cache behavior.
- Covered file/module: [UID:0000O9][StdioFile](by-file/StdioFile.md)
- Current generated issue: active `source-3/simroot_v2/class_StdioFile.cpp` uses placeholder `statBuffer_size`.

## Covered Range

| Range | Function | Notes |
| --- | --- | --- |
| `0x005820d0-0x005821c9` | `StdioFile::Open` | Stats a wide path, opens it in binary-read mode, caches `FILE*` at object offset `+4`, caches file size at `+8`, and throws `FileError` on stat/open failure. |

## IDA MCP Evidence

Checked on 2026-05-25 and 2026-05-26:

- `lookup_funcs 0x005820d0` reports a real function with size `0xf9`.
- `decompile 0x005820d0` calls imported `_wstat64i32` through [UID:0000TQ][WideApiDispatchTable](by-global/WideApiDispatchTable.md) entry `dword_69BE18(path, statBuffer)` and throws `FileError` when it returns `-1`.
- The successful path calls imported `_wfopen` through dispatch entry `dword_69BE14(path, L"rb")`, stores the returned handle to `this[1]`, copies the local stat-buffer size field to `this[2]`, and returns the handle.
- If `_wfopen` fails after `_wstat` succeeds, the function throws `FileError` for the same path.
- `xrefs_to 0x0069be14` and `xrefs_to 0x0069be18` show both entries are written by [UID:0000WD][0x0041a280-0x0041a4a8.WideApiDispatchInit](by-memory/0x0041a280-0x0041a4a8.WideApiDispatchInit.md), not by `StdioFile`.
- 2026-05-26 IDA MCP `callers 0x005820d0` reports direct callers at `0x004f5453`, `0x004f5799`, `0x004f6877`, and `0x00504cb4`, matching loose-file readers and the Miles callback bridge rather than a caller-specific owner.

## Generated Data Caveat

The generated placeholder `statBuffer_size` is not a separate global or unknown runtime value. It is the file-size field from the stack-local `_wstat` buffer copied into `StdioFile::m_size` at object offset `+8`.
