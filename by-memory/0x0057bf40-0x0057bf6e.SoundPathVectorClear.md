# 0x0057bf40-0x0057bf6e SoundPathVector Clear

## Status

- Confidence: strong for behavior and audio ownership.
- Entity kind: vector clear helper.
- Proposed owner: [UID:0000DI][SoundPathVector](by-class/SoundPathVector.md) as a helper used by [UID:0000NV][SoundManager](by-file/SoundManager.md).

## Behavior

This helper destroys the current string/path entries in a three-pointer vector and resets `end` back to `begin`.

IDA MCP decompilation shows:

- Reads `begin` and `end`.
- If the vector is already empty, writes `end = begin`.
- Otherwise walks entries from `begin` to `end`, destroying each entry through `0x00582b30`.
- Stores `end = begin` and returns the begin pointer.

## Caller Evidence

IDA MCP callers:

- `0x00579f9a` from `SoundManager::PlayTrackByIndex`-style logic after invalidating cached playlist/track filename state.
- `0x0057a214` from `SoundManager::PlayMusicByZone`-style logic when falling back from `.LST`/`.LSR` playlist files to a direct `%08d.MP3` path.

Both callers pass `SoundManager +0x109c`, matching the documented audio path-vector storage family.

2026-05-26 recheck: IDA MCP callers remain `0x00579f9a` and `0x0057a214`, and current `simroot_v2` still has no active `.cpp` body for `0x0057bf40`.
