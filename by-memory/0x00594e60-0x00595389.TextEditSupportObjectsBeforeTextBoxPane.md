## Compiler-Generated And Open-Question Closure

- `0x00594ea0` is not a scalar deleting destructor. It is the ordinary non-deleting `TextEditObject` destructor body.
- `0x00594f70` is not a scalar deleting destructor. It is the ordinary non-deleting `TextEditScrap` destructor body with real owned-buffer cleanup.
- `TextEditScrap` scalar deleting destructor remains in sibling [UID:0003M8][0x005954c0-0x00595760.TextEditSupportObjectsAfterTextBoxPane](by-memory/0x005954c0-0x00595760.TextEditSupportObjectsAfterTextBoxPane.md).
- `0x00595030` is real code and best named `TextEditScrap::IsEmpty`, not padding and not a generic `sub_`.
- `0x005951a0` is a `TextEditScrap` packed clipboard block builder, not a generic memory helper.
- `0x00595250` is a packed clipboard importer/converter, not just a generic string helper.
- The exact product names for the two `TextEditObject` no-op virtual hooks remain unresolved. They are documented and emitted in the child as provisional source-empty virtuals (`OnUpdate`, `OnAction`) rather than left as `nullsub`/`sub` names.
- `m_textLength` has a documented length-unit caveat: normal text storage behaves like a UTF-16 code-unit count, while the packed clipboard block copies the first segment as byte-oriented custom clipboard data. The child C++ preserves that ambiguity rather than forcing a false final answer.
