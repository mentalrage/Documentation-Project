# 0x0041b6d0-0x0041b9a0 MSVC String Support Helpers

## Status

- Disposition: ignored for NexusTK source reconstruction
- Entity kind: MSVC/Dinkumware `std::string` helper island
- Current IDA names: `sub_41B6D0`, `sub_41B6E0`, `sub_41B740`, `sub_41B8B0`
- Confidence: strong for runtime/library ownership.

## Covered Range

| Range | IDA name | Role |
| --- | --- | --- |
| `0x0041b6d0-0x0041b6da` | `sub_41B6D0` | Throws/reports `"string too long"` through a runtime exception helper. |
| `0x0041b6e0-0x0041b731` | `sub_41B6E0` | Allocates small/large string storage, including the MSVC aligned-large-allocation header path. |
| `0x0041b740-0x0041b8a6` | `sub_41B740` | Appends one small-string-layout buffer to another with capacity growth and free of old backing storage. |
| `0x0041b8b0-0x0041b99b` | `sub_41B8B0` | Assigns/copies external bytes into a small-string-layout buffer with capacity growth. |
| `0x0041b99b-0x0041b9a0` | alignment | `0xcc` alignment before CRT stdio option accessor. |

## Evidence

- IDA MCP decompilation of `0x0041b6d0` calls the runtime error path with literal `"string too long"`.
- `0x0041b6e0` calls `operator new`, uses a `0x1000` threshold, aligns large allocations to `0x20`, and stores the original allocation pointer immediately before the aligned result.
- `0x0041b740` and `0x0041b8b0` operate on the classic MSVC small-string layout: inline storage when capacity is below `0x10`, length at slot `+0x10`, capacity at slot `+0x14`, capacity growth with `| 0x0f`, `0x7fffffff` length guards, and invalid-parameter checks before freeing large allocations.
- Direct callers include fitting-room/cash-shop string handling (`0x0041ac4d`, `0x0041b02d`, `0x0041ab30`, `0x0041ac37`, `0x0041ada7`, `0x0041b017`) plus many later project consumers, which is consistent with compiler/library support rather than a NexusTK-owned feature helper.

## Reconstruction Notes

Ignore this island as handwritten NexusTK source. Rebuilt source should use the compiler/runtime `std::string` implementation rather than carrying these functions as project utilities.
