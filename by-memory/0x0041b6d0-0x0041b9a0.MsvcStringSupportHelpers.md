## Evidence

- 2026-06-05 IDA MCP refresh confirms modeled functions at `0x0041b6d0` (`sub_41B6D0`, size `0x0a`), `0x0041b6e0` (`sub_41B6E0`, size `0x51`), `0x0041b740` (`sub_41B740`, size `0x166`), and `0x0041b8b0` (`sub_41B8B0`, size `0xeb`).
- IDA MCP byte audit reports only `0xcc` padding in all inter-function gaps: `0x0041b6da-0x0041b6e0`, `0x0041b731-0x0041b740`, `0x0041b8a6-0x0041b8b0`, and `0x0041b99b-0x0041b9a0`.
- IDA MCP decompilation of `0x0041b6d0` calls the runtime error path with literal `"string too long"`.
- `0x0041b6e0` calls `operator new`, uses a `0x1000` threshold, aligns large allocations to `0x20`, stores the original allocation pointer immediately before the aligned result, and calls `__invalid_parameter_noinfo_noreturn` on the large-allocation null result path.
- `0x0041b740` and `0x0041b8b0` operate on the classic MSVC small-string layout: inline storage when capacity is below `0x10`, length at slot `+0x10`, capacity at slot `+0x14`, capacity growth with `| 0x0f`, `0x7fffffff` length guards, and invalid-parameter checks before freeing large allocations.
- B010 2026-06-19 source-routing reanalysis ties [UID:0002CZ][0x0041d3b0-0x0041d431.SmallStringStorageAssign](by-memory/0x0041d3b0-0x0041d431.SmallStringStorageAssign.md) to this same SSO-15 byte-string support family: `0002CZ` copy-constructs a 24-byte object, allocates heap storage through this page's `0x0041b6e0` helper for non-inline strings, and has FittingRoom/JsonCpp/runtime caller spread that rejects product owner routes.
- IDA MCP callees match runtime support: `sub_41B6E0`, `sub_41B6D0`, `sub_5C7526`, `_memmove_0`, `_memmove`, `operator new`, and `__invalid_parameter_noinfo_noreturn`.
- Direct callers include fitting-room/cash-shop string handling (`0x0041ac4d`, `0x0041b02d`, `0x0041ab30`, `0x0041ac37`, `0x0041ada7`, `0x0041b017`) plus many later JsonCpp/LodePNG/curl-facing consumers, which is consistent with compiler/library support rather than a NexusTK-owned feature helper.
