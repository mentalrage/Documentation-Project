## Behavior

`BrowserControlPaneOldDispatch` is the old-pane unhandled-message fallback bridge. It is called only from `BrowserControlPaneOld::HandleBrowserMessage` and tail-forwards the already-pushed message argument through the saved previous `MSGHandler` target stored in the message-handler subobject at slot `+4`. The body is behavior-identical to [UID:0001CN][0x00528d60-0x00528e55.MSGHandler](by-memory/0x00528d60-0x00528e55.MSGHandler.md) dispatch forwarder `0x00528dd0`, but it is a separate BrowserControlPaneOld-path helper with its own callsite. It does not dispatch through the Browser object pointer at outer `BrowserControlPaneOld + 0x110`.

B011 destructor/source-quality sync resolves the class layout for this helper: `MSGHandler` is a secondary base at outer `+0x108`; `MSGHandler::m_previousHandler` is therefore outer `+0x10c`; and the Browser object pointer remains `m_browser` at outer `+0x110`.

The earlier generated/simroot `DispatchToBrowser` interpretation is retained only as a historical rejected lead. The bridge does not dereference the Browser object; the operand at subobject slot `+4` is the saved previous `MSGHandler` target returned by `Application::ExchangeMSGHandler`, while the Browser pointer is one slot later at subobject `+8` / outer `+0x110`. For [UID:00032U][0x0046f310-0x0046f47b.BrowserControlPaneOldHandleBrowserMessage](by-memory/0x0046f310-0x0046f47b.BrowserControlPaneOldHandleBrowserMessage.md), the accepted inferred dependency spelling is `DispatchToPreviousHandler(message)`.
