IDA reports `sub_456A90` at `0x00456a90` with size `0x60e`, giving end-exclusive range `0x0045709e`. The next method, `GetVersionString`, starts at `0x004570a0`; the two bytes between are alignment.

## Behavior

The method receives a version string, a mutable hash-list text buffer, and a boolean persistence flag.

- Copies the incoming version string into the manager's current-version buffer at object offset `+0x04` using `wcscpy_s(..., 0x21, ...)`.
- When persistence is requested, builds `%APPDATA%\NexusTK`, `%APPDATA%\NexusTK\MiniMap`, and `%APPDATA%\NexusTK\MiniMap\mnmhs.hs`, opens the hash-cache file, writes a one-byte version-string length, writes the version string, then writes the hash-list text.
- Tokenizes the hash-list text with `wcstok(..., L"/", ...)`.
- For each slash-delimited token, searches for a comma delimiter separating the numeric map key from the stored version/hash text.
- Parses the left side through the runtime wide-number conversion helper.
- Hashes the four-byte key using the same FNV-1a-style bucket mask used by [UID:0000XX][0x00457580-0x00457613.DATIndexVectorFindNodeByKey](by-memory/0x00457580-0x00457613.DATIndexVectorFindNodeByKey.md).
- If a node already exists for the key, copies up to 32 wide characters from the right side of the comma into the existing node's `versionText` buffer at node offset `+0x0c`.
- If no node exists, allocates a 66-byte wide-character buffer, copies the same capped right-side text into it, packages `{ key, versionText }`, creates a linked-list node through [UID:0000XR][0x004570e0-0x004570ff.CreateListNodeWithPayload](by-memory/0x004570e0-0x004570ff.CreateListNodeWithPayload.md), increments the manager list count at `+0x50`, links the node, and inserts it into the embedded [UID:0000IP][DATIndexVector](by-file/DATIndexVector.md) at object offset `+0x48` through [UID:0000XS][0x00457100-0x0045730f.DATIndexVectorInsertNode](by-memory/0x00457100-0x0045730f.DATIndexVectorInsertNode.md).

## Layout Evidence

This method directly supports the current [UID:0001V8][MiniMapVersionNode](by-type/by-struct/MiniMapVersionNode.md) layout:

```text
+0x00  next pointer
+0x04  prev pointer
+0x08  32-bit map/version key
+0x0c  wchar_t* version/hash text buffer
```

The two payload dwords passed to `CreateListNodeWithPayload` are the parsed numeric key and the allocated `wchar_t*` text buffer. The existing-node path updates `node[3]`, and the lookup helper at [UID:0000XQ][0x004570b0-0x004570e0.MiniMapVersionLookupByMapId](by-memory/0x004570b0-0x004570e0.MiniMapVersionLookupByMapId.md) returns the dword at `node + 0x0c`, confirming that payload slot as the string pointer.

## Ownership

Keep this method with `MiniMapVersionManager`. It owns the current version string and the map-id-to-version lookup state. `StartupWindow` supplies downloaded update text and `MiniMapRenderer` consumes lookups, but neither subsystem owns the persistence/indexing logic.

The list-node allocation and DAT-index insertion helpers are dependencies. Do not move [UID:0000XR][0x004570e0-0x004570ff.CreateListNodeWithPayload](by-memory/0x004570e0-0x004570ff.CreateListNodeWithPayload.md), [UID:0000XS][0x00457100-0x0045730f.DATIndexVectorInsertNode](by-memory/0x00457100-0x0045730f.DATIndexVectorInsertNode.md), or [UID:0000XX][0x00457580-0x00457613.DATIndexVectorFindNodeByKey](by-memory/0x00457580-0x00457613.DATIndexVectorFindNodeByKey.md) into the minimap source file.
