# 0x0066d468-0x0066d47c Command-Line and Config String Pointers

## Summary

- Address range: `0x0066d468-0x0066d47c`
- Entity kind: initialized pointer table
- Disposition: reconstructable project data
- Rebuild handling: source-declared static pointer data
- Parent: [UID:0000N4][RegistryConfig](by-file/RegistryConfig.md)
- Confidence: strong for command-line/config parser ownership and the five-slot layout; capped below final because one adjacent process-name pointer has no direct code xref.

This small pointer table contains writable `.data` pointers to read-only strings used by startup, configuration, and command-line parsing helpers.

## Evidence

- 2026-06-05 live IDA byte scan gives table bytes `3c 69 61 00 d8 78 61 00 ec 78 61 00 4c 79 61 00 54 79 61 00`, i.e. five `.data` dwords pointing to `.rdata` addresses `0x0061693c`, `0x006178d8`, `0x006178ec`, `0x0061794c`, and `0x00617954`.
- Target strings decode as wide strings: `이 버전의 바람의 나라는 유니텔 전용입니다.`, `mscfg.dll`, `grcframe.exe`, `"/ \t"`, and `이 버전의 바람의 나라는 HITEL2000 전용입니다.`.
- Slot xrefs: `0x0066d468` is read at raw address `0x0048f6a3`; `0x0066d46c` is read at `0x00493d0c` in `sub_4926A0`; `0x0066d474` is read at `0x00491969`, `0x004919d1`, and `0x00491a3d` in `sub_4918E0`; `0x0066d478` is read at `0x0049195b`, `0x004919c3`, and `0x00491a2f` in `sub_4918E0`.
- No direct code xref to the `0x0066d470` slot was found in the live xref scan; only the slot-to-target data xref to `0x006178ec` is present, so that process-name role remains a confidence cap.
- The raw startup parser tail at `0x0048f6a3` pushes `off_66D468`, funnels it through `sub_4673E0`/`sub_4651D0`, calls `MessageBoxW`, then posts quit and calls `__loaddll`, confirming the first pointer is a Unitel-only startup alert string.
- `sub_4918E0` checks structured command-line tokens including `/portno:` and repeatedly pushes `lpText` on missing-token paths while using `off_66D474` as the `"/ \t"` delimiter.
- Neighbor bytes confirm the range split: `0x0066d458-0x0066d468` ends the previous browser URL escape character set, and `0x0066d47c` begins the checksum lookup table data.
