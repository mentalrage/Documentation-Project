## Behavior Evidence

- `ReleaseMidiStreamBuffers` unprepares two stream headers when `g_midiHeadersPrepared` is set, clears the flag, and frees any two backing global-memory buffers.
- `SendMidiChannelVolume` sends one channel-volume controller 7 message when the stream is running; no caller route was found.
- `MidiPlayer::MidiPlayer` initializes `g_pMidiPlayer`, `m_playbackEnabled`, `m_selectedTrackId`, WinMM globals, `g_midiVolumeScale = 500`, and the event named `L"Wait For Buffer Return"`.
- `MidiPlayer::~MidiPlayer` resets with skip-reopen when a stream exists, releases buffers, closes stream/event handles, and clears `g_pMidiPlayer`.
- `CreateMidiBufferReturnEvent`, `OpenMidiStreamCallbackOnly`, and `CloseMidiStreamResources` are raw local helpers. Current UID00041K evidence shows the event helper calls `g_pfnCreateEventW` at Wide API dispatch slot `0x0069be3c`, the stream-open helper passes [UID:0001CG][0x00525be0-0x00525dbb.MidiStreamCallback](by-memory/0x00525be0-0x00525dbb.MidiStreamCallback.md) as callback and sets `g_midiCallbackStreamOpen` at `0x0069b51c`, and the close helper resets/releases/closes stream resources before `CloseHandle(g_hMidiBufferEvent)`.
- `ApplyMidiVolume` sends controller 7 volume messages for 16 channels. Current UID00041K evidence resolves it as `__stdcall`: IDA reports `void __stdcall(int)`, the body returns with `retn 4`, raw volume callers do not clean the stack, and it intentionally computes sends from the old global `g_midiVolumeScale` before storing the incoming argument only after all sends succeed.
- `IncreaseMidiVolume` and `DecreaseMidiVolume` are raw class-shaped methods that adjust the global scale by 100 when playback is enabled and the scale is within bounds.
- `IsPlaybackEnabled`, `EnableMidiPlayback`, and `DisableMidiPlayback` use `m_playbackEnabled`; enable/disable write `g_pConfig + 0x28de50`, represented as inferred `m_musicEnabled`, not [UID:0001CH][0x00526100-0x00526332.MidiPlayerTrackSelectionHelpers](by-memory/0x00526100-0x00526332.MidiPlayerTrackSelectionHelpers.md)'s `g_pConfig + 0x84c` selector enable.
- `StopPlayback` clears `m_selectedTrackId` and calls `MidiPlayer_ResetStream(0)`.
- `OpenSelectedMidiFileNoRestart`, `ToggleMidiStreamPause`, and `RestartSelectedMidiStream` are raw stream-control helpers; they are distinct from [UID:0001CH][0x00526100-0x00526332.MidiPlayerTrackSelectionHelpers](by-memory/0x00526100-0x00526332.MidiPlayerTrackSelectionHelpers.md) `StartSelectedMidiFile`.
- `MidiPlayer_ResetStream` stops/resets the WinMM stream, waits on the buffer-return event, releases document/buffer/stream state, and optionally reopens/primes unless flag `0x10000` is set.
- The `0x00526570-0x0052664b` tail is compiler cleanup: constructor EH singleton clear plus MSVC scalar deleting destructor glue. It should not emit human source C++.
