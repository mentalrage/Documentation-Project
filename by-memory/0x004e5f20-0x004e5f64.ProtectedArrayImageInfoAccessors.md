# 0x004e5f20-0x004e5f64 ProtectedArray Image-Info Accessors

## Status

- Confidence: strong for function boundaries and behavior.
- Source-level owner: [UID:0000MU][ProtectedArray](by-file/ProtectedArray.md)

## Functions

| Range | Function | Notes |
| --- | --- | --- |
| `0x004e5f20-0x004e5f3f` | `ProtectedArray<HairInfo>::GetAtOrDefault(int index)` | Returns `entries + 0x10 * index` when in range, otherwise `this + 0x10`. |
| `0x004e5f40-0x004e5f64` | `ProtectedArray<Acc2Info>::GetAtOrDefault(int index)` | Returns `entries + 0x14 * index` when in range, otherwise `this + 0x10`. |

Both methods check `index < 0` and `index >= count` against the `count` field at offset `+0x04`. The backing pointer is at offset `+0x08`, and the inline fallback/default record begins at offset `+0x10`.

2026-05-26 recheck: IDA MCP still models `0x004e5f20` as a `0x20`-byte function and `0x004e5f40` as a `0x25`-byte function. The caller set remains concentrated in old-human image parsing/render preparation functions, supporting [UID:0000JY][HumanImageLib](by-file/HumanImageLib.md) as the concrete feature owner for these instantiations.

2026-05-31 IDA MCP recheck: `0x004e5f20` decompiles as an index bounds check against `this[1]`, fallback return of `this + 0x10`, and `this[2] + 0x10 * index` when in range. `0x004e5f40` uses the same layout but returns `this[2] + 0x14 * index`. This directly verifies the shared [UID:0001VM][ProtectedArrayLayout](by-type/by-struct/ProtectedArrayLayout.md) offsets for count, entries, and fallback storage.

## Ownership

Both accessors are human image-library support. `HumanImageLib::HumanImageLib` uses the `HairInfo` accessor while parsing `HAIRCR.TBL` color data, and uses the `Acc2Info` accessor while parsing accessory draw flags.
