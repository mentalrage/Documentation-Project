# 0x00421520-0x00421584 AllocateAlignedDwordArray

## Status

- Address range: `0x00421520-0x00421584`
- Entity kind: runtime/STL allocation helper
- Current working name: `AllocateAlignedDwordArray`
- Disposition: ignored as standalone NexusTK source, but important shared allocator behavior
- Rebuild handling: third-party/runtime or compiler/STL-generated support unless a compatibility allocator shim is required
- Confidence: strong.

## Behavior

The helper allocates storage for `count` dwords. For small requests below `0x1000` bytes it calls `operator new(count * 4)` directly, returning null for zero-byte requests. For larger requests, it overallocates by `35` bytes, aligns the returned pointer to a 32-byte boundary, stores the raw allocation pointer at `result[-1]`, and returns the aligned pointer.

If `count > 0x3fffffff`, the byte count is saturated to `0xffffffff` before large-allocation handling. Failed large allocation paths route to `_invalid_parameter_noinfo_noreturn`.

## Raw Code Evidence

IDA MCP decompilation on 2026-05-30 shows:

- input `a1` multiplied by `4`;
- direct `operator new(4 * count)` when byte size is nonzero and below `0x1000`;
- large allocation size `bytes + 35`, overflow saturation, alignment `(raw + 35) & ~0x1f`, and raw pointer storage at `aligned[-1]`.

IDA caller inventory reports callers from fitting-room vector helpers, DAT index vector growth, audio path vectors, archive/vector recovered helpers, and runtime-style container support. Historical Wave2 notes recorded this as shared global `AllocateAlignedDwordArray`.
