# 0x0066decc-0x0066dee0 LivingObjectPane Shared Word Slots

## Summary

- Address range: `0x0066decc-0x0066dee0`
- Entity kind: initialized mutable word slots plus adjacent unreferenced initialized words
- Disposition: reconstructable project data
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong for the first five mutable word slots and their two writer routines; low for the adjacent five-word tail's final purpose

This range contains ten initialized 16-bit words immediately before [UID:0001OM][0x0066dee0-0x0066dee1.FriendNameListSyncEnabled](by-memory/0x0066dee0-0x0066dee1.FriendNameListSyncEnabled.md). The first five words are a live grouped value replicated across five slots by two small IDA-unmodeled `LivingObjectPane`/`UserPane`-neighborhood setter routines. The trailing five words are initialized to `0x0028` but have no direct data xrefs in the current IDA database.

## Writer Routines

IDA does not currently model the two writer routines as functions, but raw disassembly gives clear boundaries:

| Range | Inputs | Stored value | Notes |
| --- | --- | --- | --- |
| `0x005a8b80-0x005a8c16` | two stack integer arguments | one of `0x43` through `0x4b` | Picks a word value from threshold checks, then writes that same value to all five slots. |
| `0x005a8c20-0x005a8c5c` | one stack integer argument | `0x50` by default, or `(16 - value) * 5` for values `0..5` | Also writes the same value to all five slots. |

The two routines look like shared UI sizing/timing/default setters rather than standalone global-data owners. They are embedded in the larger [UID:0001KM][0x005a2de0-0x005ad440.LivingObjectPaneLocalPlayerExtensions](by-memory/0x005a2de0-0x005ad440.LivingObjectPaneLocalPlayerExtensions.md) aggregate and should eventually be split into exact by-memory function pages when that aggregate is decomposed.

- 2026-05-30 IDA MCP `xrefs_to` reports no direct xrefs to `0x0066ded6`, `0x0066ded8`, `0x0066deda`, `0x0066dedc`, or `0x0066dede`.
- 2026-05-30 IDA MCP `lookup_funcs` reports no IDA function at `0x005a8b80` or `0x005a8c20`, but raw disassembly shows conventional `push ebp` prologues and plain `retn` endings for both setter routines.
- 2026-05-30 IDA MCP `disasm 0x005a8b80` shows the first helper selecting values `0x43` through `0x4b` from threshold checks, then storing `ax` into the five slots.
- 2026-05-30 IDA MCP `disasm 0x005a8c20` shows the second helper defaulting to `0x50`, computing `(16 - ecx) * 5` for `ecx <= 5`, then storing `ax` into the same five slots.
- The surrounding disassembly continues into modeled `sub_5A8C60` and the larger `LivingObjectPane` local-player extension neighborhood, supporting the current ownership placement but not the final semantic name.
