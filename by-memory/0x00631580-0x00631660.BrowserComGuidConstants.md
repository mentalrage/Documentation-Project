## Reconstruction Notes

Keep this child assigned to [UID:0000HV][Browser](by-file/Browser.md). Final source should use COM/OLE/MSHTML declarations and SDK GUIDs rather than raw byte arrays.

[UID:000013][Browser](by-class/Browser.md) uses this GUID band for its class declaration and `QueryInterface` policy. The Browser class should reference SDK declarations or a Browser-module `DEFINE_GUID` fallback for interface identities such as `IID_IOleClientSite`, `IID_IOleInPlaceSite`, `IID_IDispatch`, `DIID_DWebBrowserEvents2`, `IID_IDocHostUIHandler`, and `IID_IDocHostShowUI`; do not duplicate raw GUID byte arrays in the class page.

[UID:000332][0x0046fb80-0x0046fca5.BrowserDocHostShowUiStubs](by-memory/0x0046fb80-0x0046fca5.BrowserDocHostShowUiStubs.md) consumes the `IID_IDocHostUIHandler` and `IID_IDocHostShowUI` interface names as source-facing vtable/interface declarations. The checked [UID:00032Z][0x0046f540-0x0046f66f.BrowserQueryInterface](by-memory/0x0046f540-0x0046f66f.BrowserQueryInterface.md) body does not directly compare against the `0x00631630` or `0x00631640` GUID constants; preserve that as a Browser QI caveat while still keeping the GUID names available for the class declaration and method signatures.

B010's BrowserControlPane reanalysis adds the newer-pane consumer side: [UID:0000Z6][0x0046b520-0x0046cfe0.BrowserControlPaneCore](by-memory/0x0046b520-0x0046cfe0.BrowserControlPaneCore.md) constructor uses `CLSID_WebBrowser`, `IID_IOleObject`, `IID_IWebBrowser2`, and `DIID_DWebBrowserEvents2`; `BrowserControlPane::QueryInterface` compares `IID_IUnknown`, `IID_IOleClientSite`, `IID_IOleWindow`, `IID_IOleInPlaceSite`, `DIID_DWebBrowserEvents2`, `IID_IDocHostUIHandler`, and `IID_IDocHostShowUI`; document-cookie helpers consume `IID_IHTMLDocument2`; and `BrowserControlPaneTranslateAcceleratorMessage` queries `IID_IOleInPlaceActiveObject`. These remain standard SDK GUID declarations, not raw byte arrays emitted by the BrowserControlPane page.
