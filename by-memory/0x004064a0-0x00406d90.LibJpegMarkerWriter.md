The correct range is `0x004064a0-0x00406d90` half-open. The predecessor [UID:0000VY][0x004063d0-0x0040649b.LibJpegUtilityHelpers](by-memory/0x004063d0-0x0040649b.LibJpegUtilityHelpers.md) ends at `0x0040649b`; bytes `0x0040649b-0x004064a0` are NOP padding before this target. ## Call Flow And Touched State

The marker writer is reached through stock IJG compression setup. `jinit_compress_master` at `0x00406d90` calls `0x004064a0`, and `jpeg_start_compress` at `0x004047a0` calls `0x00406d90` before invoking the installed marker callback. Product screenshot writer `sub_4EFBC0` / [UID:00018N][0x004efbc0-0x004efe94.JpegScreenshotWriter](by-memory/0x004efbc0-0x004efe94.JpegScreenshotWriter.md) is only a consumer of public compression APIs; it does not own these IJG internals.

`0x004064a0` installs seven callback pointers: `write_file_header` at `0x004065f0`, `write_frame_header` at `0x00406790`, `write_scan_header` at `0x00406a30`, `write_file_trailer` at `0x00406cf0`, `write_tables_only` at `0x00406d10`, `write_marker_header` at `0x00406500`, and `write_marker_byte` at `0x004065d0`.

The code operates on IJG compressor structures and destination managers. It stores the marker writer at compressor offset `332`, writes output bytes through the destination manager, reads quant/Huffman tables and scan component descriptors, maintains private `last_restart_interval`, and references the shared `jpeg_natural_order` table at `0x00631c14`. No product UI, resource, DAT, protocol, screenshot-format, or render state is touched inside this range.
