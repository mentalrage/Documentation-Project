# 0x0060c100-0x0060c260 Static String/Container Cleanup Thunks

## Scope

- Address range: `0x0060c100-0x0060c260`
- Entity kind: static-lifetime cleanup thunks and alignment padding
- Rebuild handling: `compiler/linker-generated` for the thunk bodies; underlying globals are `source-declared/generated-binary`.
- Disposition: ignored as standalone handwritten source. Reconstruct the static strings/containers in their owner modules and let the compiler emit equivalent startup/shutdown glue.
- Confidence: strong for range boundaries, function bodies, padding, and `atexit` registrations from IDA/MCP; medium for final source owners of the backing globals.

## Summary

This range contains three static cleanup bodies registered by the startup wrapper island at [UID:0000W9][0x00419ef4-0x00419f70.StaticInitializerWrappersAfterOle](by-memory/0x00419ef4-0x00419f70.StaticInitializerWrappersAfterOle.md). The first tears down the global empty `SimpleUString`-style fallback at [UID:0000PW][g_emptySimpleUString](by-global/g_emptySimpleUString.md). The second tears down a static vector-like array whose elements are 24-byte string objects. The third destroys a static object/string at `dword_69B3D0`, which is also used by the main-menu ANSI text-dialog packet helper.

## Reconstruction Notes

- Do not hand-port these cleanup thunks as normal source-level functions.
- The source-level requirement is to identify the owners for `dword_66DAEC`, `dword_69B39C`/`dword_69B3A0`/`dword_69B3A4`, and `dword_69B3D0`, then express those static objects in the reconstructed modules.
- The `dword_66DAEC` object is already documented as [UID:0000PW][g_emptySimpleUString](by-global/g_emptySimpleUString.md); this page confirms the paired cleanup side of that object.
- `dword_69B3D0` is referenced by [UID:00022Y][0x00502e10-0x0050305c.MainMenuAnsiTextDialogPacketHelpers](by-memory/0x00502e10-0x0050305c.MainMenuAnsiTextDialogPacketHelpers.md), but final ownership still needs a separate global/source-file pass.
- The vector-like `dword_69B39C` block should receive a `by-global` page once the caller family identifies its source owner and element semantics.
