## Behavior

The first three raw helpers are ObjectList bounds helpers. They read `ObjectListLayout` fields `+0x04`, `+0x08`, `+0x0c`, and `+0x10`, then call the shared rectangle initializer `InitRectBounds` at `0x004b7c50`. The receiver is `ObjectList`; `RectBounds` is only the output object initialized by the free helper, so RectBounds source ownership is rejected. Interpreted with the current layout names, the first and third retained helpers initialize bounds using `left = m_minX - 2`, `top = m_minY - 2`, `right = m_minX + m_gridWidth + 2`, and `bottom = m_minY + m_gridHeight + 2`. The second retained helper uses the same left/top/right calculation but extends the bottom edge to `m_minY + m_gridHeight + 10`.

The raw helper at `0x00535bd0` encodes ObjectList category keys. Use `ObjectListKey` in prose for the packed `unsigned int` value, `kObjectListKeyNotFound` for `0xffffffffu`, `objectListType` for the decoded/encoded type byte, `rowSelector` for the row-list selector byte carried in bits `16..23`, and `index` for the low 16-bit list index. The low 16 bits carry the list index or row index. Row-table categories store the low byte of `rowSelector` in bits `16..23`; other categories encode only a top-nibble class marker:

| Type byte | Encoded key shape |
| --- | --- |
| `0` | `index` |
| `1` | `0x10000000 | index` |
| `2` or `4` | `((rowSelector | 0x2000) << 16) | index` |
| `3` | `((rowSelector | 0x3000) << 16) | index` |
| `5` | `((rowSelector | 0x5000) << 16) | index` |
| `6` | `0x60000000 | index` |
| `7` | `0x70000000 | index` |
| `8` | `0xc0000000 | index` |
| `9` | `0x80000000 | index` |
| `10` | `0x90000000 | index` |
| `11` | `0xa0000000 | index` |
| other | `kObjectListKeyNotFound` / `0xffffffffu` |

`sub_535CE0` is the live `DecodeObjectListKey` decoder. It reverses that key format for the surrounding lookup helpers, derives `objectListType` from the top nibble for keys whose high nibble is `0..0x0b`, writes that type to the output byte, writes the low 16-bit `index` to the index output, and writes `BYTE2(key)` to the `rowSelector` output only for types `2`, `3`, `4`, and `5`. For other decoded types it writes `0` to `rowSelector`. Older `subtype` wording is a historical decompiler alias only; `rowSelector` is the accepted source-facing name.
