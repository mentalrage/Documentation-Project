## Behavior

The first three raw helpers are ObjectList bounds helpers. They read `ObjectListLayout` fields `+0x04`, `+0x08`, `+0x0c`, and `+0x10`, then call the global rectangle initializer at `0x004b7c50`. Interpreted with the current layout names, the first and third helpers initialize bounds using left/top `min - 2` and right/bottom `min + dimension + 2`. The second helper uses the same left/top/right calculation but extends the bottom edge to `minY + gridHeight + 10`.

The raw helper at `0x00535bd0` encodes ObjectList category keys. The low 16 bits carry the list index or row index. Some categories also store an 8-bit subtype or row selector in bits `16..23`; other categories encode only a top-nibble class marker:

| Type byte | Encoded key shape |
| --- | --- |
| `0` | `index` |
| `1` | `0x10000000 | index` |
| `2` or `4` | `((subtype | 0x2000) << 16) | index` |
| `3` | `((subtype | 0x3000) << 16) | index` |
| `5` | `((subtype | 0x5000) << 16) | index` |
| `6` | `0x60000000 | index` |
| `7` | `0x70000000 | index` |
| `8` | `0xc0000000 | index` |
| `9` | `0x80000000 | index` |
| `10` | `0x90000000 | index` |
| `11` | `0xa0000000 | index` |
| other | `0xffffffff` |

`sub_535CE0` reverses that key format for the surrounding lookup helpers. It derives the object type from the top nibble for keys whose high nibble is `0..0x0b`, writes that type to the output byte, writes the low 16-bit index to the index output, and writes the byte at bits `16..23` only for types `2`, `3`, `4`, and `5`. For other decoded types it writes `0` to the subtype/row output.
