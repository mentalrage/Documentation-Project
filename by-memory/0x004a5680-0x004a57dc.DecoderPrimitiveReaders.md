## Covered Ranges

Ranges below use end-exclusive notation. IDA currently does not model these starts as functions, but raw disassembly shows complete method-shaped bodies with normal returns and alignment gaps between them.

| Range | Projected method | Behavior |
| --- | --- | --- |
| `0x004a5680-0x004a568b` | `Decoder::SetByteOrder` | Stores the caller byte argument into `this + 0x10`. Nonzero selects manual high-byte-first assembly in the multi-byte readers. |
| `0x004a5690-0x004a56b8` | `Decoder::ReadByte` | If valid, checks `cursor + 1 <= limit`, returns `buffer[cursor]`, advances cursor by one, and clears valid flag `+0x11` on underflow. |
| `0x004a56c0-0x004a570f` | `Decoder::ReadShort` | If valid and at least two bytes remain, reads a 16-bit value. When byte-order flag `+0x10` is nonzero, assembles two bytes manually as high byte then low byte; otherwise reads a native little-endian word. |
| `0x004a5710-0x004a576c` | `Decoder::ReadTriByte` | If valid and at least three bytes remain, advances one byte at a time and assembles a 24-bit value in selected byte order. |
| `0x004a5770-0x004a57dc` | `Decoder::ReadInt` | If valid and at least four bytes remain, reads a 32-bit value. Nonzero byte-order flag manually assembles high-to-low bytes; zero flag reads a native little-endian dword. |

## Field Evidence

| Offset | Role in this subrange |
| --- | --- |
| `+0x04` | Buffer base pointer used for all successful reads. |
| `+0x08` | Buffer limit/available byte count checked before advancing. |
| `+0x0c` | Current cursor offset, updated after each consumed byte or native read. |
| `+0x10` | Byte-order flag set by `0x004a5680` and tested by the 16/24/32-bit readers. |
| `+0x11` | Valid flag; zero returns `0`, and underflow clears it. |

## IDA Evidence

- IDA MCP `lookup_funcs` on 2026-05-26 reports `0x004a5680`, `0x004a5690`, `0x004a56c0`, `0x004a5710`, and `0x004a5770` as `Not a function`.
- IDA MCP `xrefs_to` on the same starts returns empty xref lists. Treat caller reachability as unresolved, not proof that the code is non-project or ignorable.
- IDA MCP `py_eval` raw disassembly confirms the listed bodies and end-exclusive boundaries:
  - `0x004a5680` stores `[ecx+0x10]` and returns with `retn 4`.
  - `0x004a5690` checks `[ecx+0x11]`, validates `cursor + 1`, reads `[buffer + cursor]`, advances `[ecx+0x0c]`, and returns `al`.
  - `0x004a56c0`, `0x004a5710`, and `0x004a5770` share the same valid/limit failure pattern and clear `[this+0x11]` on underflow.
  - The 16-bit and 32-bit readers have native little-endian fast paths when `[this+0x10] == 0`; otherwise they assemble the value byte-by-byte.

## Reconstruction Notes

These routines should become ordinary `Decoder` member functions in a source rebuild even though IDA lacks function objects today. Their shared layout and contiguous placement immediately after the modeled `Decoder` destructor make `Decoder.cpp` the best source owner. Do not migrate active `source-3/simroot_v2/class_Decoder.cpp` as complete source until Wave3 models these raw reader starts and the full `BinaryCodecCursorLayout`.
