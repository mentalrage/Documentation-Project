## Evidence

- `source-3/simroot_v2/class_ScreenDimmer.cpp` emits the constructor, destructor, paint handler, two adjustor thunks, and scalar deleting destructor.
- `source-3/simroot_v2/class_ScreenFadeOut.cpp` emits constructor, destructor, `IsHandled`, `OnUpdate`, and scalar deleting destructor; its metadata lists two disabled adjustor thunks.
- Live IDA MCP `lookup_funcs` confirms all listed child starts and sizes, including `0x0055a020` size 1, `0x0055a030` size 11, `0x0055a051` size 11, and `0x0055a05c` size 11.
- Live IDA MCP decompilation/disassembly confirms `0x0055a030` clears `dword_69AE08`, `0x0055a051` subtracts `0xa0` then jumps to `0x0055a180`, and `0x0055a05c` subtracts `0xa4` then jumps to `0x0055a180`.
- Live IDA MCP confirms `0x004a12b0` allocates `0xfc` bytes and calls `0x00559b90` with dim level `5`.
- 2026-05-26 recheck: active generated output still omits `0x0055a030`, still leaves `0x0055a051` and `0x0055a05c` out of `class_ScreenFadeOut.cpp`, and still emits `0x004a12b0` as a standalone recovered global. IDA MCP boundaries and bodies remain unchanged.
- 2026-05-31 IDA MCP recheck confirms `ScreenDimmer::ScreenDimmer` writes the dim level as `*(_BYTE *)(this + 0xf8)` and `ScreenDimmer::OnPaint` reads that same byte for the palette-index switch.

## Disposition

Treat this as reconstructable project code. The most plausible project placement is `ui/core/ScreenDimmer.cpp` plus a possible neighboring `ui/core/ScreenFadeOut.cpp`. Do not absorb the overlay classes into `render/Effects.cpp`; that module owns the later `ScreenEffecter`/filter/overlay effecter runtime family.
