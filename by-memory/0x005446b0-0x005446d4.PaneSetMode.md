| Range | Function | Notes |

| `0x005446b0-0x005446d4` | `Pane::SetMode` | Updates the `Pane` mode byte at `this + 0xb5`; if the value changes, dispatches the pane vtable slot at `+0x20` using the embedded `GrafPort`/bounds subobject pointer `this + 0x44`. |

## Behavior

The method takes an unsigned byte mode/state code. It returns immediately when `this + 0xb5` already equals the incoming value. When the mode changes, it stores the new byte and invokes the primary pane vtable slot `+0x20`, passing `this + 0x44`. The callback side effect is consistent with a bounds/dirty/redraw notification after a mode change, but the final virtual name is still unresolved.

This is the same helper called by [UID:00022N][0x004c6eb0-0x004c6f89.HelpPaneFadeStateUpdate](by-memory/0x004c6eb0-0x004c6f89.HelpPaneFadeStateUpdate.md) when `HelpPane` and its embedded text-part pane transition between mode/state values `1` and `3`. The newer [UID:00016R][0x004c65a0-0x004c6ea9.HelpPaneCore](by-memory/0x004c65a0-0x004c6ea9.HelpPaneCore.md) audit shows the same state transition shape in the raw embedded text-pane style helper at `0x004c6820-0x004c687e`; [UID:0002F3][0x00480740-0x004807aa.ChattingBackPaneUpdateVisibility](by-memory/0x00480740-0x004807aa.ChattingBackPaneUpdateVisibility.md) uses the same setter for visible/hidden chatting-backpane state values `2` and `1`.
