## Behavior

The method takes an unsigned byte mode/state code. It returns immediately when `this + 0xb5` already equals the incoming value. When the mode changes, it stores the new byte and invokes the primary pane vtable slot `+0x20`, passing inherited `GrafPort::m_visibleBounds` at `this + 0x44`. B002 2026-06-17 resolved that slot through the primary `Pane` vtable entry `0x00621a08 -> 0x00544800`, which is `Pane::InvalidateRect`; the source-facing behavior is `void Pane::SetMode(unsigned char mode)`.

This is the same helper called by [UID:00022N][0x004c6eb0-0x004c6f89.HelpPaneApplyStyleState](by-memory/0x004c6eb0-0x004c6f89.HelpPaneApplyStyleState.md) when `HelpPane` and its embedded text-part pane transition between mode/state values `1` and `3`. The newer [UID:00016R][0x004c65a0-0x004c6ea9.HelpPaneCore](by-memory/0x004c65a0-0x004c6ea9.HelpPaneCore.md) audit shows the same state transition shape in the raw embedded text-pane style helper at `0x004c6820-0x004c687e`; [UID:0002F3][0x00480740-0x004807aa.ChattingBackPaneUpdateVisibility](by-memory/0x00480740-0x004807aa.ChattingBackPaneUpdateVisibility.md) uses the same setter for visible/hidden chatting-backpane state values `2` and `1`.

[UID:0002EV][0x0047f8d0-0x0047fbc5.ChattingPaneOnPaint](by-memory/0x0047f8d0-0x0047fbc5.ChattingPaneOnPaint.md) is a saved-state consumer. In current `g_useEpfAssets == 1` layout it snapshots inherited `m_mode` from `ChattingPane+0xb5` once and calls `SetMode(savedMode)` before each row's visibility/draw gate. The legacy branch does not call this setter. This proves `+0xb5` is inherited Pane mode state rather than a ChattingPane-private draw byte.
