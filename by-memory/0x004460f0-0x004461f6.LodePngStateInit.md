# LodePNG State Init

## Status

- Address range: `0x004460f0-0x004461f6`
- Entity kind: statically linked third-party LodePNG state/default initializer
- Proposed owner: [UID:0000KW][LodePNG](by-file/LodePNG.md)
- Confidence: strong for `lodepng_state_init` role; medium-high for exact inlined sub-helper boundaries
- Evidence basis: IDA MCP `decompile` on 2026-05-25 plus local comparison against the obtained LodePNG `20160501` source archive. `wave3.py` was not executed.

## Function Role

IDA models this as `sub_4460F0`. It matches upstream `lodepng_state_init` with the small default-initializer callees inlined or flattened by the compiler. The function initializes the decoder, encoder, raw color mode, PNG info, and default error state for a `LodePNGState` / `lodepng::State` object.

Observed default writes include:

- decoder flags enabled by default;
- encoder zlib/compression defaults such as method `8`, window size `2048`, min match `3`, and nice match `128`;
- encoder filtering/default conversion settings, including palette-zero filtering and auto-convert enabled;
- raw and PNG color defaults of RGBA color type `6` and bit depth `8`;
- state error initialized to `1`.

## Evidence

- `0x00443c80` calls this function immediately after storing the `LodePNGState::vftable` into its stack state object.
- The obtained LodePNG `20160501` source initializes the same state fields through `lodepng_state_init`, `lodepng_encoder_settings_init`, `lodepng_color_mode_init`, and `lodepng_info_init`.
- The C++ header for the obtained source defines `LodePNGState` with a virtual destructor under `LODEPNG_COMPILE_CPP`; this explains the vtable write seen in `0x00443c80` and the trivial destructor glue at `0x00448520-0x00448557`.
- The default RGBA8 writes in this function line up with the public encode wrapper at `0x00443e40`, which fixes `LCT_RGBA` and bit depth `8`.

## Ownership Decision

Keep this function with [UID:0000KW][LodePNG](by-file/LodePNG.md) under `third_party/lodepng.cpp`. It is third-party codec initialization code, not render, screenshot, DAT/archive, or local image-writer code.
