# 0x0046f010-0x004710b7 Browser OLE Legacy And Helpers

## Scope

- Range: `0x0046f010-0x004710b7`
- Entity kind: class/helper aggregate
- Confirmed browser-owned participants: `BrowserThread`, `BrowserControlPaneOld`, `Browser`, `browser::Notification`, `BrowserWindow`, `BrowserControlPane`, and browser-local COM/notification helpers

This is the densest browser/OLE helper neighborhood. It contains legacy browser thread/control-pane paths, the COM-style `Browser` object, notification payload teardown, connection-point helpers, navigation helpers, and COM adjustor thunks for both old and new browser objects.

## Reconstruction Notes

- This cluster is strong evidence for a browser/OLE source module rather than isolated one-class files.
- The immediately preceding [UID:000215][0x0046eff0-0x0046f005.BrowserThreadNonDeletingDestructor](by-memory/0x0046eff0-0x0046f005.BrowserThreadNonDeletingDestructor.md) is browser-owned but sits just outside this aggregate range; keep it with `BrowserThread` when reconstructing the source module.
- The immediately following browser tail helpers [UID:000216][0x004710b8-0x004710cc.BrowserWindowReleaseAdjustorTailThunks](by-memory/0x004710b8-0x004710cc.BrowserWindowReleaseAdjustorTailThunks.md), [UID:000217][0x004710d0-0x004710df.BrowserPanePlaySound](by-memory/0x004710d0-0x004710df.BrowserPanePlaySound.md), and [UID:000218][0x004710e0-0x0047110e.BrowserGuidCompareHelper](by-memory/0x004710e0-0x0047110e.BrowserGuidCompareHelper.md) are also browser-owned; the CRT wide-format wrapper after them is ignored runtime support.
- `AutoInit` / `InitializeOleSupport` is related OLE lifetime support, but the confirmed startup initializer at `0x00419ee0` is process-wide and sits in the startup initializer table. It may share an original browser/OLE source file, but it should not be inferred as browser-instance code.
- Do not move `MSGHandler` wholesale into browser; only `BrowserControlPaneOld`'s dispatch bridge at `0x00528de0` is browser-specific.
- Browser global-data ownership is split between strong browser data and ambiguous aliases. Use the by-global pages before moving declarations into reconstructed source.
- `BrowserThread::RunMessageLoop` and `BrowserControlPaneOld::HandleBrowserMessage` use [UID:0001Q1][0x0069bec4-0x0069bec8.g_browserControlKeyCallback](by-memory/0x0069bec4-0x0069bec8.g_browserControlKeyCallback.md), now identified as the PlatformApi `SendMessageW` dispatch slot. Browser is only a consumer of that storage.
