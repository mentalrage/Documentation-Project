### Fields, clipping, palette, and modes

- `m_drawEnabled` at `+0x71` returns before any clipping, palette call, or write when
  false. `GetClipRect` fills the current clip, `IntersectRects` receives clip first and
  requested bounds second with the requested local reused as output, and
  `IsRectEmptyOrInvalid` rejects nonpositive width or height.
- Embedded `EPFTileContext m_surfaceContext` begins at GrafPort `+0x1c`.
  `pixelData` is accepted `void *` at `+0x20`, `rowStridePixels` is accepted logical
  `int` pixel count at `+0x28`, and `bounds.left/top` are at `+0x2c/+0x30`. Source
  takes an `unsigned char *` byte view before applying
  `2 * (clipped.left + rowStridePixels * (clipped.top - bounds.top) - bounds.left)`,
  then converts the resulting address to `unsigned short *`. Direct `void *`
  arithmetic and generic current member `rowStride` are rejected; `rowStride` is only
  a historical report-draft alias.
- Draw state is signed-byte-dispatched `m_drawMode +0x70`, `m_drawColor +0x74`,
  inferred target-level `m_secondaryDrawColor +0x78`, borrowed
  `DLPalette *m_palette +0x84`, `m_alpha +0x90`, and
  `m_usesSoftwareBuffer +0x94`. The software-buffer field is not a dirty flag.
- Palette selection uses borrowed `m_palette` when non-null, otherwise
  `g_pPaletteLib->GetCurrentPalette()`. Both primary and secondary colors are passed to
  `DLPalette::MapColor`; the secondary result is deliberately discarded but its call
  remains observable. Software-buffer mode plus primary palette index 128 overrides
  the mapped fill pixel with value 1.
- Mode 0 copies unconditionally. Mode 1 copies only for nonzero primary index. Mode 2
  blends unconditionally. Mode 3 blends only for nonzero primary index. Any other
  mode returns without a pixel write.
- Direct modes write the odd 16-bit tail at `width & ~1` before writing `width/2`
  packed pairs. Rows advance by `rowStridePixels` 16-bit pixels.
- Blend weight is the low byte of integer conversion of `m_alpha * 32.0f + 0.5f`,
  with no clamp. `BlendRgb565Pixel` and `BlendRgb565Pair` receive existing destination
  first and fill second, so the supplied weight preserves destination and the inverse
  weights the fill.
- Mode 2 blends even pairs and one odd trailing pixel. Mode 3 loops pairs while
  `x < width` and then performs the same odd tail; odd widths therefore blend
  `ceil(width/2)` pairs and one additional pixel, touching two pixels beyond the
  requested extent. This likely source bug is mandatory behavior and must not be
  normalized.
