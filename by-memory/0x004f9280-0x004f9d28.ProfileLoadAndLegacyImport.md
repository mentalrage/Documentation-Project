# 0x004f9280-0x004f9d28 - Profile Load And Legacy Import

## Status

- Confidence: strong
- Proposed file: [UID:0000MS][ProfileStorage](by-file/ProfileStorage.md)
- Evidence basis: Wave3 global summaries, generated recovered source, older report notes, and IDA MCP xrefs.

## Covered Structures

| Range | Entity | Role |
| --- | --- | --- |
| `0x004f9280-0x004f95a2` | `ImportLegacyUserProfileData` | Imports current-directory `users\<name>.cfg` quoted-string profile data into `g_pConfig`, then deletes the legacy file. |
| `0x004f95b0-0x004f9d28` | `LoadUserProfileData` | Resets user-data defaults, opens `Documents\NexusTK\users\<name>.usr` or current-directory fallback, loads the length-prefixed profile format, and migrates legacy data if no modern file exists. |

## Notes

`LoadUserProfileData` calls `RegistryConfig::InitializeUserDataDefaults` before overlaying profile data. That makes it dependent on `config/RegistryConfig.cpp`, but the file ownership remains profile storage because the main behavior is profile file IO and legacy migration.

IDA confirms `ImportLegacyUserProfileData` is only called from `LoadUserProfileData`, and `LoadUserProfileData` is called from the main UI graph initialization function at `0x004f7d10`.

The modern `.usr` binary layout and legacy `.cfg` quoted-string import format are documented in [UID:0001QL][client_profile_storage](by-meta/client_profile_storage.md). The current target offsets inside `RegistryConfig` are documented in [UID:0001VR][RegistryConfigUserProfileBlock](by-type/by-struct/RegistryConfigUserProfileBlock.md).

For the macro/hotkey section, IDA MCP decompilation on 2026-05-25 confirms the loader reads a row type character, maps `T`/`S`/`I` to [UID:0001V1][MacroHotkeyRecord](by-type/by-struct/MacroHotkeyRecord.md) states `1`/`2`/`3`, then reads the row text/key payload into `g_pConfig + 0x28f2f4 + i * 0x108`. Because `InitializeUserDataDefaults` runs first, unknown row type characters leave the default state `2` in place.
