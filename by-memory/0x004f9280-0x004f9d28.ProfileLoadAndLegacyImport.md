- `callers` confirms `ImportLegacyUserProfileData` is called only from `LoadUserProfileData` at `0x004f974a`; `LoadUserProfileData` is called from [UID:00019K][0x004f7d10-0x004f8b2a.InitializeMainUiGraph](by-memory/0x004f7d10-0x004f8b2a.InitializeMainUiGraph.md) at `0x004f8a83`.

- The modern loader decompilation calls `RegistryConfig::InitializeUserDataDefaults` at `0x0048ebc0` before file reads, uses `SHGetFolderPathW` with CSIDL personal documents, creates `NexusTK` and `NexusTK\users`, opens `%s/%s.usr`, falls back to `%s/users/%s.usr`, and calls the legacy importer only when both modern paths fail.
- The loader reads the fixed wide-string groups, 20 dynamic profile strings, a 256-wide display/profile field, dynamic string-vector entries, compact shortcut state, 30 macro/hotkey rows, trailing flag pairs, then promotes older shortcut fields into the [UID:0001V1][MacroHotkeyRecord](by-type/by-struct/MacroHotkeyRecord.md) array before closing the profile file.
- `callees` ties the aggregate to file/string/runtime helpers (`SHGetFolderPathW`, `_fread`, `_fgetwc`, `_fclose`, `_wcscpy_s`, `_wcscat_s`), project string-vector helpers, `RegistryConfig::InitializeUserDataDefaults`, and the legacy importer; no UI object method owns the profile storage behavior.

## Notes

`LoadUserProfileData` calls `RegistryConfig::InitializeUserDataDefaults` before overlaying profile data. That makes it dependent on `config/RegistryConfig.cpp`, but the file ownership remains profile storage because the main behavior is profile file IO and legacy migration.

IDA confirms `ImportLegacyUserProfileData` is only called from `LoadUserProfileData`, and `LoadUserProfileData` is called from the main UI graph initialization function at `0x004f7d10`.

The modern `.usr` binary layout and legacy `.cfg` quoted-string import format are documented in [UID:0001QL][client_profile_storage](by-meta/client_profile_storage.md). The current target offsets inside `RegistryConfig` are documented in [UID:0001VR][RegistryConfigUserProfileBlock](by-type/by-struct/RegistryConfigUserProfileBlock.md).

For the macro/hotkey section, IDA MCP decompilation on 2026-05-25 confirms the loader reads a row type character, maps `T`/`S`/`I` to [UID:0001V1][MacroHotkeyRecord](by-type/by-struct/MacroHotkeyRecord.md) states `1`/`2`/`3`, then reads the row text/key payload into `g_pConfig + 0x28f2f4 + i * 0x108`. Because `InitializeUserDataDefaults` runs first, unknown row type characters leave the default state `2` in place.
