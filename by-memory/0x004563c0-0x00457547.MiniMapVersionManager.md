## Behavior Summary

`MiniMapVersionManager` owns the current minimap hash/version string plus a map-id-to-version index. Startup constructs the singleton and triggers cache loading, `StartupWindow` later updates the hash list from update text, and minimap renderer code queries the expected version string before accepting an existing `.mnm` file.

The manager stores list/index state beginning at object offset `+0x48`: constructor initializes the list sentinel through `sub_457550`, resets the list count, sets the index scale/seed value to `0x3f800000`, and initializes eight buckets through `sub_423B00`. Destruction and the explicit clear helper free each node payload at node offset `+0x0c`, reset the list sentinel and count, reinitialize or destroy the embedded index, and clear `g_pMiniMapVersionManager`.

The persisted cache lives under `%APPDATA%\NexusTK\MiniMap\mnmhs.hs`. Cache read paths open the file in `rb` mode, read a one-byte version-string length, read that version string, read the remaining wide hash-list text, call `UpdateHashList` with persistence disabled, and free the temporary buffers. The cache-save shaped body opens the same path, writes the one-byte version length, then writes the version and hash-list text.

`UpdateHashList` is the parser/inserter for slash/comma-delimited minimap hash entries. It updates the manager version buffer at `+0x04`, optionally writes `mnmhs.hs`, parses numeric map ids, updates existing node payload strings, or allocates a new version string and inserts a new list/index node.
