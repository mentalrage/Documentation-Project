## Behavior

`DATIndexVector::RemoveNodeForInsertUnwind` removes one keyed intrusive node from a `DATIndexVector` bucket/list state. The binary writes the removed node's original `next` pointer through the caller-provided result slot and returns that slot; the source-facing reconstruction exposes the same value as the helper return.

Live Hex-Rays shows:

- Hashes the node key bytes at `Block + 0x08..0x0b` with the same four-byte FNV-1a sequence used by [UID:0000XS][0x00457100-0x0045730f.DATIndexVectorInsertNode](by-memory/0x00457100-0x0045730f.DATIndexVectorInsertNode.md) and [UID:0000XX][0x00457580-0x00457613.DATIndexVectorFindNodeByKey](by-memory/0x00457580-0x00457613.DATIndexVectorFindNodeByKey.md).
- Selects a bucket by applying the vector mask at object offset `+0x18` and indexing the bucket table at object offset `+0x0c`.
- Repairs bucket boundary pointers:
  - if the removed node is both `first` and `last`, sets both bucket pointers to the list sentinel at object offset `+0x04`;
  - if it is only `last`, sets `last = node->prev`;
  - if it is only `first`, sets `first = node->next`.
- Unlinks the node from the intrusive list by writing `prev->next = next` and `next->prev = prev`.
- Decrements the node count at object offset `+0x08`.
- Frees the 16-byte node through `sub_5C7526`.
- Returns the removed node's original `next` pointer through the out parameter.
- The only observed caller is the [UID:0000XS][0x00457100-0x0045730f.DATIndexVectorInsertNode](by-memory/0x00457100-0x0045730f.DATIndexVectorInsertNode.md) cleanup/unwind block at `0x00457301`, immediately before the throw path calls `__CxxThrowException@8`.
