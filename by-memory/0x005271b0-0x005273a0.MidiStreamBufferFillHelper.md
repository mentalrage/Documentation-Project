## Behavior

This helper fills a caller-provided WinMM MIDI stream buffer from the parsed Standard MIDI File document state. It resumes any partially emitted event stored in the parser scratch globals, chooses the active track with the smallest pending delta time, parses the next track event, converts it to a WinMM stream event record, and advances track/event state until the output buffer is full, parsing fails, or all tracks finish.

The helper is the producer used by the MIDI stream open and callback paths. It sits above the low-level reader/parser helpers documented in [UID:00023B][0x00526650-0x005270d5.MidiFileReaderAndSMFParserHelpers](by-memory/0x00526650-0x005270d5.MidiFileReaderAndSMFParserHelpers.md).

## Verified State Machine

- Live IDA MCP on 2026-06-03 reports the current prototype as `int __thiscall(_DWORD *this, char, _DWORD *, int)`, with the byte argument controlling reset/first-fill behavior, the third argument acting as the stream output context, and the fourth argument allowing re-prime after an end state.
- The stream output context has its used-byte count reset at dword `+0x48` on entry before any event encoding.
- When the low bit of the byte argument is set, the helper clears `dword_69B878`, `dword_69B870`, `dword_69B874`, and the 16-byte scratch event record at `xmmword_69B880`.
- `dword_69B878` is the scratch state bitfield: bit `1` records end-of-stream, bit `2` records parse failure, and bit `4` records an output-buffer-full partial event that should be retried.
- Track selection scans `this[3]` track records starting at `this[4]`, advances by 40 bytes per record, ignores records whose first byte has bit `1` set, and selects the active track with the smallest pending delta at offset `+0x14`.
- Selected-track scratch globals record the selected track pointer (`dword_69B874`), best pending delta (`dword_69B87C`), and scan cursor/end pointer (`dword_69B870`).
- Parsed event scratch is stored in `xmmword_69B880`; meta end-of-track is recognized as status/type word `0xff 0x2f`, and allocated payloads at scratch offset `+0x0c` are freed through `j___free_base` when the parser allocation counter at `this + 0x34` is nonzero.
- The helper returns `0` for normal progress or a paused/full/end state, `-101` after event parsing fails, `-102` when a previous parse-failure state is replayed, and `-103` when a previous end-of-stream state is replayed without re-prime permission.
