## Behavior

The constructor configures a small alert dialog around the active text-edit pane. It resolves localized string id `0xf1` through [UID:0000RC][g_pLanguageMan](by-global/g_pLanguageMan.md) and the lookup helper at `0x004f0350`, passes the result, [UID:00028J][0x0067a740-0x0067a744.g_pBackPane](by-memory/0x0067a740-0x0067a744.g_pBackPane.md), the primary label [UID:0003G6][0x00622f44-0x00622f4c.CopyWindowYesButtonWideString](by-memory/0x00622f44-0x00622f4c.CopyWindowYesButtonWideString.md), and the secondary label [UID:0003G5][0x00622f3c-0x00622f44.CopyWindowNoButtonWideString](by-memory/0x00622f3c-0x00622f44.CopyWindowNoButtonWideString.md) into [UID:00012W][0x0049feb0-0x004a0686.AlertPaneCore](by-memory/0x0049feb0-0x004a0686.AlertPaneCore.md) / `AlertPane::AlertPane`, then installs the three `CopyWindow` vtable pointers at offsets `+0x00`, `+0xa0`, and `+0xa4`.

`OnPrimaryButton` is the formal source name for the accept/yes behavior. It calls [UID:0000Q7][g_pActiveTextEditPane](by-global/g_pActiveTextEditPane.md)'s current target through `TextEditPane::CopyAllToClipboard` at `0x00590520`, then clears the active text edit global. `OnSecondaryButton` is the formal source name for the cancel/no behavior and only clears that global. The binary does not null-check `g_pActiveTextEditPane` before the call, so the owning inline C++ deliberately does not add a guard.
