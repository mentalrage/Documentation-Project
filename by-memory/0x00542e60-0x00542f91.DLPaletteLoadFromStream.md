## Behavior

`DLPalette::LoadFromStream` has the resolved source contract `void LoadFromStream(File *stream)`. It reads the 0x20-byte palette header into `this + 0x0c`, copies the range-record count from the header into `m_paletteRangeCount` at `this + 0x08`, conditionally allocates `DLPaletteRange[m_paletteRangeCount]` at `this + 0x04`, and reads exactly two bytes per record. It then reads a 0x400-byte RGBX table into a stack buffer, converts 256 entries through Surface-owned `SurfacePackPixelProc g_pfnPackPixel` at `0x0069b404`, forces palette index zero to transparent, and replaces zero-valued nonzero entries with a fallback color selected by high-color flag `0x0069b3d5`. This four-byte stream-table route is separate from UID0004I4's compressed three-byte `RGBTRIPLE` payload.

The typed record source shape is corroborated rather than guessed from this allocation alone: [UID:0001E5][0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves](by-memory/0x00542fa0-0x00543020.DLPaletteApplyPaletteEntryMoves.md) consumes both record bytes as rotation endpoints, [UID:000201][0x00458590-0x00458610.EPFTileContextPixelRangeTest](by-memory/0x00458590-0x00458610.EPFTileContextPixelRangeTest.md) compares them as inclusive bounds, and [UID:0004HV][0x00542be0-0x00542c95.DLPaletteCopyConstructor](by-memory/0x00542be0-0x00542c95.DLPaletteCopyConstructor.md) deep-copies `count * sizeof(DLPaletteRange)` bytes.

The decoder operates through the abstract `File` virtual read interface rather than DATFile-specific fields. Seven direct callers are confirmed at `0x00542e38`, `0x00543294`, `0x005433e1`, `0x00543866`, `0x005438a2`, `0x005438de`, and `0x00543aa9`; every caller ignores EAX. The inspected PaletteLib routes pass stack `DATFile` objects through that base interface. Together these facts support `void` plus `File *`, not an IDA-derived pointer return or a DATFile-coupled declaration.
