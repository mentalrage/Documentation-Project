## Behavior

Subtracts source bytes from destination bytes row-by-row. The helper receives a source row pointer, source row pitch, destination row pointer, destination row pitch, byte width, and row count.

For each span it splits the width into `width / 8` eight-byte blocks and a `width % 8` scalar tail. When the block count is positive it calls [UID:00020I][0x004610a0-0x004610ee.ByteSpanSubtract8Blocks](by-memory/0x004610a0-0x004610ee.ByteSpanSubtract8Blocks.md), then advances both row pointers past the completed block bytes. It subtracts each remaining tail byte from the destination with normal byte wrapping semantics and advances source/destination by their row pitches for each row.

## Rule 26 Incorporated B001 Research

The B001 source-quality report incorporated into this page resolves the helper as a row-level byte-span wrapping-subtract primitive. The sole direct caller is [UID:0000YN][0x00462e10-0x00462f1e.DrawFrameWithBlendMode](by-memory/0x00462e10-0x00462f1e.DrawFrameWithBlendMode.md), mode `2`, but the body is a generic strided source/destination byte operation and has no AlphaMaskSurface layout dependency.

[UID:0000NT][SoftwareBlend16](by-file/SoftwareBlend16.md) remains the direct owner because this helper is grouped with the SoftwareBlend16 byte-block helpers and delegates the eight-byte `psubb` bulk path to [UID:00020I][0x004610a0-0x004610ee.ByteSpanSubtract8Blocks](by-memory/0x004610a0-0x004610ee.ByteSpanSubtract8Blocks.md). [UID:0000HF][AlphaMaskSurface](by-file/AlphaMaskSurface.md) is a caller/consumer context through `DrawFrameWithBlendMode`, not the owner of this primitive. `Surface`, `GrafPort`, and higher-level callbacks are rejected as direct owners for the same reason.

The B001 report also settles pointer typing. The source-facing row wrapper should use `uint8_t*`/`const uint8_t*`, not `__m64*`, because the row helper owns byte-width arithmetic, row pitches, and scalar wrapping byte-subtract tails. The eight-byte callee is the qword/MMX component.

The historical first-draft decision required the row and byte-block helpers to be resolved coherently. B013 satisfied that requirement by populating this wrapper and the sibling helper family together; it is no longer an open code pass.

Historical assumption resolved: neither the old `95/95` gate nor helper-family coherence now justifies blank source. Current CPP/H is present, and the exact owner/emitter remains UID0000NT.
