## IDA Evidence

- B001-015 IDA MCP `lookup_funcs` reports `sub_48EAA0` size `0x57`, `sub_48EB00` size `0x4e`, and `sub_48EB50` size `0x63`.
- `callers 0x0048eaa0` reports `0x00526186` inside `sub_526100`; `callers 0x0048eb00` reports `0x005261e7` inside the same function.
- B001-015 decompilation of `sub_526100` shows MIDI track selection reading a selector-specific config string from `g_pConfig` through `0x0048eaa0`, starting playback if present, and writing a default `D%d`-style path through `0x0048eb00` when needed.
- `callers 0x0048eb50` reports five ordinary callers: `0x004fa729`, `0x004facc4`, `0x0052c14f`, `0x0052db1f`, and `0x0052f50f`.
- B001-015 caller decompilation shows login/create-user/server-message paths deriving a short UI string from list controls and storing it into `g_pConfig` through `0x0048eb50`.
- `0x0048eaa0` and `0x0048eb00` both read the config-entry vector member at `this + 0x2912b4`, fetch elements through virtual slot `+0x10`, compare the selector byte at the entry start, and operate on a wide string at entry offset `+2`.
- `0x0048eb50` frees/replaces the heap-backed wide-string member at `this + 0x2916cc`.
- B001-015 raw byte scan confirms all internal gaps are `0xcc` padding and `0x0048ebb3-0x0048ebc0` is thirteen `0xcc` bytes before [UID:00030W][0x0048ebc0-0x0048eecf.RegistryConfigInitializeUserDataDefaults](by-memory/0x0048ebc0-0x0048eecf.RegistryConfigInitializeUserDataDefaults.md).

## Ownership Analysis

Best owner: [UID:0000IE][Config](by-file/Config.md). These helpers operate on `g_pConfig` storage and Config object members, while consumers from MIDI and UI/login/create-user code only read or update configuration preferences. The helpers are not methods of those consumer dialogs; they centralize Config storage access.

Rejected owner: [UID:0000N4][RegistryConfig](by-file/RegistryConfig.md). The helpers live beside RegistryConfig defaults and run on the concrete RegistryConfig instance through `g_pConfig`, but the touched members are base config storage and preference fields rather than registry persistence behavior.

Rejected owners: MIDI player and login/create-user dialog source files. Their caller xrefs are consumers of the config preferences: MIDI asks for a track path and writes a fallback, while UI/server handlers update a stored short string.

Confidence is `88` because callers consistently pass `g_pConfig` and the helpers touch only Config storage; uncertainty remains around exact final names and field declarations.
