# 0x006104f4-0x00610ed8 MiniMap And Ranking Read-Only Data

## Summary

- Address range: `0x006104f4-0x00610ed8`
- Entity kind: project vtables, string literals, and render constants
- Disposition: reconstructable NexusTK project data
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong for exact checked children and byte/string boundaries, medium-high for the remaining unsplit MiniMap/source-module subdivision

This range contains MiniMap and Ranking subsystem vtables plus static resource names, cache paths, date labels, and UI strings used by minimap rendering/download and ranking-event panes. The final `0x00610e38-0x00610ed8` tail is not ranking data; IDA shows it is a software-blend/read-only constant island consumed by RGB555/RGB565 render helper code. The current page starts at the `MiniMapDialog` vtable base `0x006104f4`; the preceding `MiniMapDialog` RTTI locator dword at `0x006104f0` is still covered by the previous LodePNG-range page and should be moved here if the left boundary is re-ranged later.

- IDA names in this span are MiniMap and Ranking vtable symbols, with string literals matching the same subsystems.
- 2026-06-07 IDA MCP `py_eval` counted the current range as `.rdata` size `0x9e4` with 68 named addresses, 41 IDA string entries, and 93 xref-bearing targets. Representative source refs include `MiniMapDialog` constructor code at `0x00450ca0`, minimap layout/render code at `0x004523d0` and `0x00454150`, ranking event-list paint/setup at `0x0045b630`, and ranking user-list paint at `0x0045f3a0`.

## Rebuild Notes

Rebuild this data from class declarations, virtual method definitions, resource-name constants, and module-level static strings in the MiniMap and Ranking source modules. Do not port raw addresses or bytes.

## Assignment Gate

`AUTOGEN_PARENT_UID` remains blank under the corrected supervisor gate. This aggregate is now documented at `80/88`, but it is intentionally mixed: MiniMap vtables/strings, Ranking vtables/strings, and a SoftwareBlend16 render-constant tail all share the same contiguous `.rdata` island. No single direct parent owns the whole range, and the current MiniMap and Ranking source parents are below the `85/85` parent threshold (`MiniMap` is `82/84`, `RankingDialog` is `82/86`). [UID:0000NT][SoftwareBlend16](by-file/SoftwareBlend16.md) is `86/88` but only owns the final render-constant child, not the aggregate.

## Boundary Notes

- 2026-05-31 IDA MCP dword review shows `0x00610ed8 -> ??_R4AboveFrame@@6B@`, the primary RTTI locator for `AboveFrame`, followed by the `AboveFrame` primary vtable base at `0x00610edc`.
- The MiniMap/Ranking aggregate therefore ends at `0x00610ed8`, not `0x00610edc`; the four bytes at `0x00610ed8-0x00610edb` belong to the following `AboveFrame` vtable-data island.
- The Ranking-owned portion ends earlier at `0x00610e38`; the bytes through `0x00610ed8` stay in this aggregate only because they are adjacent software-render constants between Ranking strings and `AboveFrame`.
