# 0x00670258-0x00670260 Socket Connection String Parse Pointers

## Summary

- Address range: `0x00670258-0x00670260`
- Entity kind: initialized string-pointer pair
- Disposition: reconstructable project data
- Rebuild handling: source-declared static pointers/string constants
- Confidence: strong for contents and call site; medium for final helper name

This range contains two read-only-string pointers used by a socket helper that parses a `CONNADDR` connection-address payload into host and port fields.

## Layout

| Address | Current IDA name | Points to | Role |
| --- | --- | --- | --- |
| `0x00670258` | `off_670258` | `0x00624fa8` wide `CONNADDR` | Argument/key string pushed into a local parser object at `0x005778cf`. |
| `0x0067025c` | `off_67025C` | `0x00624fbc` ANSI `" :,\t"` | Delimiter string passed to `_strtok_s` while splitting host and port text. |

## Evidence

- IDA MCP xref `0x005778cf` pushes `off_670258` before a parser call inside `sub_577890`.
- IDA MCP xrefs `0x00577967` and `0x005779c8` pass `off_67025C` as `_strtok_s` delimiter.
- The same function calls `gethostbyname`, copies four address bytes to the output array, parses the next token as an integer, and stores it as the port.
- The executable code sits inside [UID:0001I1][0x00575d90-0x005796c7.SocketTransportCore](by-memory/0x00575d90-0x005796c7.SocketTransportCore.md), the socket transport cluster.

## Reconstruction Notes

Keep these constants with [UID:0000NS][Socket](by-file/Socket.md) / connection-address parsing. They are socket transport configuration strings, not general string utilities.
