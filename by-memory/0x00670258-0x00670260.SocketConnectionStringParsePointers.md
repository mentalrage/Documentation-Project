# 0x00670258-0x00670260 Socket Connection String Parse Pointers

## Summary

- Address range: `0x00670258-0x00670260`
- Entity kind: initialized string-pointer pair
- Disposition: reconstructable project data
- Rebuild handling: source-declared Socket parser constants
- Confidence: strong for contents, parser use, and neighboring boundaries; source variable names remain reconstructed

This range contains two initialized pointer slots used by the Socket connection-string endpoint parser. The first slot points to the UTF-16 `CONNADDR` key used to load a configured connection-address entry; the second slot points to the ANSI delimiter set used to split that entry into host and port tokens.

## Layout

| Range | Bytes | Points to | Role |
| --- | --- | --- | --- |
| `0x00670258-0x0067025c` | `a8 4f 62 00` | `0x00624fa8`, UTF-16 `CONNADDR` | Connection-address key passed into the parser helper before reading the selected entry. |
| `0x0067025c-0x00670260` | `bc 4f 62 00` | `0x00624fbc`, ANSI `" :,\t"` | Delimiter set passed to `strtok_s` for the host token and then the port token. |

## Evidence

- 2026-06-06 IDA MCP byte sweep of `0x00670250-0x00670268` returned `fe fe fe fe ff ff ff ff a8 4f 62 00 bc 4f 62 00 18 d4 62 00 30 d4 62 00`, placing this page immediately after the packet-transform table tail and immediately before the StartupWindow pointer pair.
- The `0x00670258` slot has one direct code reference at `0x005778cf` in the modeled `0x00577890-0x00577a4c` Socket connection-string parser. The target bytes at `0x00624fa8` decode as UTF-16 `CONNADDR`, and the read-only target is referenced only through this pointer slot.
- The `0x0067025c` slot has two direct code references at `0x00577967` and `0x005779c8` in the same parser. The target bytes at `0x00624fbc` decode as ANSI `" :,\t"`, and the read-only target is referenced only through this pointer slot.
- Live decompilation/disassembly of the parser shows it initializes a local parser object with the `CONNADDR` key, skips `arg0` entries, reads a bounded `255`-byte string, tokenizes the first field with `strtok_s`, resolves it through `gethostbyname`, copies four IPv4 address bytes into the output array, tokenizes the next field with the same delimiter set, and stores the parsed integer as the port.
- The modeled parser has no ordinary code callers in IDA, but it sits inside [UID:0001I1][0x00575d90-0x005797ae.SocketTransportCore](by-memory/0x00575d90-0x005797ae.SocketTransportCore.md), the documented Socket transport cluster.
- Neighboring-boundary evidence: `0x00670250` and `0x00670254` have no direct refs and are the final dwords of [UID:000286][0x0066fe50-0x00670258.PacketTransformAlternateSizeAndLut](by-memory/0x0066fe50-0x00670258.PacketTransformAlternateSizeAndLut.md). The next dwords at `0x00670260` and `0x00670264` are StartupWindow class/title pointer slots with refs at `0x005808ac`, `0x00580ab1`, and unmodeled notice-window code, so they belong to [UID:000288][0x00670260-0x00670268.StartupWindowNoticePointerData](by-memory/0x00670260-0x00670268.StartupWindowNoticePointerData.md).
