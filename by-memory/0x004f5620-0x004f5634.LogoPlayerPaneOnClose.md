## Reconstruction Notes

Keep the callback invocation after the delete-mark operation; changing the order would allow the callback to observe an unqueued pane. Treat `0x00544690` as the shared PaneCore `MarkForDeletion` helper, not a `LogoPlayerPane`-local routine.

The first-draft C++ intentionally uses source-facing names: `MarkForDeletion()` for the inherited Pane helper and `m_completionCallback->Invoke()` for the shared zero-argument FunctionObjects interface. Do not add a null check; the raw body unconditionally dereferences the stored callback, so the constructor contract requires a non-null completion callback.

Rejected alternatives: `bool LogoPlayerPane::OnClose()` because the verified caller ignores any return and the base slot is a no-op `ret`; `LogoPlayerPane::OnVideoDone()` because the done-message dispatcher belongs to `VideoPlayerPane`; a bespoke `LogoPlayerPaneCallback` because no dedicated vtable/RTTI/constructor evidence exists; raw function/member-function pointer because the body uses vtable slot `+0x00` for deletion and `+0x0c` for invoke; and dead/unreachable helper because the primary vtable route through `0x0061d068` is the normal virtual dispatch path.
