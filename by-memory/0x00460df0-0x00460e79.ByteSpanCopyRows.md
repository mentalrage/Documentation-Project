## Behavior

Copies byte spans row-by-row. The helper receives a source row pointer, source row pitch, destination row pointer, destination row pitch, byte width, and row count.

For each span it splits the width into `width / 8` eight-byte blocks and a `width % 8` scalar tail. When the block count is positive it calls [UID:00020G][0x00461000-0x0046104b.ByteSpanCopy8Blocks](by-memory/0x00461000-0x0046104b.ByteSpanCopy8Blocks.md), then advances both row pointers past the copied block bytes. It copies the remaining tail bytes with a byte loop and advances source/destination by their row pitches for each row.

The source-facing type should be byte pointers rather than `__m64*`. The block callee works on qwords, but the row helper also owns byte-width arithmetic and a scalar byte tail. The return type should be `void`; the sole caller uses only the destination side effect.

## Rule 26 Incorporated B001 Research

The B001 source-quality report incorporated into this page resolves the helper as a row-level byte-span copy primitive, not an AlphaMaskSurface-owned method. The sole direct caller is [UID:0000YN][0x00462e10-0x00462f1e.DrawFrameWithBlendMode](by-memory/0x00462e10-0x00462f1e.DrawFrameWithBlendMode.md), mode `0`, but the body is a generic strided source/destination byte-span operation and has no AlphaMaskSurface layout dependency.

[UID:0000NT][SoftwareBlend16](by-file/SoftwareBlend16.md) remains the direct owner because this helper is physically grouped with the SoftwareBlend16 byte-block helpers and delegates the eight-byte bulk copy to [UID:00020G][0x00461000-0x0046104b.ByteSpanCopy8Blocks](by-memory/0x00461000-0x0046104b.ByteSpanCopy8Blocks.md). [UID:0000HF][AlphaMaskSurface](by-file/AlphaMaskSurface.md) is retained only as consumer context through `DrawFrameWithBlendMode`. `Surface`, `GrafPort`, and higher-level callback families are rejected as direct owners because they do not own the local byte-span primitive.

The B001 report also settles pointer typing. The source-facing row wrapper should use `uint8_t*`/`const uint8_t*`, even though the sibling block helper works in qwords and decompiler output may present `__m64*`. The scalar tail and width arithmetic are byte-counted, so qword pointer types would misrepresent the row wrapper's interface.

The historical first-draft decision required the row and byte-block helpers to be resolved coherently. B013 satisfied that requirement by populating this wrapper and the sibling helper family together; it is no longer an open code pass.

Historical assumption resolved: neither the old `95/95` gate nor helper-family coherence now justifies blank source. Current CPP/H is present, and the exact owner/emitter remains UID0000NT.
