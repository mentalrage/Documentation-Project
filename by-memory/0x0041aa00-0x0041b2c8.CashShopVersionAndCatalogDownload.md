# 0x0041aa00-0x0041b2c8 CashShop Version And Catalog Download

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: cash-shop/fitting-room HTTP download helpers plus version request wrapper
- Current Wave3 owners: `DownloadCashShopVersion_41AA00`, `DownloadCashShopCatalog_41AE20`, and [UID:00001I][CashShopVersionRequest](by-class/CashShopVersionRequest.md)
- Likely source module: [UID:0000I1][CashShopVersionRequest](by-file/CashShopVersionRequest.md) and shared [UID:0000JC][FileDownloader](by-file/FileDownloader.md) dispatch
- Confidence: strong for function boundaries, medium for original file split.

## Evidence

- Wave3 global summaries describe the two download helpers and their owner files.
- IDA MCP confirms real starts and sizes for `0x0041aa00`, `0x0041ae20`, and `0x0041b270`.
- IDA MCP reports both download helpers are called by `0x0041b110`, and decompilation identifies that function as the `FileDownloader::OnMessage` message switch.
- Generated source for `DownloadCashShopCatalog_41AE20` uses WinINet and URL `https://secure.kru.com/itemshop/data/itemshop.json`.
- IDA caller/callee evidence shows the version/catalog path shares JsonCpp document/parse helpers: `DownloadCashShopVersion_41AA00` calls `0x004298f0` and `0x00429b30`, and `FittingRoomDialogItemState::LoadEncodedStateBuffer` uses the same parse path before loading the cached item-shop document.
- IDA MCP reports `0x0041b270` is called by `0x0041bdd0`, the fitting-room dialog constructor.
- IDA MCP decompilation on 2026-05-25 shows `0x0041bdd0` passes [UID:0000QH][g_pCashShopRequest](by-global/g_pCashShopRequest.md) / `dword_67A738`, whose direct writes are FileDownloader constructor/destructor-family writes.

## Ownership Decision

Treat the item-shop helper semantics as fitting-room/cash-shop feature code, but route the dispatcher through [UID:0000JC][FileDownloader](by-file/FileDownloader.md). These WinINet helpers should not be grouped with [UID:0000NS][Socket](by-file/Socket.md), which owns encrypted game transport. Keep `0x0041b270` provisional between the cash-shop payload file and the downloader/request-dispatcher file until the `dword_67A738` type is settled.
