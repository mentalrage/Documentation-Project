# 0x004b60c0-0x004b61d9 FontImageLib EnsureFontSlotLoaded

## Status

- Entity kind: class method.
- Owner: `FontImageLib`.
- Rebuild handling: `source-authored`.
- Evidence: IDA MCP `lookup_funcs` reports `sub_4B60C0` size `0x119`.
- C++ reconstruction status: reconstructable, but no source block is attached yet because DATFile call signatures and final source style are not 95+ verified.

## Behavior

This method lazily opens one of the two bitmap-font archives and builds the in-memory glyph pointer table for that slot.

Observed flow:

- clamps any font id greater than or equal to `2` back to slot `0`;
- computes the selected slot base as `this + 0x04 + 0x40008 * slotIndex`;
- if the archive pointer at `slot + 0x00` is already non-null, returns `slot + 0x04`;
- formats the archive/resource name with `BA%d`;
- allocates and constructs a `DATFile` object;
- opens the formatted `BA0` or `BA1` resource through the DAT file wrapper;
- obtains a payload base pointer through helper `0x0049c550`;
- reads two 16-bit slot metrics into `slot + 0x04` and `slot + 0x06`;
- subtracts `4` from the second metric at `slot + 0x06`;
- reads `0x10000` 32-bit glyph offsets;
- for each nonzero offset, stores `payloadBase + offset` into the glyph table at `slot + 0x08 + 4 * glyphId`;
- returns `slot + 0x04`.

## Data Layout Evidence

The method proves the selected slot layout:

```text
0x00000 DATFile* archive
+0x00004 int16 metric0
+0x00006 int16 metric1_adjusted
+0x00008 FontGlyphRecord* glyphPointers[65536]
```

The table size is `65536 * 4 == 0x40000` bytes, making each complete slot `0x40008` bytes.

## Caller Evidence

IDA MCP `xrefs_to 0x004b60c0` reports only two internal callers:

- `0x004b5ff6` inside the metrics helper;
- `0x004b6035` inside glyph measurement/decoding.

This supports treating it as a private/internal `FontImageLib` loader helper.
