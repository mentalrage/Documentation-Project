## Behavior

- `0x004efe00` obtains `cinfo->src` through `cinfo + 0x18`, proving the callback is a decompressor source-manager helper rather than a compressor destination-manager helper.
- On first use, the helper copies saved source pointer/count fields at manager offsets `+0x1c/+0x20` into public `next_input_byte/bytes_in_buffer`, sets byte flag `+0x24`, and returns `TRUE`.
- On later use, `0x004efe22` loads this marker base, `0x004efe27` loads count `2`, and the helper stores that pointer/count pair into `jpeg_source_mgr` before returning `TRUE`.
- The marker therefore provides a synthetic EOI after the saved memory source has already been supplied. It is not output-buffer capacity for `jpeg_destination_mgr`.
