## Behavior

This is the x86 frame-chain fallback used when dynamic ImageHlp setup fails. It initializes the walk from `CONTEXT::Eip` and `CONTEXT::Ebp`, resolves every instruction pointer through `GetLogicalAddress`, optionally prints the frame, and follows the saved EBP chain until structural validation fails.

When `pReportFile` is non-null, it first builds the executable path, writes `Call stack:\n`, and writes the exact heading `Address   Frame     Logical addr  Module\n`. Each iteration then emits `%08X  %08X  %04X:%08X %ws\n`. If the resolved module equals the executable path case-insensitively, it additionally emits `%08X\n` with the section-relative offset.

## Frame Update And Stop Contract

The order is observable and must remain unchanged:

1. Use the current instruction pointer and frame pointer for address resolution and optional output.
2. Load the next instruction pointer from `pFrame[1]`.
3. Save the current frame as `pPreviousFrame`.
4. Follow the caller frame through `pFrame[0]`.
5. Stop if the new frame is not 4-byte aligned, is not strictly greater than the previous frame, or fails `IsBadWritePtr(pFrame, 8)`.
