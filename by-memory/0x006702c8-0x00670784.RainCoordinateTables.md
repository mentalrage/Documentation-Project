## Evidence

- IDA MCP `py_eval` confirms data refs from `RainingLayerPane::OnPaint` at `0x005c1460` to `0x00670528`, `0x0067052a`, `0x0067052c`, `0x006706d8`, `0x006706da`, `0x00670730`, and `0x00670732`.
- IDA MCP `py_eval` confirms data refs from `RainingLayerPane::DrawRainOnTarget` at `0x005c1810` to `0x006702c8`, `0x006702ca`, `0x006702cc`, `0x00670478`, `0x0067047a`, `0x006704d0`, and `0x006704d2`.
- 2026-05-31 IDA MCP `lookup_funcs` confirms `0x005c1460` as a `0x3ac`-byte function and `0x005c1810` as a `0x3b7`-byte function.
- 2026-05-31 IDA MCP `xrefs_to` confirms the six table starts are referenced by those two functions only in the weather layer area: target/minimap refs from `0x005c1810`, main-view refs from `0x005c1460`.
- 2026-05-31 IDA MCP `decompile` confirms the rain streak tables are read as three 16-bit values per entry with a 24-entry frame stride, and splash tables are read as 16-bit x/y pairs with seven entries per frame.
- Current `source-3/simroot_v2/class_RainingLayerPane.cpp` describes the same table split but still emits marker-only unresolved `global-data` rows.
- The drawing loops use 18 streaks and 7 small/large splashes per rendered frame, while the streak index stride is 24 entries per frame.

## Data Caveats

IDA has individual word items rather than typed arrays for these tables. Treat the ranges above as reconstructed source-data ranges derived from neighboring table starts and observed access patterns, not as finalized IDA array definitions.
