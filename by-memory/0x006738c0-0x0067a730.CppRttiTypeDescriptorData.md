# 0x006738c0-0x0067a730 C++ RTTI Type Descriptor Data

## Summary

- Address range: `0x006738c0-0x0067a730`
- Entity kind: compiler-generated C++ RTTI type descriptors and decorated type-name strings
- Disposition: ignored as handwritten source; preserve through compiler RTTI settings and class reconstruction
- Rebuild handling: generated by MSVC from class definitions and runtime type information settings
- Confidence: strong

This range contains a dense run of MSVC C++ RTTI `type_info` descriptor records and decorated type-name strings. The names cover NexusTK classes, JsonCpp types, STL/Dinkumware templates, COM/error support, and standard exceptions. The range is important for binary matching and class discovery, but it should not be rewritten as manually declared game globals.

## Evidence

- IDA MCP range audit reports `.data`, `28272` bytes, `1509` named items, and `755` data-xref targets.
- The first item is `??_R0?AVLObject@@@8`, followed by decorated names such as `.?AVLObject@@`, request classes, pane/control classes, JsonCpp classes, STL templates, and standard exception types.
- The tail bytes end after the decorated `std::bad_exception` name, and the next byte range at `0x0067a730` is a separate CRT stdio-options storage slot.
- These records are MSVC compiler output referenced by RTTI/vtable/typeinfo metadata; they are evidence for class existence and names, not source-authored global variables.

## Reconstruction Notes

Use this range as a class-discovery and name-verification source. When class evidence is high enough, rename generated class/data names in the working code and documentation to meaningful names, then let the compiler regenerate equivalent RTTI from the reconstructed class declarations. Do not create hand-authored C++ variables for this entire range.
