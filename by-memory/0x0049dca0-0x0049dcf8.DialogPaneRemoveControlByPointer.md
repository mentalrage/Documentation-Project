## Behavior

The source-facing method calls accepted public [UID:0003KJ][0x0049dd20-0x0049dd6b.DialogPaneFindControlIndexById](by-memory/0x0049dd20-0x0049dd6b.DialogPaneFindControlIndexById.md) `FindControlIndex(control)`, tests the returned index for `>= 0`, then calls protected [UID:00012T][0x0049dd00-0x0049dd17.DialogCategorySwitch](by-memory/0x0049dd00-0x0049dd17.DialogCategorySwitch.md) `RemoveControl(controlIndex)`. The compiler expands both small same-class helpers into this body.

The expanded lookup checks generic `List *m_controlManager` at `this+0x1fc`, snapshots accepted inline `List::GetCount()` from `+0x0c`, walks element slots through `List::GetElementAt(index)`, dereferences each four-byte slot to a stored `ControlPane *`, and compares that pointer directly with the supplied pointer. The expanded integer overload calls `List::RemoveAt(index, 1)` on the first match. It does not destroy the removed control; callers retain and destroy the pointer.

Exact edge behavior is preserved through the factorized source: a null manager, empty list, or absent pointer causes no mutation; a null argument has no special guard and would match the first null entry if one existed; duplicate pointer entries remove only the first match. The count is snapshotted before scanning. No lookup, removal, or payload lifetime result is returned to the caller.

No control id field is read, no numeric id is compared, no selection state changes, and literal `1` is the removal count rather than a refresh flag.
