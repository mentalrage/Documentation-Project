# 0x0069b4cc-0x0069b4d0 InputBlockerPane Singleton

## Status

- Address range: `0x0069b4cc-0x0069b4d0`.
- Entity kind: global pointer.
- Rebuild handling: `source-declared/generated-binary`.
- Proposed name: `g_pInputBlockerPane`.

This four-byte `.data` slot stores a modal input-blocking pane created and destroyed by packet/UI state handlers. It was split out of [UID:00029Y][0x0069b4c8-0x0069b4f0.MessageStatusAndMenuPaneGlobals](by-memory/0x0069b4c8-0x0069b4f0.MessageStatusAndMenuPaneGlobals.md) because the aggregate mixes unrelated pane singleton owners.

## Evidence

- 2026-06-07 A010 live IDA MCP reports bytes `ff ff ff ff` at `0x0069b4cc`, IDA name `dword_69B4CC`, and sixteen direct data xrefs.
- `0x005a76c0` contains the strongest owner evidence: refs at `0x005a7cf9`, `0x005a7d42`, `0x005a7d49`, and `0x005a7dba` create, test, and destroy a 248-byte `InputBlockerPane`-shaped modal object through this slot.
- Additional handler references occur at `0x00507150`, `0x00509030`, `0x005abc70`, `0x005b7610`, and `0x005b79d0`, with two raw data refs at `0x00505c82` and `0x00505d6a` that IDA does not assign to a function.
- Neighbor `0x0069b4c8` is the old system-message singleton, and successor `0x0069b4d0` is the `ParcelIconPane` singleton.
