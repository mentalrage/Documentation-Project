# 0x0069b39c-0x0069b3a8 StaticStringVectorStorage_69B39C

## Summary

- Address range: `0x0069b39c-0x0069b3a8`
- Entity kind: three-pointer static string-vector control block
- Disposition: reconstructable source-declared static storage
- Parent attachment: intentionally blank until normal-use or owner evidence identifies the source module

This 12-byte range is the begin/end/capacity control block for a static vector-like container of 24-byte string objects. Live IDA currently shows only static-lifetime cleanup references to the three control words, so the storage is reconstructable but intentionally unparented.

## Evidence

- The begin pointer has three direct data refs, all in the cleanup body at `0x0060c160`: reads at `0x0060c161` and `0x0060c1d3`, then a zero clear at `0x0060c21c`.
- The end pointer has two direct data refs in the same cleanup body: read at `0x0060c170`, then a zero clear at `0x0060c226`.
- The capacity pointer has two direct data refs in the same cleanup body: read at `0x0060c1d9`, then a zero clear at `0x0060c230`.
- Live IDA decompilation of `0x0060c160` shows the cleanup body testing the begin pointer, walking from begin to end in 24-byte elements, freeing long string payloads when the element capacity is at least 8, resetting each element to an empty small-string state, freeing the backing allocation, and zeroing all three control words.
- Live IDA decompilation of the static initializer wrapper at `0x00419f40` shows an `atexit` registration for the cleanup body at `0x0060c160`.
- Boundary checks on 2026-06-06 confirm the preceding ignored initialized span has no direct refs at `0x0069b381` or `0x0069b398`; the following referenced storage starts at `0x0069b3a8` with two direct refs, and the later static string at `0x0069b3d0` has six direct refs. This supports the exact half-open range.
- Live IDA MCP recheck on 2026-06-07 confirmed the exact direct-ref split remains `3/2/2`: `0x0069b39c` is referenced at `0x0060c161`, `0x0060c1d3`, and `0x0060c21c`; `0x0069b3a0` is referenced at `0x0060c170` and `0x0060c226`; `0x0069b3a4` is referenced at `0x0060c1d9` and `0x0060c230`.
- The 2026-06-07 recheck also found no refs at `0x0069b381` or `0x0069b398`, two refs to the following `0x0069b3a8` MemoryMan storage, and six refs to the later `0x0069b3d0` static string storage. This keeps this page bounded to only the cleanup-only vector control block.
