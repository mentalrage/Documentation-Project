## Behavior

This helper decodes a compressed `ZPF` wrapper into an `EPFTileContext`-style tile context.

IDA MCP decompilation on 2026-06-03 and B006 source-quality reanalysis on 2026-06-21 show the helper:

- clears/resets the destination tile context through `EPFTileContext::ReleaseBuffers` / raw `sub_458500`;
- validates the outer `ZPF` signature with `_strncmp`;
- reads the 32-bit `ZPF` header field at `+0x04`;
- constructs a stack `_AUTOBUF<unsigned char>` temporary by calling the `LObject` constructor shell, writing the `_AUTOBUF<unsigned char>` vtable, and clearing the payload pointer/count fields;
- allocates the temporary buffer through the runtime allocation helper at `0x005c7790`;
- uses the `+0x04` field as both the temporary output capacity and the zlib input byte limit over bytes at `zpfBuffer + 8`;
- inflates the compressed payload through zlib `Uncompress` / raw `sub_414390` with `decodedSize` initialized to the same size;
- clears the destination context again before consuming the decompressed payload, so post-`ZPF` failures leave the destination reset;
- validates the decompressed inner `FPF` version word `1` at `+0x04`, then validates the `FPF` signature with `_strncmp`;
- allocates the destination tile context using dimensions from the inner FPF header at `+0x10` and `+0x12` through `EPFTileContext::AllocateRgb16Pixels` / `AllocateWordPixels` / raw `sub_458430`;
- copies `2 * (right-left) * (bottom-top)` bytes of 16-bit pixel data from `fpfBuffer + *(uint32_t *)(fpfBuffer + 0x18)` into `destination->pixelData`;
- finalizes the context through [UID:000200][0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels](by-memory/0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels.md).

The 32-bit field at `ZPF + 0x04` should be named `zpfPayloadSize` or `payloadSize` in source-facing documentation unless later asset-format source proves a narrower term. `compressedLength` is incomplete because the value is also used as output capacity, `uncompressedLength` is incomplete because the same value is passed to zlib as compressed input length, and `bufferLength` is too broad because it can be confused with the unused second formal parameter.

The binary ignores the `Uncompress` return value and does not compare the final `decodedSize`. The first-draft C++ intentionally preserves that behavior. The inner version-word check precedes the `FPF` signature check in the optimized body, and the copy byte count is computed from destination bounds after allocation rather than directly from the local width/height variables.
