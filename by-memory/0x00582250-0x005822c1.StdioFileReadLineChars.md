## Behavior

`ReadLineChars` reads raw bytes from the `FILE*` stored at object offset `+0x04` into a caller-supplied buffer. It stops at carriage return, line feed, an EOF-like low byte, or the caller limit.

| Case | Observed behavior |
| --- | --- |
| `limit > 0` | Enters the `_getc` loop and starts with `bytesRead = 0`. |
| first `_getc` low byte is `0xff` | Returns `-1` immediately. The compiled comparisons use `AL`, so a byte value `0xff` follows the same path as EOF in this body. |
| character is `0x0d` / CR | Calls `_getc(handle)` one more time unconditionally, discarding the next byte, then exits the loop. This likely consumes the LF after CR, but the binary does not check that the discarded byte is `0x0a`. |
| character is `0x0a` / LF | Exits the loop without storing the LF. |
| later `_getc` low byte is `0xff` | Exits the loop and returns the number of bytes already stored, unless no byte was stored and this was the first read. |
| normal byte | Stores the byte at `buffer[bytesRead]`, increments `bytesRead`, and continues only while `bytesRead < limit`. |
| `bytesRead == limit` at exit | Returns `-1`, so exact buffer fill is reported as failure/overflow rather than a successful count. |
| `limit == 0` | Skips the loop and returns `-1` because `bytesRead == limit`. |
| `limit < 0` | Skips the loop and returns `0` because `bytesRead` remains zero and does not equal the negative limit. |

The method does not append a null terminator. It only writes the raw non-CR/non-LF/non-`0xff` bytes it accepts before termination.
