## Evidence

- IDA MCP confirms `0x004d0f50-0x004d15c5`, `0x004d15d0-0x004d15fc`, and `0x004d1600-0x004d165d` as exact function ranges.
- IDA MCP byte audit on 2026-06-01 confirms the small intervening spans are `0xcc` padding/alignment, not source-authored logic.
- Wave3/simroot resolves the two frame-table helpers and the cleanup helper as recovered globals, but this page uses IDA MCP as the authority for ranges and behavior.
- `LoadImageFrameTable_4D0F50` depends on `DATFile`, [UID:0000T0][HasDATEntry_49C700](by-global/HasDATEntry_49C700.md), `DATFile::GetDataPointer`, allocation/free helpers, and rect initialization.
- `DestroyOwnedImageBlock_4D15D0` frees `block[2]` when present and then frees the outer block; its callers span `ScrolledPictureControlPane` and overlay effecter destructors.
- `LoadFrameDrawRecord_4D1600` has no project callees and is a table projection helper.
- IDA caller checks show both helpers are shared by multiple image/render consumers rather than owned by one asset library.

## Ownership Decision

`LoadImageFrameTable_4D0F50` and `LoadFrameDrawRecord_4D1600` should migrate to `render/ImageFrameTable.cpp`, with the shared frame-record structures in a local header or private implementation section. `DestroyOwnedImageBlock_4D15D0` is source-authored cleanup code for a compatible allocation shape, but its exact source-file parent remains open because callers span both scrolled-picture and overlay-effecter destructors. Keep it visible in this neighborhood while reviewing whether it belongs in `ImageFrameTable.cpp` or a broader render-resource cleanup file.
