# 0x005c5c87-0x005cea43 Msvc Runtime Import And STL Support

## Status

- Disposition: ignored for NexusTK source reconstruction.
- Entity kind: import jump thunks plus Microsoft C/C++ runtime and STL support.
- Rebuild handling: `third-party/runtime` plus compiler/linker-generated import jump thunks.
- Ignored ledger: [UID:0000VN][-ignored](by-memory/-ignored.md).
- Confidence: strong for external/toolchain ownership and exact outer boundaries.
- Boundary source: IDA MCP function and byte review on 2026-06-05.

## Range Summary

This range begins immediately after the corrected [UID:0001O4][0x005c2ac0-0x005c5c87.WorldMapPane](by-memory/0x005c2ac0-0x005c5c87.WorldMapPane.md) `WorldMapPane` helper end at `0x005c5c87` and ends before [UID:0001O5][0x005cea43-0x005cea6d.CrtWtolWrapper](by-memory/0x005cea43-0x005cea6d.CrtWtolWrapper.md) `CrtWtolWrapper` at `0x005cea43`.

The block is not one hand-authored NexusTK source file. It is a toolchain/runtime island containing:

- import thunks for DirectDraw, VERSION, IMM, and libcurl functions;
- `std::exception`, `std::locale`, `_Lockit`, iostream/locale support, and CRT conversion helpers;
- MSVC startup, atexit, thread-safe static, security-cookie, invalid-parameter, and string/integer parsing helpers.

The 2026-06-05 IDA MCP pass reports `0x005c5c87-0x005cea43` inside `.text` with `36284` bytes, `12424` heads, `12341` code heads, `83` data heads, and no unknown heads. IDA currently models `295` function starts in the range. The import-thunk island contains `23` six-byte `ff 25` IAT jumps, of which `22` are IDA-modeled function starts and `0x005c5ccf` is a code-only thunk to `ImmGetConversionStatus`.

## Reconstruction Guidance

Do not port this as NexusTK project code. Rebuilds should get equivalent behavior from the selected compiler/runtime, import libraries, and separately documented third-party libraries. Use this page only as a boundary marker so project-code coverage does not treat the runtime island as an open NexusTK implementation gap.

`RECONSTRUCTABLE:FALSE` is deliberate: the source-level reconstruction should keep the product call sites and declarations that cause these imports/runtime helpers to be linked, but this address range itself is not a NexusTK-authored source object and should not receive parent attachment or final C++.
