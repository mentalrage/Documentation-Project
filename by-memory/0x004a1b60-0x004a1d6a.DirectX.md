## Source-Quality Resolution

B014 reanalysis closes the prior source-quality blockers that kept this page below first-draft C++ readiness. The `0x00631570` GUID used by the constructor's `QueryInterface` call is SDK `IID_IDirectDraw`, not a project-authored `kDirectDrawInterfaceId` and not Browser COM data despite the broader mixed GUID range. The persistent field at `this + 4` is the stored `IDirectDraw`/`LPDIRECTDRAW` interface pointer; `m_pDirectDraw` is the preferred descriptive first-draft name, while older `m_directDraw` wording remains only a semantic alias.

Both DirectDraw setup failure paths allocate and pointer-throw `MyError` using the DirectX diagnostic string at `0x00618e70`; source should use `throw new MyError(...)`, not by-value `throw MyError(...)`. The ordinary destructor calls COM vtable slot `+8`, the `IUnknown::Release` slot, with no observed null guard, then clears the field and `g_pDirectX`. A defensive source-level null check or local cleanup release of the temporary `lpDD` would be an improvement, not a reconstruction of this binary.

The source `Singleton<DirectX>` constructor specialization publishes the complete object before throwing DirectDraw calls; its destructor specialization is inlined in ordinary/scalar teardown and emitted out of line at `0x004a1cc0` for constructor unwind. That specialization is emitted once by UID0000QS, not as a DirectX method. The scalar deleting destructor remains compiler-only. This page emits only the constructor and ordinary virtual destructor.

The external dependency set is `DirectDrawCreate` via IAT `0x0060d024`, COM `QueryInterface` and `Release`, `LObject`, the shared Singleton template/specializations, allocation/throw runtime support, SDK `IID_IDirectDraw`, and coordinated `MyError` declarations/source under `util/Error.h` and `Error.cpp`. No external routine receives a reconstructed project body here.
