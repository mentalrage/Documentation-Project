## Evidence Notes

- `lookup_funcs` confirms `sub_4A1B60` size `0xf6`, `sub_4A1C60` size `0x5c`, `sub_4A1CC0` size `0x0b`, and `sub_4A1CD0` size `0x9a`; `0x004a1d6a` is not a function and `0x004a1d70` is the next function start.
- Constructor decompilation/disassembly calls `sub_4F4A80` for `LObject` construction, stores `g_pDirectX` at `0x0067ab20`, stores the [UID:0002MD][0x00618e60-0x00618e70.DirectXVtableData](by-memory/0x00618e60-0x00618e70.DirectXVtableData.md) at `0x004a1bbf`, zeroes `this + 4`, calls `DirectDrawCreate`, then calls the returned interface vtable slot with GUID data at `0x00631570` and output pointer `this + 4`.
- Both `DirectDrawCreate` and `QueryInterface` failure paths allocate an 8-byte `MyError` object, initialize it from the DirectX diagnostic string, and throw via `__CxxThrowException`.
- Destructor decompilation/disassembly loads `this + 4`, calls COM vtable slot `+8`, clears the interface field, clears `g_pDirectX`, and tail-runs `sub_4F4A90` for `LObject` destruction.
- The tiny `0x004a1cc0` helper only clears `g_pDirectX`; `xrefs_to 0x004a1cc0` shows the reference from the constructor's far compiler EH/unwind chunk at `0x005fd71e`.
- Scalar deleting destructor repeats the release/clear/base-destroy sequence, conditionally frees the object through `sub_4F4AC0` when delete flag bit `1` is set and bit `4` is clear, and includes an IDA-reported guarded-delete branch.
- `callers` reports the constructor's direct caller at `0x004645aa` inside application startup `sub_4639D0`; other methods have no normal direct callers because they are reached through vtable/EH/destructor machinery.
- `callees` reports constructor dependencies on `sub_4F4A80`, allocator `sub_4F4AA0`, `MyError` initializer `sub_4A67A0`, `DirectDrawCreate`, and `__CxxThrowException`; destructor methods use `sub_4F4A90`, and the deleting destructor also uses `sub_4F4AC0`.
- `xrefs_to 0x00618e64` reports DirectX vtable stores at `0x004a1bbf`, `0x004a1c88`, and `0x004a1cf8`.
- `xrefs_to 0x0067ab20` reports writes from the constructor, destructor, unwind helper, and deleting destructor, plus reader references from application/render/surface code including `0x00464b44`, `0x004b8d78`, `0x004b92bc`, `0x004b9800`, `0x004bb83f`, and several `0x00556xxx-0x00559xxx` render helpers.
- IDA also associates far compiler EH chunks with the constructor/destructor functions. Those chunks are compiler support for unwinding and security-cookie handling, not separate handwritten DirectX methods owned by this local range.
