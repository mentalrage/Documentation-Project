## Behavior Evidence

- `lookup_funcs` confirms real IDA functions at `0x00530020`, `0x00530230`, `0x005304c0`, `0x005304f0`, `0x00530565`, `0x00530570`, and `0x00530580`.

- Submit reads account/password controls `2` and `3`, calls `sub_528310(dword_67AB50, account, password)` through the [UID:00008I][MiscWorkThread](by-class/MiscWorkThread.md) NCA submission path, assigns `sub_530020` into a `PlainMemberFunctionObject` callback object, stores the pending alert pointer at primary object offset `+0x274`, and starts a `30000` millisecond timer.
- `sub_530020` clears the pending flag at `+0x270`, cancels timer state at `+0xa4`, destroys the pending alert pointer at `+0x274`, and nulls that pointer.
- `sub_530230` rejects non-registration response packets or inactive requests, clears pending/timer/alert state, closes the global active dialog when present, and dispatches result code `0` through the success callback.
- On success, `sub_530230` calls `sub_5304C0` to read control slot `2` through the text-control `GetText` path, invokes the result handler, then destroys the temporary string.
- For result codes `1` through `5`, `sub_530230` calls `sub_5304F0` with message ids `228`, `229`, `230`, `231`, and `232`.
- 2026-06-04 live IDA immediate search finds the only consumer-side `0x4e634175` (`NCAu`) compare at `0x0053025a` inside `sub_530230`.

- `sub_530410` mirrors the pending-alert cleanup path and creates a status alert for message id `234`.
- `sub_5304F0` allocates a `624` byte alert object, looks up the localized message string through language/global string table data, and constructs a predefined/status alert with callback table `off_613A18`.
