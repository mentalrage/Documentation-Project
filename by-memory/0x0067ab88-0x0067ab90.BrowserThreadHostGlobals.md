## Ownership And Source Placement

Keep this pair under [UID:0000HV][Browser](by-file/Browser.md). These are Browser module globals, not a BrowserThread class member pair and not two independent source roots. The first slot is a BrowserThread object pointer consumed by BrowserDialogOld and Browser event code; the second slot bridges BrowserThread setup into a free/static Win32 WndProc callback that operates on the legacy [UID:000013][Browser](by-class/Browser.md) object.

The individual by-global pages [UID:0000QE][g_pBrowserThread](by-global/g_pBrowserThread.md) and [UID:0000QO][g_pCurrentBrowserHost](by-global/g_pCurrentBrowserHost.md) remain the canonical symbol/support pages for each slot, but neither owns this two-slot storage item alone. Reowning the by-memory pair to one by-global page would orphan the other slot. Reowning to [UID:00001A][BrowserThread](by-class/BrowserThread.md), [UID:000013][Browser](by-class/Browser.md), BrowserDialogOld, BrowserControlPaneOld, or PlatformApi would confuse consumers/callees with the source declaration owner. PlatformApi owns unrelated dispatch slots such as `g_pfnDefWindowProcW`, not these Browser globals.

The active IDB's `Singleton<BrowserThread>` RTTI names are a source-spelling caveat. Current docs do not prove that `0x0067ab88` must be emitted as an exact template static-member declaration. Use the established source-facing declaration `static BrowserThread *g_pBrowserThread` unless a later Browser source-layout pass proves a different original declaration shape.

## Rejected Alternatives

- Padding or unknown-data treatment is rejected because the slots are referenced writable zero-initialized storage with constructor, destructor, publish, clear, and consumer paths.
- Raw `DWORD` or `void *` typing is rejected for `0x0067ab88` because all meaningful consumers use BrowserThread offsets such as `+0x60`, `+0x68`, and `+0x70`.
- `BrowserThread` class ownership is rejected for the storage pair because the declaration is Browser module state and has BrowserDialogOld/Browser consumers outside the class.
- Individual by-global ownership for the pair is rejected because [UID:0000QE][g_pBrowserThread](by-global/g_pBrowserThread.md) and [UID:0000QO][g_pCurrentBrowserHost](by-global/g_pCurrentBrowserHost.md) each cover only one slot.
- Browser class-only ownership is rejected because the pair includes BrowserThread singleton storage as well as the current-host Browser object bridge.
- PlatformApi ownership is rejected because the slots are browser host/thread state, not Win32 API dispatch storage.
- Persistent `BrowserWindow *` typing is rejected for `0x0067ab8c`: the producer publishes the legacy `Browser` object from `BrowserThread +0x68`, the same pointer is installed in `GWL_USERDATA`, and the WndProc reads Browser fields `+0x14` and `+0x18`.
- Mandatory `Singleton<BrowserThread>` static-member declaration is not adopted because RTTI exists but no current storage/linkage evidence ties this exact slot to a required template static-member spelling.
