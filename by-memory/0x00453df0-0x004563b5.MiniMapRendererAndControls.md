## Support-Helper Caveats

The physical gap between `MiniMapRenderer::BuildSymbolViews` and `MiniMapSymbolControlPane` contains renderer support helpers, vector/string helpers, and local file-loader helpers referenced by the renderer. Current evidence supports keeping them near minimap during review, but not all should be renamed as `MiniMapRenderer` methods without a separate helper pass. Known support-helper addresses from IDA callee evidence include `0x004550d0`, `0x004551e0`, `0x00455350`, `0x00455600`, `0x00455a40`, `0x00455a90`, and `0x00455b40`.

The 2026-06-07 live IDA MCP pass splits that caveat into three buckets:

| Range | Current role | Ownership note |
| --- | --- | --- |
| `0x004550d0-0x004551df` | 80-byte record-vector insert/grow helper | Called by `BuildSymbolViews` only in this range; operates on renderer-owned symbol/view records but still reads like generated vector support. |
| `0x004551e0-0x00455349` | 108-byte record-vector insert/grow helper | Called by `BuildSymbolViews`; allocates/copies larger renderer label/view records and uses local element-copy helpers. |
| `0x00455350-0x004554df` | 24-byte UTF-16 small-string vector insert/grow helper | Called by `BuildSymbolViews` and also by non-minimap runtime/string helper paths at `0x005bc970` and `0x005bffe0`, so treat as shared string-vector support inside the aggregate until split. |
| `0x00455600-0x0045578d` | 24-byte UTF-16 small-string vector copy/clone helper | Used by `BuildSymbolViews` and several local helpers, with the same shared-string caveat. |
| `0x00455a40-0x00455a8f` | 80-byte record-vector reserve/copy helper | Called by `BuildSymbolViews`; likely renderer-local vector support. |
| `0x00455a90-0x00455b34` | 108-byte record-vector reserve/copy helper | Called by `BuildSymbolViews`; likely renderer-local vector support. |
| `0x00455b40-0x00455bb5` | 24-byte string-vector cleanup helper | Called by `BuildSymbolViews`, local string-vector helpers, MetaTable cleanup, and late string/runtime helpers; keep as shared support caveat rather than a renderer method name. |

`MiniMapRenderer::BuildSymbolViews` also calls file-loader helpers at `0x00457620`, `0x004576b0`, and `0x00457850`; those sit closer to the [UID:0000XP][0x004563c0-0x00457547.MiniMapVersionManager](by-memory/0x004563c0-0x00457547.MiniMapVersionManager.md) range and should get separate documentation if the `.mnm` parser/file-loader format is researched in detail.

The version checks at `0x00454150` and `0x00454d80` call [UID:0000XQ][0x004570b0-0x004570e0.MiniMapVersionLookupByMapId](by-memory/0x004570b0-0x004570e0.MiniMapVersionLookupByMapId.md). That helper belongs to `MiniMapVersionManager`, not the renderer, because it queries the manager-owned hash index at `g_pMiniMapVersionManager`.
