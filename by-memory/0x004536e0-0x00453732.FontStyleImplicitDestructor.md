## Behavior

This lowered cleanup releases the `FontStyle` rule-vector backing allocation and resets the vector triplet at object offsets `+0x14`, `+0x18`, and `+0x1c`.

| Object offset | Meaning |
| --- | --- |
| `+0x14` | `rulesBegin` allocation/user pointer |
| `+0x18` | `rulesEnd` |
| `+0x1c` | `rulesCapacity` / allocation end |

If `rulesBegin` is null, the method returns without touching the object. Otherwise, it checks whether the rounded vector span `(rulesCapacity - rulesBegin) & 0xfffffff0` is at least `0x1000`. Large spans use the MSVC aligned-allocation header convention: the true allocation base is read from the dword immediately before `rulesBegin`, and the header gap must be at most `0x1f`. Failure calls `_invalid_parameter_noinfo_noreturn`.

After validation, the lowered body frees the selected allocation pointer through the shared heap-free helper at `0x005c7526`, then zeros `rulesBegin`, `rulesEnd`, and `rulesCapacity`.

This is compiler/container cleanup detail. Do not hand-port the allocation guard, free helper, triplet zeroing, or an empty destructor into source C++; all would duplicate or distort what the vector member generates.
