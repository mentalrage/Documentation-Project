# 0x004f5b20-0x004f5c73 MAPI Send Mail Helper

## Status

- Disposition: reconstructable NexusTK project code.
- Entity kind: standalone Win32 Simple MAPI helper function.
- Likely source file: [UID:0000ML][PlatformApi](by-file/PlatformApi.md).
- Current route: [UID:0000ML][PlatformApi](by-file/PlatformApi.md) emits this helper into `auto-generated/NexusTK/platform/PlatformApi.cpp`.
- Confidence: strong for range, body behavior, SDK structure interpretation, PlatformApi placement, and first-draft C++; still below final audit because no original symbol, direct feature caller, or fresh 2026-06-19 live IDA session is available.

## Behavior

This helper dynamically loads `MAPI32.DLL`, resolves `MAPISendMail`, converts caller-provided UTF-16 strings to ANSI/default-codepage buffers through [UID:000249][0x00599440-0x005995a7.PlatformStringConversionHelpers](by-memory/0x00599440-0x005995a7.PlatformStringConversionHelpers.md), builds one stack-local `MapiRecipDesc`, optional `MapiFileDesc`, and `MapiMessage`, calls `MAPISendMail(0, 0, &message, 0, 0)`, ignores the MAPI return value, frees the converted strings, and unloads the MAPI library.

The first wide-string input is converted twice and used for both `MapiRecipDesc.lpszAddress` and `MapiRecipDesc.lpszName`. That makes `recipient` the best current source-facing parameter name. It is not a sender/originator value: `MapiMessage.lpOriginator` stays null and the populated structure is `lpRecips`.

The second wide-string input is the message subject, the third is the `MapiMessage.lpszNoteText` body text, and the fourth is an optional attachment path. When an attachment is supplied, the helper fills one `MapiFileDesc` with `nPosition = (ULONG)-1`, `lpszPathName = attachmentPathAnsi`, `lpszFileName = NULL`, and `lpFileType = NULL`; the message then receives `nFileCount = 1` and `lpFiles = &fileDesc`.

The message flag value `2` is `MAPI_RECEIPT_REQUESTED`, not `MAPI_SENT`. Current Windows `MAPI.h` defines `MAPI_RECEIPT_REQUESTED` as `0x00000002` and `MAPI_SENT` as `0x00000004`, so earlier generated-summary interpretations that called this a sent-message flag are rejected.

`GetProcAddress` failure currently returns without a `FreeLibrary` call in the observed Ghidra/exported shape. The draft C++ intentionally preserves that behavior rather than silently "fixing" it, because the current evidence places `FreeLibrary` only on the successful resolved/send path.

## Heuristic / Inference Reanalysis And Validation

### Function Name

`MapiSendMailHelper` is a descriptive/inferred source-facing name, not an original symbol. It is the best current name because the body loads `MAPI32.DLL`, resolves `MAPISendMail`, constructs SDK MAPI records, and calls the function pointer. Rejected alternatives:

- `MAPISendMailHelper`: too close to Microsoft SDK/shim naming and implies an SDK helper rather than product-local glue.
- `SendMailPacket` or in-game mail names: rejected because the helper uses Win32 Simple MAPI, not NexusTK packet buffers.
