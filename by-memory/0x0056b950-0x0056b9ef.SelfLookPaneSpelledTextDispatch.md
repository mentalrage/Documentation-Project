## Behavior

This helper decodes one packet text payload and forwards it to the `SpelledPane` child stored at `this+0xfc` (`0xfc` / 252 decimal, Verified with `tools/int_convert.py`). B006's 2026-06-25 MCP pass reports the current decompiler prototype as `char __thiscall(_DWORD **this, int)`, correcting the older `__stdcall` wording from the A002 pass. The body treats `ecx` as the `SelfLookPane` instance, saves it in `edi`, initializes a packet cursor to `1`, reads a one-byte length-prefixed text field through [UID:0001HZ][0x00575380-0x00575abb.PacketBufferHelpers](by-memory/0x00575380-0x00575abb.PacketBufferHelpers.md) helper `0x00575a10`, then asks `0x00575790` for an optional big-endian 32-bit value from the same cursor.

When the optional value is zero or absent, the helper extracts the temporary text buffer through `0x00584540` and calls `0x0056be20` on the embedded `SpelledPane` child with `(text, 0)`. When the optional value is nonzero, it extracts the same text buffer and calls `0x0056bca0` on the child with `(text, value, 0)`. It then releases the temporary string-like object through `0x00582b70` and returns `0`.

This is dispatch glue owned by `SelfLookPane`, not a `SpelledPane` entry-vector method. The target reads the child pointer from the self-look object and merely calls the `SpelledPane` add/update or remove helper after packet decoding.

Source-facing names used in the first-draft C++ are inferred but evidence-backed. `m_spelledPane` names the `this+0xfc` child pointer, `DispatchSpelledText` names this standalone dispatch helper, `PacketBufferReadAnsiString8` and `PacketBufferReadUInt32BE` name the existing packet helpers at `0x00575a10` and `0x00575790`, and `SpelledPane::AddOrUpdateEntry` / `SpelledPane::RemoveEntry` name the revalidated child callees. Exact original spelling remains below final audit, but these names are the current best source-facing reconstruction and no longer justify leaving the formal C++ block blank.
