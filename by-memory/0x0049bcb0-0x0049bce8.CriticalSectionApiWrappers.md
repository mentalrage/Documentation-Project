## Behavior

These are tiny thiscall-style methods for a source-facing `CriticalSection` utility object around Win32 critical-section APIs. The storage layout is consistent with a `CRITICAL_SECTION` member at offset zero: construction initializes the storage, destruction deletes it, and the emitted enter/leave methods forward the same storage to the Win32 API.

`0x0049bcb0` is the only helper IDA currently promotes as an ordinary direct function in this island. `0x0049bcc0` is reached from the static cleanup helper at `0x0060c0e0`, which loads the static critical-section object at `0x0067a9a4` and jumps into the delete wrapper. `0x0049bcd0` and `0x0049bce0` are present as aligned callable bodies but have no direct xrefs in the current IDA database and no current section-wide VA/RVA pointer hits. Application uses the same static instance through [UID:00003C][CriticalSectionLock](by-class/CriticalSectionLock.md), not through these raw enter/leave methods.
