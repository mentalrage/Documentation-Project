# 0x0046ff50-0x00470159 BrowserControlPaneOld Constructor

## Scope

- Likely source file: [UID:0000HV][Browser](by-file/Browser.md).

## Summary

This constructor builds the legacy browser control pane, constructs its `MSGHandler` secondary base, allocates the embedded COM-style `Browser` host object, copies the initial URL string into the `Browser` object through Browser-owned initialization support, allocates/starts a `BrowserThread`, stores `g_pBrowserThread`, and stores the constructed `Browser` pointer at the control-pane object offset `+0x110`.

The range is reconstructable NexusTK project code and now emits first-draft C++ above. The previous "Browser field names incomplete" blocker is superseded: `Browser` field names are resolved enough for documentation, and direct private-field writes are avoided by the accepted support-declaration plan for `Browser::Browser(const wchar_t *initialUrl)` and `BrowserThread::BrowserThread(Browser *browser, const RectBounds &bounds)`.

BrowserControlPaneOld::BrowserControlPaneOld(const RectBounds *bounds, const wchar_t *initialUrl);

Confidence is high for `BrowserControlPaneOld` ownership and the two logical arguments. `RectBounds` is the current project-local rectangle spelling used by the accepted [UID:0002PB][0x004949e0-0x00494a81.ControlPaneConstructor](by-memory/0x004949e0-0x00494a81.ControlPaneConstructor.md); exact original helper/global names for the null-bounds quirk remain confidence caps.

## Behavior

- Calls the control-pane/base constructor at `0x004949e0` with style/id value `8` and the caller-supplied bounds pointer.
- Constructs the `MSGHandler` secondary base through `0x00528d60` at `this + 0x108`.
- Installs four `BrowserControlPaneOld` vtable pointers across the primary, inherited pane-family, and `MSGHandler` secondary-base views: `0x00613780`, `0x006137e8`, `0x00613818`, and `0x00613824`.
- Clears the embedded browser pointer at `this + 0x110`.
- If the bounds pointer is null, calls `0x004b78d0` with zero rectangle inputs plus `word_66DA94/word_66DA98`.
- Allocates a `0x234` byte `Browser` object and installs five Browser vtable/interface pointers at offsets `+0x00` through `+0x10`.
- Initializes Browser fields at `+0x14`, `+0x18`, `+0x228`, `+0x22c`, and `+0x230`.
- Writes the Browser initialization word `0x0101` at Browser offset `+0x22c`.
- Allocates a heap copy of the input wide URL string and stores it at Browser offset `+0x228`.
- Allocates a `0x80` byte `BrowserThread` object, constructs its `Thread` base, stores it in `g_pBrowserThread`, installs the BrowserThread vtable, attaches the Browser pointer at thread offset `+0x68`, clears byte `+0x6c`, copies the bounds rectangle to `+0x70`, and starts the thread through `0x005965e0`.
- The emitted first draft uses source-level `new Browser(initialUrl)`, `new BrowserThread(browser, *bounds)`, `g_pBrowserThread = thread`, and `thread->StartThread()` rather than raw allocation/vtable/offset stores.
