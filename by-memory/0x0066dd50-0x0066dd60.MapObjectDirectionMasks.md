# 0x0066dd50-0x0066dd60 Map Object Direction Masks

## Summary

- Address range: `0x0066dd50-0x0066dd60`
- Entity kind: initialized byte lookup masks
- Disposition: reconstructable project data
- Rebuild handling: owner-local static byte tables
- Confidence: strong for bytes, xrefs, caller contexts, and boundaries; medium for final table names and the meaning of the repeated index-4 entries
- Parent attachment: attached to [UID:0000L3][MapPane](by-file/MapPane.md), whose current confidence is `80`.
- Reconstruction note: C++ intentionally left blank because the exact directional mapping and final source symbol names are not final-source quality.

This range contains two adjacent eight-byte direction/mask lookup tables used by MapPane movement, occupancy, and object-nation gating. Live IDA shows the main MapPane movement helper indexing both tables with the movement direction and testing the results against map/object classification bytes; two tiny unmodeled accessor bodies also return one byte from the corresponding table by signed index. Each half has five nonzero bytes followed by three zero bytes, so the previous "four active bytes plus padding" description was too narrow.

## Consumer Details

- `0x00505430-0x005055ca` is a MapPane movement/occupancy helper. Live decompilation shows it derives a neighbor coordinate from the direction byte, checks visible/map bounds, handles an override flag, probes the object list for a blocking object, reads the object-record count and object-nation map, and then tests the two table lookups against the current and target map-cell bytes before returning pass/fail status.
- Live `callers` for `0x00505430` report nine code callers: four sites in the `0x0050c790` path-scanning body, four sites in the `0x0050d010` path-scanning body, and one local-player movement call at `0x005a3207`. The first eight sites sit in [UID:0001AT][0x00506970-0x0050e320.MapPaneInputPacketRenderCore](by-memory/0x00506970-0x0050e320.MapPaneInputPacketRenderCore.md); the local-player site sits in [UID:0001KM][0x005a2de0-0x005ad440.LivingObjectPaneLocalPlayerExtensions](by-memory/0x005a2de0-0x005ad440.LivingObjectPaneLocalPlayerExtensions.md).
- The two unmodeled accessor bodies at `0x0050c430-0x0050c43e` and `0x0050c450-0x0050c45e` each load a signed byte index and return the corresponding table byte. Live IDA has no code xrefs to those body starts, so they are useful table-consumer evidence but not a proven high-level API boundary.
