## IDA MCP Evidence

- `decompile 0x00582d80` assigns `0x00670290` for empty ANSI strings, otherwise selects 64/128/256/512 capacity pools at `0x0069bb6c`, `0x0069bb94`, `0x0069bbbc`, and `0x0069bbe4`, or heap-allocates `requested + 13` bytes. It writes `refCount=1`, `length=requested`, `capacity`, the NUL terminator, and returns `header + 0x0c`.
- `decompile 0x00582e30` mirrors the same model for wide strings, using `0x00670278` for empty strings and wide-capacity pools including `0x0069bacc`; heap allocation uses `2 * requested + 14` bytes.
- `decompile 0x00582ef0` retains the old ANSI buffer, releases the current pointer through `0x005832f0`, allocates a larger buffer with `0x00582d80`, copies the old bytes, and releases the temporary retained pointer.
- `decompile 0x00583050` checks `refCount > 1`, allocates a same-sized ANSI buffer, copies the bytes, and releases the old shared buffer. The wide sibling at `0x005830c0` follows the same shape.
- Caller checks for `0x00582d80` show use from constructors, assignment, grow, COW, formatting continuation helpers, and later mutation helpers, confirming central string allocator ownership.
