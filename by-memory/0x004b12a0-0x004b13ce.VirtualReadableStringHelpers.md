## Ownership Analysis

### Accepted: [UID:00004V][File](by-class/File.md) `File` Class

Evidence for:

- Both bodies are `__thiscall` helpers that dispatch through `this->vtable`, making them class/interface helpers rather than ordinary free functions.
- The exact virtual slot offsets match the documented File stream contract: `+0x14` position, `+0x1c` size, `+0x20` read, and `+0x24` line-read.
- The abstract [UID:00004V][File](by-class/File.md) class is `86/89` and the source root [UID:0000JB][File](by-file/File.md) is `86/88`, so the child and direct parent chain clear the current strict `85/85` gate.
- The helper pair is generic over concrete file implementations: the same slots are implemented by [UID:00003G][DATFile](by-class/DATFile.md) and [UID:0000E6][StdioFile](by-class/StdioFile.md), so assigning to either concrete class would be too narrow.

Evidence against / uncertainty:

- Current IDA reports no direct callers or address-taken refs, so final method names and whether these were public, protected, or local inline-like helpers are not proven.
- The original source may have grouped the implementations in a compact `FileIO.cpp` rather than a separate `File.cpp`; direct class parent remains `File` either way.

### Rejected: [UID:0000OB][StringUtil](by-file/StringUtil.md) `StringUtil`

Evidence for:

- The helpers call shared string routines in the `0x00582xxx` / `0x00584xxx` family.
- The destination types are string objects.

Evidence against:

- String routines are callees used to allocate/assign destination buffers; they are not the primary receiver.
- The primary receiver dispatches File stream vtable slots. Consumer/callee similarity is weaker ownership evidence than a `this`-based class/interface contract.
- B001-021 IDA evidence identifies the unresolved "virtual readable" interface as the File stream contract, so `StringUtil` is a dependency, not the direct owner.

### Rejected: [UID:0000OA][StringBase](by-file/StringBase.md) `StringBase`

Evidence for:

- The helper bodies call `StringBase` allocation, conversion, assignment, and release helpers.

Evidence against:

- Same as `StringUtil`: the string layer is destination-buffer infrastructure. The owning object is the File stream receiver.
- These bodies do not operate on a `StringBase` object as `this`; they pass string objects as output parameters/temporaries.

### Rejected: `DATFile` or `StdioFile`

Evidence for:

- Concrete DATFile and StdioFile vtables implement the slots used by the helpers.

Evidence against:

- The helpers use only the abstract File contract and do not touch DAT-specific fields, CRT `FILE*`, or Stdio-specific state.
- Assigning to one concrete implementation would exclude the other implementation that satisfies the same slots.
