## Behavior

At source level, the method clears the item-state equipment-entry vector:

```cpp
m_selectedFittingItems.clear();
```

The compiled body resets an active vector of fixed-size equipment entries without releasing the vector storage itself. It walks entries from `this + 0x240` to `this + 0x244`, stepping by `0xb4` bytes per entry, releases each entry-local trailing buffer, zeros that buffer triplet, then collapses the vector by assigning `end = begin`.

| Object offset | Meaning |
| --- | --- |
| `+0x240` | `EquipmentEntry* begin` |
| `+0x244` | `EquipmentEntry* end` |
| `+0x248` | likely `EquipmentEntry* capacity`; initialized by the constructor and not modified here. |

Each `0xb4`-byte entry contains a vector/string-like heap buffer at the tail:

| Entry offset | Meaning |
| --- | --- |
| `+0x0a8` | buffer begin/allocation pointer |
| `+0x0ac` | buffer current pointer |
| `+0x0b0` | buffer end pointer |

If the buffer pointer is null, the entry is already empty and is skipped. Otherwise, the helper computes `(end - begin) & 0xfffffffc`. For spans at least `0x1000`, it treats `begin[-1]` as the true allocation base, verifies `begin - allocationBase - 4 <= 0x1f`, and calls `_invalid_parameter_noinfo_noreturn` if the header fails the MSVC aligned-allocation guard. It then frees the allocation base. For smaller spans, it frees `begin` directly through `sub_5C7526`.

After freeing, the method writes zero to the three entry buffer pointers. Once every active entry has been handled, it writes `this[145] = this[144]`, collapsing the active entry range to empty while leaving capacity untouched.
