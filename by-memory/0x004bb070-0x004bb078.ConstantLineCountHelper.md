## Exact Bytes And Boundary

```asm
004bb06a: cc cc cc cc cc cc          ; six bytes of pre-padding
004bb070: b8 01 00 00 00             ; mov eax, 1
004bb075: c2 0c 00                   ; ret 0x0c
004bb078: cc cc cc cc cc cc cc cc    ; eight bytes of post-padding
```

The half-open range `0x004bb070-0x004bb078` is exact. The helper has no callees, no data reads, no global reads, no global writes, no vtable writes, no locals, no exception/unwind scaffolding, and no side effects beyond returning `1`.

`ret 0x0c` means the callee pops three explicit stack arguments. The caller-provided context is not on the stack; both live caller families load it into `ecx` immediately before the helper call. The old plain `__stdcall(int,int,int)` decompiler projection is behaviorally close but hides the important callback-compatible `ecx` receiver shape.
