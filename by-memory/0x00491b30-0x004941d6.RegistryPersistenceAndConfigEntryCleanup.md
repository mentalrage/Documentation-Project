## Notes

`SaveToRegistry` and `LoadFromRegistry` are the registry persistence half of `config/RegistryConfig.cpp`; `Config::DeletingDestructor` and `ConfigEntryBlock::ReleaseOwnedBuffers` are base storage cleanup paths physically adjacent after the registry load function.

The immediately preceding [UID:000220][0x0048f400-0x00491b28.RegistryCommandLineParsers](by-memory/0x0048f400-0x00491b28.RegistryCommandLineParsers.md) page covers the command-line/login/session helper island that sits between default initialization and registry save/load.

IDA confirms `ConfigEntryBlock::ReleaseOwnedBuffers` callers from `RegistryConfig::~RegistryConfig`, `RegistryConfig::LoadFromRegistry`, `Config::DeletingDestructor`, and a shared cleanup wrapper around `0x00493f90`.

2026-05-25 IDA MCP recheck confirms `0x00491b30` and `0x004926a0` remain real functions. `SaveToRegistry` opens `Software\Nexon\Kingdom of the Winds`, writes option/server/color values, and closes registry handles. `LoadFromRegistry` creates/reads a CLSID value under `HKEY_CLASSES_ROOT`, loads the same Nexon registry key family, and rebuilds adapter/server metadata.

A later 2026-05-25 MD5 pass confirms `LoadFromRegistry` calls [UID:0001B6][0x005151f0-0x00515f48.MD5HashHelpers](by-memory/0x005151f0-0x00515f48.MD5HashHelpers.md) at `0x004928ba`, passing a registry-derived string/length and a 16-byte output buffer near the config object. This is a dependency on the shared [UID:0000L6][MD5](by-file/MD5.md) utility, not registry-module ownership of the hash implementation.

2026-05-27 boundary recheck: IDA MCP `lookup_funcs` reports `sub_494130` size `0xa6`, so the end-exclusive address is `0x004941d6`. Direct PE bytes show the final `ret` byte at `0x004941d5`, followed by padding before [UID:000221][0x004941e0-0x00494519.MsvcComAndFormattingHelpers](by-memory/0x004941e0-0x00494519.MsvcComAndFormattingHelpers.md).

2026-06-01 IDA MCP function inventory splits exact child pages for `RegistryConfig::SaveToRegistry`, `RegistryConfig::LoadFromRegistry`, `Config` deleting-destructor cleanup, and `ConfigEntryBlock::ReleaseOwnedBuffers`. The same pass finds unresolved non-padding bytes in `0x00493e29-0x00493ef0` and `0x00493efb-0x00493f10`, so this aggregate is not fully split yet and should stay below high completion.
