## Registry Evidence

`LoadAndRenderImage` calls the function currently recovered as `g_pEPFLib->GetFrame(...)`. The call target resolves to `ResourceLayoutTable::LookupLayoutEntry` at `0x004d02f0`, while `g_pEPFLib` itself is initialized by `ImageLib::ImageLib`. This class is therefore a UI consumer of the shared image/layout registry, not an owner of it.

## Render Callback Caveat

Active `simroot_v2` emits `g_pfnLockSurface(drawSurface)`, but IDA MCP decompilation on 2026-05-25 shows the real callback-table call shape as `dword_69B3FC(this, this + 68)`. Treat `g_pfnLockSurface` as a generated alias for shared [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md) storage, not as an `EPFImageControlPane`-owned global or a proven one-argument function pointer.
