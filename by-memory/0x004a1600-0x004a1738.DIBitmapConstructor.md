## Behavior

The constructor initializes the `LObject` base, clears only the DIB bits member before the first throwing allocation, allocates and zeroes `sizeof(BITMAPINFOHEADER) + 2 * width * height` temporary bytes, builds a top-down 16-bpp `BI_RGB` header, aligns the DIB width to a multiple of four pixels, and copies the 40-byte header into both the temporary `BITMAPINFO` and object. It then calls `CreateDIBSection`, stores the returned `HBITMAP`, stores requested width/height, releases the temporary bytes, and returns the constructed object.

The aligned row width is `width + (width % 4 != 0 ? 4 - width % 4 : 0)`. At two bytes per pixel, row stride is `2 * alignedWidth` and is divisible by eight for valid positive dimensions; describing this only as generic DWORD alignment loses the stricter observed four-pixel rule. The constructor performs no dimension, overflow, allocation-result, or GDI-result validation of its own.
