## Layout Evidence

Every exact child uses the same Decoder cursor-state fields:

```text
+0x04  input buffer pointer
+0x08  input buffer size/limit
+0x0c  current read position
+0x10  byte-order flag for 16-bit length fields
+0x11  valid/readable flag
```

The text and byte readers check `+0x11`, bounds-check against `+0x08`, advance `+0x0c` only after accepted input, and clear `+0x11` on failure. The 16-bit length readers branch on byte-order flag `+0x10`. The multibyte readers call `MultiByteToWideChar`; [UID:0003LC][0x004a5cd0-0x004a5d79.DecoderReadCompressedBytes](by-memory/0x004a5cd0-0x004a5d79.DecoderReadCompressedBytes.md) calls [UID:0000W2][0x004142c0-0x00414565.ZlibPublicCompressChecksum](by-memory/0x004142c0-0x00414565.ZlibPublicCompressChecksum.md)'s `uncompress` wrapper at `0x00414390`.
