# 0x00470dd0-0x00470f10 Browser Navigate

## Scope

- Range: `0x00470dd0-0x00470f10` half-open.
- Entity kind: class method.
- Owner: [UID:000013][Browser](by-class/Browser.md).
- Parent inventory: [UID:0000ZF][0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers](by-memory/0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers.md).

This is the source-authored `Browser::Navigate` method used by BrowserDialogOld, Browser event handling, and BrowserThread host initialization to navigate the hosted WebBrowser object from the legacy Browser COM/event-sink object. It was previously documented as `BrowserWindow::Navigate`; that interpretation is historical and rejected because every checked route supplies a Browser object while BrowserWindow owns a separate method at `0x00469ca0`.

## Ownership, Cleanup, And EH

- Normal cleanup order is flags VariantClear, targetFrameName VariantClear, headers VariantClear, SafeArrayDestroy(postData.parray), SysFreeString(browserUrl), then postData VariantClear.
- SafeArrayDestroy and normal VariantClear return values are ignored. SysFreeString has no result.
- The two branches to [UID:00033I][0x00470960-0x0047097c.CAtlExceptionThrowHelper](by-memory/0x00470960-0x0047097c.CAtlExceptionThrowHelper.md) occur before Navigate and are only the inlined `CComVariant` null-BSTR constructors' ClearThrow checks. They are not Navigate failure handling.
