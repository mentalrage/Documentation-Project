# 0x005c12a0-0x005c1bc7 Weather And Raining Layer Panes

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: class aggregate over base weather pane and rain overlay methods
- Current Wave3 owners: `WeatherLayerPane` and `RainingLayerPane`
- Likely source modules: [UID:0000P8][WeatherLayerPane](by-file/WeatherLayerPane.md) and [UID:0000MY][RainingLayerPane](by-file/RainingLayerPane.md)
- Confidence: strong for function boundaries and behavior, medium for final file split

## Covered Ranges

| Range | Current owner | Function | Notes |
| --- | --- | --- | --- |
| `0x005c12a0-0x005c13a0` | `WeatherLayerPane` | constructor | Initializes pane, vtables, tile-derived bounds, animation state, and timer/layout base. |
| `0x005c13b0-0x005c1407` | `WeatherLayerPane` | `OnTimerEvent` | Advances animation frame, invalidates/repaints parent, and schedules next timer. |
| `0x005c1410-0x005c1459` | `RainingLayerPane` | constructor | Calls `WeatherLayerPane`, installs rain vtables, and sets rain animation parameters. |
| `0x005c1460-0x005c180b` | `RainingLayerPane` | `OnPaint` | Draws main-view rain streaks and splash patterns. |
| `0x005c1810-0x005c1bc7` | `RainingLayerPane` | `DrawRainOnTarget` | Draws rain pattern on a supplied target `GrafPort`. |

## Evidence Notes

- IDA MCP confirms all listed starts and sizes on 2026-05-24.
- IDA caller checks show `WeatherLayerPane::WeatherLayerPane` is called by the rain, snow, and swallow constructors.
- IDA caller checks show `MapPane` weather setup at `0x0050db50` allocates 268 bytes and calls `RainingLayerPane::RainingLayerPane` when weather type `1` is selected.
- 2026-05-24 recheck: `WeatherLayerPane::OnTimerEvent` has vtable data refs at `0x00631218`, `0x006312a8`, and `0x00631338`; `RainingLayerPane::OnPaint` has a vtable ref at `0x00631264`; `RainingLayerPane::DrawRainOnTarget` has a vtable ref at `0x00631230`.
- Current simroot metadata describes rain coordinate tables for 18 streaks, 7 small splashes, and 7 large splashes per frame, with alternate target/minimap table variants.
- IDA decompilation shows the target/minimap rain table starts at `0x006702c8`, `0x00670478`, and `0x006704d0`, while the main-view table starts are `0x00670528`, `0x006706d8`, and `0x00670730`.
- Exact rain table ranges are documented in [UID:0001ON][0x006702c8-0x00670784.RainCoordinateTables](by-memory/0x006702c8-0x00670784.RainCoordinateTables.md).
- The generated `g_pWeatherState` table/user is actually `dword_67A764`, the active map-pane singleton; rain rendering checks byte `g_activeMapPane + 0x3f0`.
- Current `source-3/simroot_v2/class_WeatherLayerPane.cpp` and `class_RainingLayerPane.cpp` still contain duplicate marker-only `global-data` rows for weather/rain globals. The duplicate marker rows are not separate storage evidence.

## Ownership Decision

This is map weather rendering support. The base class may deserve a separate `WeatherLayerPane.cpp`, while `RainingLayerPane` may stay in `RainingLayerPane.cpp` or fold into a broader weather-layer source family. Do not move this code into generic render solely because it draws graphics; lifetime and construction are driven by map weather state.
