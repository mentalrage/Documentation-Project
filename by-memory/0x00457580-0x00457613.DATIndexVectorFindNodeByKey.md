## Behavior

`DATIndexVector::FindNodeByKey` hashes an incoming four-byte key and returns the first matching intrusive node in the selected bucket range. If no node matches, it returns the list sentinel through the caller-provided result object.

Live Hex-Rays shows:

- Hashes exactly four key bytes with FNV-1a seed `0x811c9dc5`, multiply constant `16777619`, and the bucket mask at object offset `+0x18`.
- Reads the bucket table pointer at object offset `+0x0c`, the list sentinel at object offset `+0x04`, and the selected bucket's first/last pair.
- Computes the scan stop as the sentinel when `bucket.last` is the sentinel, otherwise as `bucket.last->next`.
- Walks forward from `bucket.first` using `node->next` at offset `+0x00`.
- Compares the stored 32-bit node key at offset `+0x08` against the requested four-byte key.
- Returns the matching node through `*result` or returns the sentinel when no match is found.

There are no external function calls in the normal body; live IDA sees only intra-function jump labels.
