## Formal C++ Rationale

The formal C++ block intentionally uses a normal human source overload rather than raw helper calls:

- `StringBase result(lhs)` preserves the `0x00582a90` share/copy construction without spelling the low-level helper in caller-shaped code.
- `rhs.length()` preserves the `0x00584cf0` length accessor. Comparable StringBase docs already use `length()` as the source-facing spelling for that accessor.
- `result.AppendWideSliceFromString(rhs, 0, rhs.length())` preserves the `0x00584320` append-with-offset/count behavior and the full-right-operand append.
- Returning `result` models the hidden return-storage ABI as source-level return by value.

If a later project-wide StringBase API pass rejects free `operator+`, the same body can be renamed to a conservative descriptive helper such as `StringBaseConcatWideStrings`. That would be an API/facade spelling change, not a reason to return to PatchPane2 ownership or blank formal C++.
