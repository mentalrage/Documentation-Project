## Evidence Notes

- IDA MCP `py_eval` on 2026-05-28 shows all modeled helpers are tiny wrappers around `0x00596960` or `0x00596a00`.
- Callers reach these helpers from UI/input and socket paths, so these are project glue wrappers rather than third-party code.
- The bytes before `0x00574ae0` and after `0x00574b83` are alignment before the next packet queue helper range.
- 2026-06-01 live IDA MCP `lookup_funcs` confirms modeled helpers: `sub_574AE0` size `0x16`, `sub_574B00` size `0x16`, `sub_574B20` size `0x0c`, `sub_574B30` size `0x17`, and `sub_574B50` size `0x16`; `0x00574b70` and `0x00574b83` are not IDA functions, and `0x00574b90` starts the following packet queue helper.
- 2026-06-01 live IDA MCP decompilation confirms wrapper event ids and payload shape: `0x00574ae0` posts `(4, signed byte, payload)`, `0x00574b00` posts `(3, signed byte, payload)`, `0x00574b20` posts `(5, 0, 0)`, `0x00574b30` calls the synchronous/event-backed helper with id `0x0c`, and `0x00574b50` posts `(6, value, word)`.
- 2026-06-01 raw bytes confirm `0x00574b70-0x00574b83` is a function-shaped wrapper that pushes `0`, caller argument, and event id `0x0d`, calls `0x00596960`, and returns with `retn 4`; current IDA has no direct xrefs to this raw start.
- 2026-06-01 `xrefs_to` confirms caller families: terminal/setup/dial paths call the `3`, `4`, and `5` wrappers; main-menu/login, timer heartbeat, and dialog/network maintenance paths call the `0x0c` and `6` wrappers; `0x00596a00` is only reached by the `0x0c` wrapper in this island. The broader `0x00596960` fan-in includes these wrappers plus later packet queue/send wrappers.
- 2026-06-01 `callees` confirms all modeled wrappers call only `0x00596960` except `0x00574b30`, which calls `0x00596a00`. Decompilation of `0x00596960` shows it packs six dwords into a queue message and releases the thread semaphore; `0x00596a00` allocates/records an event-backed message and can throw `Win32Error` if event creation fails.
- 2026-06-01 byte sweep confirms exact internal padding: `0x00574ad8-0x00574ae0`, `0x00574af6-0x00574b00`, `0x00574b16-0x00574b20`, `0x00574b2c-0x00574b30`, `0x00574b47-0x00574b50`, `0x00574b66-0x00574b70`, and `0x00574b83-0x00574b90` are all `0xcc` alignment.

These wrappers are rebuild-relevant source-authored convenience shims over the generic [UID:0000OR][Thread](by-file/Thread.md) queue helpers. Do not classify them as CRT/runtime code.
