## Ownership Decision

`TakeOffInputPane` belongs with direct item-action input panes because it is a thin command prompt that validates player equipment selection and sends item/equipment action packets. The destructor at `0x004f2010` is physically far from the main command cluster, so source migration should attach it to the class only after the constructor boundary issue is resolved.

`SendTakeOffPacket` is behaviorally part of equipment removal, but its `SelfLookPane` callers mean final source placement should stay open until the self-look equipment-click path is reconstructed. A shared equipment-action helper or an `ItemActionInputPanes.cpp` file-local helper are both plausible.
