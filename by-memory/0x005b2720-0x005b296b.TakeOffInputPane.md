## Ownership Decision

`TakeOffInputPane` belongs with direct item-action input panes because it is a thin command prompt that validates player equipment selection and sends item/equipment action packets. The destructor at `0x004f2010` is physically far from the main command cluster, but the vtable family, constructor-shaped bytes, shortcut handler, and command handler now make the class-to-file attachment strong enough for autogen.

`SendTakeOffPacket` is behaviorally part of equipment removal, but its `SelfLookPane` callers mean final source placement should stay open until the self-look equipment-click path is reconstructed. A shared equipment-action helper or an `ItemActionInputPanes.cpp` file-local helper are both plausible.

Do not emit reconstructed C++ yet. The exact packet behavior is strong, but final method names, event-structure fields, and shared helper ownership are still below the 95% source-quality threshold.
