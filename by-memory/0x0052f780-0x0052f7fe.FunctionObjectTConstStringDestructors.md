# 0x0052f780-0x0052f7fe FunctionObjectTConstStringDestructors

## Status

- Disposition: compiler-emitted const-string callback-template destructor support.
- Primary source-family doc: [UID:0000JO][FunctionObjects](by-file/FunctionObjects.md)

| `0x0052f7c0-0x0052f7fe` | `PlainMemberFunctionObjectT<..., const StringBase&>` scalar deleting destructor | Similar emitted destructor body used by multiple const-reference string callback vtables; live IDA shows the same `flags & 4` guard. |

## Evidence Notes

- 2026-06-03 IDA MCP `lookup_funcs` confirms `0x0052f780` and `0x0052f7c0` are both `0x3e`-byte modeled destructor bodies.
- IDA `xrefs_to 0x0052f780` reports a data/vtable reference at `0x0061ff58`.
- IDA `xrefs_to 0x0052f7c0` reports additional vtable/data refs at `0x0061ff70`, `0x0062004c`, `0x00620094`, and `0x00622cf4`.
- IDA `callers` reports no direct code callers for either destructor, matching virtual callback-template support.
- IDA `callees` reports both bodies call base cleanup `sub_4F4A90`, conditional delete helper `sub_4F4AC0`, and the guard-check helper.
- IDA decompilation shows both functions write `off_61FF58`, call `sub_4F4A90`, and call `sub_4F4AC0` only when scalar-delete flags request deletion and do not set `flags & 4`.
- IDA vtable reads identify `0x0061ff70`, `0x0062004c`, `0x00620094`, and `0x00622cf4` as `PlainMemberFunctionObjectT<..., const StringBase&>` vtables for create-user / Nexonclub dialog callback contexts.
- The string type parameter is evidence for the [UID:0001WS][StringBaseTemplate](by-type/by-template/StringBaseTemplate.md) type spelling, but not for [UID:0000OB][StringUtil](by-file/StringUtil.md) source ownership of this callback-template support.
