# 0x0061e9fc-0x0061ea24 MapPane User Face Asset Path Strings

## Range

- Address range: `0x0061e9fc-0x0061ea24`
- Entity kind: `string-data`
- Decoded payloads: UTF-16 `/users/`, `.epf`, and `.face`.
- Rebuild handling: `source-declared/generated-binary`
- Direct parent: [UID:0000L3][MapPane](by-file/MapPane.md)

## Summary

This child covers a raw MapPane-side path-building literal group for per-user face/EPF assets. The strings were previously listed with profile sidecar data, but live disassembly shows they are used by a separate raw body beginning at `0x0050f620`, not by `ProfileSidecarRefresh`.

## Evidence

- 2026-06-12 C001 live IDA MCP `get_bytes` decoded `/users/`, `.epf`, and `.face` in this exact range.
- `xrefs_to` reports `/users/` references at `0x0050f678` and `0x0050f6fb`, `.epf` at `0x0050f6a6`, and `.face` at `0x0050f729`.
- 2026-06-12 C001 IDA `disasm 0x0050f600` shows a raw function-shaped body starting at `0x0050f620`: it calls `sub_516030`, builds `/users/<name>.epf`, opens it through imported file APIs, then falls back to `/users/<name>.face`.
- The raw body sits in the MapPane packet/render neighborhood around modeled MapPane handlers [UID:0001AT][0x00506970-0x0050e320.MapPaneInputPacketRenderCore](by-memory/0x00506970-0x0050e320.MapPaneInputPacketRenderCore.md), so source ownership uses the [UID:0000L3][MapPane](by-file/MapPane.md) file root rather than [UID:0000MS][ProfileStorage](by-file/ProfileStorage.md).

## Reconstruction Notes

Keep this as MapPane file-local asset path data until the raw `0x0050f620` body gets its own exact documentation page. The direct parent is the file root because the raw helper is not yet modeled as a class method and the strings are file-local literals.
