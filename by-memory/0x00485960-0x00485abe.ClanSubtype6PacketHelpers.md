## Behavior

This page covers the subtype `6` helper pair immediately before [UID:00010E][0x00485ac0-0x00485cbd.SendClanAttributePacket](by-memory/0x00485ac0-0x00485cbd.SendClanAttributePacket.md), which sends the same opcode/subtype with action `2` and three strings plus a 16-bit value.

Known callers:

- `0x00485960` is called by [UID:00010H][0x00487600-0x0048779f.ClanStatusRowActionPacket](by-memory/0x00487600-0x0048779f.ClanStatusRowActionPacket.md) case `7` and by [UID:00021U][0x00488900-0x00488b3d.ClanListPaneInputHandlers](by-memory/0x00488900-0x00488b3d.ClanListPaneInputHandlers.md) `0x004889a0`.
- `0x004859d0` is called by [UID:00021U][0x00488900-0x00488b3d.ClanListPaneInputHandlers](by-memory/0x00488900-0x00488b3d.ClanListPaneInputHandlers.md) `0x00488970` and `0x004889a0`.

The string helper converts the wide argument with `WideCharToMultiByte`, stores the converted byte length, appends the payload, range-checks against `0x100` conversion length and `0x80` packet length, and sends `convertedLength + 4` bytes.

Both helpers write a zero byte just after the queued packet span (`packet[3]` for action `0`, `packet[convertedLength + 4]` for action `1`). The queued lengths are exactly `3` and `convertedLength + 4`, so those local terminator/padding bytes are not sent.
