## Request Path

Observed outbound path:

1. Feature/UI code builds packet bytes in feature-owned code.
2. Feature/UI code calls this wrapper through [UID:0000Q5][g_packetSender](by-global/g_packetSender.md) or one of its generated aliases.
3. This function copies the packet and dispatches request code `8`.
4. `Socket::HandleSocketCommand` handles command `8`, calls `Socket::SendEncodedPacket`, then frees the queued payload buffer.
5. `Socket::SendEncodedPacket` applies final packet encoding/framing and writes to Winsock, mode-6 dispatch, or serial transport.

The `sub_596960` request record shape explains why this helper passes the copied buffer and size to the queue rather than writing immediately. The send-disabled flag suppresses queueing before allocation, so callers can build packet bytes freely while a login/account/transport path temporarily blocks outbound sends.
