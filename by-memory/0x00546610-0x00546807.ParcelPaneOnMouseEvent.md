## Behavior

Handles parcel alert mouse interaction through the secondary-vtable view. The callback receives the secondary subobject pointer, so decompiler offsets must be normalized by subtracting `0xa0` to reach the owning `ParcelPane`.

The method behaves as a two-slot mouse state machine:

| Input event category | Left slot behavior | Right slot behavior |
| --- | --- | --- |
| move/hover (`event type 0`) | Hit-tests owner bounds and the `+0x100` left rectangle, then toggles the visual state byte at `+0xfc` between idle/hover unless the slot is already locked or pressed. | Hit-tests the `+0x110` right rectangle and updates visual state byte `+0xfd` under the same lock/press rules. |
| press (`event type 1`) | Sets `+0xfc` to pressed state `2` when the left rectangle is hit. | Sets `+0xfd` to pressed state `2` when the right rectangle is hit. |
| release/action (`event type 3`) | Clears both visual state bytes, checks the left slot byte at `+0xf9`, queues action byte `0x41` through [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md) using [UID:0000Q5][g_packetSender](by-global/g_packetSender.md), and marks consumed byte `+0x120`. | Clears both visual state bytes, checks activation byte `+0xfb` and [UID:0000QG][g_pBulletinSession](by-global/g_pBulletinSession.md), allocates/constructs a [UID:00001D][BulletinSession](by-class/BulletinSession.md) through the constructor island at [UID:0000ZH][0x00471150-0x00471ff1.BulletinSessionCore](by-memory/0x00471150-0x00471ff1.BulletinSessionCore.md), and marks consumed byte `+0x121`. |

The visual state bytes feed [UID:0002KI][0x005469e0-0x00546aab.ParcelPaneGetButtonFrameIndex](by-memory/0x005469e0-0x00546aab.ParcelPaneGetButtonFrameIndex.md), which maps states `0..3` to `ALERTBTN` frame indices or live animation-frame bytes. That keeps the mouse handler's state writes tied to the parcel drawing path rather than treating them as anonymous byte flags.
