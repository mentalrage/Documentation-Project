# IJG libjpeg Decompress API Front End `0x004011b0-0x004019e3`

## Status

- Confidence: strong for public API/source-file identity.
- Proposed owner: [UID:0000KN][LibJPEG](by-file/LibJPEG.md)
- Source files: `jpeg-6b/jdapimin.c` and `jpeg-6b/jdapistd.c`
- Evidence basis: obtained official `jpegsrc.v6b.tar.gz` source comparison plus read-only IDA MCP decompile/callee checks on 2026-05-25. `wave3.py` was not executed.

## Range Role

This range is the decompression application-interface front end from IJG libjpeg 6b. It is stock third-party code and should remain under `third_party/libjpeg/`, not under NexusTK image-loader source.

The product-owned callers are [UID:000175][0x004d05f0-0x004d0c57.ImageDecodeWrappers](by-memory/0x004d05f0-0x004d0c57.ImageDecodeWrappers.md), which use these routines to decode `JPF` portrait payloads and raw minimap JPEG blobs into RGB565 tile contexts.

The downstream decompression internals reached from this API are now split into focused source-file pages for the [UID:0000VR][0x00401b00-0x004038c7.LibJpegMarkerReader](by-memory/0x00401b00-0x004038c7.LibJpegMarkerReader.md), [UID:0000VV][0x00404a60-0x0040505b.LibJpegInputController](by-memory/0x00404a60-0x0040505b.LibJpegInputController.md), and [UID:0000VX][0x00405c80-0x004063c8.LibJpegDecompressMaster](by-memory/0x00405c80-0x004063c8.LibJpegDecompressMaster.md).

## Product Caller Evidence

- [UID:000175][0x004d05f0-0x004d0c57.ImageDecodeWrappers](by-memory/0x004d05f0-0x004d0c57.ImageDecodeWrappers.md) calls `0x004011b0`, `0x004012b0`, `0x004016e0`, `0x00401890`, `0x00401620`, and `0x00401290`.

## Ownership Decision

Vendor `jdapimin.c` and `jdapistd.c` from [UID:0001QX][README](by-meta/obtained_thirdparty_files/README.md). Keep NexusTK-specific `JPF`/minimap buffer handling and RGB565 conversion in [UID:0000K3][ImageLoaders](by-file/ImageLoaders.md).
