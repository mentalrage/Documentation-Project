## Behavior

Changes the logical element count and resizes backing storage only when the required page count changes. It computes the old page count from current `m_count` and the requested page count from the new `count`. If the requested count needs more pages, it allocates or reallocates `newPageCount * m_pageSize * m_elementSize` bytes. If fewer pages are needed, it shrinks the allocation. In all paths it stores the requested count at `m_count`.

The page-count calculation keeps at least one page: non-positive counts use one page, and positive counts use `((count - 1) / m_pageSize) + 1`. During shrink, a zero capacity product is corrected back to one `m_pageSize` chunk before multiplying by `m_elementSize`.

The grow-without-data path calls `GetMemoryMan()->AllocateBufferMemory`, then stores `m_count = count`, stores `m_data = newData`, and returns. The grow-with-existing-data and shrink paths call `GetMemoryMan()->ReallocateBufferMemory`, store the returned `m_data`, then store `m_count = count`. Equal page counts update only `m_count`.
