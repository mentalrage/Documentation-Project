## Behavior

Validates the executable version-resource fields against the embedded product key material `7TK5E-KRU-2K`.

Observed flow:

- calls [UID:0002JX][0x004651f0-0x004652dc.BuildExecutablePathForVersionInfo](by-memory/0x004651f0-0x004652dc.BuildExecutablePathForVersionInfo.md) to build the current executable path from the command line;
- calls `GetFileVersionInfoSizeW`, allocates a temporary version block, calls `GetFileVersionInfoW`, and queries the root `VS_FIXEDFILEINFO` block with `VerQueryValueW(block, L"\\", ...)`;
- on version-resource failure, writes `0x0136` (`310`) to Application object offset `0x850`, clears offset `0x842`, and returns `0`;
- on successful query, stores the low 16 bits of `dwFileVersionLS` into offset `0x842`;
- computes a three-digit code from version components: `HIWORD(dwFileVersionLS) % 10 + 10 * (LOWORD(dwFileVersionMS) % 10 + 10 * (HIWORD(dwFileVersionMS) % 10))`;
- formats the hardcoded key string, strips all non-digit characters left-to-right to produce `752`, converts that through the CRT integer parser at `0x005cea6d`, and compares it to the computed version code;
- when the computed code matches `752` (`0x02f0`), writes that code to offset `0x850` and returns it;
- when it does not match, writes and returns `0x02a8` (`680`).

## Reconstruction Notes

First-draft C++ is now recommended. Behavior, helper ownership, status constants, key semantics, and source placement are resolved to high confidence. Remaining uncertainty is limited to final project naming style for the Application fields and PlatformApi dispatch-table slots.

The method formats the embedded ASCII key literal `"7TK5E-KRU-2K"`, copies only ASCII digits in left-to-right order, and parses the resulting digit string `"752"` as a base-10 integer. The extracted key code is therefore `752` (`0x02f0`), not `572`.

`Application + 0x842` is best modeled as `m_clientVersionLowWord`: it receives `LOWORD(VS_FIXEDFILEINFO.dwFileVersionLS)` after a successful version query and is cleared to zero on version-query failure. `Application + 0x850` is best modeled as `m_clientVersionCode`: it receives the computed 3-digit version code on success, `0x0136` (`310`) on version-query/allocation failure, or `0x02a8` (`680`) on key/version-code mismatch. Existing `GetVersionMajor` / `GetVersionMinor` accessor names are caller-compatible display/protocol names, but `+0x850` is not a raw file-version major field.

The raw dispatch-table slots `dword_69BEB0`, `dword_69BEB4`, and `dword_69BEB8` correspond to the PlatformApi wide VERSION API slots `GetFileVersionInfoSizeW`, `GetFileVersionInfoW`, and `VerQueryValueW`, installed by [UID:0000WD][0x0041a280-0x0041a4a8.WideApiDispatchInit](by-memory/0x0041a280-0x0041a4a8.WideApiDispatchInit.md). Source-facing code should use the project-selected dispatch names rather than raw IDA data labels.

The formal C++ block uses role-based names `m_clientVersionCode`, `m_clientVersionLowWord`, `g_pfnGetFileVersionInfoSizeW`, `g_pfnGetFileVersionInfoW`, and `g_pfnVerQueryValueW`. These are source-quality first-draft names, not proof of original spelling.
