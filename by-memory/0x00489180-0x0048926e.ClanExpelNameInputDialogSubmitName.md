The exact operation order is behaviorally significant:

1. Write opcode `0x4b`, subtype `0x07`, and action `0x01` with the value-first API `PacketBufferWriteUInt8(value, destination)`.
2. Convert the submitted text and perform the indexed source write `convertedName[convertedLength] = 0`.

4. Compute `packetLength = convertedLength + 4`, then perform the indexed scratch write `packet[packetLength] = 0`.
5. Queue exactly `packetLength` counted bytes. Neither caller scratch NUL is included in the protocol length.

The binary's unsigned `0x100` branch immediately protects the indexed conversion-buffer terminator, and its unsigned `0x80` branch occurs after `memmove` and protects the indexed packet scratch terminator. Both calls to range-failure support are compiler instrumentation. Human-written C++ therefore retains the two indexed writes and the observed copy-before-second-guard ordering but does not call `__report_rangecheckfailure` explicitly; matching original MSVC instrumentation is expected to regenerate those branches.

`convertedName` and `packet` remain caller-owned stack storage. `Socket::QueueAndSendPacket` returns `void`, allocates a separate queued buffer, copies exactly the counted caller bytes, appends its own NUL to that copy, and owns/frees the queued allocation.
