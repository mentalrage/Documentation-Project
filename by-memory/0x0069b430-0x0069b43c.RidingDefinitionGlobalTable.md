## Lifetime And Behavior

The static initialization wrapper at `0x00419fd0-0x00419fe6` calls the table-object initializer at `0x00528930-0x00528947` on this range and registers `0x0060c290` for shutdown cleanup. The initializer zeroes all three dwords in the object.

The static cleanup wrapper at `0x0060c290-0x0060c29a` calls the cleanup helper at `0x00528950-0x005289c6`. That helper reads the entry pointer from the third dword, destroys each eight-byte group row when the pointer is non-null, frees the backing allocation, clears the count byte inside the middle field, and clears the entry pointer.

The `RIDINGS.DNA` loader at [UID:0002LA][0x004dc420-0x004dc68d.RidingImageLibLoadRidingDefinitions](by-memory/0x004dc420-0x004dc68d.RidingImageLibLoadRidingDefinitions.md) uses this object as the process-wide default riding-definition table:

1. It reads the riding definition count and allocates the owning array of 12-byte `RidingDefinition` records.
2. It calls the shared outer-table allocation helper on this static object with count `0x15`.
3. It walks `0xa8` bytes through the entry-pointer field at `0x0069b438`.
4. For each eight-byte group row, it allocates one ten-byte entry.
5. It seeds each entry with frame offset `0`, frame duration `30000`, and alpha/flag byte `0`.
6. It then parses the resource-backed riding definition rows and their nested groups from the file.

The lookup helper at `0x004dca20-0x004dca43` returns `loadedDefinitionBase + 12 * index` when the index is in range; otherwise it returns the address `0x0069b430`. The repeated fallback selections in later riding render paths match this same shape, so this object is the default outer table used when riding-definition lookup fails or an index is outside the loaded table.
