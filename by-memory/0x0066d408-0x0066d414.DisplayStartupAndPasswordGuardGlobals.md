# 0x0066d408-0x0066d414 Display Startup And Password Guard Globals

## Summary

- Address range: `0x0066d408-0x0066d414`
- Entity kind: initialized writable global data
- Disposition: reconstructable project data
- Rebuild handling: `source-declared/generated-binary`
- Confidence: strong for `xRight` and the password-guard seed; medium for the final source name of `dword_66D40C`

This span contains two adjacent source-declared global groups that happen to share a compact `.data` island: display startup/presentation state at `0x0066d408-0x0066d410`, followed by the password-guard XOR seed at `0x0066d410-0x0066d412`. The source reconstruction should not treat the whole range as one `Application` structure; it should place each symbol with the owning source module once final file ownership is settled.

## Layout

| Range | Current IDA name | Proposed role | Initial value | Notes |
| --- | --- | --- | --- | --- |
| `0x0066d408-0x0066d40c` | `xRight` | startup display width/right edge | `1024` | Written by `Application::Initialize` after it clamps the configured width to `0x400..0x0f00` and aligns it to a four-pixel boundary; read later by the same startup path for window/surface geometry. |
| `0x0066d40c-0x0066d410` | `dword_66D40C` | display presentation/stretch mode selector | `1` | Initialized to direct presentation mode, rewritten by `Application::Initialize` from a bounded `1..3` startup/config value, and read by `SurfacePresentation` to choose direct blit versus GDI stretch handling. Final source name remains open. |
| `0x0066d410-0x0066d412` | `word_66D410` | password-guard XOR seed | `0xd544` | Seed loaded by `SetProtectedPasswordToken` and `ValidateChatInputOrThrowPasswordError`; each encoded/decoded wchar is XORed with this value and then an incrementing seed. |
| `0x0066d412-0x0066d414` | padding/unused bytes | alignment padding | `0` | Zero padding between the word seed and the following object-pane mask data at `0x0066d414`. |

## Evidence

- IDA bytes at `0x0066d408` are `00 04 00 00 01 00 00 00 44 d5 00 00`, matching `xRight = 1024`, `dword_66D40C = 1`, `word_66D410 = 0xd544`, and two zero bytes.
- IDA xrefs to `xRight` are `0x00463da7` and `0x004642f3` in `Application::Initialize`. The write path clamps the width against `0x400` and `0x0f00`, aligns it with `and eax, 0FFFFFFFCh`, then stores it to `xRight`.
- IDA xrefs to `dword_66D40C` are `0x00463dbe`, `0x00463dde`, and `0x005597b4`. Startup keeps the default value unless a candidate value minus one is `<= 2`; presentation code compares it against `1`, uses the non-stretch DirectDraw blit path for that value, and otherwise uses `SetStretchBltMode` with mode `3` for value `2` and mode `4` for the remaining non-`1` value.
- IDA xrefs to `word_66D410` are `0x004657e5`, `0x00465866`, and `0x004658d2`. `SetProtectedPasswordToken` loads it immediately after copying into `word_67A940`, and `ValidateChatInputOrThrowPasswordError` loads the same seed after copying the protected token to a local buffer.
- IDA decompilation shows the password guard transform as `*p++ = seed++ ^ ch` in both encode and decode paths, so `word_66D410` is the initial XOR seed rather than an application/window helper.

## Reconstruction Notes

- Keep `xRight` and `dword_66D40C` with application/display startup state unless later caller review finds a dedicated display configuration module.
- Keep `word_66D410` with [UID:0000MG][PasswordGuard](by-file/PasswordGuard.md), likely as a file-scope constant or initialized static such as `g_passwordProtectSeed`. Do not place it in `Application` just because it is adjacent to display startup globals.
- Keep this range separate from the following object-pane mask data because the callers and ownership differ.
- `0xd544` is also the Unicode code point for Hangul syllable PIL, but the binary evidence supports an obfuscation seed role; do not infer a text/string meaning from the code point.
