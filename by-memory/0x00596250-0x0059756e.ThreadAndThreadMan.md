## Evidence

- IDA MCP confirms all listed modeled function starts and sizes; ranges are end-exclusive where IDA models a function.
- `Thread::Thread` has broad derived-constructor fan-in, including [UID:00008I][MiscWorkThread](by-class/MiscWorkThread.md) at `0x005281db`.
- `RingBuffer`, `Monitor`, and `List` constructor calls are direct dependencies.
- `ThreadMan::ThreadMan` writes [UID:0000SH][g_pThreadMan](by-global/g_pThreadMan.md) at `0x0069be08`.
- `ThreadMan::ThreadMan` allocates a 20-byte-record list documented as [UID:0001WB][ThreadManWatchRecord](by-type/by-struct/ThreadManWatchRecord.md).
- 2026-05-25 IDA MCP recheck confirmed raw ThreadMan helper starts in the `0x00596d20-0x00596e0b` gap: destructor cleanup at `0x00596d20`, then message-posting wrappers for ids `0x0464` through `0x0468`.
- 2026-05-25 IDA MCP boundary check reported `0x00596bf0` size `0x123`, `0x005974e0` size `0x0b`, and `0x005974f0` size `0x7e`.
- The next function at `0x00597570` installs `TimerHandler::vftable`; it is the start of the [UID:0001K6][0x00597570-0x005986da.TimerMgrAndTimerQueue](by-memory/0x00597570-0x005986da.TimerMgrAndTimerQueue.md) cluster and should not be included in ThreadMan.
- Current generated files have improved coverage for this island, but still contain polluted owner names and low-fidelity message-loop reconstruction, so the range should be used as the migration anchor rather than trusting active source alone.
- 2026-05-26 IDA MCP recheck reconfirmed modeled ThreadMan functions at `0x00596bf0`, `0x00596e10`, `0x00597100`, `0x005974e0`, and `0x005974f0`. The raw helper starts in `0x00596d20-0x00596e0b` still return `Not a function` and have no direct xrefs.
- The same recheck reconfirmed the false-positive rows outside this range: `0x0045004b` belongs to `sub_450030`, `0x004e0052` belongs to `NewHumanImageLib::NewHumanImageLib`, and `0x00597570` starts `TimerHandler::TimerHandler`.
