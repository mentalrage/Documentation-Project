# 0x004673c0-0x004673d1 DestroyKeySpeedMgr

## Scope

- Range: `0x004673c0-0x004673d1`
- Entity kind: startup/early-exit cleanup helper
- Selected source owner: [UID:0000PA][WinMain](by-file/WinMain.md)
- Object/global owner: [UID:0000KJ][KeySpeedMgr](by-file/KeySpeedMgr.md) through [UID:0000RB][g_pKeySpeedMgr](by-global/g_pKeySpeedMgr.md) and [UID:0001P7][0x0067ab48-0x0067ab4c.g_pKeySpeedMgr](by-memory/0x0067ab48-0x0067ab4c.g_pKeySpeedMgr.md)
- Parent aggregate: [UID:0000YU][0x004671a0-0x004673f6.ApplicationFunctionObject0Callbacks](by-memory/0x004671a0-0x004673f6.ApplicationFunctionObject0Callbacks.md)

## Behavior

This helper reads `g_pKeySpeedMgr`, checks it for null, and if present invokes the active object through vtable slot zero with deleting-destructor flag `1`.

```asm
004673c0  mov ecx, dword_67AB48
004673c6  test ecx, ecx
004673c8  jz 004673d0
004673ca  mov eax, [ecx]
004673cc  push 1
004673ce  call dword ptr [eax]
004673d0  retn
```

## IDA Evidence

- `lookup_funcs` reports `sub_4673C0` at `0x004673c0`, size `0x11`, exclusive end `0x004673d1`.
- `analyze_funcs` decompiles it as a null-checked indirect deleting-destructor dispatch through `dword_67AB48`.
- `xrefs_to 0x004673c0` reports one direct caller at `0x004f5eeb` inside `_WinMain@16`.
- The direct data xref is `0x004673c0 -> 0x0067ab48`, the documented `g_pKeySpeedMgr` storage.
- IDA xrefs to `0x0067ab48` include normal Application cleanup/BaramApp/ExceptionHandler/KeySpeedMgr lifecycle refs plus this helper and `_WinMain@16` at `0x004f5edc`.
- The `_WinMain@16` instruction window shows `0x004f5edc` loading `g_pKeySpeedMgr`, `0x004f5ee6` calling `0x004eff30` to restore keyboard settings when the manager exists, then `0x004f5eeb` calling this cleanup wrapper before the WinMain shutdown/message-box tail.

## Ranked Ownership Decision

1. [UID:0000PA][WinMain](by-file/WinMain.md) - selected.
   - For: the wrapper has exactly one code caller and it is inside `_WinMain@16` at the updater/early-exit cleanup tail. The caller context first uses the KeySpeedMgr object to restore keyboard settings, then calls this wrapper to delete it as part of WinMain's local early-exit sequence.
   - Against: the helper body touches only the KeySpeedMgr singleton, so object lifecycle semantics are KeySpeedMgr-related.
2. [UID:0000HG][Application](by-file/Application.md) - rejected as direct owner.
   - For: the surrounding cleanup neighborhood includes Application/fatal-load helpers and WinMain is application startup glue.
   - Against: the sole caller is `_WinMain@16`, not Application constructor/Initialize/fatal-DAT callers. B001-012 and B001-013 Application assignments for `0x00467380`/`0x004673a0` were based on many Application/resource failure callers, which this helper lacks.
3. [UID:0000KJ][KeySpeedMgr](by-file/KeySpeedMgr.md) - rejected as source owner, retained as object/global owner.
   - For: the helper deletes the object stored in `g_pKeySpeedMgr`.
   - Against: the helper is not called by KeySpeedMgr methods, does not clear the singleton, and sits in a WinMain early-exit sequence. Normal KeySpeedMgr construction/destruction and object behavior remain owned by KeySpeedMgr.
4. [UID:0000JO][FunctionObjects](by-file/FunctionObjects.md) - rejected.
   - For: physical adjacency to FunctionObject0 callback helpers.
   - Against: the body has no callback-object fields, vtable data refs, or FunctionObject callers.
