## Behavior

Computes local rectangle bounds for a complete new-human sprite composition. The method receives a 30-entry draw-order table, an avatar/equipment state blob, the requested sequence/frame, a primary output rectangle, an optional projected overlay rectangle, and a direction byte.

The IDA decompile and generated source lead agree on this high-level flow:

1. Copy the avatar state into local storage and derive an extra Y offset only when the state mode byte at `+0x22` equals `3`.
2. If the base appearance id is absent, return without changing the outputs.
3. Clear the primary bounds rectangle.
4. For appearance mode `2`, emit the default centered bounds using `word_66DAA0` and `word_66DA9C`, then optionally build the projected overlay rectangle.
5. If a special part id is present, call the shared part-frame rectangle helper `0x004e4140`, optionally union in an overlay rectangle through [UID:0002KT][0x004d05a0-0x004d05e6.ResourceLayoutRawRecordGetEntryRect](by-memory/0x004d05a0-0x004d05e6.ResourceLayoutRawRecordGetEntryRect.md), center the result, and build the projected overlay rectangle.
6. For appearance mode `1`, lazy-load `GFACE.EPF` through the shared [UID:0000QU][g_pEPFLib](by-global/g_pEPFLib.md) resource-layout table, copy the first rectangle from the loaded record when present, otherwise clear the bounds.
7. Otherwise loop over 30 draw-order tags, map tags `0x32` through `0x3e` to body, alternate body, hair layers, item/equipment groups, adornments, cape, and overlay resources, and union each present part rectangle into an aggregate.
8. Center the aggregate by half of `word_66DA9C` and `word_66DAA0`, then optionally compute projected overlay bounds using the projection state at `dword_67A764 + 0x3d0/+0x3d4` and the `1.0f` constant path.
