# 0x004f5ae0-0x004f5b1e Startup Logo Bink Midpoint Restart

## Status

- Disposition: reconstructable NexusTK project code.
- Entity kind: startup logo media helper.
- Likely source file: [UID:0000O4][StartupLogoPanes](by-file/StartupLogoPanes.md).
- Related playback loop: [UID:00022T][0x004f5710-0x004f5ac7.StartupLogoBinkPlaybackLoop](by-memory/0x004f5710-0x004f5ac7.StartupLogoBinkPlaybackLoop.md).
- Confidence: strong for boundary and behavior; medium for final function name.

## Behavior

This helper is called by the temporary startup-logo Bink window procedure for selected keyboard/mouse messages. If `byte_66DB42` is set and the current Bink frame is before the halfway point, it clears `byte_66DB42`, closes the current Bink handle, and reopens Bink from `dword_69B474` with the same memory-backed open flags used by the main playback loop.

The observed behavior looks like a one-shot restart or alternate-half switch for startup-logo movie playback.

## Evidence

- 2026-05-28 IDA MCP function inventory lists `sub_4F5AE0` as `0x004f5ae0-0x004f5b1e`.
- The only direct xref found by IDA MCP is from [UID:00022T][0x004f5710-0x004f5ac7.StartupLogoBinkPlaybackLoop](by-memory/0x004f5710-0x004f5ac7.StartupLogoBinkPlaybackLoop.md) at `0x004f5aaf`.
- Raw disassembly reads `byte_66DB42`, compares the current Bink frame index against half of another Bink field, calls `BinkClose`, then calls `BinkOpen(dword_69B474, 0x04080000)`.
- `0x004f5b1e-0x004f5b20` is `0xcc` alignment before an unrelated MAPI helper.
