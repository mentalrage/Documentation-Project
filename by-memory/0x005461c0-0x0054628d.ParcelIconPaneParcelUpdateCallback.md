## Behavior

The callback receives a handler/event object and reads the packet payload pointer from `event + 0x0c`. If the first payload byte is not `8`, it returns `0` without changing state.

For parcel update packets, it reads the flag byte at `payload + 1` through `std::_Narrow_char_traits<char,int>::to_char_type`, then chooses the packed-count byte offset as follows:

- Start at offset `31` when flag `0x40` is set, otherwise offset `2`.
- Add `8` when flag `0x20` is set.
- Add `9` when flag `0x10` is set.
- Add `5` when flag `0x08` is set.

The byte at that calculated payload offset stores two parcel-side counts. The low nibble becomes one side count, the high nibble becomes the other side count, and their sum becomes the total parcel count. In the secondary `ParcelIconPane` view these fields are `this + 0x58`, `this + 0x59`, and `this + 0x5a`; normalized back to the primary owner they match `ParcelIconPane + 0xf8`, `+0xf9`, and `+0xfa`.

The method writes the new total every time a valid packet is parsed. It only forwards to [UID:0002KC][0x005464b0-0x00546575.ParcelPaneSetParcelSlotData](by-memory/0x005464b0-0x00546575.ParcelPaneSetParcelSlotData.md) when the previous total was larger than the new total, or either stored side count is lower than the packet side count. On that path it loads the child pane from secondary `this + 0x5c` (primary owner `+0xfc`), updates the stored side counts, and calls `sub_5464B0(childPane, total, lowNibble, highNibble)`.
