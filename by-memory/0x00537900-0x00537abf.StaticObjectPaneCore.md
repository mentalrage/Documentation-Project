## Behavior Details

- The `0x00537950` helper is now confirmed as a real live static-object solid/pixel-test delegate, not dead padding: IDA reports a code xref from `0x0050c691`, while ordinary `callers` cannot attribute it to a modeled function.
- The image-library helper at `0x004dd8b0` walks the selected `StaticObjEntry` layer list and tests the resolved tile frame pixels, returning true if the target pixel or its immediate neighbors are nonzero. That makes the `0x00537950` pane method the click/solid-mask test that pairs with the bounds and render virtuals.
- `CopyStaticObjectBounds` uses [UID:0000SD][g_pStaticObjImageLib](by-global/g_pStaticObjImageLib.md) and `this+0x128`, then copies the four-word/eight-word rectangle result from the caller scratch buffer to the destination output.
- `RenderStaticObjectForTarget` is a thin bridge into [UID:00017J][0x004dd2c0-0x004dd84a.StaticObjImageLibRenderStaticObject](by-memory/0x004dd2c0-0x004dd84a.StaticObjImageLibRenderStaticObject.md); IDA reconfirms that renderer has exactly two callers, this pane at `0x005379c3` and map-photo composition at `0x00549847`.
- The event handler is entered through a secondary/adjusted vtable view, so IDA prints some base-rectangle loads as negative offsets and the packet identity fields as adjusted `this+0x60/+0x64`. Treat these as the same static-object identity fields documented on the raw packet helper until the final class layout names are settled.
- The packet path uses byte-writer `0x00575380`, word-writer `0x005753a0`, [UID:0000Q5][g_packetSender](by-global/g_packetSender.md), and [UID:0001HU][0x00574bb0-0x00574c13.QueueAndSendPacket](by-memory/0x00574bb0-0x00574c13.QueueAndSendPacket.md) with length `7`.
