## Behavior

This method loads persisted configuration from the Windows registry, initializes missing identity data, rebuilds server/adapter metadata, and prepares the inherited server-directory buffers used by the client.

Known high-level behavior from IDA-backed existing docs:

- creates or queries a CLSID/identity value under the Windows class-root registry area when needed;
- opens and reads the same Nexon/Kingdom of the Winds registry key family saved by `RegistryConfig::SaveToRegistry`;
- reads client options, color values, and multi-server metadata;
- enumerates or queries network adapter data through the adapter-address helper path;
- seeds random/time data where needed for generated identity material;
- calls the shared [UID:0000L6][MD5](by-file/MD5.md) helper at `0x005153e0` with a registry-derived string/length and 16-byte output buffer near the config object;
- calls `ServerSelectDirectory::ReleaseOwnedBuffers` at `0x00494130` as part of rebuilding owned buffers.

Best source-facing signature:

```cpp
bool RegistryConfig::LoadFromRegistry();
```

High-level behavior after B003 source-quality reanalysis:

1. Opens/creates `HKEY_CLASSES_ROOT\NXKRI.Ctrl.1` with `KEY_ALL_ACCESS`.
2. Reads value `CLSID` as a four-byte `REG_DWORD`; if the value is missing, zero, wrong-typed, or wrong-sized, it generates a pseudorandom DWORD from four `rand()` bytes seeded by current time, writes the DWORD back as `CLSID`, and stores it at `this + 0x28de34`.
3. If the class key cannot be opened, it leaves fallback identity DWORD `0xff00ff00` at `this + 0x28de34`.
4. Queries the first adapter with `GetAdaptersAddresses`, formats physical-address bytes with the narrow strings `%s%.2X-` for interior bytes and `%s%.2X]` for the last byte, MD5-hashes that string, and stores the 16-byte digest at `this + 0x28de38`.
5. Opens/creates `HKEY_CURRENT_USER\Software\Nexon\Kingdom of the Winds` with `KEY_READ`. Failure to open this root returns `false`.
6. Loads scalar options, string/blob settings, chat window settings, chat colors, palette colors, dialog-position records, the `Midi` subkey, and the `Servers` subkey.
7. Rebuilds inherited multi-server storage through `m_serverDirectory.ReleaseOwnedBuffers()` before reading `Servers`.
8. Closes registry handles on success and failure paths.
9. Probes `%SystemRoot%\System32\mscfg.dll` and `%SystemRoot%\System32\grcframe.exe`; if either exists, it writes word `0x0a01` to `this + 0x2918f8`.
10. Returns `true` on the successful main load path. Failure to open the root key or `Midi` subkey takes the false return path. Failure to open `Servers` is tolerated; the method closes the root key and continues to the system-directory probe tail.

B006 UID0003FX support sync records the current literal starts used by this method: `0x004926f3` pushes `0x00617908` for `NXKRI.Ctrl.1`, `0x00492737` and `0x004927b0` push `0x00617924` for `CLSID`, `0x00492877` and `0x0049287e` push `%s%.2X]` / `%s%.2X-`, `0x00492c27` pushes `SoundLatency`, and the helper-file tail at `0x00493d0c` reads the table rooted at `0x0066d46c` for `mscfg.dll` then `grcframe.exe`.
