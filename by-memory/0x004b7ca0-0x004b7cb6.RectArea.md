## Behavior

Returns the signed area of a four-int rectangle:

```text
(right - left) * (bottom - top)
```

The helper does not clamp or check for empty/invalid rectangles. Negative width or height can therefore affect the signed result.

The arithmetic is a plain signed 32-bit source expression. Do not rewrite it as an absolute area, a clamped non-negative area, an unsigned `size_t` product, a 64-bit-widened product, or an overflow-checked allocation helper. If one axis is inverted and the other is not, the returned value can be negative; if both axes are inverted, the product can be positive even though the rectangle is invalid by the `right <= left || bottom <= top` predicate. The observed callers are expected to pass valid small rectangles when they use the result for allocation sizing.

This is not a `RectBounds` thiscall method. The binary/source-shape evidence is cdecl/free-helper style: the rectangle pointer is a stack argument, there is no `ecx` receiver, and the helper returns with a plain `ret`. Keep it cross-referenced from the class page as a related helper, but emit/declaration ownership should be the RectBounds source file [UID:0000N2][RectBounds](by-file/RectBounds.md), not the class [UID:0000BU][RectBounds](by-class/RectBounds.md).
