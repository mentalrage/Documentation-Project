## Covered Ranges

| Range | Entity | Notes |
| --- | --- | --- |
| `0x0048e310-0x0048e408` | config row lookup/append helper | Ghidra export models `FUN_0048e310`; IDA does not name/model this as a normal function. The body initializes a 40-byte local wide buffer, scans the large 100-row config table using row count at `+0x28d9d4`, compares each row against the zeroed local buffer and against a global wide string reached through `dword_67AB1C + 0x858`, and increments the row count when no matching row is found. |
| `0x0048e410-0x0048e479` | config row reset helper | Raw function-shaped body that clears the large fixed config table: loops 100 rows at stride `0x6894`, zeroes lead/trailing wide fields, clears row counters, uses `xorps`/`movups` for part of each row, and zeroes two 20-entry wide-value subarrays. |

## Evidence

- Direct PE byte review of `E:\NTK\Resources\NexusTK\NexusTK.exe` shows the preceding `CollectionEntryControlPane` destructor returns at `0x0048e304`, followed by eleven `0xcc` bytes from `0x0048e305-0x0048e310`.
- `0x0048e310` begins `55 8b ec 83 ec 5c ...` and ends at `0x0048e408` after a stack-cookie check and `ret`; `0x0048e408-0x0048e410` is eight `0xcc` alignment bytes.
- `0x0048e410` begins `56 57 8d 91 06 02 00 00 ...`, returns at `0x0048e478`, and is followed by seven `0xcc` bytes through `0x0048e480`.
- 2026-06-06 live IDA MCP `lookup_funcs` reports no function object at `0x0048e310`, `0x0048e408`, `0x0048e410`, or `0x0048e479`, while the neighboring modeled functions are `sub_48E2B0` covering `0x0048e2b0-0x0048e305` and `sub_48E480` size `0x28`.
- 2026-06-06 live IDA MCP `xrefs_to` reports no direct xrefs to `0x0048e310` or `0x0048e410`. The `find_bytes` direct-call/jump probes for the obvious relative `call`/`jmp` encodings to both starts also returned zero matches.
- 2026-06-06 live IDA MCP disassembly confirms the first helper saves `ecx` as the config object, clears a stack buffer with `sub_5A2DA0`, reads row count from `this + 0x28d9d4`, compares row text at `this + 0x6` and `this + 0x208`-relative fields, compares a second key from `dword_67AB1C + 0x858`, returns the found/scanned index in `eax`, and runs a stack-cookie check before returning.
- 2026-06-06 live IDA MCP disassembly confirms the second helper uses `ecx` as the config object, starts at `this + 0x206`, iterates `0x64` rows at stride `0x6894`, clears leading/trailing UTF-16 slots, clears a row count/value dword at `+0x668e`, and loops `0x14` times per row over two wide-value subarrays.
- `resources/exported_data/master_function_list.json` includes a Ghidra/GhidrAssist entry for `0x0048e310` summarized as a wide-string config-table lookup/append helper, but no IDA function name. No corresponding generated `simroot_v2` source body was found for `0x0048e310` or `0x0048e410`.
- The second helper's constants match the `Config` constructor/default table layout documented in [UID:000110][0x0048e480-0x0048f3f1.ConfigAndRegistryDefaults](by-memory/0x0048e480-0x0048f3f1.ConfigAndRegistryDefaults.md): 100 rows, row stride `0x6894`, and repeated 20-wide-value clears.
