## Behavior

This constructor-only loader opens the monster animation table resource, allocates the main [UID:0001VC][MonsterImageEntry](by-type/by-struct/MonsterImageEntry.md) row array, seeds the process-wide monster default table, and fills nested animation groups and frame records used by the monster render and bounds paths.

Observed flow:

1. Construct a local [UID:00003G][DATFile](by-class/DATFile.md)-style reader.
2. Open `MONSTER.DNA` when `byte_66DA97 == 1`; otherwise open `MONSTER.DND`. The file-level docs use the source-facing inferred flag name `g_usesCompactMonsterTable`.
3. Read a 32-bit monster row count.
4. Allocate a counted vector array with `rowCount` elements of size `0x0c` / 12 bytes (Verified with int_convert.py), using the outer table constructor at `0x00528930` and destructor at `0x00528950`.
5. Store the row pointer at `MonsterImageLib +0x04` and row count at `MonsterImageLib +0x08`.
6. Allocate the static monster default table [UID:00029K][0x0069b424-0x0069b430.ImageLibraryFallbackRecord](by-memory/0x0069b424-0x0069b430.ImageLibraryFallbackRecord.md), source-facing inferred as `g_defaultMonsterAnimationTable`, with `0x15` / 21 groups (Verified with int_convert.py).
7. Walk `0x0a8` / 168 bytes (Verified with int_convert.py) as 21 groups of 8 bytes each; allocate one 10-byte frame record per group and seed each default frame as frame offset `0`, frame duration `30000`, and blend alpha `0`.
8. For each file-backed monster row, read `+0x00` dword, `+0x04` byte, `+0x05` byte, and `+0x06` word, then allocate the row's group array through helper `0x005289d0`.
9. For each 8-byte group, read its 16-bit frame count at `+0x04`, allocate 10-byte frame records through helper `0x00528be0`, and read each frame entry in offset order `+0x00`, `+0x02`, `+0x06`, `+0x04`, `+0x08`, `+0x09`.
10. Close the DAT reader through `DATFile::Close`; the local reader destructor runs during function exit.
