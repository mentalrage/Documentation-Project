## Behavior

This constructor-only loader opens the monster table resource, allocates the main [UID:0001VC][MonsterImageEntry](by-type/by-struct/MonsterImageEntry.md) vector, initializes global monster grouping tables, and then populates nested palette/frame records used by the monster render and bounds paths.

Observed flow:

1. Construct/open a DAT reader object.
2. Select `MONSTER.DNA` when `byte_66DA97 == 1`; otherwise select `MONSTER.DND`.
3. Read a 32-bit monster row count.
4. Allocate a vector-style array with a 4-byte count prefix and `rowCount` elements of size `0x0c`; the element constructor at `0x00528930` zeroes the three dwords and the element destructor at `0x00528950` tears down nested records.
5. Store the array pointer at `MonsterImageLib +0x04` and the row count at `MonsterImageLib +0x08`.
6. Initialize the 21-entry global monster grouping table rooted at `dword_69B424` / `dword_69B42C`.
7. For each monster row, read 4 bytes into `entry +0x00`, 1 byte into `entry +0x04`, 1 byte into `entry +0x05`, and 2 bytes into `entry +0x06`.
8. Allocate the entry's nested 8-byte record array through `0x005289d0` using the count at `entry +0x04`; that helper writes the nested pointer to `entry +0x08`.
9. For each nested 8-byte record, read a 16-bit nested count at record `+0x04`, allocate a 10-byte child-record array through `0x00528be0`, and read child record fields in the order 2, 2, 2, 1, 1, 1 bytes at offsets `+0x00`, `+0x02`, `+0x06`, `+0x04`, `+0x08`, and `+0x09`.
10. Close/destroy the DAT reader object before returning.
