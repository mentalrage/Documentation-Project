# MSVC STL Iostream Numeric Support

## Address Range

- `0x00439ee0-0x0043e0a3`
- Entity kind: runtime / third-party standard-library support.
- Disposition: ignored for NexusTK-owned reconstruction.
- Rebuild handling: `third-party/runtime` plus `compiler/linker-generated`.

## Summary

This range is a dense MSVC/Dinkumware support island after the project `DequeDestroy` method and before `DequeEnsureCapacity`. It contains standard-library string, stream, locale, exception, and numeric-conversion helpers used by JsonCpp and other C++ code. It is not a coherent NexusTK product source module.

The rebuilt project should preserve source-level uses of `std::string`, streams, locales, numeric parsing, exceptions, and vendored JsonCpp. Equivalent helper code should be supplied by the selected compiler/runtime and template instantiation, not manually ported as NexusTK code.

## Evidence

- Read-only IDA MCP `py_eval` on 2026-05-27 reports 80 primary functions from `sub_439EE0` at `0x00439ee0` through `sub_43E090` ending at `0x0043e0a3`.
- Representative standard-library diagnostics and constants in the range include `ios_base::badbit set`, `ios_base::failbit set`, `ios_base::eofbit set`, `0123456789-+Ee`, `0123456789ABCDEFabcdef-+XxPp`, and `0123456789ABCDEFabcdef-+Xx`.
- IDA names one helper as `?append@?$basic_string@DU?$char_traits@D@std@@V?$allocator@D@2@@std@@QAEAAV12@ABV12@@Z`, confirming Dinkumware `std::basic_string` support.
- Early callers include JsonCpp value/writer/parser helpers such as `0x0042d7f0`, `0x0042ee10`, `0x00428720`, `0x00428940`, and related runtime chunks. Later numeric helpers are called by parser/conversion routines around `0x0043f9a0-0x004406f0`.
- Boundary check: `0x00439ed5-0x00439ee0` is `0xcc` alignment before `sub_439EE0`; `0x0043e0a3-0x0043e0b0` is `0xcc` alignment before [UID:0000XB][0x0043e0b0-0x0043e241.DequeEnsureCapacity](by-memory/0x0043e0b0-0x0043e241.DequeEnsureCapacity.md).
