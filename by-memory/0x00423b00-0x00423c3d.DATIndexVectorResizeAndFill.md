## Behavior

`DATIndexVector::ResizeAndFill` treats the requested logical entry count as paired 32-bit slots. It doubles the requested count, checks the `0x3fffffff` slot limit, ensures the value-table storage at object offsets `+0x0c`, `+0x10`, and `+0x14` can hold the requested slot count, and fills the target slot range with the object's stored fill value at offset `+0x04`.

The method has three fill cases:

- When the requested slots exceed current capacity, it grows/replaces the storage, then scalar-fills the full requested slot count.
- When the requested slots fit capacity but exceed the active end, it fills the existing active range through [UID:0002U7][0x004233f0-0x00423465.DATIndexVectorFillSlotRaw](by-memory/0x004233f0-0x00423465.DATIndexVectorFillSlotRaw.md), then scalar-appends the remaining slots.
- When the requested slots are within the active range, it fills only `[begin, begin + requestedSlots)` through [UID:0002U7][0x004233f0-0x00423465.DATIndexVectorFillSlotRaw](by-memory/0x004233f0-0x00423465.DATIndexVectorFillSlotRaw.md).

After filling, it stores the new active end pointer, writes `entryCount - 1` at offset `+0x18`, writes `entryCount` at offset `+0x1c`, and returns `entryCount - 1`.

The local capacity helper at `0x00423c50` allocates a replacement DWORD array through [UID:0002E2][0x00421520-0x00421584.AllocateAlignedDwordArray](by-memory/0x00421520-0x00421584.AllocateAlignedDwordArray.md), copies the existing active slots, frees the old backing storage with large-allocation header validation, then commits the new begin/end/capacity triple. The local free helper at `0x00423e00` releases a DWORD backing array with the same large-allocation guard. These two helpers are not yet split into dedicated pages.
