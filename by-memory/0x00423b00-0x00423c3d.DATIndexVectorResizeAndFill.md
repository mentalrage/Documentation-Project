## Behavior

`DATIndexVector::ResizeAndFill` treats the requested logical bucket count as paired 32-bit slots. It doubles the requested count, checks the `0x3fffffff` slot limit, ensures the bucket-table storage at object offsets `+0x0c`, `+0x10`, and `+0x14` can hold the requested slot count, and fills the target slot range with the object's list head/sentinel pointer at offset `+0x04`.

The stored fill value at object offset `+0x04` is `DATIndexVector::m_listHead`, not evidence for a separate value-vector class. `ResizeAndFill` uses it to initialize every bucket's `first` and `last` pointer in the two-dword bucket table. The writes to `+0x18` and `+0x1c` are source-facing `m_bucketMask = bucketCount - 1` and `m_bucketCount = bucketCount`.

The method has three fill cases:

- When the requested slots exceed current capacity, it grows/replaces the storage, then scalar-fills the full requested slot count.
- When the requested slots fit capacity but exceed the active end, it fills the existing active range through [UID:0002U7][0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper](by-memory/0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper.md), then scalar-appends the remaining slots. [UID:0002U7][0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper](by-memory/0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper.md) is non-emitting local fill lowering for this source operation, not an independently emitted helper.
- When the requested slots are within the active range, it fills only `[begin, begin + requestedSlots)` through [UID:0002U7][0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper](by-memory/0x004233f0-0x00423465.DATIndexVectorFillValueRangeHelper.md). The source-level expression still belongs in `ResizeAndFill` because this method chooses the bucket span and supplies `m_listHead`.

After filling, it stores the new active end pointer, writes `bucketCount - 1` at offset `+0x18`, writes `bucketCount` at offset `+0x1c`, and leaves `bucketCount - 1` in `EAX`. No documented caller currently depends on that incidental return value, so a source-facing declaration can remain `void ResizeAndFill(int bucketCount)` unless later caller evidence proves the return is source-visible.

The local capacity helper [UID:0004HG][0x00423c50-0x00423cf6.DATIndexVectorEnsureBucketStorageCapacity](by-memory/0x00423c50-0x00423cf6.DATIndexVectorEnsureBucketStorageCapacity.md) allocates a replacement DWORD array through [UID:0002E2][0x00421520-0x00421584.AllocateAlignedDwordArray](by-memory/0x00421520-0x00421584.AllocateAlignedDwordArray.md), copies the existing active slots, frees the old backing storage through runtime allocation/free lowering, then commits the new begin/end/capacity triple.
