## Behavior

This helper island mirrors the opcode `0x43` subtype handling in [UID:00021C][0x00484f70-0x0048540b.ClanStatusPacketDispatcher](by-memory/0x00484f70-0x0048540b.ClanStatusPacketDispatcher.md). The first, second, and sixth functions are directly called by the dispatcher:

- `0x00484fdb -> 0x004877d0`
- `0x00484fec -> 0x004879e0`
- `0x00485181 -> 0x00487ea0`

The remaining sibling functions have no IDA code or data xrefs, but they are byte-for-byte coherent dialog-opening helpers for the same packet subtype sequence. Treat them as retained source functions from the same original Clan module unless a stronger linker/object-layout explanation proves otherwise, even if the active dispatcher inlines equivalent logic for cases `3-5` and `7-12`.

The three dispatcher-called handlers update the `ClanStatusPane`/enlist dialog child-pane cluster through fixed offsets:

- Handler `0x004877d0` copies a 40-wide-character clan name to receiver offset `0xfe`, writes the request body into [UID:0002B7][0x0067adf0-0x0069adf0.WideCharStrGlobalBuffer](by-memory/0x0067adf0-0x0069adf0.WideCharStrGlobalBuffer.md), clears and fills child pointer offset `0x2510`, sets view byte offset `0xf8` to `2`, and activates that child with rectangle `18,71,174,263`.
- Handler `0x004879e0` rejects nonzero `packet[2]`, clears child pointer offset `0x2514`, appends each counted clan-name entry through [UID:00035D][0x00488680-0x0048873e.ClanStringListPaneInsertOrReplaceText](by-memory/0x00488680-0x0048873e.ClanStringListPaneInsertOrReplaceText.md), copies the heading/name to receiver offset `0xfe`, sets view byte offset `0xf8` to `3`, and activates child offset `0x2514`.
- Handler `0x00487ea0` uses a switch on `packet[2]`: action `0` clears/fills child pointer offset `0x2518` and sets mode `4`; action `1` allocates `0x870` bytes, calls `0x00489600`, and installs the `ClanEnlistInputDialog` vtable family; action `2` returns success without opening a dialog; other actions return failure.

The standalone dialog opener siblings all use the same shape:

1. Initialize packet text decoding via helper `0x00516030`.
2. Check `packet[2]` for action/state.
3. Allocate either a one-field name dialog (`0x26c` bytes), the leave-confirm dialog (`0x270` bytes), a multi-field attribute dialog (`0x870` bytes), or an item dialog wrapper.
4. Call the shared base constructor (`0x00488b40`, `0x00489600`, `0x0048a1c0`, or `0x0048a810`) and install the derived Clan dialog vtables.

Action handling for the no-xref siblings matches the inline dispatcher cases: leave/deposit-item/appear open only for action `0`; deposit-money, expel, summon, withdraw-money, and withdraw-item accept action `1` without opening a new dialog; change opens the name dialog for action `0`, opens the attribute dialog for action `1`, and accepts action `2`.
