## Behavior

This is the main tab/page switch helper for the seven-child [UID:00005Q][GeneralPurposePanel](by-class/GeneralPurposePanel.md).

Observed flow:

1. Selects the valid tab count from [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md): seven tabs in EPF/new-layout mode, four tabs in legacy mode.
2. Rejects out-of-range tab requests and most redundant active-tab requests.
3. If [UID:0000SK][g_pTotemFrame](by-global/g_pTotemFrame.md) is active, marks it for deletion before switching the panel.
4. Hides and collapses the old active child pane when one is active.
5. Stores the new active child index.
6. Sets the new child bounds, attaches the child to the active UI layer/root, activates it, and optionally shows it with the caller-supplied argument.
7. In the new-layout branch, runs [UID:0000YI][0x004615b0-0x00461657.AboveFrameRefreshHelpers](by-memory/0x004615b0-0x00461657.AboveFrameRefreshHelpers.md): `0x004615b0` releases the dynamic frame slot and the adjacent creator rebuilds the `0x0067a840` `AboveFrame` slot.
8. In the legacy branch, triggers [UID:0000R8][g_pInterfaceEfxMgr](by-global/g_pInterfaceEfxMgr.md) through `0x004e9ee0`.

The two layout rectangles observed in IDA are:

| Mode | Rectangle |
| --- | --- |
| EPF/new layout | `(832, 79, 1021, 367)` |
| Legacy layout | `(434, 12, 626, 300)` |

## Callee And State Evidence

Live IDA MCP `decompile`/`callees` on 2026-06-06 shows:

- EPF/new-layout mode allows tab indexes `< 7`; legacy mode allows indexes `< 4`, using [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md).
- The old active child is read from `this[8]`, then hidden/collapsed through helper `0x00544ee0` and vtable offset `0x40` when present.
- The new active index is stored back to `this[8]`; child pointers are read from `this[index + 1]`.
- New-layout bounds use `(832, 79, 1021, 367)` and always call the child show/activation slot with the caller flag, then call frame-refresh helpers at `0x004615b0` and `0x004615d0`.
- Legacy bounds use `(434, 12, 626, 300)`, conditionally calls the child show/activation slot when the caller flag is nonzero, then calls [UID:0000R8][g_pInterfaceEfxMgr](by-global/g_pInterfaceEfxMgr.md) through `0x004e9ee0`.
- Both paths clear [UID:0000SK][g_pTotemFrame](by-global/g_pTotemFrame.md) first through `0x00544690` when the totem frame singleton is active.

## Packet Dispatch Notes

The map dispatcher uses this helper for server-driven panel tab changes. IDA disassembly shows opcode case `0x34` calling it with tab `1`, case `0x39` calling it with tab `0`, and another dispatcher case calling it with tab `5`. These are side-panel page switches, not dialog-message helper calls.

## Ownership Notes

`source-3/simroot_v2/class_SpellOneArgInputPane.cpp` currently emits this function as `SpellOneArgInputPane::SwitchActiveTab`. That owner is contradicted by the object layout, constructor ownership, and caller mix. Reconstruct it as `GeneralPurposePanel::SwitchActiveTab` or an equivalently named method on the side-panel shell.

The frame refresh callees belong to [UID:0000JL][FrameChrome](by-file/FrameChrome.md), not to the panel shell. This method depends on them after tab changes.
