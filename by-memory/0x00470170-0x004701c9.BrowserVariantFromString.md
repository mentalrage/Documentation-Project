# 0x00470170-0x004701c9 CComVariant LPCOLESTR Constructor Lowering

## Scope

- Range: `0x00470170-0x004701c9` half-open.
- Entity kind: ATL template/compiler-generated out-of-line constructor lowering.
- Direct owner: none; this range has no independent project source owner or emitter.
- Parent inventory: [UID:0000ZF][0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers](by-memory/0x0046f010-0x004710b8.BrowserOleLegacyAndHelpers.md).

The historical `BrowserVariantFromString` name described the raw behavior but incorrectly promoted compiler/template output to a project free helper. The exact body is ATL `CComVariant(LPCOLESTR)` construction: initialize/clear the destination VARIANT, set `VT_BSTR`, allocate with `SysAllocString`, and use ATL exception behavior for failure.

## IDA Evidence

- 2026-06-10 B001-024 live IDA MCP reports `sub_470170` at `0x00470170-0x004701c9`.
- Direct callers are exactly `0x00469d38` in `BrowserWindow::NavigateBrowser` and `0x0046bdb6` in `BrowserControlPane::NavigateBrowser`. Both calls are constructor-shaped uses on local VARIANT storage; they do not establish a project helper owner.
- Decompilation sets `pvarg->vt = 0`, calls `VariantClear`, throws through the ATL exception helper on failure, sets `vt = VT_BSTR`, calls `SysAllocString`, and records `VT_ERROR` / `E_OUTOFMEMORY` when allocation fails for a non-null input.
- The helper is padded by `0xcc` bytes at `0x0047016e-0x00470170` before it and `0x004701c9-0x004701d0` after it.
- 2026-06-29 B002 accepted implementation pass rechecked the current `supervisor_resume_20260629` MCP evidence from the accepted report: the function still decompiles as a `VARIANTARG *` helper with BrowserWindow and BrowserControlPane callers, and the throwing helper at `0x00470960` remains source-equivalent to `AtlThrow`.
- 2026-07-12 B001 reanalysis matched the entire operation sequence and return convention to ATL `CComVariant(LPCOLESTR)` lowering. UID00033K independently inlines the same source operation twice for null-BSTR variants and therefore requires no call to a project-named helper.

## Reconstruction Notes

Do not reconstruct or emit this range as a browser-local static/free helper. Source consumers should write ordinary `CComVariant` construction at each use site and let ATL/compiler instantiation account for this body. The formal managed block is intentionally blank, canonical owner is `NONE`, reconstructable is false, and emitter metadata is blank.

The exact binary behavior remains important no-source proof: the destination starts as `VT_EMPTY`, `VariantClear` failure reaches [UID:00033I][0x00470960-0x0047097c.CAtlExceptionThrowHelper](by-memory/0x00470960-0x0047097c.CAtlExceptionThrowHelper.md), successful construction sets `VT_BSTR` and calls `SysAllocString`, and a null allocation for non-null input records `VT_ERROR`/`E_OUTOFMEMORY` before the ATL throw path. The returned destination pointer is normal constructor-lowering convention, not evidence for a source-authored return type.

Rejected alternatives: retain neither `BrowserVariantFromString` nor another invented project helper name; do not assign the range to BrowserWindow, BrowserControlPane, Browser class, or Browser file ownership merely because those source consumers instantiate the ATL template; do not emit raw `VARIANTARG` mechanics in Browser.cpp.
