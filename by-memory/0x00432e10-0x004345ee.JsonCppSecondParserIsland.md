# JsonCpp Second Parser Island `0x00432e10-0x004345ee`

## Status

- Confidence: strong for JsonCpp ownership; high for the current upstream snapshot candidate (`b299d3581f4dc670734f1fe1a34fce1282337802`), medium-low for per-function names.
- Proposed owner: [UID:0000KI][JsonCpp](by-file/JsonCpp.md)
- Disposition: third-party static library code; exclude from NexusTK product source modules.
- Evidence basis: read-only IDA MCP function-list, lookup, callee, string, decompile, and string-xref checks on 2026-05-25. `wave3.py` was not executed for this pass.

## Range Role

This is the current second IDA-modeled JsonCpp parser island. It mirrors the earlier reader parser family, but includes the duplicate-key diagnostic and additional helper calls associated with the builder-era `OurReader`/`OurCharReader` path.

The range is recorded separately from [UID:0000X2][0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland](by-memory/0x0042ae90-0x0042edeb.JsonCppReaderBuilderIsland.md) because there is a substantial code gap between the two islands and because the duplicate-key diagnostic appears only in this second parser family. The immediately preceding parse front end is documented as [UID:0000X7][0x00431d50-0x00431f1c.JsonCppOurReaderParse](by-memory/0x00431d50-0x00431f1c.JsonCppOurReaderParse.md).

## Evidence

- IDA string xrefs tie `0x00432f10`, `0x004331f0`, `0x00433860`, and `0x004340f0` to JsonCpp parser diagnostics.
- [UID:0000X7][0x00431d50-0x00431f1c.JsonCppOurReaderParse](by-memory/0x00431d50-0x00431f1c.JsonCppOurReaderParse.md) calls `0x00432f10` and contains the `Extra non-whitespace after JSON value.` fail-if-extra discriminator. Its control flow predates the `strictRoot` branch change added after upstream commit `b299d358`.
- `Duplicate key: '` at `0x0060e71c` has an IDA xref from `0x004331f0`, supporting the builder-era duplicate-key-aware parser family.
- [UID:0000X9][0x004345f0-0x00434887.JsonCppNumberTokenParseHelper](by-memory/0x004345f0-0x00434887.JsonCppNumberTokenParseHelper.md) immediately follows this island. It references `Unable to parse token length` at `0x0060e730` from `0x0043463c`; this string is present in JsonCpp `1.7.x` and absent from the staged `0.10.6` source, while the `0.10.6`-specific `reader error` string was not found in IDA strings.
- `0x00432f10` calls local object/array parser helpers and value/string support functions, matching the first parser island's structure.
- `0x004331f0` calls `0x00432f10` recursively and references JsonCpp value/object helpers.
- RTTI-ish strings identify `Json::OurCharReader` and `Json::CharReaderBuilder`, which fit this duplicate-key-aware reader family.

## Ownership Decision

Keep this island with [UID:0000KI][JsonCpp](by-file/JsonCpp.md) and `third_party/jsoncpp/`. Product modules should not absorb these functions even when they are called from item-shop, fitting-room, or downloader code.

- Whether any nearby support functions outside this exact range also belong to the same parser family.
