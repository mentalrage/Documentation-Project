# 0x00575b90-0x00575caa PacketTransform String-Key Helpers

## Status

- Disposition: reconstructable NexusTK project code
- Entity kind: packet transform key/string helper pair
- Current generated owner: recovered global helpers
- Likely source module: [UID:0000M9][PacketTransform](by-file/PacketTransform.md)
- Shared state: [UID:0000TG][PacketTransformGlobals](by-global/PacketTransformGlobals.md)
- Confidence: strong for address behavior; medium for exact final names and whether the first helper is live.

## Covered Range

This page covers two transform-adjacent helpers identified while splitting the former `0x00575abb-0x00575cb0` UNKNOWN row. They are not scalar [UID:0000M8][PacketBuffer](by-file/PacketBuffer.md) readers; both operate on packet transform key material and the `0x0069ba4c` / `0x0069ba58` / `0x0069ba94` global region.

| Range | Current name | Notes |
| --- | --- | --- |
| `0x00575b90-0x00575c2e` | raw/IDA-missed helper | Duplicates the incoming string, copies `g_packetXorAlternateSize` bytes into `g_packetNonceScratch`, and copies four windows into `g_packetXorTableAlternate`. |
| `0x00575c30-0x00575caa` | `sub_575C30` | Copies the login/process string into `ArgList`/`g_processArgList` at `0x0069ba58`, then repeatedly concatenates the string with itself for 31 more iterations. |

The tiny padding at `0x00575c2e-0x00575c30` is internal alignment between the helpers.

## Evidence

- 2026-05-28 IDA MCP byte review shows real code beginning at `0x00575b90`, despite the prior coverage row treating `0x00575b8c-0x00575c30` as part of one UNKNOWN gap.
- The raw `0x00575b90` helper calls `sub_516030`, duplicates the input via `sub_515290`, copies from the duplicated buffer into `byte_69BA4C`, then copies that scratch block into the alternate transform table at `0x0069ba94`, `0x0069ba94 + size`, `+ size * 2`, and `+ size * 3`.
- IDA MCP identifies `sub_575C30` as `0x00575c30-0x00575caa` with one direct code ref at `0x004f8544` from [UID:00019K][0x004f7d10-0x004f8b2a.InitializeMainUiGraph](by-memory/0x004f7d10-0x004f8b2a.InitializeMainUiGraph.md) after `WideCharToMultiByte` converts the login name.
- `sub_575C30` writes to IDA `ArgList` at `0x0069ba58`, which [UID:0001I0][0x00575cb0-0x00575d83.PacketNonceInitialization](by-memory/0x00575cb0-0x00575d83.PacketNonceInitialization.md) consumes as packet transform key/process material.

## Ownership Decision

Keep these helpers with [UID:0000M9][PacketTransform](by-file/PacketTransform.md) or a private transform section inside [UID:0000NS][Socket](by-file/Socket.md). They derive transform key material from process/login text and update the same globals used by nonce initialization and XOR transforms. They should not be folded into [UID:0000M8][PacketBuffer](by-file/PacketBuffer.md), which owns scalar packet serialization/parsing.

## Open Questions

- Confirm whether the raw `0x00575b90` helper is live through an indirect or exception-only path, or dead leftover transform setup code.
- Rename `ArgList` / `g_processArgList` after the key-material lifetime and allocation sites are fully reconciled with Socket setup.
