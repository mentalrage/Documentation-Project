## Behavior

This tiny helper snapshots the current timer tick from [UID:0000SI][g_pTimerMgr](by-global/g_pTimerMgr.md) into EventDispatcher state at offset `+0x2c`, now best described as `m_idleTickBaseline`. The binary leaves that tick value in `eax`, but the only caller ignores the result. `Application::RunMessageLoop` calls it once before entering the wait/message pump loop so the later idle worker can compute elapsed tick slices against a fresh baseline.

## Source-Structure Decision

Keep this as a private EventDispatcher idle/message-loop helper paired with [UID:000142][0x004a6c40-0x004a6cda.ApplicationIdleWorkScheduler](by-memory/0x004a6c40-0x004a6cda.ApplicationIdleWorkScheduler.md). It is too small and too tightly coupled to the idle worker's private EventDispatcher state to justify `Application.cpp`, `TimerMgr.cpp`, or a standalone generated `ApplicationHelper_4A6C40.cpp` source module.

The best current source-facing helper name is `EventDispatcher::CaptureIdleTickBaseline()`. `ApplicationIdleTickBaseline` remains acceptable as a documentation title, while `CaptureCurrentTickBaseline` remains a generated/wrapper lead rather than recovered original spelling. A small `MessageLoopScheduler.cpp` companion is a weaker future source-organization option only if the project later chooses to wrap this EventDispatcher-private state.

The 2026-06-20 B001 aggregate audit for [UID:000141][0x004a6a80-0x004a82a9.EventDispatcher](by-memory/0x004a6a80-0x004a82a9.EventDispatcher.md) confirms that this helper should be modeled with the EventDispatcher idle scheduler pair and not as an `ApplicationHelper_4A6C40` class method. The accepted B010 callback now emits the first-draft formal body alongside [UID:000142][0x004a6c40-0x004a6cda.ApplicationIdleWorkScheduler](by-memory/0x004a6c40-0x004a6cda.ApplicationIdleWorkScheduler.md), using an unsigned return to preserve the ABI-visible `eax` value.

The companion scheduler flag [UID:00027B][0x0066d880-0x0066d888.ApplicationIdleSchedulerStaticFlag](by-memory/0x0066d880-0x0066d888.ApplicationIdleSchedulerStaticFlag.md) is now `s_idleTimerSetupPending`.
