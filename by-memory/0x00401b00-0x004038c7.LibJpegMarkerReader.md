# IJG libjpeg Marker Reader `0x00401b00-0x004038c7`

## Status

- Confidence: strong for `jpeg-6b/jdmarker.c` source-file ownership.
- Proposed owner: [UID:0000KN][LibJPEG](by-file/LibJPEG.md)
- Disposition: third-party static IJG libjpeg code; exclude from NexusTK product files.
- Evidence basis: read-only IDA MCP decompile/callee/function-list checks and source comparison against `jpegsrc.v6b.tar.gz` on 2026-05-25. `wave3.py` was not executed for this pass.

## Range Role

This range is the decompression marker-reader module from IJG libjpeg 6b. It owns marker parsing after the public decompression API has created the decompressor and before the input controller/master controller starts scan decoding.

The range begins at `0x00401b00`, immediately after the documented decompression public API cluster ending at `0x004019e3`; IDA has no modeled function in the padding gap. The last function in this cluster ends at `0x004038c7`, before the compression API front-end range at `0x00403920`.

## Evidence Notes

- `jpeg_CreateDecompress` at `0x004011b0` calls `0x00401d10`, matching `jinit_marker_reader`.
- IDA decompilation of `0x00401d10` allocates a 168-byte marker reader object and installs callback pointers to functions in this range.
- IDA decompilation of `0x004022d0` is a marker-dispatch loop over JPEG marker constants and directly calls local helpers in this range.
- The function family contains JFIF/Adobe marker literals and frame/scan/table parsing structure that matches stock `jdmarker.c`.

## Ownership Decision

Keep the whole range under `third_party/libjpeg/jdmarker.c`. Product image loaders consume this module through public IJG decompression calls; they do not own marker parsing.
