## Behavior

Converts a parsed MIDI/meta event into a 12-byte WinMM `midiStreamOut` event record. It handles tempo meta-event `0xff 0x51`, volume controller event tagging, meta/SysEx payload cleanup, and negative status returns for unsupported events or output-buffer exhaustion.

## Verified Stream Encoding Flow

- Live IDA MCP on 2026-06-03 reports the current prototype as `int __thiscall(_DWORD *this, int, _DWORD *)`, with the second argument acting as the parsed 16-byte MIDI event record and the third argument acting as the stream-output context.
- The stream-output context uses base pointer at dword `+0x00`, buffer offset at `+0x40`, capacity/limit at `+0x44`, used byte count at `+0x48`, first-event timestamp/cache at `+0x4c`, and overflow debounce flag at `+0x50`.
- For channel events (`status < 0xf0`), the helper writes one 12-byte stream record: delta at dword `+0`, zero stream ID at dword `+4`, and packed MIDI short message at dword `+8`.
- Controller `0xb0` with controller number `7` is tagged by OR-ing the packed message with `0x40000000`, matching the MIDI callback's later controller-volume handling.
- For SysEx statuses `0xf0` and `0xf7`, the helper does not emit a stream record; it frees the event payload when the parser allocation counter is nonzero.
- For meta type `0x51`, the helper reads the three-byte tempo payload, stores microseconds-per-quarter state at `this + 0x40`, emits a tempo stream record tagged with `0x01000000`, updates the cached tick/tempo divisor at `this + 0x38`, frees the payload, and advances the stream used byte count by `0x0c`.
- Return values observed by IDA are `0` for success/ignored SysEx, `-104` for stream output space or overflow gating, and `-105` for unsupported meta events after payload cleanup.
