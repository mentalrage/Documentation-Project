# 0x00530d00-0x00530ed9 ObjectList Static Object Lighting Sync Helper

## Boundary

The preceding bytes `0x00530cf7-0x00530d00` are `0xcc` padding after [UID:0001D0][0x00530c90-0x00530cf7.NumberInputDialogScalarDeletingDestructor](by-memory/0x00530c90-0x00530cf7.NumberInputDialogScalarDeletingDestructor.md), and the following bytes `0x00530ed9-0x00530ee0` are `0xcc` padding before [UID:0001D1][0x00530ee0-0x00531473.ObjectListLifecycle](by-memory/0x00530ee0-0x00531473.ObjectListLifecycle.md).

## Signature

IDA decompiles the function as `int __thiscall sub_530D00(ObjectList* this, unsigned short staticObjectId)`.

The return value is incidental decompiler carry-through from the last helper call or loop state. The source-facing method should most likely be `void`.

## Behavior

The helper searches the `ObjectList` row bucket that stores static object panes and synchronizes the lighting companion for every static object pane whose stored object id matches the supplied `staticObjectId`.

1. It resolves static-object metadata through [UID:0000SD][g_pStaticObjImageLib](by-global/g_pStaticObjImageLib.md) by calling `sub_4DDA30(g_pStaticObjImageLib, staticObjectId)`.
2. It iterates `rowCount + 12` row lists from the `ObjectList` list-array field at `this + 0x28`.
3. For each object pane in each row list, it compares the 16-bit object id at object offset `+0x128` with `staticObjectId`.
4. For a match, it first calls virtual slot `+0x20` with zero, which appears to detach or disable the current static object state before lighting synchronization.
5. It reads the current attached light through `sub_5376C0(objectPane)`, which IDA decompiles as `return this[70]` and therefore reads object offset `+0x118`.
6. If an attached light exists and the static-object metadata light value is negative, it removes that light from the `ObjectList` global lighting/list tier at `this + 0x3c`, calls the object pane virtual detach slot at `+0x4c`, and destroys the attached light.
7. If an attached light exists and the metadata light value is non-negative, it calls [UID:0001DI][0x0053c980-0x0053c9b5.LightingObjectPaneSetIntensity](by-memory/0x0053c980-0x0053c9b5.LightingObjectPaneSetIntensity.md) to update the existing light.
8. If no attached light exists and the metadata light value is non-negative, it allocates a 312-byte [UID:000075][LightingObjectPane](by-class/LightingObjectPane.md), obtains the static object's map position through `sub_5374D0`, constructs the light through [UID:0001DG][0x0053c5e0-0x0053c6a1.LightingObjectPaneLifecycle](by-memory/0x0053c5e0-0x0053c6a1.LightingObjectPaneLifecycle.md), inserts the new light through [UID:00023E][0x00531480-0x00532530.ObjectListCategorizeLookupHelpers](by-memory/0x00531480-0x00532530.ObjectListCategorizeLookupHelpers.md) at `sub_5314A0`, and attaches the light back to the static object through virtual slot `+0x48`.

This makes the old `RemoveByObjectId` name incomplete. The function can remove an obsolete attached light, but its central job is to refresh static-object lighting state by object id.
