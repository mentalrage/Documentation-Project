# 0x0069b4f8-0x0069b4f9 MapPaneRenderScratchFlag

## Status

- Entity kind: one-byte initialized render-state cache flag.
- Disposition: reconstructable NexusTK project global state.
- Rebuild handling: MapPane-owned initialized byte; final declaration pending.
- Parent: [UID:0000L3][MapPane](by-file/MapPane.md).
- Confidence: strong for MapPane render ownership, xrefs, and exact boundary; medium for final symbol name and config-field name.

## Storage

`0x0069b4f8-0x0069b4f9` is a one-byte `.data` item initialized to `0xff`. Live IDA reports item head `0x0069b4f8`, size `1`, and exactly two direct data refs from the MapPane render body.

The following `0x0069b4f9-0x0069b4fc` bytes are a three-byte unreferenced tail initialized to `ff ff ff`. They are split out as ignored tail/alignment bytes in [UID:0000VN][-ignored](by-memory/-ignored.md) and the memory coverage report. Keep this page focused on the source-bearing flag byte.

The final source declaration/name is provisional until the exact render-mode branch is named from the surrounding `MapPane::RenderMapView` decompilation. Do not emit C++ for this page yet.

## Evidence

- Live IDA `xrefs_to 0x0069b4f8` reports exactly two data refs, both inside the modeled `0x005094b0-0x0050a4fd` MapPane render function: a compare at `0x00509579` and a store at `0x005095b0`.
- Live IDA `lookup_funcs` confirms `0x005094b0`, `0x00509579`, and `0x005095b0` all belong to the same `0x104d`-byte modeled render body.
- The render body reads a config/state byte through [UID:00028Q][0x0067a7c8-0x0067a7cc.g_pConfig](by-memory/0x0067a7c8-0x0067a7cc.g_pConfig.md) at offset `0x28de5e`, compares it with this cached flag, and skips the refresh path when the values match.
- On mismatch, the render body calls palette/render refresh helpers at `0x00543f80` and `0x0050d840`, invalidates the MapPane through virtual slot `+0x20`, then stores the new config byte back to `0x0069b4f8`.
- Live IDA reports no refs to `0x0069b4f9`; the following three bytes stay ignored padding/tail bytes.
- Live IDA `xrefs_to 0x0069b4fc` reports four MemoryMan refs from `0x00516008`, `0x00516016`, `0x00516030`, and `0x00516270`, proving the following pointer is a different subsystem.
- Live IDA `xrefs_to 0x0069b4f4` reports MessageShowPane refs ending at the previous four-byte pointer, proving the lower boundary.
