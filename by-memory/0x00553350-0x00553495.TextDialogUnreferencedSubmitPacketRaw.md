## Behavior

The raw bytes decode as a TextDialog-like opcode `0x3a` submit-packet clone. The body uses an `ECX`-style object pointer and a wide-string argument, writes dialog-family fields corresponding to `+0x26c`, `+0x270`, `+0x274`, and `+0x276 + 1`, writes subtype byte `2`, converts the supplied wide text with `WideCharToMultiByte`, appends the converted bytes through the packet buffer helper, and sends through `g_packetSender` / `QueueAndSendPacket`.

Packet layout reconstructed from the raw body:

| Packet offset | Writer | Source | Current meaning |
| --- | --- | --- | --- |
| `+0x00` | `PacketBufferWriteUInt8` | literal `0x3a` | dialog/message reply opcode |
| `+0x01` | `PacketBufferWriteUInt8` | byte `this+0x26c` | dialog reply type/subtype byte |
| `+0x02..+0x05` | `PacketBufferWriteUInt32BE` | dword `this+0x270` | dialog/session/object id |
| `+0x06..+0x07` | `PacketBufferWriteUInt16BE` | word `this+0x274` | dialog state/sequence word |
| `+0x08..+0x09` | `PacketBufferWriteUInt16BE` | word `this+0x276 + 1` | one-based page/index value for text submit |
| `+0x0a` | `PacketBufferWriteUInt8` | literal `2` | text-submit subtype/action |
| `+0x0b` | `PacketBufferWriteUInt8` | converted byte count | one-byte text length |
| `+0x0c...` | `MemmoveWrapper` | converted bytes | ANSI/MBCS text payload |

The helper manually measures the UTF-16 input, passes only the low byte of the measured wide-character count to `WideCharToMultiByte(0, 0, ...)`, converts into a 256-byte local buffer, range-checks the converted byte count against `0x100`, writes the converted byte count as the packet length byte at `+0x0b`, copies the payload at `+0x0c`, writes a non-sent scratch terminator at `packet[convertedLength + 12]`, and queues exactly `convertedLength + 12` bytes. The low-byte source count likely depends on an external 255-character caller precondition; the routed [UID:0003VR][0x00553180-0x00553338.TextDialogHandleDialogAction](by-memory/0x00553180-0x00553338.TextDialogHandleDialogAction.md) submit path performs that kind of text-read limit before building its inline packet, but this raw island has no route proving the same precondition.

```cpp
// Non-emitting sketch only. If a route is proven later, this is likely
// a private TextDialog member helper.
void TextDialog::SendTextReplyPacket(const wchar_t *text)
{
    char converted[256];
    unsigned char packet[512];

    int wideChars = 0;
    while (text[wideChars] != 0)
        ++wideChars;

    PacketBufferWriteUInt8(0x3a, packet + 0);
    PacketBufferWriteUInt8(m_dialogReplyType, packet + 1);
    PacketBufferWriteUInt32BE(m_dialogId, packet + 2);
    PacketBufferWriteUInt16BE(m_dialogState, packet + 6);
    PacketBufferWriteUInt16BE(
        static_cast<unsigned short>(m_currentPageIndex + 1), packet + 8);
    PacketBufferWriteUInt8(2, packet + 10);

    int byteCount = WideCharToMultiByte(
        0, 0, text, static_cast<unsigned char>(wideChars),
        converted, sizeof(converted), 0, 0);
    if (byteCount >= sizeof(converted))
        _report_rangecheckfailure();

    converted[byteCount] = 0;
    PacketBufferWriteUInt8(static_cast<unsigned char>(byteCount), packet + 11);
    memmove(packet + 12, converted, byteCount);

    int packetLength = byteCount + 12;
    if (packetLength >= sizeof(packet))
        _report_rangecheckfailure();

    packet[packetLength] = 0;
    g_packetSender->QueueAndSendPacket(packet, packetLength);
}
```

The sketch intentionally uses descriptive member names and models the observed `movzx eax, bl` with the `unsigned char` cast. It documents behavior only; it does not establish source liveness or emission eligibility.
