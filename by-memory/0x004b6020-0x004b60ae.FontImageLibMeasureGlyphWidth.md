## Behavior

This method resolves a glyph record from a lazily loaded font slot, returns glyph metrics, and optionally decodes the glyph image into a caller-provided drawing/tile context.

Observed flow from live IDA:

- calls [UID:0002HS][0x004b60c0-0x004b61d9.FontImageLibEnsureFontSlotLoaded](by-memory/0x004b60c0-0x004b61d9.FontImageLibEnsureFontSlotLoaded.md);
- indexes the selected [UID:0001UM][FontSlotStorage](by-type/by-struct/FontSlotStorage.md) glyph pointer table at `slot + 0x08 + 4 * uint16(glyphId)`;
- falls back to glyph id `63` when the table entry is null;
- also falls back to glyph id `63` when the selected [UID:0001UK][FontGlyphRecord](by-type/by-struct/FontGlyphRecord.md) has zero visible width, tested as `right - left == 0`;
- reads the visible glyph fields:
  - `record + 0x00`: advance;
  - `record + 0x02`: top;
  - `record + 0x04`: left;
  - `record + 0x06`: bottom;
  - `record + 0x08`: right;
- writes an optional [UID:0001VP][RectBoundsLayout](by-type/by-struct/RectBoundsLayout.md) through [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md) subrange `0x004b7c50`, passing `left`, `top`, `right`, and `bottom`;
- writes the optional advance output from `record + 0x00`;
- resets an optional [UID:00004I][EPFTileContext](by-class/EPFTileContext.md) through `0x00458500`;
- calls [UID:0002HT][0x004b61e0-0x004b6341.FontImageLibDecodeGlyphBitmap](by-memory/0x004b61e0-0x004b6341.FontImageLibDecodeGlyphBitmap.md) when decode output is requested.

The body receives a next-glyph or spacing-looking explicit argument from text iterators, but live disassembly does not read that stack slot. Treat kerning/next-glyph semantics as unproven for this binary.
