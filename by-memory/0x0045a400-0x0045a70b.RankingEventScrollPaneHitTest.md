## Summary

This helper hit-tests a mouse point against the ranking scrollbar's logical part rectangles and returns a part code. It iterates part codes `0..4`, computes each candidate rectangle using the current orientation, scroll position, max range, enabled state, and drag state, then checks whether the input point is inside that rectangle.

The helper is not generic input dispatch. It is local scrollbar geometry for `RankingEventScrollPane`, with confirmed callers from the modeled mouse handler and the raw hover/drag helper island.

Known part codes match the neighboring scroll-volume pane convention:

| Code | Meaning |
| --- | --- |
| `0` | collapsed leading edge/arrow region |
| `1` | track before the thumb |
| `2` | thumb |
| `3` | track after the thumb |
| `4` | collapsed trailing edge/arrow region |
| `0xff` | no hit |

## Source-Shape Notes

Do not emit final C++ for this helper yet. The control flow and field reads are stable, but final names for scroll-part constants, the shared geometry API, and the internal rectangle-building shape are still provisional.

The helper should eventually reconstruct as local scrollbar hit-testing that loops part codes `0..4`, builds the corresponding rectangle, point-tests it, and returns `0xff` on miss.

The inlined rectangle construction behavior is:

- Part `0` and part `4` collapse to the leading/trailing edge line of the control bounds.
- Part `1` is the track segment before the thumb.
- Part `2` is the thumb rectangle.
- Part `3` is the track segment after the thumb.
- If the scrollbar is enabled and `maxPosition > 0`, the thumb position is derived from `currentPosition / maxPosition`.
- Nonzero orientation uses horizontal/left-right geometry; zero orientation uses vertical/top-bottom geometry.
- While the drag flag is set, the vertical thumb rectangle is derived from the current input point and drag anchor, clamped to the track; otherwise it is derived from `currentPosition`.
- Disabled/no-range track-before and track-after parts collapse to an empty rectangle; the thumb falls back to the remaining inner track area.

Keep `ScrollPart_LeadingEdge`, `ScrollPart_TrailingEdge`, `ScrollPart_None`, and `BuildHitTestRectForPart` as behavior labels only. `BuildHitTestRectForPart` is not a separate function in this binary; it names the inlined rectangle construction logic inside `0x0045a400`. The final orientation enum and geometry type names should come from the shared pane/control layout once those docs are stronger.
