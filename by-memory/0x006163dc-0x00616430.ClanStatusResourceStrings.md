# 0x006163dc-0x00616430 Clan Status Resource Strings

## Range

- Address range: `0x006163dc-0x00616430` exclusive.
- Entity kind: `resource-string-data`
- Disposition: reconstructable NexusTK source string/resource-name data.
- Rebuild handling: `source-authored` / `resource-derived`
- Intended parent: [UID:0000I8][Clan](by-file/Clan.md) `Clan`, which clears the strict `85/85` direct-parent gate.

## Summary

This child range splits the clan status-pane resource names out of the mixed [UID:0002MP][0x006163dc-0x006164f0.ClanResourceStringData](by-memory/0x006163dc-0x006164f0.ClanResourceStringData.md) clan resource-string aggregate. The strings are full UTF-16 resource names used by the clan status pane frame/resource loader, not pointer-table cells and not standalone `AN*` suffix strings.

Live IDA MCP on 2026-06-11 verified the IDB as `NexusTK.exe`, base `0x00400000`, MD5 `4247e04e20b65d6414c7238aa8ff5515`, and decoded the bytes from `0x006163dc` through `0x00616430` as the four full status-pane resource names listed below.

## Boundary Evidence

- The first 16 bytes at `0x006163dc` are `43 00 4c 00 41 00 4e 00 31 00 2e 00 45 00 50 00`, the UTF-16 start of `CLAN1.EPF`.
- The `0x00616430` successor is the full `DLGCLAN1.EPF` modal-dialog resource string, separating this status-pane resource group from the modal-dialog resource group.
- IDA interior labels such as `aAn1Epf`, `aAn2Epf`, `aAn3Epf`, and `aAnbutEpf` point into these full strings and should be treated as suffix labels unless a future callsite intentionally references the suffix.
