## Address Range

## Behavior

`Thread::ThreadProc()` is an infinite worker loop whose stop condition is checked after each wait/dispatch path. Each iteration begins with `Sleep(1)`, then calls `WaitForMultipleObjects(m_waitHandleCount, m_waitHandles, FALSE, m_waitTimeout)`. A primary result (`WAIT_OBJECT_0`) invokes virtual slot `+0x24`, source-named `OnDispatchBegin`, before queue selection.

The priority queue at `this+0x50` is selected first when `RingBuffer::IsEmpty()` reports it nonempty; the default queue at `this+0x4c` is only the fallback. The function performs exactly one `RingBuffer::Dequeue()` into the 24-byte `ThreadMessage` record for that wake. It does not drain either queue and does not loop around the dequeue.

Messages with a null `resultEvent` call `OnMessage(messageId, arg1, arg2)`. Event-backed messages call `OnMessageEx(messageId, syncArg1, syncArg2, arg1, arg2)`, lock `m_resultMonitor`, read the inline `List::GetCount()`, scan through virtual `List::GetElementAt(int)`, and write the result into the caller-created `ThreadResultEntry` whose event matches. The worker does not construct or append a result entry. It unlocks and calls `SetEvent(message.resultEvent)` even when no matching list entry is found.

A nonzero wait result below the sign-extended handle count is passed directly to `OnWaitObject(int)`. Timeout, failure, empty-primary-queue, message-dispatch, and secondary-handle paths converge at the stop byte at `this+0x64`. A set stop byte returns `0` immediately; otherwise virtual slot `+0x28`, source-named `OnIdle`, executes before the next iteration. Socket's override at `0x00575da0` performs nonblocking receive polling, which proves `OnIdle` is broader than the historical `OnDispatchEnd` label.
