## Evidence

- Wave3 metadata lists these as `CashShopRequest` methods and owner file `class_CashShopRequest.cpp`.
- Generated source shows item/fitting-room payload allocations and request dispatch through `DispatchRequest`.
- The destructor body is clearly tied to the class embedded string state.
- IDA MCP on 2026-05-30 does not currently define a function object at `0x0041a5d0`; manual/raw disassembly still shows constructor-shaped bytes at `0x0041a5d0-0x0041a607` and destructor-shaped bytes at `0x0041a610-0x0041a662`, so these are split as raw exact children.
- IDA MCP decompilation on 2026-05-25 shows `0x0041b180`, `0x0041b200`, and `0x0041b270` call the thread/request queue helper with message IDs `10000`, `10001`, and `10002`.
- IDA MCP decompilation of fitting-room callers shows the receiver argument for those helpers is [UID:0000QH][g_pCashShopRequest](by-global/g_pCashShopRequest.md) / `dword_67A738`, whose direct writes are all FileDownloader constructor/destructor-family writes.

## Ownership Decision

Keep the small payload constructor/destructor with `cashshop/CashShopRequest.cpp` for now. Treat `0x0041b180`, `0x0041b200`, and `0x0041b270` as provisional request submission helpers: they are cash-shop/minimap request setup code by behavior, but they operate on the FileDownloader-lifetime singleton and may ultimately belong to a downloader/request dispatcher source boundary.
