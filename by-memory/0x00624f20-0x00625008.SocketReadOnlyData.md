# 0x00624f20-0x00625008 Socket Read-Only Data

## Range

- Address range: `0x00624f20-0x00625008`
- Entity kind: `vtable/string-data`
- Disposition: reconstructable source-declared/generated-binary data.
- Rebuild handling: source class declaration and socket protocol/error string literals must be reconstructed; vtable is compiler-emitted.

## Summary

This `.rdata` span contains the `Socket` vtable and a short run of socket/login/protocol strings. It ends before the fixed-width server-packet name/debug string table.

## Observed Contents

| Address | Item | Notes |
|---|---|---|
| `0x00624f20` | `Socket` vtable | Socket class virtual table. |
| `0x00624f58-0x00624f9c` | socket/session strings | IDA labels include `Urkcnitni`, `Uconn`, `CCCC`, and `ComD`. |
| `0x00624fa8` | `connaddr` string | Referenced from static/global initialization data. |
| `0x00624fc8` | `Too long data in c...` string | Socket packet/frame error text. |

## Evidence

- IDA MCP `py_eval` on 2026-05-28 reports `??_7Socket@@6B@` at `0x00624f20` and socket-related strings through `0x00625008`.
- Vtable xrefs point to socket lifecycle/transport code at `0x0057483f`, `0x00574a11`, and `0x005795d8`.
- String xrefs point into socket transport logic at `0x005763d6`, `0x0057755c`, `0x00577645`, and `0x00578932`.
- IDA byte/string review on 2026-05-28 shows `0x00625008` is the first fixed-width wide packet-name entry (`KServerVersionCheck`), not part of the preceding socket string cluster.

## Reconstruction Notes

- Keep the vtable with the `Socket` source file. The adjacent protocol strings should remain with socket transport unless later evidence splits handshake/version constants into a separate module.
- The `connaddr` xref from data initialization needs a later global/static-data pass before assigning final owner.
