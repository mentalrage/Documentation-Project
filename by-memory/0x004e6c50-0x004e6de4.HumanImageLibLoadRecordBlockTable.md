## Behavior

This helper receives a `ProtectedArray<WeaponInfo>`, an already opened `DATFile`, and a narrow descriptive source name. It initializes only the default row's first three fields to `{-1, -1, 0}` and intentionally leaves the fourth fallback field untouched. It initializes the decoded count to `-1`, resizes only when that count is positive and differs from the existing count, then reads exactly four encoded integers for every 16-byte row. The loaded fourth value is stored after exchanging its upper and lower 16-bit halves. Every failed count or field read latches [UID:00029J][0x0069b420-0x0069b424.ImageLibraryLoadErrorFlag](by-memory/0x0069b420-0x0069b424.ImageLibraryLoadErrorFlag.md) `g_imageLibraryLoadErrorFlag` at `0x0069b420`.

The compiled allocation, `_memmove`, and free traffic is the lowering of `ProtectedArray<WeaponInfo>::Resize` and indexed/default access; it is not separate hand-authored vector-management source. The third ABI argument is retained as `sourceName` because all six constructor calls pass the corresponding narrow table literal, although the recovered helper body does not otherwise consume it.

The helper belongs with HumanImageLib old-human table parsing. It is not a generic vector helper and should not be emitted from the former aggregate [UID:00022R][0x004e6ae0-0x004e70e9.ImageLibVectorSupportHelpers](by-memory/0x004e6ae0-0x004e70e9.ImageLibVectorSupportHelpers.md) as a combined `VectorHelpers` body.
