## Behavior

This method loads `Motion.tbl` into the [UID:0001VF][NewHumanImageLibLayout](by-type/by-struct/NewHumanImageLibLayout.md) `m_motionEntries` vector at object offsets `+0x1c/+0x20/+0x24`.

The loader:

1. Opens the supplied wide table name. The constructor passes the UTF-16 `Motion.tbl` literal.
2. Reads a 23-byte table header and a 4-byte row count.
3. For each row, zeroes a 0x42-byte in-memory `NewHumanMotionEntry`.
4. Reads a 33-byte fixed file prefix into the in-memory entry:
   - `motionId` at in-memory offset `+0x17`;
   - 20-byte `name` at `+0x1b`;
   - one-byte `direction` at `+0x31`;
   - `fallbackMotionId` at `+0x32`;
   - `frameCount` at `+0x36`.
5. Allocates `frameOffsets` at in-memory offset `+0x3a` as `frameCount * 2` bytes.
6. Allocates `frameData` at in-memory offset `+0x3e` as `frameCount * 120` bytes.
7. For each frame, reads one 2-byte frame offset/value and one 120-byte frame-data block.
8. Appends the completed 0x42-byte entry to `m_motionEntries`; the binary copies directly when capacity remains and calls [UID:00017T][0x004e5240-0x004e5415.VectorGrowMotion](by-memory/0x004e5240-0x004e5415.VectorGrowMotion.md) at `0x004e0ff2` when the vector is full.

The file payload is therefore not a simple fixed 0x42-byte row stream. `0x42` is the in-memory `NewHumanMotionEntry` stride and vector element size. Each file record is a fixed 33-byte prefix followed by `frameCount` variable frame payloads.
