## Behavior

`ReadLine` constructs a temporary ANSI/ref-counted string object, reads bytes through `fgetc(this[1])`, appends non-newline bytes into the temporary, assigns the temporary to the caller-supplied output object on success, destroys the temporary, and returns a byte-sized boolean status.

| Case | Observed behavior |
| --- | --- |
| Entry | Calls `sub_582A80(&temp)` to initialize the temporary ANSI string object, then sets the EH state for cleanup. |
| First `fgetc` low byte is `0xff` | Returns `false` without assigning to the caller output. The compiled test compares `AL` to `0xff`, matching the local decompiler's `char` result. |
| Character is `0x0d` / CR | Calls `fgetc(this[1])` one more time, discarding that byte, then assigns the accumulated temporary string to the output and returns `true`. The body does not check whether the discarded byte is LF. |
| Character is `0x0a` / LF | Assigns the accumulated temporary string to the output and returns `true`, without storing the LF. |
| Other byte | Calls `sub_584200(&temp, 1, ch)` to append one ANSI character, then continues reading. |
| EOF-like low byte after the first read | There is no later EOF check in the visible loop; after the first read has succeeded, a later low byte `0xff` follows the append path as a byte value. Preserve this as observed binary behavior until a final source audit proves a safer source-level intent. |
| Exit cleanup | Calls `sub_582B30(&temp)` before returning either status. |

The method reads from the `FILE*` field at object offset `+0x04`; it does not test the handle for null. The output parameter is assigned only on the success path after CR or LF.
