## Behavior

`LightingObjectPane::SetIntensity` compares the requested intensity against the stored field at `+0x128`. If the value is unchanged, it falls through without writing fields or calling the attached object/interface pointer. The binary does not explicitly set `eax` on this no-change path, so the old "returns `0`" wording was too strong.

If the value changed, the method calls virtual slot `19` (`+0x4c`) on the pointer stored at `+0x134`, stores the new intensity into `+0x128`, and then calls virtual slot `18` (`+0x48`) on the same pointer with `this` as the argument. Constructor evidence shows `+0x134` is the first constructor argument and creator paths pass the owning/attached object pane there; this page therefore treats it as an attached object/light-binding interface pointer rather than a proven owned light-manager allocation.
