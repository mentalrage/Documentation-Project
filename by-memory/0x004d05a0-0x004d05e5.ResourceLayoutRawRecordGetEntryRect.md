# 0x004d05a0-0x004d05e5 ResourceLayoutRawRecordGetEntryRect

## Status

- Entity kind: free helper / static helper
- Disposition: reconstructable NexusTK project code, but final owner remains open.
- Rebuild handling: `source-authored`
- Parent aggregate: [UID:000174][0x004d0120-0x004d182e.ResourceLayoutTable](by-memory/0x004d0120-0x004d182e.ResourceLayoutTable.md)

- Autogen handling: reconstructable, but parent and C++ remain blank because the final `ImageLib` versus `ResourceLayoutTable` source boundary and original helper name are not final-source quality.

## Behavior

Copies a rectangle from a raw resource-layout record array into the caller's output rectangle, or zeros the output rectangle when the requested index is out of range.

IDA MCP decompilation on 2026-05-31 shows the helper expects:

- `a1[0]` as an entry count;
- `*((DWORD*)a1 + 2)` as a pointer to 24-byte [UID:0000VB][ResourceLayoutEntry](by-item/ResourceLayoutEntry.md)-like records;
- `a2` as the requested frame index;
- `a3` as the 16-byte output rectangle.

If `a2 >= *a1`, it writes a zero rectangle. Otherwise it copies the first 16 bytes of the selected 24-byte entry.

## Ownership Notes

This helper should stay under the ResourceLayout/ImageLib layout-record family, not the image codec wrapper group. It consumes a raw record-array pointer and an index, not the `g_pEPFLib` registry object directly, so it is probably a file-local/static helper used by higher-level image composition code that already has a materialized record block.

Do not attach it to [UID:0000N5][ResourceLayoutTable](by-file/ResourceLayoutTable.md) or [UID:0000K2][ImageLib](by-file/ImageLib.md) yet. The parent aggregate still records the class/file boundary as open, and this helper's final source name depends on the caller audit.
