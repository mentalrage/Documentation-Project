## Behavior Detail

Parameters are still named provisionally, but IDA's stack frame and callsites support a `thiscall` shape equivalent to:

```text
int SurfaceSpriteBlitHelper(SurfaceLike *dst,
                            SurfaceLike *src,
                            const RECT *srcRect,
                            const RECT *dstRect,
                            int mode);
```

Observed paths:

- If destination byte `+0x94` is set, the helper uses software/composition immediately: update the source and destination surface metadata, copy source float `+0x90` to the destination when it is `<= 1.0`, call `dword_69B3E8(src + 0x1c, srcRect, dstRect, mode, 0, 0)`, restore the saved destination float when appropriate, and clear cached/locked state fields at offsets `+0x20` and `+0x28` after optional vtable unlock calls.
- If destination byte `+0x94` is clear and `mode == 1`, it builds Win32 `RECT` locals and calls the destination DirectDraw-surface vtable slot `+0x1c` with flag `17`.
- If destination byte `+0x94` is clear and `mode == 0`, it uses the same DirectDraw-surface vtable slot with flag `16`.
- For other modes on a DirectDraw-backed destination, it falls back to the same metadata/update, float borrow/restore, `dword_69B3E8`, and `EndPaint` sequence.

The exact public names for byte `+0x94`, float `+0x90`, surface pointer `+0x18`, callback payload `+0x1c`, and cached state fields `+0x20/+0x28` remain provisional.
