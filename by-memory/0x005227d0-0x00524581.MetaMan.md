## Behavior Summary

The island owns metadata lifecycle:

- startup/load: constructor and `LoadMetaDat`;
- network sync: `LoadMetaDatAndRequestSync` sends opcode `123`, subtype `1`, and `HandleMetaPacket` handles subtype `1` table/checksum lists plus subtype `0` table payload responses;
- lookup API: materialized table row count, alias-aware value-count lookup, `FindEntry`, `LoadStatValues`, and lower direct helpers;
- persistence: private dirty-cache writer at `0x005237d0`, best named `SaveMetaDatIfDirty`;
- teardown: destructor, `ClearTables`, singleton-clear helper, scalar deleting destructor wrapper, and generated map/tree cleanup.

The concrete [UID:000088][MetaMan](by-class/MetaMan.md) object is `0x14` bytes: implicit vptr at `+0x00`, old MSVC `std::map<SimpleUString, MetaTable *>` storage beginning at `+0x04`, table count at `+0x08`, pending request count at `+0x0c`, synchronized flag at `+0x10`, dirty flag at `+0x11`, and padding/reserved bytes at `+0x12/+0x13`. This aggregate keeps raw helper ranges visible for audit, but source should model the map as `m_tables` rather than exposing raw node members.

`LoadMetaDat` reads loose `Meta.dat`, not a packed DAT archive. `SaveMetaDatIfDirty` gates on the dirty byte, opens `Meta.dat` for write/create, serializes table count, header byte count, header records, and compressed payload blocks, clears each table payload pointer/size after writing, closes the file, and clears `m_dirty`.
