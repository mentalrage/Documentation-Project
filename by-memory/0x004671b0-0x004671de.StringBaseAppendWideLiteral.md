## Behavior

The helper receives a pointer-backed wide string object in `ecx` and a NUL-terminated UTF-16 source pointer at `[ebp+8]`. It does not allocate, copy, grow, or mutate string-buffer storage directly. It computes the source length in UTF-16 code units and delegates mutation to the shared counted wide append helper at `0x00584470`.

Target-local roles:

| Binary item | Meaning |
| --- | --- |
| `ecx` at entry / saved `esi` | `this`, pointer-backed `mystr::StringBase<wchar_t, mystr::mychar_traits<wchar_t>>` object. |
| `[ebp+8]` / `edx` | `const wchar_t *rhs`, a NUL-terminated UTF-16 source. |
| `eax` | Scan cursor advanced by two bytes per code unit. |
| `cx` | Current UTF-16 code unit. |
| `edi` | `rhs + 2`, used to compensate for the post-increment before computing length. |
| pushed `eax` | UTF-16 code-unit count excluding the terminator. |
| pushed `edx` | Original source pointer. |

The wrapper forwards:

```text
this = ecx
source = rhs
count = inline_wcslen(rhs)
callee = 0x00584470 AppendWideLiteral(source, count)
```

The count is in UTF-16 code units, not bytes, not Unicode scalar values, and not terminator-inclusive. Surrogate pairs count as two code units. Empty string produces count `0`. The helper does not check for `nullptr`; it dereferences `rhs` immediately.

## UTF-16 Length / Count Semantics

The loop is an inline `wcslen`-equivalent over 16-bit code units:

```text
edx = rhs
eax = rhs
edi = rhs + 2

loop:
    cx = *(uint16_t *)eax
    eax += 2
    if (cx != 0) goto loop

countBytes = eax - (rhs + 2)
count = countBytes >> 1
```

For a source with `N` nonzero UTF-16 code units followed by a NUL word:

```text
eax after loop = rhs + 2 * (N + 1)
edi            = rhs + 2
eax - edi      = 2 * N
(eax - edi)>>1 = N
```

`sar eax, 1` reflects signed pointer-difference code generation. For a valid NUL-terminated source the computed count is nonnegative.

## Rejected Alternatives

- `Application` direct ownership: rejected because Application is the only direct caller of this wrapper but only supplies `_32bit` / `_64bit` data. The target performs generic string append/count work and calls a shared StringBase routine with broad caller fan-in.
- `StringUtil` direct ownership: rejected because `StringUtil` is the utility umbrella, while `StringBase`, `StringBaseTemplate`, `RefCountedStringBufferHeader`, and `StringBaseAppendAndFind` route this ref-counted pointer-backed implementation to `StringBase`.
- `AppendWideData` as the callee name: rejected because `0x00584470` scans for a NUL terminator and clamps the requested count to `wcslen(src)`.
- Byte-count semantics: rejected because the target advances by two bytes, divides the byte difference by two, and the callee copies `2 * count` bytes.
- Terminator-inclusive count: rejected because `edi = rhs + 2` compensates for the post-increment past the NUL; empty string yields count zero.
- Direct CRT `wcslen` call: rejected because the wrapper contains an inline scan loop. It is `wcslen`-equivalent, not a direct import call.
- Null-safe helper: rejected because the first memory read dereferences `rhs` before any null check.
- Split/range change: rejected because the target ends at `ret 4` at `0x004671db-0x004671de`, and the successor thunk starts immediately at `0x004671de`.
- Compiler-generated destructor/thunk classification: rejected because this target has a normal frame, scans a source string, calls a StringBase append helper, and returns with one argument popped. The adjacent `0x004671de` function is the destructor adjustor thunk.
