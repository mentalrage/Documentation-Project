## Behavior

The helper receives a pointer-backed string object in `ecx` and a NUL-terminated UTF-16 source pointer, measures the source length with an inline `wcslen` loop, then forwards to [UID:0002RS][0x00584160-0x005845af.StringBaseAppendAndFind](by-memory/0x00584160-0x005845af.StringBaseAppendAndFind.md) helper `0x00584470` with the counted length.

IDA decompiles it as:

```c
return sub_584470(this, Src, wcslen(Src));
```

## IDA Evidence

- `lookup_funcs` reports `sub_4671B0` at `0x004671b0`, size `0x2e`, exclusive end `0x004671de`.
- The body scans two-byte characters until NUL, computes `length = (end - (src + 2)) >> 1`, pushes the count and source pointer, and calls `sub_584470` at `0x004671d3`.
- `analyze_funcs 0x00584470` decompiles `sub_584470` as `AppendWideData`: it reads the ref-counted string header fields, calls `wcslen`, grows through `0x00582fa0` when needed, and copies UTF-16 data with `memmove`.
- `callers 0x004671b0` reports one direct caller at `0x0046509f` inside `sub_464F50`, an `Application::DetectOS`/OS-string setup helper that appends `_32bit` or `_64bit` to the OS string at `Application + 0x854`.
- `callers 0x00584470` reports this helper plus other StringBase users, supporting shared string ownership rather than Application-local ownership.
