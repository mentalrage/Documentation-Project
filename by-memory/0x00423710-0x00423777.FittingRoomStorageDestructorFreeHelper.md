## Behavior

The receiver is the category lookup object embedded inside [UID:000051][FittingRoomDialogItemState](by-class/FittingRoomDialogItemState.md) at item-state offset `+0x220`. This helper is final destruction for that member, not reset/reinitialization.

First, if the backing/bucket vector begin pointer at receiver `+0x0c` is non-null, the helper computes the allocation span from the capacity pointer at `+0x14`. For ordinary allocations below `0x1000`, it frees the begin pointer through `0x005c7526`. For large aligned allocations, it reads the allocation base from `begin[-1]`, verifies that the front padding is at most `0x1f`, adds the aligned-allocation overhead, and frees the stored base pointer. It then clears the backing-vector triple at `+0x0c/+0x10/+0x14`.

Next, it calls the category-node list clear helper at `0x00423d70` on receiver offset `+0x04`. Current MCP decompile of `0x00423d70` shows that helper resets the sentinel links and count, then walks category nodes until it returns to the sentinel. For each node, it frees that node's payload vector at node offsets `+0x0c/+0x10/+0x14`, clears the node payload triple, and frees the node block.

Finally, after `0x00423d70` clears/destroys the category-node list, this helper frees the 24-byte sentinel/root block stored at receiver `+0x04`.

This differs from [UID:0002EC][0x00422470-0x0042259a.FittingRoomDialogItemStateResetCategoryEntries](by-memory/0x00422470-0x0042259a.FittingRoomDialogItemStateResetCategoryEntries.md): reset walks category entries, destroys `0xc0` entry objects and their part vectors, calls `0x00423d70`, then reinitializes the lookup with eight buckets for reuse. [UID:0002UB] performs final destruction: it frees bucket/backing storage, clears the node list, frees the sentinel/root block, and does not reinitialize the lookup.
