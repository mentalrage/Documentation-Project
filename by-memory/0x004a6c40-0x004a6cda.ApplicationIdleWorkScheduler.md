## Behavior

This function runs the idle-side maintenance pass after the application message loop drains pending Win32 messages or wakes from `MsgWaitForMultipleObjects`.

The observed order is:

1. Drain [UID:0000HR][BlackHole](by-file/BlackHole.md) through `dword_67A74C`, now documented as [UID:0000Q8][g_pApplicationCleanupQueue](by-global/g_pApplicationCleanupQueue.md).
2. If the timer-resolution refresh flag is set, begin or refresh the timer period through [UID:0000OT][TimerMgr](by-file/TimerMgr.md).
3. Dispatch due timer events through [UID:0000SI][g_pTimerMgr](by-global/g_pTimerMgr.md).
4. Rebuild or normalize dispatcher traversal state by calling `0x004a7e70`, currently documented as `EventDispatcher::RebuildHandlerTraversalOrder`.
5. If the refresh flag was set, refresh the current timer tick, clear the flag, store the new baseline tick at helper offset `+0x2c`, and reset the last dispatched slice at `+0x30`.
6. Divide elapsed timer ticks by `0x14` and, when the slice changes, call [UID:00015M][0x004b6cb0-0x004b7112.FrameScheduler](by-memory/0x004b6cb0-0x004b7112.FrameScheduler.md) through [UID:0000Q0][g_frameRegistry](by-global/g_frameRegistry.md), then store the new slice at `+0x30`.
