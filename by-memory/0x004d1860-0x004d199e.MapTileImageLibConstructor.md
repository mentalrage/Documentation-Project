## IDA Evidence

- `lookup_funcs 0x004d1860` reports `sub_4D1860` size `0x13e`, so the half-open function range is `0x004d1860-0x004d199e`.
- Bytes at `0x004d199e` start with two `0xcc` padding bytes before the destructor at `0x004d19a0`, confirming the constructor does not run into the next function.
- The constructor calls the `LObject` base constructor, writes [UID:0000RG][g_pMapTileImageLib](by-global/g_pMapTileImageLib.md) at `0x004d18a3`, installs [UID:0001Y3][MapTileImageLibVtable](by-type/by-vtable/MapTileImageLibVtable.md) at `0x004d18bb`, and calls `sub_4D1B80` / [UID:0000V0][LoadTileEpfMetadata_004D1B80](by-item/LoadTileEpfMetadata_004D1B80.md).
- `this + 0x04` receives the tile EPF metadata table pointer returned by the metadata loader.
- `TILE.TBL` is opened through the DAT file helper family, a 32-bit tile count is read, and the count is compared against the first 16-bit metadata-table count. A mismatch tears down DAT state and shows `Error on Tile File!`.
- The constructor allocates `4 * tileCount` bytes for [UID:0001V3][MapTileRecord](by-type/by-struct/MapTileRecord.md) storage at `this + 0x08`.
- Each `TILE.TBL` 16-bit packed word is decoded as `(word & 0x7fff)` into record `+0x00` and `(word < 0)` into record `+0x02`. Record byte `+0x03` is not explicitly initialized in the observed constructor path and should be treated as padding/reserved.
- `callers 0x004d1860` reports one constructor caller at `0x004f6055` inside `Application::Startup`.
