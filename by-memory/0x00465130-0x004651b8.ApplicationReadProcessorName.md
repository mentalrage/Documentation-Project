# 0x00465130-0x004651b8 Application ReadProcessorName

## Scope

- Range: `0x00465130-0x004651b8`
- Entity kind: Application-local raw method-shaped code
- Owner: [UID:00000D][Application](by-class/Application.md)
- Parent aggregate: [UID:0000YR][0x00463310-0x004679be.ApplicationLifecycle](by-memory/0x00463310-0x004679be.ApplicationLifecycle.md)
- Disposition: reconstructable project code.

## Behavior

Reads the CPU processor-name registry value and stores it into the `Application` object's wide-string field at offset `0x1c`.

Observed flow:

- opens `HKEY_LOCAL_MACHINE\HARDWARE\DESCRIPTION\System\CentralProcessor\0` with `RegOpenKeyExW`;
- queries `ProcessorNameString` with `RegQueryValueExW` into a local `0x800`-byte stack buffer;
- closes the registry key with `RegCloseKey`;
- assigns the queried wide string into the Application processor-name field through the SimpleUString assignment helper at `0x00582d20`.

Live IDA on 2026-06-04 also shows the same registry/key/value/string-assignment sequence in the real `Application__Constructor` body at `0x00463527-0x00463585`. This `0x00465130` body is therefore best treated as an Application-local source-authored helper candidate or unreferenced duplicate of constructor logic, not as compiler/runtime library support.

The companion copy accessor at [UID:0002JY][0x004652e0-0x004652fc.ApplicationCopyProcessorName](by-memory/0x004652e0-0x004652fc.ApplicationCopyProcessorName.md) now proves the read-side buffer address as `Application + 0x428`; reconcile that concrete copy source with this writer's `SimpleUString` owner at `Application + 0x1c` before finalizing the `Application` layout or method names.
