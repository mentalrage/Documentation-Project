## Behavior

Reads the CPU processor-name registry value and stores it into the `Application` object's wide-string field at offset `0x1c`. The source-facing method name `Application::ReadProcessorName` and member name `m_processorName` are inferred from behavior, field use, and surrounding Application naming; they are not recovered original symbols.

Observed flow:

- builds a normal stack frame with `/GS` security-cookie setup, reserves an `0x80c`-byte local area, and saves `this` in `esi`;
- opens `HKEY_LOCAL_MACHINE\HARDWARE\DESCRIPTION\System\CentralProcessor\0` with `RegOpenKeyExW(..., KEY_QUERY_VALUE, &processorKey)`;
- sets a local `DWORD` byte-count variable to `0x800`, matching the `sizeof(wchar_t processorName[0x400])` buffer size;
- queries `ProcessorNameString` with `RegQueryValueExW` into the local `0x400`-wide-character stack buffer;
- closes the registry key with `RegCloseKey`;
- assigns the queried wide string into the Application processor-name field through the StringBase-style `AssignWideLiteral` helper at `0x00582d20`;
- performs the security-cookie check and returns.

Return values from `RegOpenKeyExW`, `RegQueryValueExW`, and `RegCloseKey` are ignored, and the key handle is used unconditionally. The emitted C++ intentionally preserves that behavior; it does not add registry error handling, key-handle guards, default strings, or local-buffer zeroing that the target bytes do not contain.
