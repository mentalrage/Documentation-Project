## Behavior

The destructor tears down a `StdioFile` object without freeing the object storage:

| Step | Evidence |
| --- | --- |
| Read open stream handle | IDA decompilation loads `this[1]`, matching the `FILE*` field at offset `+0x04` in [UID:0001UG][FileStreamLayouts](by-type/by-struct/FileStreamLayouts.md). |
| Restore `StdioFile` vtable | Vtable xref evidence records a write to `0x0062d5ac` at `0x005820a6`, matching the destructor's top-level class restore. |
| Close handle when present | IDA decompilation calls `_fclose` only when the saved handle is non-null. |
| Restore `File` vtable | File vtable xref evidence records a write to `0x006188e4` at `0x005820b9`, matching transition into the base destructor state. |
| Destroy `LObject` base | The function tail-jumps to `0x004f4a90`; [UID:000195][0x004f4a80-0x004f4c0d.LObjectRuntimeShell](by-memory/0x004f4a80-0x004f4c0d.LObjectRuntimeShell.md) documents that body as restoring the `LObject` vtable. |

The destructor intentionally does not clear the cached file size at `+0x08` because the object is being destroyed. The virtual `Close` method at [UID:0001IU][0x005821d0-0x005821f7.StdioFileClose](by-memory/0x005821d0-0x005821f7.StdioFileClose.md) is the reusable close operation that clears cached size and returns a success boolean.
