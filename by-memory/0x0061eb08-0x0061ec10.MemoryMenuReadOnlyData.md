# 0x0061eb08-0x0061ec10 Memory/Menu Read-Only Data

## Range

- Entity kind: `vtable/string-data`
- Disposition: reconstructable source-declared/generated-binary data.

## Summary

This `.rdata` span contains the `MemoryMan`, `MenuPane`, `MenuItem`, `StringMenuItem`, and `SeparatorMenuItem` vtables plus the menu background resource name. It ends at the `MerchantDialogPane` vtable.

Parent handling: keep `AUTOGEN_PARENT_UID` blank. The range is reconstructable, but it is a mixed contiguous `.rdata` island: the first vtable belongs to [UID:0000L7][MemoryMan](by-file/MemoryMan.md), while the rest belongs to the reusable popup/menu item source family [UID:0000MN][PopupMenuControls](by-file/PopupMenuControls.md). No single file-level parent owns the whole span cleanly.

## Reconstruction Notes

- `MemoryMan` is included because it is the exact boundary vtable immediately before the menu data; its executable code is documented separately.
- Menu item vtables should be emitted from source-level inheritance rather than manually recreated as raw tables.
- The page is marked reconstructable because every data item corresponds to source-level class declarations or resource literals, but generated C++ remains blank: this is compiler-produced `.rdata`, and the mixed owner span is below the final-source gate for manually emitted code.
- Do not attach this aggregate to `MemoryMan` or `PopupMenuControls`. Attach lower-level executable/class/type pages to their owners instead, and use this page as range/boundary evidence for the contiguous `.rdata` layout.
