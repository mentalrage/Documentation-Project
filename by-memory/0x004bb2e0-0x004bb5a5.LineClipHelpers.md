# 0x004bb2e0-0x004bb5a5 Line Clip Helpers

## Status

- Confidence: strong for function boundaries, behavior, and software-render ownership; medium for final helper names.
- Current generated owner: [UID:0000BN][RankingEventListPane](by-class/RankingEventListPane.md) for `0x004bb2e0`, plus one-function recovered global output for `0x004bb520`.
- Preferred reconstruction owner: shared software-render geometry support under [UID:0000OC][Surface](by-file/Surface.md) / callback implementation review.
- Role: clips a two-point line segment against a half-open rectangle before software line drawing.

## Covered Functions

| Range | Proposed name | Current generated name | Role |
| --- | --- | --- | --- |
| `0x004bb2e0-0x004bb517` | `ClipLineToRect` / `ClipSegmentToRect` | `RankingEventListPane::ClipLine` | Liang-Barsky style line clipping; mutates the two endpoint records and returns success/failure. |
| `0x004bb520-0x004bb5a5` | `ClipTestParameter` | `ClipTestParameter_4BB520` | Private parameter-test helper for the left/right bounds; updates enter/leave parameters or rejects the segment. |

## Evidence Notes

- IDA MCP lookup on 2026-05-25 reports `0x004bb2e0` as `sub_4BB2E0` size `0x237` and `0x004bb520` as `sub_4BB520` size `0x85`.
- IDA MCP lookup on 2026-06-01 reconfirms `sub_4BB2E0` at `0x004bb2e0` with size `0x237`, ending at exclusive address `0x004bb517`; `0x004bb517` is not a function start.
- IDA MCP lookup on 2026-06-01 reconfirms `sub_4BB520` at `0x004bb520` with size `0x85`, ending at exclusive address `0x004bb5a5`; `0x004bb5a5` is not a function start.
- IDA caller checks report only two callers for `0x004bb2e0`: the compatibility line callback at `0x004bb9b0` and the RGB565 line callback at `0x004c0850`.
- IDA caller checks report only two callers for `0x004bb520`, both inside `0x004bb2e0`.
- IDA callee checks show `0x004bb2e0` calls [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md) and `0x004bb520`; it does not reference ranking dialog state.
- The decompiled body performs parametric clipping over `tEnter` and `tLeave`, mutates endpoint coordinates when the visible range narrows, and returns a boolean-like `char`.
- The 2026-06-01 decompile first checks both endpoints against the rectangle using `0x004b7e80`, then clips Y bounds inline and X bounds through the private `0x004bb520` parameter-test helper. When a segment survives, it rewrites the end point for `tLeave < 1.0` and the start point for `tEnter > 0.0`.
- The `0x004bb520` decompile is the standard Liang-Barsky edge test: positive denominator updates the enter parameter, negative denominator updates the leave parameter, zero denominator accepts only if the point is not outside that boundary.
- Raw-byte inspection on 2026-06-01 shows `0x004bb517-0x004bb520` is nine `0xcc` alignment bytes. The later `0x004bb5a5-0x004bb5e0` interval is not pure padding: it contains an uncreated, unreferenced stdcall-looking byte-pack helper at `0x004bb5b0-0x004bb5d1`, followed by `0xcc` alignment before [UID:00016I][0x004bb5e0-0x004bb7df.GrafPortDrawGlyph](by-memory/0x004bb5e0-0x004bb7df.GrafPortDrawGlyph.md). Do not fold that byte island into LineClip without new xref evidence.

## Ownership Decision

Do not migrate `0x004bb2e0` into `RankingDialog.cpp` or `RankingEventListPane.cpp`. The active `simroot_v2` owner is a side effect of the software render callbacks also being emitted under `RankingEventListPane`.

The strongest current owner is [UID:0000OC][Surface](by-file/Surface.md) / software-render callback support because both external callers are line-drawing callbacks selected through [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md). [UID:0000N2][RectBounds](by-file/RectBounds.md) remains a dependency/reference bucket because the helper consumes four-int rectangle records and calls [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md), but the caller evidence favors render-callback placement.
