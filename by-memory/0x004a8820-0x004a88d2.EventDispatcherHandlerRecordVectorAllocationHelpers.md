# 0x004a8820-0x004a88d2 EventDispatcher Handler Record Vector Allocation Helpers

## Status

- Disposition: reconstructable NexusTK project code.
- Entity kind: internal container allocation helper pair.
- Proposed owner: [UID:0000J7][EventDispatcher](by-file/EventDispatcher.md)
- Related layout: [UID:0001UF][EventDispatcherHandlerTreeLayouts](by-type/by-struct/EventDispatcherHandlerTreeLayouts.md)
- Confidence: strong for behavior and bounds; medium for final source names.

## Covered Ranges

| Range | IDA name | Observed role |
| --- | --- | --- |
| `0x004a8820-0x004a8889` | `sub_4A8820` | Allocates storage for a vector of 28-byte handler records, using normal `operator new` for small blocks and over-aligned large-block allocation with the raw base pointer stored immediately before the aligned pointer. |
| `0x004a8890-0x004a88d2` | `sub_4A8890` | Frees storage produced by the paired allocator; validates the saved large-allocation base pointer before calling the shared deallocator. |

## Evidence

- IDA MCP `py_eval` on 2026-05-27 lists function starts at `0x004a8820`, `0x004a8890`, and the next documented function at `0x004a88e0`.
- IDA MCP decompilation of `0x004a8820` shows `28 * count` sizing, a `0x9249249` count limit, small allocation via `operator new(28 * count)`, and large allocation rounding to a 32-byte aligned pointer with the original allocation stored at `result[-1]`.
- IDA MCP decompilation of `0x004a8890` shows paired large-allocation validation and deallocation before calling the shared free routine.
- IDA MCP `xrefs_to 0x004a8820` reports callers from the handler record rebuild path at `0x004a7980`, the vector insert helper at `0x004a7b10`, and the vector reallocation helper at `0x004a8740`.
- IDA MCP `xrefs_to 0x004a8890` reports a caller from `0x004a7980`.
- Raw byte review shows `0x004a8810-0x004a8820`, `0x004a8889-0x004a8890`, and `0x004a88d2-0x004a88e0` are `0xcc` alignment padding outside the helper bodies.

## Reconstruction Notes

Keep these helpers with the `EventDispatcher` handler-record vector implementation. They are not feature behavior; they are the allocator/deallocator pair for the dispatcher internal 28-byte record vector. The final source should likely collapse them behind a typed vector/container helper after the record struct is named.
