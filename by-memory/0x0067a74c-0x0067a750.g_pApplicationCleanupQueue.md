# 0x0067a74c-0x0067a750 g_pApplicationCleanupQueue

## Summary

- Address range: `0x0067a74c-0x0067a750`
- Entity kind: global data pointer
- Current IDA name: `dword_67A74C`
- Proposed source name: `g_pApplicationCleanupQueue`
- Disposition: reconstructable project global
- Confidence: strong

This four-byte zero-initialized `.data` global stores the `BlackHole` deferred-deletion queue singleton. Pane/dialog teardown paths enqueue objects through this global, and the application idle loop drains it.

## Storage And Lifetime

| Address | Initial value | Role |
| --- | --- | --- |
| `0x0067a74c` | `0x00000000` | `BlackHole*` singleton / deferred object cleanup queue |

Observed lifetime anchors:

- `0x004690d0` and `0x004690e4` inside `BlackHole::BlackHole` store the singleton pointer.
- `0x00469106` and `0x0046924c` clear the pointer in non-deleting and scalar-deleting destructor paths.
- `Application::CleanupResources` and idle-work scheduling paths drain and destroy queued objects through this global.

## Evidence

- IDA MCP xref review reports direct constructor/destructor writes from [UID:0000Z0][0x004690b0-0x00469288.BlackHoleDeferredDeletionQueue](by-memory/0x004690b0-0x00469288.BlackHoleDeferredDeletionQueue.md), plus broad teardown consumers.

- Existing [UID:0000HR][BlackHole](by-file/BlackHole.md) records `g_pApplicationCleanupQueue` as the global pointer to the singleton queue.
- `ApplicationHelper_4A6C40::ProcessIdleWork` begins by draining [UID:0000HR][BlackHole](by-file/BlackHole.md) through this pointer.

## Reconstruction Notes

Keep this declaration with [UID:0000HR][BlackHole](by-file/BlackHole.md), probably as:

```cpp
extern BlackHole* g_pApplicationCleanupQueue;
```

The global is not owned by individual panes that enqueue themselves; those classes are consumers of the deferred-deletion service.
