## Behavior

Copies the object-owned inline label buffer at `this + 0x18` into a caller-owned wide-character destination buffer using `wcscpy_s`, then returns the CRT `errno_t` result unchanged. This is the vtable-exposed text-copy slot for `StringMenuItem`, distinct from [UID:0002J7][0x00517070-0x00517089.StringMenuItemCopyText](by-memory/0x00517070-0x00517089.StringMenuItemCopyText.md), which is the same copy operation as a directly called helper.

Current IDA types the function `errno_t __thiscall(const StringMenuItem *this, wchar_t *destination, rsize_t sizeInWords)`. Historical `const wchar_t *` receiver output explained the old decompiler expression `this + 12`, but it is superseded; the instruction stream still independently proves byte offset `+0x18`. The method performs no menu-item mutation, local validation, or allocation.

The called CRT returns `0` on success, `EINVAL` / `22` on invalid-argument paths, and `ERANGE` / `34` when the destination capacity is insufficient. Where the destination pointer/capacity are valid, `_wcscpy_s` clears `destination[0]` on source-invalid or range failure. This wrapper neither converts nor suppresses those results: callers receive the exact status even when a particular caller intentionally ignores it.
