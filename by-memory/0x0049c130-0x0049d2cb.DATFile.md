## Evidence

- Wave3 `inspect class DATFile` reports 16 methods and an aggregate range from `0x0049c130` to `0x0049d2cb`.
- Wave3 class layout reports four fields totaling 20 bytes: embedded `File` storage at `0x0`, dword fields at `0x8`, `0xc`, and `0x10`.
- Generated source for `Open` and `OpenByIndex` shows 17-byte DAT entry records. Both methods set the current absolute payload offset from the current record's first dword and compute payload size from the next record/sentinel's first dword at `record + 0x11`.
- IDA MCP `lookup_funcs` on 2026-05-22 confirmed function sizes for `0x0049c130`, `0x0049c180`, `0x0049c4a0`, `0x0049c4f0`, and `0x0049c720`.
- IDA MCP `callees` confirmed `0x0049c180` calls `_DATFileMgr::FindEntryByName` at `0x0049cad0`.
- IDA MCP `callees` confirmed `0x0049c4a0` calls [UID:00013W][0x004a5e60-0x004a609f.ParseEntries](by-memory/0x004a5e60-0x004a609f.ParseEntries.md) at `0x004a5e60`.
- IDA MCP recheck on 2026-05-25 confirmed [UID:00013W][0x004a5e60-0x004a609f.ParseEntries](by-memory/0x004a5e60-0x004a609f.ParseEntries.md) has only the two `DATFile` bulk-reader callers at `0x0049c4d4` and `0x0049c524`; decompilation shows both wrappers only compute `GetSize() >> 1`, read eight bytes, and dispatch to the helper.

## Ownership Decision

This range belongs in `archive/DATFile.cpp`. It should not be placed with higher-level image, tile, effect, or map loaders, even though those callers rely on it. Manager-side lookup, mapping, and [UID:0000T0][HasDATEntry_49C700](by-global/HasDATEntry_49C700.md) belong in the companion [UID:0000IO][DATFileMgr](by-file/DATFileMgr.md) module.

[UID:00013W][0x004a5e60-0x004a609f.ParseEntries](by-memory/0x004a5e60-0x004a609f.ParseEntries.md) should be treated as private/static-style support code in the same `archive/DATFile.cpp` module, not as a separate project file.
