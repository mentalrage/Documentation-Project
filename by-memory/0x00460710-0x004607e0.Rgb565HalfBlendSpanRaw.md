`widthPixels` is split into a four-pixel block count and a scalar remainder. `rowCount` controls the outer row loop. The exact original helper name is still open, but the source/destination argument roles are supported by the block-helper call and by scalar-tail storage: `[ebp+8]/[ebp+0c]` are passed as the source pointer/pitch, `[ebp+10]/[ebp+14]` are passed as the destination pointer/pitch, and the scalar loop stores the blended result back through the destination pointer.

## Behavior

This is an RGB565 row/span half-blend helper. It divides each row into four-pixel blocks, dispatches the block body to [UID:0000YG][0x00460c10-0x00460c8c.HalfBlendSpan16Blocks](by-memory/0x00460c10-0x00460c8c.HalfBlendSpan16Blocks.md) `HalfBlendSpan16Blocks`, then handles the scalar tail with the RGB565 half-blend identity:

```text
((src >> 1) & 0x7bef) + ((dst >> 1) & 0x7bef) + (src & dst & 0x0821)
```

The body advances source and destination row pointers by caller-supplied pitches and repeats for the row count.

## Reconstructed C++ Candidate

```cpp
static inline uint16_t HalfBlendRgb565(uint16_t a, uint16_t b)
{
    return static_cast<uint16_t>(((a >> 1) & 0x7bef) +
                                 ((b >> 1) & 0x7bef) +
                                 (a & b & 0x0821));
}

void Rgb565HalfBlendSpanRaw(const uint16_t* src, int srcPitchBytes,
                            uint16_t* dst, int dstPitchBytes,
                            int widthPixels, int rowCount)
{
    const int blockCount = widthPixels / 4;
    const int blockPixels = blockCount * 4;
    const int tailPixels = widthPixels - blockPixels;

    if (blockCount > 0)
        HalfBlendSpan16Blocks(src, srcPitchBytes, dst, dstPitchBytes,
                              blockCount, rowCount);

    dst += blockPixels;
    src += blockPixels;

    for (int y = 0; y < rowCount; ++y)
    {
        for (int x = 0; x < tailPixels; ++x)
            dst[x] = HalfBlendRgb565(src[x], dst[x]);

        dst = reinterpret_cast<uint16_t*>(reinterpret_cast<unsigned char*>(dst) + dstPitchBytes);
        src = reinterpret_cast<const uint16_t*>(reinterpret_cast<const unsigned char*>(src) + srcPitchBytes);
    }
}
```

The candidate keeps byte pitches because the assembly adds the pitch arguments directly to the 16-bit pointers at the end of each row. It is not promoted into the reconstruction metadata because the final source-facing name and raw reachability are not source-quality yet.
