## Behavior

These helpers update a SelfLookPane ObjectStatusBlob from packet data. Both are raw `thiscall`-style bodies that receive the packet pointer as the single stack argument, use [UID:0001HZ][0x00575380-0x00575abb.PacketBufferHelpers](by-memory/0x00575380-0x00575abb.PacketBufferHelpers.md) readers, accept only mode byte `0` or `1`, and return `0` after either applying or skipping the update.

The first helper at `0x0056a500` loads two leading BE16 packet fields before the selected-object check. Mode byte at `packet+10` selects UID0004LL full parsing from `packet+11` or UID0004LM partial parsing from the same address. It decodes into a 68-byte stack ObjectStatusBlob, copies four XMM-sized chunks plus the final dword into `this+0x108..+0x14b`, then calls the pane virtual at vtable slot `+0x20` with `this+0x44`. The second helper at `0x0056a5c0` is the in-place variant: it verifies the same selected-object key, selects by `packet+5`, parses from `packet+6` directly into the same ObjectStatusBlob member, and invalidates the same rectangle. Both fixed-layout paths intentionally ignore parser return lengths.

The mode byte controls which decoder is used: mode `0` calls `0x004d1fa0`, and mode `1` calls `0x004d2640`. Final source names for those two decoder helpers are still open, so this page keeps behavior-oriented names rather than emitting final C++.

The modeled `SelfLookPane` packet/event handler at `0x005693d0` contains inline mirror logic for both shapes: packet case `0x33` at `0x00569444-0x005694f3` uses the leading 16-bit fields plus the `packet+6` selected-object key, and packet case `0x1d` at `0x00569501-0x00569579` uses the shorter in-place form. These mirror blocks do not create direct xrefs to the raw helper starts, but they confirm the packet offsets, selected-object check, decoder choices, destination field, and redraw behavior belong to the `SelfLookPane` packet-update family.
