## Behavior

Handles article action/read result packets delegated from dispatcher submode `3`. MCP session `d3e83820` confirms the single caller at `0x004716cf` in [UID:0004G1][0x00471550-0x00471872.BulletinSessionPacketDispatcher](by-memory/0x00471550-0x00471872.BulletinSessionPacketDispatcher.md) and confirms this modeled function at `0x00471a30` with size `0x1cd`.

The handler initializes a 256-wide-character title/context buffer to `L"N/A"`, then follows the shared modal/screen-dimmer pattern: if the ScreenDimmer/global active predicate at `0x004a1380` reports an active modal object, it calls the release/dismiss helper at `0x004a1360`. Those helpers are ScreenDimmer/global support, not `BulletinSession`-owned methods.

The packet gate is `PacketBufferReadUInt16BE(payload + 2)` at `0x00575480`, not an opaque validation helper. MCP decompilation of `0x00575480` returns `a1[1] + (a1[0] << 8)`. A nonzero value drives the article-open path; zero drives the localized alert fallback.

On the article-open path, the method reads inherited [UID:00003U][DialogSession](by-class/DialogSession.md) state `m_activeDialogIndex` at `this + 0xfc`. When the active index is not `0xff`, it calls `DialogSession::GetDialogAtIndex` (`0x004a1390`) and checks the active [UID:00003S][DialogInSession](by-class/DialogInSession.md) tail field `m_dialogType` at `+0x26c`. If the dialog type is `2`, it calls `DialogSession::PopCurrentDialog` (`0x004a10e0`) with flag `0` before opening the article. It then rechecks the active index; when the current dialog type is `1`, it copies a derived current-dialog wide title/context string from `current + 0x276` into the local title buffer with `_wcscpy_s`. The best descriptive field name for `+0x276` is `m_titleText` or `m_contextTitle`, but the exact derived dialog owner is not formal enough for C++.

The dialog rectangle uses `byte_66DA97`: value `1` selects `(10, 10, 461, 430)`, otherwise `(10, 10, 456, 376)`, passed through the rectangle helper at `0x004b7c50`. The method allocates `0x278` bytes, constructs [UID:00000J][ArticleDialog](by-class/ArticleDialog.md) through constructor/setup `0x004753e0` at call site `0x00471b7a`, passing the session, title/context buffer, rectangle, and original packet pointer, then calls `DialogSession::PushDialog` (`0x004a0fc0`) with the constructed dialog. If allocation fails, it still calls `PushDialog(nullptr)`. SEH cleanup thunks free partially allocated blocks, matching normal C++ `new`/constructor cleanup semantics.

On the zero-payload path, the method allocates `0x270` bytes, looks up localized string id `65` through the global language/string table helper `0x004f0350`, and constructs a generic `AlertPane` through `0x0049feb0` with layout/table pointer `off_613A18` and no extra callback. This is a localized "no article" style fallback, not a `BulletinSession`-private alert subclass and not a `BulletinReplyAlerts` wrapper.
