# 0x0049bbf0-0x0049bca9 Checksum Table Helpers

## Status

- Disposition: reconstructable helper code, owner not yet assigned.
- Entity kind: checksum/hash helper family.
- Confidence: strong for exact instruction boundaries, table references, and accumulator behavior; medium for final source names and ownership.
- Final C++ is intentionally blank because the owning source file and production helper names are not yet proven from IDA evidence.

## Behavior

This is a compact table-driven 16-bit checksum family. The first pair uses `word_66D480` and consumes 16-bit input words. The second pair uses `word_66D680` and consumes bytes. Each helper shifts the current checksum by eight bits, indexes the high byte into a 256-entry word table, xors in the next input value, and returns the updated 16-bit accumulator.

No direct code xrefs were found to the helper entrypoints in the current IDA database, but the table xrefs are limited to these four bodies:

- `word_66D480`: `0x0049bbff`, `0x0049bc2c`.
- `word_66D680`: `0x0049bc5f`, `0x0049bc92`.

The table data page `UID:00027A` records both lookup tables as 256-entry 16-bit sequences. IDA MCP byte reads confirmed the first twelve words of both `word_66D480` and `word_66D680` are identical: `0x0000`, `0x1021`, `0x2042`, `0x3063`, `0x4084`, `0x50a5`, `0x60c6`, `0x70e7`, `0x8108`, `0x9129`, `0xa14a`, `0xb16b`. That supports a CRC-CCITT-style update table, but the final project-facing helper names remain open.

### Helper Shapes

- `0x0049bbf0-0x0049bc0d` loads `word ptr [ebp+0Ch]` as the current accumulator, indexes `word_66D480` with `accumulator >> 8`, xors the shifted accumulator and `word ptr [ebp+8]`, and returns `AX`.
- `0x0049bc10-0x0049bc47` starts with accumulator zero and loops over `count` 16-bit words from `[ebp+8]`, using `word_66D480[(accumulator >> 8)]` each iteration.
- `0x0049bc50-0x0049bc70` mirrors the first helper with `word_66D680` and an unsigned byte input loaded from `[ebp+8]`.
- `0x0049bc70-0x0049bca9` starts with accumulator zero and loops over signed-positive `count` bytes from `[ebp+8]`, using `word_66D680[(accumulator >> 8)]` each iteration.

## Non-final Reconstruction Sketch

```cpp
uint16_t UpdateChecksum16Word(uint16_t value, uint16_t seed)
{
    uint16_t index = seed >> 8;
    return static_cast<uint16_t>((seed << 8) ^ g_checksumWordTable[index] ^ value);
}

uint16_t Checksum16Words(const uint16_t* values, unsigned count)
{
    uint16_t seed = 0;
    for (unsigned i = 0; i < count; ++i) {
        seed = UpdateChecksum16Word(values[i], seed);
    }
    return seed;
}
```

The byte-table pair has the same shape, with `uint8_t` input bytes and `word_66D680`.
