## Evidence

- Wave3 metadata describes `SnowingLayerPane` as a weather layer pane for snow animation.
- IDA MCP on 2026-05-24 confirms all selected method boundaries, including `0x005c1bd0-0x005c1c7e`, `0x005c1c80-0x005c1f4c`, `0x005c1f50-0x005c20d4`, `0x005c20e0-0x005c2228`, `0x005c29ec-0x005c29f7`, `0x005c29f7-0x005c2a02`, and `0x005c2a20-0x005c2a5b`.
- The filename is historical. `SwallowLayerPane` starts at `0x005c2230` inside this broader span, so only the listed rows should be treated as Snowing-owned.
- Wave3 currently reports the two excluded thunks as class children that overflow the aggregate class ranges and lowers `SnowingLayerPane` completion; see [wave3_noticed_problems](../wave3_noticed_problems.md).
- `MapPane` weather setup at `0x0050db50` is the confirmed constructor path for rain, snow, and swallow layers; snow is selected when that switch allocates `4268` bytes and calls `0x005c1bd0`.
- Exact snow static data ranges are documented in [UID:0001OO][0x00670784-0x006707d0.SnowPatternByteTables](by-memory/0x00670784-0x006707d0.SnowPatternByteTables.md) and [UID:0001Q4][0x0069bf98-0x0069c044.SnowLookupDescriptorStorage](by-memory/0x0069bf98-0x0069c044.SnowLookupDescriptorStorage.md).
