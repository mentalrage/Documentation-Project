# MSVC STL JsonCpp String Support

## Address Range

- `0x0043e250-0x004417dd`
- Entity kind: mixed third-party/runtime support island.
- Disposition: ignored for NexusTK-owned reconstruction.
- Rebuild handling: `third-party/runtime` plus `compiler/linker-generated`.

## Summary

This range is a mixed MSVC/Dinkumware and JsonCpp support island between `DequeEnsureCapacity` and the JsonCpp valid-reader-key helper. It contains standard-library stream, locale, string, numeric, error-category, ctype, and template helpers, plus a small JsonCpp value string-allocation helper cluster near the end.

The range is not a NexusTK feature module. The rebuilt project should preserve the source-level JsonCpp code and ordinary C++ standard-library usage, while letting the selected MSVC-era toolchain/runtime emit equivalent helper code.

## Evidence

- Live IDA MCP audit on 2026-06-04 against `NexusTK.exe` (`md5 4247e04e20b65d6414c7238aa8ff5515`, image base `0x00400000`) reports 70 modeled functions from `sub_43E250` at `0x0043e250-0x0043e3e2` through `sub_4416E0` at `0x004416e0-0x004417dd`.
- Live boundary check is clean: previous start-order function is [UID:0000XB][0x0043e0b0-0x0043e241.DequeEnsureCapacity](by-memory/0x0043e0b0-0x0043e241.DequeEnsureCapacity.md), bytes `0x0043e241-0x0043e250` are fifteen `0xcc` bytes, bytes `0x004417dd-0x004417e0` are three `0xcc` bytes, and [UID:0000XC][0x004417e0-0x00441d24.JsonCppValidReaderKeys](by-memory/0x004417e0-0x00441d24.JsonCppValidReaderKeys.md) starts at `0x004417e0`.
- Live string-xref audit confirms standard-library/runtime diagnostics in this range: `ios_base::badbit set`, `ios_base::failbit set`, and `ios_base::eofbit set` are each referenced by five helper sites (`sub_43E620`, `sub_43EDD0`, `sub_43F560`, `sub_4416E0`); `deque<T> too long` is referenced from `sub_43F190`; `invalid string position` is referenced from `sub_43F1A0`.
- Live decorated-name audit confirms Dinkumware helpers at `0x0043f930-0x0043f942` (`std::error_category::default_error_condition`), `0x00440a30-0x00440a3a` (`std::ctype<char>::do_narrow`), and `0x00441340-0x0044134a` (`std::ctype<char>::do_widen`).

## Rebuild Decision

Ignore this as a NexusTK source-reconstruction target. Keep the JsonCpp string-allocation behavior in the vendored JsonCpp source and preserve ordinary standard-library use in callers; do not hand-port the generated STL/runtime helper bodies.
