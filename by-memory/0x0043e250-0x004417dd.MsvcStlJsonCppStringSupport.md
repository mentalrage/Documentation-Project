# MSVC STL JsonCpp String Support

## Address Range

- `0x0043e250-0x004417dd`
- Entity kind: mixed third-party/runtime support island.
- Disposition: ignored for NexusTK-owned reconstruction.
- Rebuild handling: `third-party/runtime` plus `compiler/linker-generated`.

## Summary

This range is a mixed MSVC/Dinkumware and JsonCpp support island between `DequeEnsureCapacity` and the JsonCpp valid-reader-key helper. It contains standard-library stream, locale, string, numeric, error-category, ctype, and template helpers, plus a small JsonCpp value string-allocation helper cluster near the end.

The range is not a NexusTK feature module. The rebuilt project should preserve the source-level JsonCpp code and ordinary C++ standard-library usage, while letting the selected MSVC-era toolchain/runtime emit equivalent helper code.

## Evidence

- Read-only IDA MCP `py_eval` on 2026-05-27 reports 70 modeled primary functions from `sub_43E250` at `0x0043e250` through `sub_4416E0` ending at `0x004417dd`.
- Standard-library/runtime diagnostics and constants in the range include `ios_base::badbit set`, `ios_base::failbit set`, `ios_base::eofbit set`, `deque<T> too long`, `invalid string position`, `0123456789-+Ee`, `0123456789ABCDEFabcdef-+Xx`, `ld`, `lu`, `Ld`, `Lu`, and `%p`.
- Decorated Dinkumware names appear in the range, including `?default_error_condition@error_category@std@@UBE?AVerror_condition@2@H@Z`, `?do_narrow@?$ctype@D@std@@MBEDDD@Z`, and `?do_widen@?$ctype@D@std@@MBEDD@Z`.
- JsonCpp-specific strings identify source-level value helpers: `in Json::Value::duplicateAndPrefixStringValue(): length too big for prefixing`, `in Json::Value::duplicateAndPrefixStringValue(): Failed to allocate string value buffer`, and `in Json::Value::duplicateStringValue(): Failed to allocate string value buffer`.
- IDA caller evidence links the JsonCpp helper cluster back to value constructors/destructors and object/member helpers at `0x00424ec0`, `0x00425010`, `0x00425200`, `0x00427020`, `0x004275a0`, `0x00427990`, `0x00427d30`, and `0x00428b70`.
- Boundary check: `0x0043e241-0x0043e250` is `0xcc` filler/alignment after [UID:0000XB][0x0043e0b0-0x0043e241.DequeEnsureCapacity](by-memory/0x0043e0b0-0x0043e241.DequeEnsureCapacity.md); `0x004417dd-0x004417e0` is `0xcc` alignment before [UID:0000XC][0x004417e0-0x00441d24.JsonCppValidReaderKeys](by-memory/0x004417e0-0x00441d24.JsonCppValidReaderKeys.md).

## Rebuild Decision

Ignore this as a NexusTK source-reconstruction target. Keep the JsonCpp string-allocation behavior in the vendored JsonCpp source and preserve ordinary standard-library use in callers; do not hand-port the generated STL/runtime helper bodies.
