Checked on 2026-06-06:

- Live IDA function enumeration reports all eight starts above as real functions with size `0xb`, with the final function ending at `0x00502600`.
- Decompilation shows each first thunk forwarding after a `0xa0` receiver adjustment and each second thunk forwarding after a `0xa4` receiver adjustment.
- `xrefs_to` reports vtable/data refs at `0x0061df2c`, `0x0061df5c`, `0x0061de88`, `0x0061deb8`, `0x0061dde4`, `0x0061de14`, `0x0061d5cc`, and `0x0061d5fc`.
- `callers` reports no ordinary caller list for any thunk, matching vtable-only destructor dispatch.
- `callees` reports no ordinary callee list for the thunk bodies because the forward jumps are represented through xrefs to the scalar deleting destructors rather than source-level calls.
- The target destructors are documented in [UID:00022X][0x00502d10-0x00502e0b.UserCreateAppearanceScalarDeletingDestructors](by-memory/0x00502d10-0x00502e0b.UserCreateAppearanceScalarDeletingDestructors.md): `0x00502d10`, `0x00502d50`, `0x00502d90`, and `0x00502dd0`.

## Ownership Decision

These are compiler/vtable support thunks, not source-level feature methods. Keep them documented with the appearance-control module so they do not become unresolved missing bodies or evidence for a separate source file.

The scalar deleting destructors remain reconstructable owner methods. Only these `this`-adjusting wrappers are excluded from source reconstruction.
