## Current Layout, Ownership, And Behavior

`Layer` is an eight-byte LObject-derived object with `HierList *m_nodes` at `+0x04`. A LayerNode payload is exactly 48 bytes: pane pointer `+0x00`, paneFlags `+0x04`, padding `+0x05..+0x07`, current bounds `+0x08`, previous bounds `+0x18`, visible `+0x28`, blocks-child-traversal `+0x29`, dirty `+0x2a`, padding `+0x2b`, and owned Region pointer `+0x2c`. HierList adds parent and child-list pointers before the payload; the complete row stride is 59 bytes, matching the constructor's `0x3b` root allocation.

The root borrows `g_pScreenPane`, owns its Region and HierList tree, initializes both rectangles from the screen dimensions, and leaves paneFlags/padding uninitialized. AddChildAfter intentionally leaves previousBounds plus flag/padding bytes uninitialized; AddChildBefore initializes both rectangles but still leaves flag/padding bytes uninitialized. Removal and destruction release node Regions and list storage but do not own Pane objects. `MarkAllPanesForDeletion` traverses every top-level row, skips null/sentinel rows and null pane pointers, and delegates each surviving pane to `Pane::MarkForDeletion`; independent B002 UID0002AF caller research corroborates the MainMenu initialization route.

The raw starts `0x004f0b80`, `0x004f0ca0`, and `0x004f13a0` are complete retained source members despite zero recovered inbound xrefs. `0x004f1390` is the direct source `Layer::EndRender()` call used by ScreenPane, not a virtual callback or padding. ## Historical Pre-Split Behavior

`Layer` is a small object around an owned tree/list pointer. The constructor calls the `LObject` setup helper, installs the Layer vtable, allocates a root node of size `0x3b`, stores the global pane/context value from `dword_67A7CC`, initializes root rectangles from screen dimension globals, constructs a `Region` for the root node, and constructs the child `HierList` with element size `48`.

The child attach APIs are called from Pane layer integration:

- `0x004f0630` is called from `0x00544c93`, matching `Pane::AddToLayer`.
- `0x004f0840` is called from `0x00544cc6`, matching `Pane::InsertInLayer`.
- `0x004f0a60` is called from `0x0054460a`, `0x00544d19`, and `0x00544fe1`, matching Pane removal/teardown paths.

Insertion builds a stack node descriptor, normalizes pane bounds through Pane virtual calls, searches for optional reference panes with `0x004f1ab0`, constructs node `Region` state, and inserts through the existing `HierList` methods rather than a separate container implementation. Removal uses the same recursive lookup, releases the node's region and child tree, calls Pane-side update helpers, and removes the node through `HierListRemoveNode`.

The dirty/render half of the range is centered on `Region` and `Motion` helpers at `0x00554680-0x00554b38`. `0x004f0f90` starts a dirty-region pass, `0x004f15a0` propagates pane movement/dirty state through the tree, `0x004f1910` handles recursive node dirty marking/search, and `0x004f0ff0` performs the visible-child render traversal. The render path calls graphics helpers around pane draw dispatch, intersects and offsets regions, clears node dirty state after processing, and keeps child traversal tied to pane visibility/flag checks. B002's 2026-06-17 MapPane source-quality pass resolves the active-MapPane branch at `0x004f1277/0x004f1286` as a `ScreenEffecter`-specific path: it checks the MapPane screen-effecter list, finds the active pixel/primary effecter, and applies that effecter instead of falling through to the normal `0x004ba250` sprite/blit helper.

[UID:0003A3][0x00559410-0x005595ca.ScreenPanePresentationTraversal](by-memory/0x00559410-0x005595ca.ScreenPanePresentationTraversal.md) is the current named ScreenPane caller for the short `0x004f0f30`, `0x004f0f50`, `0x004f0f70`, `0x004f0f90`, `0x004f0fd0`, and `0x004f0ff0` presentation helpers. That caller drives the root ScreenPane layer list and uses these Layer-node helpers as dependencies; the call pattern strengthens Layer helper semantics without moving the helpers to ScreenPane.

The final helpers are structural: `0x004f1a50` recursively frees child trees, `0x004f1ab0` recursively searches pane nodes, and `0x004f1b40` is the vtable-owned scalar deleting destructor.
