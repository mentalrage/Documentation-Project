## Packet Behavior

- Opcode route: `MainMenuPane::OnServerMessage` routes opcode `0x66` to this helper.
- Subtype field: the helper reads subtype byte `packet[1]`; packet offset `0` is the dispatcher-level opcode already handled by the caller. Payload parsing starts at `packet+2`.
- Subtype `1`: reads a two-byte big-endian URL byte length, preserves the following URL byte span and explicit length, reads a second two-byte big-endian ANSI prompt-text length, converts up to `999` wide characters through `MultiByteToWideChar(0, 0, ..., 999)`, NUL-terminates the stack wide buffer, allocates `632` bytes, and constructs a `UrlAlertPane` with `g_pMainMenuPane` and `exitAfterOpen = true`.
- Subtype `2`: uses the same counted URL/text parse shape and constructs `UrlAlertPane` with `exitAfterOpen = false`.
- Subtype `3`: calls [UID:0003YP][0x00575a10-0x00575abb.PacketBufferOneByteStringReadHelpers](by-memory/0x00575a10-0x00575abb.PacketBufferOneByteStringReadHelpers.md) / `PacketBufferReadAnsiBytes8`, assigns the resulting string object into [UID:00029T][0x0069b3d0-0x0069b3d4.MainMenuTextUrlStaticString](by-memory/0x0069b3d0-0x0069b3d4.MainMenuTextUrlStaticString.md), and releases the temporary string object. The semantic destination is the MiscWorkThread-owned NCA confirm-user URL override string; the filename label `MainMenuTextUrlStaticString` is retained only for generated/report compatibility.
- Other subtype values return success without constructing a dialog or updating the static string.
- Rejected subtype wording: "clickable" versus "non-clickable" is too vague. Both subtype `1` and `2` are URL alert flows; the supported distinction is the `UrlAlertPane+0x274` exit-after-open flag.
