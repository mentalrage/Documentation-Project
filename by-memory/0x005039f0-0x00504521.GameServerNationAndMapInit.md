## Notes

IDA confirms `0x00503a80`, `0x00503c70`, and `0x00504110` as real function starts. IDA does not currently define a function at `0x005039f0`, but disassembly there is valid code matching the Wave3 constructor body.

The `InitializeMapPane` body is strong `MapPane` evidence even though Wave3 currently attributes it to `GameServerConfig`. Final migration should consider moving that function to `map/MapPane.cpp` while keeping nation-table helpers nearby.

2026-05-31 IDA MCP split pass:

- `py_eval`/`idautils.Functions` over `0x005039f0-0x00504521` found modeled function starts at `0x00503a80`, `0x00503c70`, `0x00503d10`, `0x00503e80`, `0x00503e90`, `0x00503ed0`, `0x00503ef0`, `0x00504090`, `0x005040a0`, and `0x00504110`.
- Raw byte decoding also found valid non-modeled code islands at `0x005039f0`, `0x00503a50`, and `0x00503b60`.
- Padding subranges listed above were byte-checked as `0xcc` alignment.
- The old `0x00503a50-0x00503a78` destructor note was too short; the tail-jump instruction starts at `0x00503a78` and ends before `0x00503a7d`.

2026-05-25 IDA MCP recheck:

- `lookup_funcs` still reports `0x005039f0` and `0x00503a50` as not functions, while `0x00503a80`, `0x00503c70`, and `0x00504110` remain real starts.
- Disassembly at `0x005039f0` calls base object setup, writes `dword_69B4C4`, installs `GameServerConfig` and `ProtectedArray<GameServerConfig::NationEntry>` vtables, sets capacity `10`, count `0`, and null backing data, then returns `this`.
- Disassembly at `0x00503a50` resets the same vtables, frees the backing storage pointer, clears `dword_69B4C4`, and jumps to base cleanup.
- `0x00503a80` scans 68-byte nation-entry records by id and copies the matching record or a fallback `L"????"` record.
- `0x00503c70` sends the fixed opcode `0x66` / subcode `0x4000` request packet only when the table count is not populated.
- The adjacent raw helper [UID:000230][0x00503960-0x005039ed.GameServerNationRequestPacketRawHelper](by-memory/0x00503960-0x005039ed.GameServerNationRequestPacketRawHelper.md) sends the same fixed request payload without the table-count guard, but has no current function object or caller xrefs.
- `0x00504110` writes [UID:0000PR][g_activeMapPane](by-global/g_activeMapPane.md), installs `MapPane` vtables, loads `SOBJ.TBL` into [UID:0000Q4][g_objectRecordCount](by-global/g_objectRecordCount.md) and [UID:0000Q3][g_objectNationMap](by-global/g_objectNationMap.md), and allocates [UID:0000Q1][g_gameServerNationTable](by-global/g_gameServerNationTable.md).

IDA MCP recheck on 2026-05-24 confirmed the relevant globals in this range:

- `dword_69B4BC` is the `SOBJ.TBL` object record count used by the compact map cache.
- `dword_69B4C0` is [UID:0000Q3][g_objectNationMap](by-global/g_objectNationMap.md).
- `dword_69B4C4` is [UID:0000Q1][g_gameServerNationTable](by-global/g_gameServerNationTable.md).
- `dword_67A764` is [UID:0000PR][g_activeMapPane](by-global/g_activeMapPane.md), currently named `g_activeGameServerConfig` by Wave3.
- `off_61C1A4` is the wide `SOBJ.TBL` string.

- `0x00503a50` appears to be destructor-like code in IDA disassembly but is not a modeled function. Its exact byte range is [UID:0002HW][0x00503a50-0x00503a7d.GameServerConfigNationTableDestructorRaw](by-memory/0x00503a50-0x00503a7d.GameServerConfigNationTableDestructorRaw.md).

- `0x00503b60-0x00503c61` is valid raw default-entry seeding code with no current function object or caller xrefs; keep it separate from [UID:0002HX][0x00503a80-0x00503b58.GameServerConfigCopyNationEntryOrFallback](by-memory/0x00503a80-0x00503b58.GameServerConfigCopyNationEntryOrFallback.md) and [UID:0002HZ][0x00503c70-0x00503d03.GameServerConfigRequestNationEntries](by-memory/0x00503c70-0x00503d03.GameServerConfigRequestNationEntries.md).
