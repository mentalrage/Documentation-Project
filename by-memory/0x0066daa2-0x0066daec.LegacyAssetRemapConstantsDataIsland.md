## Source-Quality Decisions

The accepted split is the only current source-quality answer:

- It keeps padding out of source emission.
- It keeps MapPane-only constants in `MapPane.cpp`.
- It keeps ItemObjImageLib-only constants in `ItemObjImageLib.cpp`.
- It preserves no-xref source-shaped triplets as documented orphan source data without inventing an owner.
- It prevents the old combined page from polluting `MapPane.cpp` with unrelated ItemObjImageLib constants or duplicating unrelated declarations through multiple emitters.

Rejected alternatives:

- Keep one mixed page owned/emitted by MapPane: rejected because the item-remap subgroup is read only by ItemObjImageLib/item-glyph helpers, and the no-xref triplets would be assigned from adjacency alone.
- Give the mixed page multiple emitters: rejected because the constants are not a single shared declaration block consumed by both source files; multiple emitters would duplicate unrelated constants into both outputs.
- Create a new shared `LegacyAssetRemapConstants.cpp`: rejected for now because no source-tree entry, writer, startup initializer, pointer table, helper wrapper, or xref cluster proves that file.
- Reclassify the no-xref triplets as padding: rejected because they are nonzero four-byte-spaced triplets with the same legacy-current remap shape as the live groups. Only `0x0066daa2-0x0066daa4` is padding.
