# 0x0058da20-0x0058db94 DialDialog Modem Response Parser

## Status

- Confidence: strong for range and dial-dialog ownership, medium for final callback name.
- Covered file/module: [UID:0000MJ][PhoneBookDialog](by-file/PhoneBookDialog.md)
- Current Wave3 state: real IDA function, not emitted as an active `DialDialog` method in `class_DialDialog.cpp`.
- Recommended source name: `DialDialog::ParseModemResponse`.

## Function Role

This callback parses incoming modem response bytes for the dialing dialog. It recognizes `CONNECT` and `BUSY` response tokens, then closes or advances the dialog through the same slide/close path used by the OK action.

## Behavior Notes

- Reads packet data pointer and length from the incoming packet/buffer object.
- If the input length is greater than 100 bytes, immediately closes the adjusted `DialDialog` instance.
- Tracks a response parser state at offset `0x24c` relative to the callback subobject.
- State sequence recognizes `CONNECT` from `C O N N E C T` and `BUSY` from `B U S Y`.
- On a recognized terminal state, calls the slide/close helper at `0x0049eb90` and close helper at `0x0049dad0` on the adjusted dialog instance.

## IDA MCP Evidence

- `lookup_funcs 0x0058da20` reports `sub_58DA20`, size `0x175`, ending at `0x0058db95`.
- `xrefs_to 0x0058da20` reports a data reference at `0x0062ddb4`, consistent with callback/vtable slot ownership.
- `callers 0x0058da20` reports no direct code callers.
- Decompilation shows the `CONNECT` and `BUSY` byte-state parser and the close path described above.

## Ownership Decision

Keep this with `DialDialog` in `login/PhoneBookDialog.cpp`. It is physically adjacent to the dial dialog and uses dial-dialog offsets; the absence of direct code callers reflects callback dispatch, not standalone ownership.
