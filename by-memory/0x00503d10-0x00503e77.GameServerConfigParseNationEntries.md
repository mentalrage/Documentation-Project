## Behavior

The parser first checks packet remaining/available length through `sub_575480`. It reads a count-like byte from packet offset `+2`, increments it, resizes the embedded [UID:0000B4][ProtectedArray_struct_GameServerConfig__NationEntry_](by-class/ProtectedArray_struct_GameServerConfig__NationEntry_.md) through [UID:000234][0x00514ee0-0x00514f6b.GameServerNationEntryArrayResize](by-memory/0x00514ee0-0x00514f6b.GameServerNationEntryArrayResize.md), then iterates through each packet record.

For each entry it writes the 16-bit nation id into the first field, reads a byte string length, converts that many bytes to wide text through `MultiByteToWideChar`, writes the result into the `+0x02` label field, and terminates the wide string. After the packet-provided records, it writes a sentinel/default entry id `10` and label `aNe_2`.

## IDA Evidence

- `lookup_funcs` reports `sub_503D10` at `0x00503d10`, size `0x167`.
- Decompilation shows the direct call to `sub_514EE0((this + 1), count)`, with `sub_514EE0` using a `68` byte stride.
- Decompilation shows `MultiByteToWideChar(0, 0, ..., length, destination + 1, 32)`, matching a 32-character payload plus terminator inside the 33-wide-character label field.
- `xrefs_to 0x00514ee0` reports this parser at `0x00503d4f` as the sole direct caller of the resize helper.
- `0x00503d03-0x00503d10` and `0x00503e77-0x00503e80` are `0xcc` padding.
