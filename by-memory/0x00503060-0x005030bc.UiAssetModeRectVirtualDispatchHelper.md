## Behavior

The helper receives `this` in `ecx` and one stack argument. It decrements the stack argument and only initializes the local rectangle when the adjusted value is zero. The rectangle initializer is [UID:00015S][0x004b7c30-0x004b7f87.RectGeometryHelpers](by-memory/0x004b7c30-0x004b7f87.RectGeometryHelpers.md) `0x004b7c50`, so the `0x00a6` / `0x00ad` constants are right-edge extents, not proven resource ids:

- [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md) `== 1`: initializes local bounds to `(0, 0, 0x00a6, 0x10)`.
- otherwise: initializes local bounds to `(0, 0, 0x00ad, 0x10)`.

After the optional rectangle setup, the helper always dispatches through the receiver vtable slot `+0x20`, passing the local rectangle pointer. The 2026-06-18 B002 slot recheck identifies `+0x20` as inherited [UID:0003CA][0x006219e8-0x00621a6c.PaneVtableData](by-memory/0x006219e8-0x00621a6c.PaneVtableData.md) `Pane::InvalidateRect`: MapName primary base `0x0061e5b4` has `0x0061e5d4 -> 0x00544800`, MiniMapButton primary base `0x0061e63c` has `0x0061e65c -> 0x00544800`, and Pane primary base `0x006219e8` has `0x00621a08 -> 0x00544800`. Because that slot is inherited/shared rather than class-specific, it explains the behavior but does not identify the concrete owner.

Because the non-`1` state path skips local initialization but still dispatches a local rectangle pointer, either real callers only used the initializing state, a surrounding source contract made the skipped path unreachable, the virtual method tolerated or ignored the argument in other states, or this is stale retained code. No direct caller, vtable-table entry, raw pointer reference, generated source route, singleton/global caller, or object-file/source-map evidence currently proves which source-level pattern was used.

The `0x00a6`/`0x00ad` width pair is consistent with nearby map-name UI sizing: [UID:00007P][MapNamePane](by-class/MapNamePane.md) documents a `173`-pixel map-name clamp, matching `0x00ad`, and the EPF/current branch uses the narrower `0x00a6`. This is useful association evidence, but the PE and vtable scans above still show no direct reference path from `MapNamePane` or any table to this helper, so ownership remains unresolved rather than assigned.

Source-facing naming remains neutral. `UiAssetModeRectVirtualDispatchHelper` is acceptable for documentation; if a future caller/receiver route is proven, the behavior-level name should mention Pane invalidation and asset-mode rectangle selection, not MapName/MiniMap ownership by default. B002's non-final discussion alias `InvalidatePaneWithAssetModeRectStateRaw` is recorded only as an inference candidate, not a committed source name.
