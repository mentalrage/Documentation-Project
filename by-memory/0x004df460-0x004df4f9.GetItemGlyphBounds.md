## Behavior

`ItemObjImageLib::GetItemGlyphBounds` resolves an item sprite rectangle for icon/list rendering. The source-facing signature is `void GetItemGlyphBounds(short itemId, RectBounds *outBounds)`: the binary returns with `retn 8`, every caller supplies the singleton receiver, every caller ignores or overwrites `eax`, and the meaningful result is the mutated out-rectangle.

The helper starts from `itemId + 0x4000`, applies the legacy non-EPF remap policy when extended item archives are disabled, asks [UID:0000BY][ResourceLayoutTable](by-class/ResourceLayoutTable.md) through `g_pEPFLib->GetEntryRect` for the frame rectangle from `ITEM.EPF` or `ITEM.EPD`, then offsets the rectangle by half of the configured [UID:0000T7][MapTilePixelDimensions](by-global/MapTilePixelDimensions.md) through `OffsetRect(outRect, g_mapTilePixelWidth / 2, g_mapTilePixelHeight / 2)`.

Callers usually pair this helper with the item-image singleton [UID:0000RA][g_pItemObjImageLib](by-global/g_pItemObjImageLib.md) before invoking `ItemObjImageLib::DrawItemImage` or `DrawItemImageScaled`.

[UID:0001BU][0x00520540-0x00520816.ObjectImageControlPane](by-memory/0x00520540-0x00520816.ObjectImageControlPane.md) is a concrete preview consumer: its item/status-kind `2` paint branch passes `ObjectStatusBlob` offset `+4` / `m_objectStatus.m_appearanceId` to this helper, centers the returned rectangle inside the pane bounds, then calls `ItemObjImageLib::DrawItemImage` with the same item id and descriptor offset `+6` / `m_variantOrPalette`.

Historical B008/B005 analysis classified this as a free helper because the body does not read `this`, Hex-Rays printed `__stdcall`, and the caller fanout is broad. The exhaustive receiver audit supersedes that conclusion: all 48 callers supply the same singleton in `ECX`, which is positive member evidence, and broad fanout is consistent with a public library method.

The non-EPF remap policy is:

- the thresholds are source data at [UID:0003ZN][0x0066dad4-0x0066dae0.ItemObjImageLibLegacyItemRemapConstants](by-memory/0x0066dad4-0x0066dae0.ItemObjImageLibLegacyItemRemapConstants.md), not literals unique to this helper;
- use source-facing names `g_legacyItemImageMaxEntry`, `g_currentItemImageRemapFirstEntry`, and `g_currentItemImageRemapLastEntry` for the `0x0972`, `0x0a20`, and `0x0a56` values;

- if it is above `0x0972` and outside the translated band, clamp to entry `0x0972` / 2418;
