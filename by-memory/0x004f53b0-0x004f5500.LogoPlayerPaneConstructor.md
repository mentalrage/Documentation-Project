## Behavior

The constructor signature is best modeled as `LogoPlayerPane::LogoPlayerPane(const wchar_t *moviePath, FunctionObject0 *completionCallback)`. The first stack argument is the caller-supplied movie path passed to `StdioFile::Open`; the second is the zero-argument completion callback stored as `m_completionCallback` at `+0x10c`, released by the destructor paths, and invoked by [UID:0002PW][0x004f5620-0x004f5634.LogoPlayerPaneOnClose](by-memory/0x004f5620-0x004f5634.LogoPlayerPaneOnClose.md).

It builds the `VideoPlayerPane` base, installs the three `LogoPlayerPane` vtable pointers at offsets `+0`, `+0xa0`, and `+0xa4`, constructs the embedded `_AUTOBUF<unsigned char> m_movieData` object at `+0x100`, stores `m_completionCallback` at `+0x10c`, clears the one-shot segment-advance request guard `m_hasRequestedSegmentAdvance` at `+0x110`, reads the segmented movie payload into `m_movieData`, stores the first segment size at `+0x114`, and opens the first in-memory Bink segment through protected `VideoPlayerPane::OpenBinkVideo(const void *segmentData, unsigned int segmentSize)` at `0x005c0110`.

The payload contract is direct byte parsing: after `StdioFile::ReadRemaining` fills the embedded AUTOBUF, the constructor reads `*(uint32_t *)m_movieData.m_data` as `m_firstSegmentSize`, stores that value at `this + 0x114`, and calls the Bink helper with `m_movieData.m_data + 4` and the first segment size. If the first segment cannot be opened, it preserves the source-level failure shape by formatting `L"%s corrupted"` with `moviePath`, constructing `FileError`, and throwing it through the C++ exception path. The binary does not clear `+0x114` before the payload read, so the first-draft C++ intentionally does not initialize `m_firstSegmentSize` in the initializer list.
