# 0x004a82b0-0x004a8795 EventDispatcher Handler Record Relink Helpers

- Disposition: reconstructable NexusTK project code.
- Entity kind: internal container/helper cluster.
- Proposed owner: [UID:0000J7][EventDispatcher](by-file/EventDispatcher.md)

| Range | IDA name | Observed role |
| --- | --- | --- |
| `0x004a82b0-0x004a8350` | `sub_4A82B0` | Adds/relinks a 28-byte handler record after pane-order changes, then appends a corresponding record through the handler-record vector insert helper. |
| `0x004a8350-0x004a8418` | `sub_4A8350` | Adjusts existing record links/parent indexes for pane-order changes and appends a record through the same vector insert helper. |

| `0x004a86b0-0x004a873b` | `sub_4A86B0` | Rebinds the 28-byte handler-record vector after freeing/replacing the prior allocation; validates large allocation headers before freeing. |
| `0x004a8740-0x004a8795` | `sub_4A8740` | Allocates a larger handler-record vector, copies existing records, and publishes the new begin/end/capacity pointers through `sub_4A86B0`. |

## Evidence

- IDA MCP `py_eval` on 2026-05-27 lists function starts at `0x004a82b0`, `0x004a8350`, `0x004a8420`, `0x004a8680`, `0x004a86b0`, and `0x004a8740`, with the next documented helper beginning at `0x004a87a0`.
- IDA MCP `xrefs_to` shows:
  - `0x004a82b0` and `0x004a8350` are called from `EventDispatcher::SetPaneOrder` at `0x004a6ce0`.
  - `0x004a8420` is called from `EventDispatcher::RemovePaneEntry` at `0x004a6dd0`.
  - `0x004a8680` is called from the dispatcher constructor and `sub_4A7AF0`.
  - `0x004a86b0` is called from the existing record-vector insert helper and the realloc helper at `0x004a8740`.
  - `0x004a8740` is called from the dispatcher traversal rebuild cluster at `0x004a7e70`.
- IDA MCP decompilation shows all record-vector arithmetic uses 28-byte elements, matching [UID:000145][0x004a7b10-0x004a7c29.EventDispatcherHandlerRecordVectorInsert](by-memory/0x004a7b10-0x004a7c29.EventDispatcherHandlerRecordVectorInsert.md) and [UID:000148][0x004a87a0-0x004a8810.EventDispatcherHandlerRecordVectorFree](by-memory/0x004a87a0-0x004a8810.EventDispatcherHandlerRecordVectorFree.md).
- The vector reallocation helper at `0x004a8740` calls [UID:00022B][0x004a8820-0x004a88d2.EventDispatcherHandlerRecordVectorAllocationHelpers](by-memory/0x004a8820-0x004a88d2.EventDispatcherHandlerRecordVectorAllocationHelpers.md) to allocate the replacement record buffer.
- Raw byte review shows `0x004a82a9-0x004a82b0` and `0x004a8795-0x004a87a0` are `0xcc` alignment padding outside this helper cluster.

## Reconstruction Notes

Keep these helpers under the `EventDispatcher`/handler-tree implementation rather than promoting them to a feature class. They appear to be private support for pane ordering, handler removal, traversal rebuilds, and the internal 28-byte handler-record vector.

The final C++ should likely express these as local helper functions or small container methods near `EventDispatcher.cpp`, with names based on record relinking, subtree removal, vector reallocation, and sentinel node allocation after the handler record layout is finalized.
