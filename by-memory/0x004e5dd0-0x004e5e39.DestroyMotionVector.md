## Function Role

`DestroyMotionVector` releases the `Motion.tbl` entry vector owned by [UID:000092][NewHumanImageLib](by-class/NewHumanImageLib.md). It frees the vector storage when present and clears the `begin`, `end`, and `capacity` pointers.

This is a source-adjacent helper for the new-human image library, not a method on the unrelated runtime [UID:00008R][Motion](by-class/Motion.md) class.

## Observed Shape

```text
m_motionEntries vector header / three-pointer vector storage
  +0x00 begin
  +0x04 end
  +0x08 capacity

NewHumanMotionEntry in-memory stride: 0x42 bytes
```

`DestroyMotionVector` is a by-memory/by-global page name and useful search alias for this lowered helper. Current IDA does not prove it as an original source-authored function name. Do not introduce `MotionEntryVector` as a formal source type; use `m_motionEntries` or "three-pointer vector header" in source-facing prose. Use the accepted inferred `NewHumanMotionEntry` row name rather than `MotionEntry`, and keep `sub_5C7526` described as checked-free/runtime allocator evidence rather than inventing a local source wrapper.

For small allocations the helper frees `begin` directly. For large aligned allocations it validates the stored raw allocation pointer located immediately before `begin`, frees that raw pointer, then zeros the vector triplet. If `begin` is already null, the helper returns without touching the triplet.
