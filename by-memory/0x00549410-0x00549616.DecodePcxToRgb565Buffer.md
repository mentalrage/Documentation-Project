## Behavior

This helper validates and decodes an 8-bit PCX buffer with palette-backed pixels. It expands the PCX RLE stream, optionally remaps palette indices through caller-supplied data, converts RGB triples to RGB565, writes transparent-index pixels as zero, allocates the destination pixel buffer, and reports the decoded dimensions to the caller.

The only documented direct caller is [UID:0000U9][CreateDIBitmapFromPcxBuffer_004A18B0](by-item/CreateDIBitmapFromPcxBuffer_004A18B0.md), which wraps the decoded RGB565 rows into a [UID:0000IV][DIBitmap](by-file/DIBitmap.md). That keeps this range in the image-loading/render family, not in the patch-pane family despite its address adjacency after the PatchPane2 island.

## Parameter And Decode Mechanics

| Decompiler parameter | Inferred role | Evidence |
| --- | --- | --- |
| `a1` | PCX file buffer | Header is copied from the first 128 bytes; encoded image data starts at `a1 + 128`; palette is read from the final 768 bytes after checking the palette marker byte before it. |
| `a2` | PCX file size | Used to locate the palette marker at `a1[a2 - 769]` and the 256-entry RGB palette footer at `a1 + a2 - 768`. |
| `a3` | output RGB565 buffer pointer | Must initially be null; function allocates `2 * width * height` bytes and stores the result here. |
| `a4` | output width pointer | Receives `xmax - xmin + 1`; the low bit is also used by the decoder to skip the padded byte at the end of odd-width rows. |
| `a5` | output height pointer | Receives `ymax - ymin + 1`. |
| `a6` | transparent palette index | When non-negative and equal to the decoded/remapped index, the destination RGB565 pixel is written as zero. |
| `a7` | optional remap table | When non-null, the palette index is replaced with the byte at `a7 + 4 * index` before transparency and RGB565 conversion. |

The decode loop tracks the PCX RLE repeat count from bytes with the high two bits set (`0xc0`) and otherwise treats source bytes as literal palette indices. It writes exactly `width * height` logical pixels while walking an even-width source stride (`width + width % 2`), which accounts for the PCX scanline padding byte without adding an output pixel.
