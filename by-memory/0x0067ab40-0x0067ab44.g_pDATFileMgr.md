## Lifecycle And Users

`g_pDATFileMgr` stores the active public [UID:00003I][DATFileMgr](by-class/DATFileMgr.md) singleton. The wrapper constructor stores this pointer, the wrapper destructor clears it, and archive APIs read it to reach the internal `_DATFileMgr` implementation pointer at wrapper offset `+0x04`.

Confirmed users include:

- `DATFileMgr::DATFileMgr` at `0x0049bd30`, which writes the singleton.
- `DATFileMgr` scalar deleting destructor at `0x0049d350`, which clears the singleton.
- [UID:00012E][0x0049c700-0x0049c71d.HasDATEntry](by-memory/0x0049c700-0x0049c71d.HasDATEntry.md), which reads the singleton and forwards to `_DATFileMgr::FindEntryByName`.
- `DATFile::Open`, which uses the manager lookup path to resolve named entries.
- [UID:0000YV][0x00467380-0x00467391.DestroyDATFileMgr](by-memory/0x00467380-0x00467391.DestroyDATFileMgr.md), which reads the singleton and invokes the manager deleting destructor on fatal image/resource load cleanup paths.
- Application startup/shutdown and archive sidecar initialization paths that create, inspect, or destroy the manager.
