## ServerSelectEntry Cleanup Layout

Both helper bodies operate on the same 0x18-byte `ServerSelectEntry` layout:

- `+0x04` / `name`, `+0x08` / `description`, and `+0x0c` / `agreementText` are heap-owned wide-string pointers proven by the corresponding registry values and packet/selection consumers.
- Each helper tests each pointer, frees it through the CRT free path when non-null, and then clears `+0x0c`, `+0x08`, and `+0x04`. The explicit two-body C++ mirrors the two emitted functions instead of making the destructor call the direct helper.
- `0x0048e4b0` is used as the MSVC EH vector destructor callback for arrays of live `ServerSelectEntry` records, so `ServerSelectEntry::~ServerSelectEntry()` is the accepted source presentation.
- `0x0048e500` is a direct scratch-entry cleanup helper used by `sub_4F6D80` / server-select temporary records. It is byte-equivalent cleanup for the same record shape, not a separate unrelated type.
- `name`, `description`, and `agreementText` are the accepted semantic field names. Exact original private lexical spelling remains unavailable but no generic text alias is needed in current source.
- `ReleaseServerSelectEntryOwnedBuffers` is a descriptive inferred helper name for `0x0048e500`; the direct-body distinction is exact even though original helper spelling is unproven.
