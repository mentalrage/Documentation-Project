## Ownership Analysis

Best owner: [UID:0000IE][Config](by-file/Config.md). Both helpers operate only on the private 0x18-byte config-entry record owned by the Config storage family. Their primary xrefs are Config construction, RegistryConfig teardown inherited from Config storage, Config deleting destructor cleanup, and server-select temporary record parsing.

Rejected owner: [UID:0000N4][RegistryConfig](by-file/RegistryConfig.md). RegistryConfig teardown uses `sub_48E4B0`, but it uses it because RegistryConfig inherits/owns a Config entry block; the helper itself is not registry-specific.

Rejected owner: `sub_4F6D80` / server-select UI. The direct call to `sub_48E500` proves a consumer and explains the duplicate helper, but the helper body and adjacency to the Config constructor support Config-private storage ownership.
