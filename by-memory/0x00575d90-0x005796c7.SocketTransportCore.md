## Evidence

- Wave3 reports the range as `Socket` child methods with owner file `class_Socket.cpp`.
- IDA MCP confirms key starts in this cluster and specifically confirms `SendEncodedPacket` as `0x00576660-0x00576c75` and `BuildEncryptedPacket` as `0x00578c40-0x00578df1`.
- `SendEncodedPacket` has three direct callers: `Socket` destructor, scalar deleting destructor, and `HandleSocketCommand`.
- IDA MCP confirms `BuildHandshakeBlock` at `0x00577030` is called by the `Socket` constructor and `HandleSocketCommand`, while `XorTransformBuffer` at `0x00578e00` is called only from `TransformFramePayload` and `BuildEncryptedPacket`.
- IDA MCP confirms `BuildEncryptedPacket` calls the [UID:0000V2][PacketDigest_00515380](by-item/PacketDigest_00515380.md) at `0x00515380`; that helper belongs to the shared [UID:0000L6][MD5](by-file/MD5.md) utility island, not this socket range.
- IDA MCP disassembly on 2026-05-25 pins the transform state used by these methods in [UID:0000TG][PacketTransformGlobals](by-global/PacketTransformGlobals.md), including the dword LUT at `0x0066fe58`, stride at `0x0069ba5c`, sequence byte at `0x0069ba60`, and primary/alternate tables at `0x0069ba64`/`0x0069ba94`.
- IDA MCP review on 2026-05-28 identifies the `0x00578f70-0x005797ae` helper family as MSVC STL/Dinkumware tree/string-map support with cross-feature callers, so its physical placement inside and after the Socket address neighborhood is not Socket ownership.
- IDA MCP recheck on 2026-05-25 confirms [UID:0001I6][0x005794c0-0x005794cb.ClearPacketSenderGlobal](by-memory/0x005794c0-0x005794cb.ClearPacketSenderGlobal.md) as an 11-byte `g_packetSender` clear helper referenced from the Socket constructor unwind block at `0x0060805e`.
- IDA MCP disassembly of `.rdata` at `0x00624f20` confirms `0x005795a0` as the first Socket vtable slot target, matching a scalar deleting destructor.
- A 2026-05-25 IDA MCP `py_eval` sweep found five direct writes to `0x0067a7ec`; all are in the Socket constructor/destructor family.
- The generated source routes outbound data through Winsock `send`, mode-6 callback dispatch, or serial `WriteFile`.
- Receive code is split by the same transport modes, supporting one stateful transport class rather than independent feature handlers.

## Ownership Decision

The Socket methods in this cluster belong to `network/Socket.cpp`. It should be the source anchor for packet framing, receive parsing, transport setup, and connection state. The free transform helpers inside the address neighborhood belong with [UID:0000M9][PacketTransform](by-file/PacketTransform.md) or a private packet-transform section of `Socket.cpp`, not with [UID:0000M8][PacketBuffer](by-file/PacketBuffer.md).

The [UID:000245][0x00578f70-0x005797ae.StlTreeStringMapSupport](by-memory/0x00578f70-0x005797ae.StlTreeStringMapSupport.md) family is compiler/STL support and should be reconstructed through owner container declarations, not as Socket source.
