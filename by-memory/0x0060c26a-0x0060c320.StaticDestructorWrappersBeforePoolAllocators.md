# 0x0060c26a-0x0060c320 Static Destructor Wrappers Before Pool Allocators

## Scope

- Address range: `0x0060c26a-0x0060c320`
- Entity kind: static-lifetime destructor wrappers, one null destructor stub, and alignment padding
- Rebuild handling: `compiler/linker-generated` for the wrapper bodies; underlying globals are `source-declared/generated-binary`.
- Disposition: ignored as standalone handwritten source. Reconstruct the owning static globals/classes and let compiler static lifetime code emit equivalent startup/shutdown glue.
- Confidence: strong for function boundaries, padding, and paired `atexit` registrations from IDA/MCP; medium for the final owner/name of every helper-table global.

## Summary

This range is the shutdown-side companion for the startup wrapper island at [UID:0000WB][0x00419f86-0x0041a040.StaticInitializerWrappersBeforePoolAllocators](by-memory/0x00419f86-0x0041a040.StaticInitializerWrappersBeforePoolAllocators.md). It starts with padding after the [UID:0001O7][0x0060c260-0x0060c26a.MemoryManAtexitResetThunk](by-memory/0x0060c260-0x0060c26a.MemoryManAtexitResetThunk.md), then contains cleanup wrappers for the static `TimerMgr` instance, image-definition helper tables, metadata alias string, MIDI document state, and an empty registered destructor.

## Reconstruction Notes

- Do not hand-port these wrappers as normal source functions.
- Reconstruct static storage and lifetime in the owning modules:
  - `TimerMgr.cpp` for the static `TimerMgr` instance at `dword_69B3AC`.
  - `RidingImageLib`/image-table support for `dword_69B430`; `dword_69B424` still needs a separate ownership pass.
  - `MetaMan.cpp` for `g_metaAliasTableName`.
  - `MidiPlayer.cpp` for MIDI document/parser state around `dword_69B828`/`dword_69B840`.
- The exact purpose of `dword_69B424` should be resolved later from the `sub_528930`/`sub_528950` helper family and image-library table callers.
- `nullsub_14` should stay ignored as empty compiler/static-lifetime glue.
