## Behavior

`0x004b85f0` returns `this[index + 1]` when the requested child index is below the active child-count limit. The maximum child count is selected by [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md) with the exact binary comparison `g_useEpfAssets == 1`: seven children in EPF/new-layout mode and four children otherwise. The helper performs only the signed upper-bound check (`index >= childCount` returns null); it does not perform a lower-bound `index < 0` guard.

`0x004b8620` reads `m_activeChildIndex` from `this[8]` / object offset `+0x20`. It returns null when the active index is `-1`; otherwise it returns the active child pointer from the same child array.

`0x004b8630` reads the active child index and, when valid, dispatches the active child virtual refresh/update slot at vtable offset `0x20` with argument `0`. PaneCore support now identifies this inherited slot as `Pane::InvalidateRect`, so the formal source shape calls `m_childPanes[m_activeChildIndex]->InvalidateRect(NULL)`. `DispatchActiveChildRefresh` is the preferred source-facing name after the B007 ScreenPane palette-helper pass because this method is used as a dispatcher from both `ScreenPane::HandleMessage` and the raw ScreenPane.cpp palette bridge. Earlier docs used `RefreshActiveChild`; keep that as a descriptive alias until original public spelling is recovered.
