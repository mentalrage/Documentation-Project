## Behavior

`0x004b85f0` returns `this[index + 1]` when the requested child index is in range. The maximum child count is selected by [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md): seven children in EPF/new-layout mode and four children in legacy mode.

`0x004b8620` reads the active child index from `this[8]`. It returns null when the active index is `-1`; otherwise it returns the active child pointer from the same child array.

`0x004b8630` reads the active child index and, when valid, dispatches the active child virtual refresh slot at vtable offset `0x20` with argument `0`.

## Caller Evidence

The caller set is broad UI/gameplay code, which is exactly what a global side-panel accessor should have:

- `0x004b85f0` is called from a broad set including `0x004c78e0`, `0x004c82d0`, `0x0050feb0`, `0x00514640`, `0x00568cb0`, `0x005a3e30`, `0x005a76c0`, item/spell/living-object helper wrappers, and other UI paths that need a child side-panel pane by index.
- `0x004b8620` is called from `0x0049e240`, `0x00569860`, and twice from `0x005a5bd0`, matching currently-active-panel lookup from dialog/input and user-pane flows.
- `0x004b8630` is called from `ScreenPane::HandleMessage` at `0x00556e06` and has an additional code xref at `0x005593fc`, matching active-child refresh dispatch.

The helpers do not read spell-input-pane local fields. They read the same child-array and active-index layout used by `GeneralPurposePanel::GeneralPurposePanel` and `GeneralPurposePanel::SwitchActiveTab`.

The child order inherited from `GeneralPurposePanel::GeneralPurposePanel` is `0` self look, `1` user look/profile, `2` inventory, `3` spell inventory, `4` group, `5` collection, and `6` option. Current callers rely on this exact index map; for example, the integrated macro editor maps active index `3` to [UID:0001V1][MacroHotkeyRecord](by-type/by-struct/MacroHotkeyRecord.md) state `2` / `.usr` `S`, and active index `2` to state `3` / `.usr` `I`.
