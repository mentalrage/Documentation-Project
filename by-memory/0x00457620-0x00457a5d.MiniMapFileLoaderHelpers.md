## Behavior

`MiniMapRenderer::BuildSymbolViews` uses this loader to read local `.mnm` minimap files. The loader keeps:

- a decode-key wide string at offset `+0x00`;
- an expected `.mnm` version/header wide string at offset `+0x18`;
- a decoded payload pointer at offset `+0x30`;
- a payload length or file-body length at offset `+0x34`.

The `.mnm` file path is not the field at `this+0x00`. Current call-site evidence shows `BuildSymbolViews` pushes the renderer path buffer at `MiniMapRenderer+0x02` before calling `0x00457850` at `0x00454457`; the checked loader methods do not store that caller path into `this+0x00`. The constructor initializes `this+0x00` from default string data at `0x0061093c`, and the decode helper uses it as the XOR key source.

The load path opens the caller-supplied `.mnm` path through `dword_69BE14` with binary-read mode, seeks from the observed `0x42` file offset, stores a computed payload length at `+0x34`, reads a UTF-16 version string sized from the expected-version length field at `+0x28`, compares it with the expected version string at `+0x18`, and only allocates/reads the payload when the strings match and no payload is already loaded. The decode helper derives two one-byte XOR key streams from the decode-key string at `+0x00` and its reverse, then applies both streams to the first 200 bytes of the loaded payload or to the full payload when it is shorter.

Current B013 recheck confirms this island is the direct `MiniMapRenderer::BuildSymbolViews` loader/decode dependency. The renderer constructs the stack loader at `0x00454441`, passes the prepared `.mnm` path from `MiniMapRenderer+0x02` to the load helper at `0x00454457`, consumes the decoded payload pointer/length at `+0x30/+0x34`, copies the decoded payload header into renderer fields beginning around `+0x218`, reads the image length from decoded payload offset `+0x1c`, passes image bytes at payload offset `+0x20`, and then routes the tile payload through [UID:0002TN][0x004d0a90-0x004d0c58.DecodeJpegBufferToTileContext](by-memory/0x004d0a90-0x004d0c58.DecodeJpegBufferToTileContext.md) at `0x004544a8`. The old BMP route through [UID:0002TM][0x004d09b0-0x004d0a8a.Decode8BitBmpToTileContext](by-memory/0x004d09b0-0x004d0a8a.Decode8BitBmpToTileContext.md) is rejected for this `BuildSymbolViews` path; that helper belongs to the `LEVEL.BMP` route.
