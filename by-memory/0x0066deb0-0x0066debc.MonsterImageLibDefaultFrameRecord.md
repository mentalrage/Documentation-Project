## Evidence

- IDA MCP on 2026-06-02 reports `0x0066deb0` as `unk_66DEB0` with exactly two data xrefs: `0x00528b2f` and `0x00528d11`.
- Raw bytes for `0x0066deb0-0x0066debc` are `00 00 00 00 ff 00 ff ff 00 00 00 00`.
- `0x00528b10` is an outer-table frame lookup helper. It reads the outer entry count at `this+0x04`, selects an 8-byte child table from `this+0x08`, checks that child's word count at `+0x04`, returns `base + 10 * frame_index` when in range, and returns `offset unk_66DEB0` at `0x00528b2f` on failure.
- `0x00528d00` is the inner-table frame lookup helper. It checks `this[2]` against the requested frame index, returns `*this + 10 * index` when in range, and returns `offset unk_66DEB0` at `0x00528d11` on failure.
- `0x00528d30` initializes normal 10-byte frame records with null pointer, byte sentinel `-1`, word sentinel `-1`, and zero tail word; the fallback bytes match that default record shape.
- IDA MCP reports `0x0066debc` as the next named data item, `RootPathName`, with data xrefs from `0x00529304`, `0x00529309`, `0x0052a061`, and `0x0052a066`. This confirms the fallback record range ends before the root path buffer.
