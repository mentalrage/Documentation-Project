# MetaMan Lookup Helpers `0x00523a00-0x00523c99`

## Status

- Entity kind: metadata lookup helper island.
- Proposed owner: [UID:0000LC][MetaMan](by-file/MetaMan.md)
- Confidence: strong for ownership and API role; medium for final source-facing helper names.
- Evidence basis: read-only IDA MCP `lookup_funcs`, `decompile`, `callers`, and `callees` on 2026-05-25 plus existing `simroot_v2/class_MetaMan.cpp`. `wave3.py` was not executed for this pass.

## Covered Functions

| Range | IDA name | Proposed role |
| --- | --- | --- |
| `0x00523a00-0x00523a64` | `sub_523A00` | Direct row value-count helper. Looks up a table and row key, materializes the table if needed, and returns the row's value count or `0`. No current IDA direct callers were reported in this pass. |
| `0x00523a70-0x00523b38` | `sub_523A70` | Indexed row-value lookup helper. Returns a pointer to the requested `SimpleUString` value or [UID:0000PW][g_emptySimpleUString](by-global/g_emptySimpleUString.md) on missing table, missing row, or out-of-range index. |
| `0x00523b40-0x00523c98` | `sub_523B40` | Multi-value copy helper used by `LoadStatValues`. Allocates an output pointer array and fixed `0x50`-byte wide buffers, then copies up to the requested number of row values. |

## Behavior

All three helpers follow the same table access pattern:

1. Call `MetaMan::FindTableByName` (`0x00523330`).
2. If the table exists and `MetaTable::m_isLoaded` at `+0x18` is false, call [UID:0001CC][0x00524870-0x00524c55.MetaTableMaterializeRows](by-memory/0x00524870-0x00524c55.MetaTableMaterializeRows.md).
3. Search the table row tree through [UID:0001CA][0x005245c0-0x0052462a.MetaTableRowFindByKey](by-memory/0x005245c0-0x0052462a.MetaTableRowFindByKey.md).
4. Read or copy values from the matched row node's `std::vector<SimpleUString>`-style value span.

`0x00523a70` and `0x00523b40` return the process-wide empty `SimpleUString` at `0x0066daec` when the lookup fails. That empty return value is a shared fallback, not a heap object owned by the caller.

## Caller Evidence

- `0x00523a70` is called by `MetaMan::FindEntry` at `0x00523120` from the direct and alias-aware lookup branches.
- `0x00523b40` is called by `MetaMan::LoadStatValues` at `0x005231f0` from the direct and alias-aware multi-value branches.
- `0x00523a00` had no direct IDA callers in this pass, but its callee pattern matches the same row-tree lookup family and it remains source-local metadata support.
- IDA MCP `lookup_funcs` rechecked on 2026-06-01 reports exact helper sizes: `0x00523a00` size `0x65`, `0x00523a70` size `0xc9`, and `0x00523b40` size `0x159`.
- IDA MCP `callers` rechecked on 2026-06-01 reports no direct callers for `0x00523a00`, four callers for `0x00523a70` (`0x0052313c`, `0x0052319f`, `0x005231cd`, `0x0052324c`), and two callers for `0x00523b40` (`0x005232b6`, `0x0052330a`).
- IDA MCP `xrefs_to` rechecked on 2026-06-01 shows all three helpers call `MetaTableMaterializeRows` (`0x00524870`) and `MetaTableRowFindByKey` (`0x005245c0`) before reading row value storage.
- IDA MCP `xrefs_to 0x0066daec` shows failed lookup return paths from `0x00523b16` inside `sub_523A70` and `0x00523c76` inside `sub_523B40`, matching the shared empty-string fallback.

## Ownership Decision

Keep these helpers in `metadata/MetaMan.cpp` beside `MetaMan::FindEntry`, `MetaMan::LoadStatValues`, and `MetaTable`. They are not CollectionPane, ItemHelpPane, or resource-loader code even when those features consume metadata rows.
