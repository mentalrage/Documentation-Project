## Behavior Notes

The storage-family destructors are separated by object layout:

- Base-only and status-code wrappers have only the inherited `LObject`/vtable field plus, for concrete wrappers, a status or HRESULT code at `+0x04`; no class-owned heap storage is released.
- `ErrorMessage` and `FileError` use inline message buffers, so their destructors only reset the base vtable and delete the object when requested.
- `InternetError` and `InternetConnectionError` own a string subobject at `+0x04`; their shared destructor calls `sub_582B70` on that member before base teardown.
- `MyError` owns a heap wide-string pointer at `+0x04`; its destructor frees that pointer before resetting to `Error` and calling the base cleanup path.
- The helper at `0x004a6a70` is the common name/descriptor virtual used by every main error hierarchy vtable in `0x00619344-0x00619448`.

The base cleanup helper [UID:00013Y][0x004a6400-0x004a640b.ErrorBaseCleanupHelper](by-memory/0x004a6400-0x004a640b.ErrorBaseCleanupHelper.md) is the non-deleting counterpart for resetting an object to the base `Error` vtable and tail-calling `LObject` cleanup.
