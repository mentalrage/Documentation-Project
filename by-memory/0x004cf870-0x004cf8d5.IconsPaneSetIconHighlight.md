## Behavior

This helper updates the selected icon's pressed/highlight state and invalidates the affected icon rectangle so the icon strip repaints. It first compares the requested state against `m_isPressed` at `this + 0x100`; if the byte is already equal, the method returns without building a rectangle or invalidating anything.

When the state changes, the method reads `m_selectedIconIndex` from `this + 0xfc`, computes the icon slot rectangle, calls inherited `InvalidateRect(&iconRect)` through the primary `Pane` vtable slot `+0x20`, and then stores the new state byte at `m_isPressed` / `this + 0x100`. `0xfc` is decimal 252, `0x100` is decimal 256, and vtable slot `0x20` is decimal 32 (Verified with int_convert.py).

The rectangle matches the accepted [UID:0002T3][0x004cf7d0-0x004cf862.IconsPaneHitTestIcon](by-memory/0x004cf7d0-0x004cf862.IconsPaneHitTestIcon.md) and [UID:0002T1][0x004cf300-0x004cf3d3.IconsPaneOnPaint](by-memory/0x004cf300-0x004cf3d3.IconsPaneOnPaint.md) icon geometry: `left = m_selectedIconIndex * 0x14`, `top = 0`, `right = left + 0x13`, and `bottom = 0x0e`. `0x14` is decimal 20, `0x13` is decimal 19, and `0x0e` is decimal 14 (Verified with int_convert.py). The disassembly computes `index * 20` as `lea eax, [eax+eax*4]` followed by `shl eax, 2`.

The store-after-invalidate order is intentional binary behavior: the helper builds the rectangle, invalidates it, and only then writes the new `m_isPressed` state. The source block preserves this order. There is no explicit `m_selectedIconIndex == -1` guard in this helper; caller flow keeps the field valid while highlight state is being changed and resets the selected icon to `-1` only after the release-path `SetIconHighlight(false)` call.
