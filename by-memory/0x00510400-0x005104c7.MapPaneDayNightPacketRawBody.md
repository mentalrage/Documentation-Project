## Summary

This raw body parses the day/night payload used by `MapPane` opcode `0x20`.

It reads:

- `packet[1]` as a time-of-day or mode index, valid only below `24`;
- `packet[2]` as a minute-like index, valid only when `60 * value < 3600`.

When valid, it stores the mode byte at `MapPane + 0x40f`, looks up `dword_66DD78[mode]`, applies the day/night scale and bias fields at `MapPane + 0x3e4` and `MapPane + 0x3e8`, clamps the result to `[0.0, 1.0]`, computes a curve duration from the current fade value and fields at `MapPane + 0x3c8` and `MapPane + 0x3cc`, then calls `0x0050a8b0` to apply the day/night cycle. The return value is always true.

## Boundary Caveat

IDA MCP lookup on 2026-05-25 reports `0x00510400` and `0x005104c0` as `Not a function`. Disassembly still shows a normal function-shaped body:

- prologue at `0x00510400`: `push ebp; mov ebp, esp; push ebx; push esi; push edi`;
- call to `0x0050a8b0` at `0x005104b9`;
- return epilogue begins at `0x005104c0`; the `retn 4` instruction spans through byte `0x005104c6`, making `0x005104c7` the end-exclusive raw-body endpoint;
- alignment before the next modeled function at `0x005104d0`.

IDA MCP `xrefs_to` and `callers` report no direct references to `0x00510400`. By contrast, `0x005104d0` is a modeled function with a direct dispatcher caller at `0x00507f10`.

## Duplicate Dispatcher Evidence

`MapPane::HandlePacket` at `0x00507c90` contains the same day/night packet body inline under switch case `0x20`. The inline dispatcher body runs from roughly `0x00507e45` through `0x00507f04` and calls `0x0050a8b0` at `0x00507efd`.

This means the generated standalone `MapPane::HandleWeatherPacket` row is useful behavior evidence, but should not be migrated as a clean source method until the dispatcher split is reconciled.
