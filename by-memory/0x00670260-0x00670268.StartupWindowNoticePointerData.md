# 0x00670260-0x00670268 StartupWindow Notice Pointer Data

## Summary

- Address range: `0x00670260-0x00670268`
- Entity kind: initialized window string pointer pair
- Disposition: reconstructable project data
- Rebuild handling: source-declared StartupWindow static pointer slots
- Confidence: strong for contents, use sites, owner module, and neighboring boundaries

This range stores the `StartupWindow` notice-window class and title string pointers used by the startup update/notice window creation paths. Both slots point into the StartupWindow read-only string span and are consumed by the notice-window registration/create code.

## Layout

| Range | Bytes | Points to | Role |
| --- | --- | --- | --- |
| `0x00670260-0x00670264` | `18 d4 62 00` | `0x0062d418`, ANSI `"BaramNoticeWnd_Class"` | Notice window class name used in class registration and window creation. |
| `0x00670264-0x00670268` | `30 d4 62 00` | `0x0062d430`, ANSI `"Notice"` | Notice window title used when creating the notice HWND. |

## Evidence

- 2026-06-06 IDA MCP byte sweep of `0x00670258-0x00670270` returned `a8 4f 62 00 bc 4f 62 00 18 d4 62 00 30 d4 62 00 ff ff ff ff 00 00 00 00`, placing this pair after the Socket connection-string pointer pair and before the string-buffer sentinel header.
- The `0x00670260` slot has two direct code references: `0x005808ac` in [UID:0001IO][0x005807d0-0x0058206e.StartupWindowUpdateCheck](by-memory/0x005807d0-0x0058206e.StartupWindowUpdateCheck.md) and `0x005819e1` in the unmodeled alternate notice setup bytes.
- The `0x00670264` slot has two direct code references: `0x00580ab1` in the same modeled update-check function and `0x00581b47` in the unmodeled alternate notice setup bytes.
- Live decompilation of `StartupWindow::RunUpdateCheck` shows the class-name slot feeding `WNDCLASSEXA.lpszClassName`, `RegisterClassExA`, and the class argument to `CreateWindowExA`; the title slot feeds the title argument to `CreateWindowExA`.
- Live disassembly of the `0x005819d0` alternate setup bytes shows another `WNDCLASSEXA` build using the class-name slot, the notice WndProc at `0x00581100`, `RegisterClassExA`, and a later create-window path using the title slot.
- The targets at `0x0062d418` and `0x0062d430` decode as ANSI `"BaramNoticeWnd_Class"` and `"Notice"` respectively. IDA reports each target string is referenced only through its writable pointer slot.
- Neighboring-boundary evidence: the previous dwords at `0x00670258` and `0x0067025c` belong to [UID:000287][0x00670258-0x00670260.SocketConnectionStringParsePointers](by-memory/0x00670258-0x00670260.SocketConnectionStringParsePointers.md). The next range starts at `0x00670268` with an empty string-buffer sentinel header and belongs to [UID:000289][0x00670268-0x00670294.StringBufferSentinelHeadersAndWhitespacePointer](by-memory/0x00670268-0x00670294.StringBufferSentinelHeadersAndWhitespacePointer.md); IDA reports no direct refs to `0x00670268`, while the sentinel pointer at `0x00670278` has broad string-helper refs.
