## Constructor Evidence

IDA decompilation of `0x00549620` gives signature shape:

```text
PhotoPane *__thiscall PhotoPane::PhotoPane(PhotoPane *this,
                                           unsigned __int16 mapId,
                                           unsigned __int8 avatarShape,
                                           int avatarTileX,
                                           int avatarTileY,
                                           unsigned __int8 avatarDirection)
```

Observed phases:

1. Call `PictureViewPane::PictureViewPane` at `0x00549a30`, then install `PhotoPane` vtables.
2. Construct cached draw target `m_snapshotPort` at `this + 0xf8`.
3. Format and open `C%04d.MAP` using the `unsigned __int16` map id.
4. Compute a rectangle from global tile dimensions `g_mapTilePixelWidth` (`0x0066da9c`) and `g_mapTilePixelHeight` (`0x0066daa0`), then size/clip the pane draw target.
5. Read terrain/static-object triples from the loaded map buffer and draw `17 x 15` terrain tiles through `g_pMapTileImageLib` (`0x0067a75c`).
6. Draw nonzero static-object ids through `g_pStaticObjImageLib` (`0x0069b448`) using `GetStaticObjectBounds` and `RenderStaticObject`.
7. Build a temporary human/avatar descriptor and draw it through `g_pNewHumanImageLib` (`0x0067a760`) at `avatarTileX * tileWidth`, `avatarTileY * tileHeight`.
8. End drawing and clean up the DAT/string temporaries.

Both constructor callers parse the same packet shape: `uint16 mapId`, a second `uint16` whose low byte becomes the avatar shape/body byte, then `uint8 avatarDirection`, `uint8 avatarTileX`, and `uint8 avatarTileY`. The tile coordinates are promoted to ints for pixel conversion.
