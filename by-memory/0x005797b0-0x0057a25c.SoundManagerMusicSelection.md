## Detailed Behavior

`LoadTrackListFromFile` is the DAT-backed playlist loader. It opens a supplied `.LST` or `.LSR` entry through `DATFile`, reads the first line as a track count, reads subsequent decimal track IDs, and formats each accepted entry as `%08d.MP3`. DAT archive lookup and file access remain dependencies owned by [UID:0000IM][DATArchive](by-file/DATArchive.md); SoundManager owns the music-resource naming and playback policy.

`StopStreamAndResetZone` is distinct from [UID:0001I9][0x0057a260-0x0057a88e.SoundManagerPlaybackControls](by-memory/0x0057a260-0x0057a88e.SoundManagerPlaybackControls.md) `SoundManager::StopStream` at `0x0057a260`. This earlier helper resets the active zone/music-selection state during map/effect transitions. Immediate stop clears the current track and zone; fade mode marks the current track negative and schedules stream fade/stop state.

The constructor initializes the process singleton, installs the `SoundManager` vtable, brings up Miles digital-driver state, imports config playback settings, scans DAT-backed sound-effect resources with `%03d.wav`, and kicks off local music-directory scanning. The destructor releases the same owned audio state and clears singleton ownership.

`GetDigitalDriver` at `0x00579dc0` was previously described as a lifetime-tail fragment. Current source-quality evidence rejects that: the exact body is a four-byte `[ecx+8]` accessor, and the startup-logo/Bink caller uses it to obtain SoundManager's Miles digital driver. [UID:0001I9][0x0057a260-0x0057a88e.SoundManagerPlaybackControls](by-memory/0x0057a260-0x0057a88e.SoundManagerPlaybackControls.md) already owns the separate DirectSound bridge at `0x0057a7e0`.

`PlayTrackByIndex` opens the resolved stream through Miles AIL. DAT mode consumes either a direct `%08d.MP3` entry or a playlist vector entry. Argument three is `volumeScale`: the method stores it in `m_currentTrackVolumeScale`, and the active volume path applies it to the Miles stream. When direct DAT playback replaces playlist mode, the method clears `m_zonePlaylistActive` at `0x00579f93` and reaches the compiler-emitted [UID:0001IF][0x0057bf40-0x0057bf6e.SoundPathVectorClear](by-memory/0x0057bf40-0x0057bf6e.SoundPathVectorClear.md) lowering of `m_zoneMusicTracks.clear()` at `0x00579f9a`. Local-directory mode consumes `m_localMusicPaths`, the distinct `std::vector<SoundPathString>` populated by source-ready [UID:0001IA][0x0057a890-0x0057afce.SoundManagerMusicDirectoryScan](by-memory/0x0057a890-0x0057afce.SoundManagerMusicDirectoryScan.md). Separate fade/restart fields queue a new track when the old stream is fading.

`PlayMusicByZone` applies the DAT-zone policy: `.LST` means sequential playlist, `.LSR` means randomized playlist, direct `.MP3` means single-zone track, and if none exists the fallback track is played. The `.LST`/`.LSR` paths fill `m_zoneMusicTracks`; direct MP3 clears playlist mode and then invokes compiler lowering for `m_zoneMusicTracks.clear()` through UID0001IF at `0x0057a214`. Actual stream opening remains delegated to `PlayTrackByIndex`.
