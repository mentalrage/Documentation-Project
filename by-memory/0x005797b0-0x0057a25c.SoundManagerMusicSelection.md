## Detailed Behavior

`LoadTrackListFromFile` is the DAT-backed playlist loader. Existing IDA-backed docs show it opens the supplied `.LST` or `.LSR` entry through `DATFile`, reads line-based track identifiers, and formats each accepted entry as `%08d.MP3` for later stream selection. It is a SoundManager policy method, not DAT archive ownership: DAT parsing and lookup remain dependencies owned by [UID:0000IM][DATArchive](by-file/DATArchive.md).

`StopStreamAndReset` is the local stream reset path used before changing music state. The surrounding SoundManager docs tie it to active AIL stream shutdown or fade scheduling, current-zone/current-track reset, and transition cleanup before Redbook or stream playback is restarted.

The constructor initializes the process singleton, installs the `SoundManager` vtable, brings up Miles digital-driver state through the audio-driver helper path, imports user/config playback settings, scans DAT-backed sound-effect resources with `%03d.wav`, and kicks off local music-directory scanning. The constructor's DAT interactions mirror the file-level split documented in [UID:0000NV][SoundManager](by-file/SoundManager.md): `SoundManager` owns audio resource policy, while `DATFile`/`HasDATEntry` own archive lookup and payload access.

The destructor/lifetime tail releases the same owned audio resources: cached sample state, active stream, digital-driver state, Redbook handle/state, path vectors, timer integration, and singleton ownership. The broader aggregate [UID:0001I8][0x005797b0-0x0057bc58.SoundManager](by-memory/0x005797b0-0x0057bc58.SoundManager.md) records a separate modeled start at `0x00579dc0`; this page keeps that under the lifetime-tail description until a narrower helper page proves the exact source-level split.

`PlayTrackByIndex` resolves the next stream path from the current direct-track name, playlist vector, or scanned local music paths, opens the stream through Miles AIL, starts playback, and updates transition state. The path-vector clear helper [UID:0001IF][0x0057bf40-0x0057bf6e.SoundPathVectorClear](by-memory/0x0057bf40-0x0057bf6e.SoundPathVectorClear.md) is called at `0x00579f9a` with `SoundManager +0x109c`, showing this method clears the track-filename/local-path vector when rebuilding direct playback state.

`PlayMusicByZone` is the zone music chooser. It checks for `%08d.LST`, `%08d.LSR`, and direct `%08d.MP3` DAT entries through [UID:0000T0][HasDATEntry_49C700](by-global/HasDATEntry_49C700.md), loads playlist files when present, falls back to the direct MP3 naming path when appropriate, clears the same `SoundManager +0x109c` path vector at `0x0057a214`, and then delegates actual stream playback to `PlayTrackByIndex`.
