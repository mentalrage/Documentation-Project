## Behavior

`sub_4A88E0` appends one 4-byte integer from the source object referenced by its second machine argument. The pointer is the lowering of `const int&`, not a `void *` payload API:

- reads `count` from `+0x10` and `frontIndex` from `+0x0c`;
- when `(frontIndex + count) & 3` is zero and `blockCount <= (count + 4) >> 2`, calls [UID:0000XB][0x0043e0b0-0x0043e241.DequeEnsureCapacity](by-memory/0x0043e0b0-0x0043e241.DequeEnsureCapacity.md) with one additional block request and reloads `frontIndex`;
- normalizes `frontIndex` with `frontIndex & (4 * blockCount - 1)` and writes the normalized value back to `+0x0c`;
- computes the logical append index as `frontIndex + count`;
- computes the block-map slot as `4 * (((frontIndex + count) >> 2) & (blockCount - 1))`;
- allocates a 16-byte block with `operator new(uint)` when the selected block-map entry is null;
- writes the copied 4-byte value to `block[(frontIndex + count) & 3]`;
- increments `count` at `+0x10` and returns with `retn 4`.

The source return is `void`. The final payload load remains in `EAX` because that register feeds the store; there is no post-store return-value construction. All eight calls discard or overwrite `EAX`, rejecting appended-value, pointer, and index returns.

The field use matches [UID:0001U2][DequeLayout](by-type/by-struct/DequeLayout.md): `+0x04` block map, `+0x08` block count, `+0x0c` front index, and `+0x10` count. Each allocated block stores four 4-byte entries.
