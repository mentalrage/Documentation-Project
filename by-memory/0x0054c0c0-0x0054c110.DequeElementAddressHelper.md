| `0x0054c0c0-0x0054c110` | `sub_54C0C0`, size `0x50` | `Deque::ElementAddress` / `Deque::GetAtAddress` | Computes the address of a 4-byte deque element from `frontIndex + index`, the power-of-two block map, and four-entry block layout. |

## Behavior

The helper takes a deque-like object and an index, then:

- adds the requested index to the deque front offset at `+0x0c`;
- divides by four to select a block-map slot;
- masks the block index by `blockCount - 1`;
- selects an entry within the four-entry block with `logicalIndex & 3`;
- returns the address of the 4-byte element.

IDA's decompiler currently shows deeply nested pointer types because the helper is untyped. The assembly still matches the [UID:0001U2][DequeLayout](by-type/by-struct/DequeLayout.md) block-map model: it reads the front index at `this+0x0c`, reaches the active deque state through the `+0x00` auxiliary pointer chain, uses the state block count at `+0x08`, uses the block map at `+0x04`, and returns `blockMap[((frontIndex + index) >> 2) & (blockCount - 1)] + 4 * ((frontIndex + index) & 3)`.
