# Client Current Rendering Mode

## Status

- Confidence: medium for the 16-bit RGB565 surface path, open for the full old/new feature distinction.
- Scope: current/default render path evidence from recovered source and IDA checks.

## Current Findings

The documented active render path is DirectDraw-backed and RGB565-oriented:

- [UID:0000IW][DirectX](by-file/DirectX.md) initializes the process-wide DirectDraw wrapper and stores it in `g_pDirectX`.
- [UID:0000JR][GrafPort](by-file/GrafPort.md) creates RGB565 DirectDraw surfaces with masks `0xf800`, `0x07e0`, and `0x001f`, or falls back to an owned two-byte-per-pixel software buffer.
- [UID:0000SU][g_screenWidth](by-global/g_screenWidth.md) and [UID:0000ST][g_screenHeight](by-global/g_screenHeight.md) are the process-wide 16-bit display dimensions at `0x0066da94` and `0x0066da98`, initialized to `1024x768` in the current IDA data. `GrafPort::UpdateRenderRegion` reads the width global during DirectDraw backing-store sizing.
- [UID:0000T7][MapTilePixelDimensions](by-global/MapTilePixelDimensions.md) are the process-wide `48x48` map tile pixel globals at `0x0066da9c` and `0x0066daa0`. They feed map playfield bounds, tile-offset scaling, and item/effect sprite centering.
- [UID:0000SW][g_useEpfAssets](by-global/g_useEpfAssets.md) / `byte_66DA97` is the broad EPF/current-layout selector. `StartupWindow::StartupWindow` forces it to `1`; new/current UI branches then choose EPF assets, palette-backed draw paths, and the newer in-game pane graph.
- [UID:0000OC][Surface](by-file/Surface.md) tracks generic surface metadata, paint lifecycle, scroll-buffer, presentation, and display-blit helpers whose current recovered owners are still provisional.
- [UID:0000TN][SurfaceRenderCallbackTable](by-global/SurfaceRenderCallbackTable.md) is the process-wide software-render dispatch table selected by the surface initializer at `0x00558840`; its slots switch between the [UID:00016J][0x004bb8d0-0x004c069e.SoftwareRenderCompatCallbacks](by-memory/0x004bb8d0-0x004c069e.SoftwareRenderCompatCallbacks.md) and the [UID:00016L][0x004c0770-0x004c5fde.SoftwareRenderRgb565Callbacks](by-memory/0x004c0770-0x004c5fde.SoftwareRenderRgb565Callbacks.md).
- [UID:00016H][0x004bb2e0-0x004bb5a5.LineClipHelpers](by-memory/0x004bb2e0-0x004bb5a5.LineClipHelpers.md) clip line segments for both software line callback families and should stay with shared render/geometry code, not ranking UI code.
- [UID:0000NT][SoftwareBlend16](by-file/SoftwareBlend16.md) contains the RGB565 pixel, pair, span, and block blend helpers used by software drawing paths.
- The [UID:0000YD][0x0045fa00-0x004604f4.Rgb555565BlitHelpers](by-memory/0x0045fa00-0x004604f4.Rgb555565BlitHelpers.md) also contains RGB565 transparent-shadow and alpha-map helpers at `0x00460370` and `0x00460410`, both called from the RGB565 callback family.
- [UID:000200][0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels](by-memory/0x00458560-0x00458585.EPFTileContextNormalizePostDecodePixels.md) provides a narrow post-decode compatibility example: it checks descriptive `g_surfaceUsesRgb565Pixels` / raw `byte_69B3D5` and calls [UID:0003ZP][0x004bb0e0-0x004bb111.ConvertRgb565ToRgb555Pixels](by-memory/0x004bb0e0-0x004bb111.ConvertRgb565ToRgb555Pixels.md) only when the active Surface path is not RGB565-capable. This is evidence for the RGB565/RGB555 pixel-format split, not standalone proof of the whole product-level "new rendering mode" switch.
- [UID:0000IV][DIBitmap](by-file/DIBitmap.md) convert PCX/startup image buffers into RGB565 DIB storage.
- [UID:0000HF][AlphaMaskSurface](by-file/AlphaMaskSurface.md) provide byte alpha-mask surfaces and blend-mode helpers consumed by image libraries. [UID:0000K8][IntAlphaSurface](by-file/IntAlphaSurface.md) is the neighboring provisional integer/per-pixel alpha surface currently proven only by destructor and vtable evidence.

## Mode Split Evidence

[UID:0000JX][HourPane](by-file/HourPane.md) gives a concrete small UI example of the `byte_66DA97 == 1` branch: its paint handler at `0x004cf010` loads `TIME.EPF`, selects frame `word_66DB04[(hour / 2) % 12]`, and draws through the palette path with `TIME.PAL`. [UID:0000UV][InitializeMainUiGraph_004F7D10](by-item/InitializeMainUiGraph_004F7D10.md) gives the larger UI-graph example: this same byte selects the newer post-login pane graph. This supports treating EPF plus palette resource use as current/new-mode evidence for pane UI rendering, while still requiring more work before defining the full product-level mode switch.

## Interpretation

For source-structure purposes, "new rendering mode" should currently mean the RGB565 DirectDraw/software-buffer pipeline plus the newer table-driven asset libraries, especially `NewHumanImageLib`. Do not treat that as a final product-level definition until the actual runtime mode switch is recovered.
