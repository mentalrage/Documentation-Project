# By-Resource Guidance

Use `by-resource` for DAT entries, UI resources, image/palette/audio assets, embedded resource formats, string tables, and resource-to-class ownership.

This folder should hold resource-level evidence that is too concrete for broad `by-meta` pages but not primarily a C++ class/file/type decision.

Examples:

- DAT entry families and inferred filenames;
- sprite, palette, alpha-mask, sound, or map-tile resource groups;
- UI resource ids and dialog/control resource ownership;
- resource loaders and cache/index globals.

Keep exact binary format specifications in `../by-meta` when they span many resources, and keep source-module ownership decisions in `../by-file`.

## Naming

Filename examples:

```text
dat-entry-name-table.md
palette-resources.md
mail-dialog-ui-resources.md
map-tile-resources.md
```

## Page Contents

Each resource page should include:

- resource family, ids, filenames, DAT names, or inferred keys;
- loader/owner classes and global indexes;
- binary format notes when localized to that resource family;
- evidence from code, strings, DAT research, and memory ranges;
- links to broader `../by-meta` specs and relevant `../by-file`, `../by-class`, and `../by-global` docs.

## Scoring Discipline

Do not rate a resource page at `95+` completion or confidence lightly. Those values mean the resource identity, format, loader path, owning classes/files/globals, DAT or asset evidence, rebuild packaging role, and all relevant binary references have already been audited and documented well enough for another agent to verify the score from the page alone. If any ids, filenames, formats, owners, loaders, source assets, or packaging assumptions remain uncertain, keep the score below `95`.

## Coverage Report Rows

Use resource family names, concrete resource ids, or inferred DAT/resource keys as row keys in `-coverage-report.md`, sorted alphabetically unless the resource format has a natural numeric/table order. Mark a resource reconstructable when its source asset, loader path, owner class/file, or rebuild packaging role is at least partially known. Put resources that are confirmed external, unused, duplicate, or intentionally generated by packaging in `-ignored.md` with evidence.

## Reconstruction Autogen

`by-resource` pages are excluded from validator reconstruction autogen metadata in the first implementation because this folder does not exclusively contain source code that should be assembled into generated C++. Resource pages may still link to reconstructable classes, globals, functions, or file pages that consume the resource. If a resource-derived declaration needs source code later, document the consuming code item in an eligible folder and attach that item to its source-file/class parent.
