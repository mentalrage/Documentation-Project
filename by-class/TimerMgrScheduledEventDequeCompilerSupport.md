## Responsibility

`TimerMgrTimerQueue` is the embedded queue inside [UID:0000F1][TimerMgr](by-class/TimerMgr.md). It stores pointers to `ScheduledTimerEvent` records in a ring-style slot array, tracks logical start and count, grows capacity as needed, shifts entries for insert/remove, and releases queued event records during destruction.

This is not a general project container. Its element type and helpers are specific to timer scheduling.

2026-06-30 B009 implementation keeps this as a class route page and emits `[[CHILDREN]]`; the range algorithms [UID:0002L0][0x00597eb0-0x00597f17.TimerQueueReverseRange](by-memory/0x00597eb0-0x00597f17.TimerQueueReverseRange.md) and [UID:0002L1][0x00597f20-0x00597fc9.TimerQueueRotateRange](by-memory/0x00597f20-0x00597fc9.TimerQueueRotateRange.md) are file-local static helper bodies, not public queue API. This preserves the existing filled queue emitters, including [UID:0002L7][0x00598480-0x005986d9.TimerMgrTimerQueueInsertTimer](by-memory/0x00598480-0x005986d9.TimerMgrTimerQueueInsertTimer.md), which already calls `RotateRange`.

## Layout Notes

See [UID:0001WD][TimerMgrLayout](by-type/by-struct/TimerMgrLayout.md). The queue portion is currently modeled as:

- root/sentinel pointer;
- pointer array of `ScheduledTimerEvent*`;
- slot capacity;
- logical start index;
- count.

Large slot arrays use MSVC-style aligned allocation with a raw allocation pointer stored just before the aligned pointer. The destructor validates the alignment slack before freeing.

## B015 Source-Quality Normalization

B015 reanalysis confirms [UID:0001KA][0x00597dc0-0x005986da.TimerMgrQueueHelpers](by-memory/0x00597dc0-0x005986da.TimerMgrQueueHelpers.md) is non-emitting context, so queue source output belongs directly on this class's exact children. The owner/emitter route for [UID:0002L5][0x005980f0-0x00598281.TimerMgrTimerQueueEnsureCapacity](by-memory/0x005980f0-0x00598281.TimerMgrTimerQueueEnsureCapacity.md), [UID:0002L6][0x00598290-0x00598471.TimerMgrTimerQueueSpliceTimerRange](by-memory/0x00598290-0x00598471.TimerMgrTimerQueueSpliceTimerRange.md), and [UID:0002L7][0x00598480-0x005986d9.TimerMgrTimerQueueInsertTimer](by-memory/0x00598480-0x005986d9.TimerMgrTimerQueueInsertTimer.md) should be [UID:0000F2][TimerMgrTimerQueue](by-class/TimerMgrTimerQueue.md), not the aggregate.

Source-quality naming decisions:

- `EnsureCapacityForInsert(unsigned int additionalCount)` is preferred for the grow helper because both direct callers are insert-side one-additional-slot checks.
- `EraseRange(first,last)` is preferred over `SpliceTimerRange` for the remove helper. Keep the filename for UID stability, but use the source-facing name in C++ and prose.
- `InsertTimer(Iterator where, const ScheduledTimerEvent &event)` is the best-supported insert signature direction. The exact iterator type name remains provisional.
- `TimerQueueReverseRange` and `TimerQueueRotateRange` are static/template-style queue-local algorithms. They operate on iterator/control/index triples, use no public API caller surface, and should not be promoted to public methods.
- The queue is still not a generic reusable container. Its only proven use is the TimerMgr scheduler, with 20-byte [UID:0001VX][ScheduledTimerEvent](by-type/by-struct/ScheduledTimerEvent.md) records and scheduler-specific caller paths.
