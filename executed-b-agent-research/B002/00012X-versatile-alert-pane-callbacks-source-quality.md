### Constructor role and ABI

The constructor has 21 instructions, one basic block, five explicit stack arguments, and `retn 0x14`. It forwards message text, layout reference, primary text, and secondary text to `AlertPane::AlertPane`, stores only `resultCallback` at `this+0x270`, then installs primary/secondary/tertiary `VersatileAlertPane` vtables. ### Callback type and ownership

Both callers allocate 24-byte `PlainMemberFunctionObject`-style objects, install function-object vtables, store a member target at `+0x08`, adjustment at `+0x0c`, and object pointer at `+0x10`, then transfer the pointer into the pane constructor. The pane invokes virtual slot `+0x0c` and destroys through virtual slot `+0x00` with deleting value `1`. Current [UID:0001WQ] proves the source-facing base is `FunctionObjectT<unsigned long>` with void `Invoke(unsigned long)` and virtual destruction. The field is owning `m_resultCallback`, not a flag, generic control, borrowed pointer, or pane-specific interface.

### Primary and secondary behavior

Each callback is a seven-instruction, three-block virtual leaf. Primary null-checks `m_resultCallback` and invokes it with unsigned-long value `1`; secondary performs the same sequence with value `0`. Neither returns a value or mutates pane state. ### Caller semantics

`NexonclubRegistrationDialog` constructs a callback targeting `0x00530020`; that callback ignores the result and clears timer/pending-alert state. `TerminalPane` constructs a callback targeting `0x0058b620`; nonzero takes reconnect/restart while zero takes leave/shutdown.
