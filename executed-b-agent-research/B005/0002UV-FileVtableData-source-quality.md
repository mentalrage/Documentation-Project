## Heuristic / Inference Reanalysis And Validation

### Physical record and range

The target is exactly 48 bytes in `.rdata`, from the File complete-object-locator pointer through eight pure virtual slots. The predecessor and successor dwords belong to different classes. There is no padding inside the target and no reason to widen or shrink it.

### RTTI and inheritance

The File complete-object locator points to a type descriptor whose decorated payload is `.?AVFile@@`. Its class hierarchy descriptor has two base entries: File and LObject. Both PMDs are at displacement zero and the hierarchy has no multiple/virtual-inheritance attributes. This proves `File : public LObject` and rejects a standalone unrelated stream interface.

### Inherited slots

Slot `+0x04` targets the inherited LObject runtime-class accessor. Slot `+0x08` targets the inherited no-op change-message implementation. The File declaration must not redeclare these slots merely to force the vtable shape; inheritance supplies them.

### Destructor form

No separate ordinary `File::~File` body is modeled. The scalar deleting wrapper restores the File vptr, directly performs empty File teardown by invoking the LObject destructor, and then handles delete flags. Derived destructors likewise restore the File table and call LObject directly. The strongest human source shape is an inline empty virtual File destructor in the class declaration.

### File object size

The File scalar deleting wrapper's compiler branch pushes `4`; DATFile pushes `0x14`; StdioFile pushes `0x0c`. These values match complete object sizes, not method-local arbitrary constants. Therefore File contributes only the inherited vptr-sized LObject object and declares no data field.

Rejected 8-byte/shared-handle model:

- it would place the currently accepted Stdio concrete fields at `+0x08/+0x0c`, contradicting observed `+0x04/+0x08`;
- it would require a generic base field type capable of serving as both `FILE *` and DAT container pointer, with source casts that have no positive evidence;
- File constructor/destructor/runtime methods never read or write `+0x04`;
- the compiler-generated File object-size immediate is `4`.

### Stream method order and signatures

Concrete DAT and Stdio tables match all eight operation slots exactly.

1. Open: one wide path pointer; source return is void. Both concrete bodies leave incidental values in `EAX`, but accepted Stdio caller review shows the value is ignored and a shared override cannot have different return types.
2. Close: boolean success.
3. Position: signed integer, with DAT failure `-1` and Stdio `ftell`.
4. Seek: signed offset and origin, boolean success.
5. Size: signed integer, with DAT failure `-1`.
6. Read: `size_t` byte-count return and signed integer count. DAT explicitly checks `count < 0` and substitutes full payload size.
7. ANSI line read: boolean result and `StringBaseA &` destination.
8. raw line read: signed integer result, `char *` buffer, signed integer limit.

No `const` qualifier is recommended. It is not symbol-proven, and the current accepted concrete declarations are non-const. The x86 ABI is ordinary non-static member `__thiscall`; that calling convention remains implicit in human C++.

### Position naming

`Tell` remains a useful historical alias, but `GetPosition` is selected because:

- current accepted Stdio class/formal source uses it;
- `ReadRemaining` and generated consumer source use it;
- DAT behavior returns the same current-position concept;
- no decorated original method symbol survives to favor `Tell`.

### File string helper pair

The two helper bodies are not virtual slots, but a complete File class surface needs their declarations.

- `0x004b12a0` has a hidden return-object pointer, one signed count argument, direct construction into the return object, File virtual calls to position/size/read, and EH cleanup of the hidden result only if construction succeeded. The strongest source form is a `StringBaseA` by-value `ReadString` method.
- `0x004b1340` has one explicit wide-string destination, returns a byte boolean, invokes the virtual ANSI line method, converts/assigns only on success, and destroys both temporaries. The strongest source form is a nonvirtual wide `ReadLine` overload.
- No caller/xref survives for either helper. That caps lexical confidence but does not block a realistic source name because behavior, receiver type, parameter ABI, return ABI, and StringBase operations are all now resolved.
