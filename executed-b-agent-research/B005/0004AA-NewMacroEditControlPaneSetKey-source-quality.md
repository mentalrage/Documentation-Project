## Heuristic / Inference Reanalysis And Validation

1. **Function and boundary identity.** `lookup_funcs` models
   `sub_57FA40` at exact size `0x12` / 18 bytes (Verified with MCP
   `int_convert`). The complete range contains six instructions and no
   interior function, table, exception record, thunk, or tail merge.
2. **Exact bytes and uniqueness.** Exact target bytes are
   `55 8b ec 66 8b 45 08 66 89 81 0c 01 00 00 5d c2 04 00`.
   The exact range signature and both fixed/wildcard function signatures are
   unique. An exact full-body byte search returns only `0x0057fa40`.
3. **Instruction and CFG shape.** The body is one straight-line basic block,
   cyclomatic complexity `1`, with `push ebp`, frame setup, low-word argument
   load into AX, two-byte object store, frame restore, and `retn 4`. It has no
   strings, constants of semantic interest, or callees.
4. **Receiver and argument ABI.** ECX is the complete-object `this` receiver.
   The only explicit argument occupies a normal four-byte x86 stack home at
   `[EBP+8]`; the body reads its low two bytes and consumes four stack bytes
   with `retn 4`.
5. **Source return type.** Hex-Rays infers a 16-bit return because AX still
   holds the argument at exit. That is not a proven source return. At the sole
   caller, the next instruction after the call loads the adjacent mode byte
   into EAX, so the setter result is unused and overwritten. UID0004A9 and
   UID0004AB have the same incidental argument-through-EAX/AL form. The
   established class/caller source convention and semantic role therefore
   support `void`, not a fluent or scalar-returning setter.
6. **Field offset and width.** The only semantic write is
   `mov [ecx+10Ch], ax`: exactly two bytes at complete-object `+0x10c`
   (decimal 268, Verified with MCP `int_convert`). No four-byte write, signed
   extension, mask, bitfield operation, or adjacent byte write occurs.
7. **Caller and order.** The sole external xref is direct callsite
   `0x0053f27e` in UID00049O. The loop resolves a row control, calls the
   `+0x108` index setter, zero-extends `record.code`, calls this setter,
   zero-extends `record.isSpellMode`, calls the adjacent mode setter, and then
   refreshes the row.
8. **No alternate route.** MCP reports exactly one code xref to the target,
   zero xrefs to exclusive end `0x0057fa52`, zero data xrefs, and no callees.
   Searches for little-endian target VA `40 fa 57 00` and RVA
   `40 fa 17 00` return no image matches. Current vtable inventories contain
   no target address.
9. **Boundary/padding.** UID0004A9 ends exactly at the target start. The target

   covers `[0x0057fa52,0x0057fa60)`; no duplicate entry or target expansion

    two-byte argument at the same `+0x10c` field.

15. **Method-name ranking.** `SetKey` is strongest because it pairs with the
