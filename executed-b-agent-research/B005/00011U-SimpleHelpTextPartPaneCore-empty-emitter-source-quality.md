### Virtual/source method model

The `0x0049a080` body has exactly one data route through primary vtable cell `0x006185c0`
and no direct code callers. Existing Pane/control naming supports `virtual void OnPaint()`.
The constructor and `DrawTextLine` are non-virtual source methods. The raw helpers have no
external route and are not declared in the class surface. The inline empty virtual
destructor is the smallest source expression that regenerates the observed string/base
teardown and deleting wrapper without inventing an ordinary standalone destructor body.

### Field and lifetime model

The Pane base occupies the prefix through `+0xf7`. The nested object owns
`SimpleUString m_text` at `+0xf8`, stores signed integer layout values at
`+0xfc/+0x100/+0x104`, and borrows `FontStyle *m_fontStyle` at `+0x108`. The scalar wrapper
destroys only the string and Pane base; it never deletes or destroys the style pointer.
Inherited text alignment is at `+0x8c`, inherited alpha at `+0x90`, and shared GrafPort
draw/text colors are manipulated through existing helpers.

### Style and line scanner model

The record stride is exactly sixteen bytes: text color `+0x00`, secondary color `+0x04`,
effect byte `+0x08`, three reserved bytes, and alignment `+0x0c`. `OnPaint` initializes
only the four semantic fields to `0x8f`, `0x80`, `0`, and `0`; the reserved bytes are not
explicitly initialized by this body. CR, LF, and tab are all segment/line separators. A tab
does not carry an inline formatting opcode. Empty segments are dispatched too, including
adjacent separators and the final empty segment. A successful in-range `GetRule` updates
the current record; out-of-range lookup preserves the previous/default record.

### Draw helper model

`DrawTextLine` consumes `const FontStyleRule&`, signed `x/y`, a UTF-16 pointer, and a signed
short count. It copies alignment, applies text and secondary colors, constructs a
12-pixel-high rectangle with width
`m_bounds.right - (2 * x) - m_bounds.left`, then dispatches effect `0` to
`DrawTextInRect`, `1` to shared `DrawOutlinedText`, and `3` to shared
`DrawShadowedText`; other values draw nothing. The raw Hex-Rays integer return is incidental
tail-register state. Both callers ignore it, and the source-facing method is void.

### Raw helper liveness model

The raw setter stores three arguments and returns with `retn 0x0c`; the raw opacity helper
has a normal thiscall-shaped body and returns without stack arguments. Neither has any
external MCP xref, direct branch entry, VA/RVA pointer route, or matching duplicate body.
UID00011V's constructor writes the same child layout fields directly and contains the same
style-opacity branch, establishing inlining/coverage. The safest nonduplicating source plan
documents both exact bodies, emits neither as an external method body, and gives each exact
raw child the required minimal formal comment that emitted code is covered by UID00011V.

### Score-blocker exhaustion

The previous blockers were final nested spelling, legal outer/nested declaration order,
parent/child half-open containment, exact raw endpoint, outer text storage, helper
names/types, style pointer ownership, destructor source shape, draw callback naming, raw
liveness, covered-range marker policy, and split/nesting. Decorated names, focused
UID00011V decompilation, direct bytes, B002's independently repaired layout report, sibling
constructor inlining, destructor/adjustor analysis, `by-structure.md`, accepted support

original physical text-array count intent, historical private spelling, and compiler

or leave a blank-C++ blocker.
