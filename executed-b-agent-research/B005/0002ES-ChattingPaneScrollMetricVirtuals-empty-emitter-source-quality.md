## Heuristic / Inference Reanalysis And Validation

1. **Six names.** Current base consumers identify slots `+0x48..+0x5c` as range, overflow/current-unit count, page size, unit-to-pixel offset, content size, and scroll delta. The surviving ListPane inventory names all six slot-equivalent methods `GetScrollRange`, `GetOverflowCount`, `GetPageSize`, `GetScrollOffset`, `GetContentSize`, and `GetScrollDelta`. Those names fit Chatting behavior and avoid a hard C++ collision: slot `+0x4c` cannot be `GetScrollPosition(char)` because ScrollablePane already has a separate same-signature cached-child getter at `0x0055e950`. Historical B002 `GetScrollPosition` for slot `+0x4c`, `ConvertScrollUnit` for slot `+0x54`, and `ConvertScrollDelta` for slot `+0x5c` are therefore superseded; descriptive target labels remain historical role text rather than override names.
2. **Axis contract.** `sub_55E990` calls slots `+0x48/+0x4c` with axis `1` for child `+0xf8` and axis `0` for child `+0xfc`; constructor evidence identifies these as horizontal and vertical scroll panes respectively. Chatting returns meaningful values only for axis `0`, so axis `0` is vertical and axis `1` horizontal.
3. **Scalar return types.** Core and keyboard callers consume `AX` with `movzx`, `movsx`, or `cwde`; `ComputeLineCount` itself accumulates and returns a 16-bit value. The four scalar virtuals and `ComputeLineCount` should therefore be `short`, not `int` or `unsigned int`.
4. **Rectangle fields.** Accepted `RectBounds` layout is left/top/right/bottom. ScrollablePane fixed visible content bounds occupy `+0x110`, and its positioned full content bounds occupy `+0x120`. Therefore `+0x114` is `m_contentRect.top`, `+0x124` is `m_scrollContentRect.top`, and their difference is the positive vertical scroll displacement.
5. **Output type.** Slot `+0x58` is consumed as `[0]=height`, `[1]=width`; slot `+0x5c` is consumed as `[0]=vertical delta`, `[1]=horizontal delta`. The project's accepted `Point` stores `y` then `x`, exactly matching both uses. Win32 `POINT` and `SIZE` are rejected because their field order/names communicate the opposite layout.
6. **Delta argument order.** `ApplyScrollPosition(axis, oldPosition, targetPosition)` passes its old/current position first and new/target position second to slot `+0x5c`; Chatting computes `old-new`, which translates content opposite the scrollbar movement. Historical `currentPos, previousPos` wording is reversed and should be corrected to `oldPosition, newPosition`.
7. **Line unit and formulas.** All conversions use 13 pixels. Current assets derive visible rows from `m_visibleChatPixelHeight/13`; legacy range subtracts five rows while legacy page step returns seven. Those are distinct binary constants and must not be normalized.
8. **Width constants.** `GetContentSize` returns width 783 current and 420 legacy. `ComputeLineCount` wraps at 783 current and 408 legacy. The legacy 12-pixel difference is intentional binary behavior, plausibly reserved UI margin/scrollbar space; replacing 420 with 408 is rejected.
9. **Repeated line-count calls.** `GetScrollRange` calls `ComputeLineCount` once for the negative test and again for the successful return. Destination 2 preserves that call count instead of silently commoning it.
10. **Inheritance.** The ChattingPane constructor calls the ScrollablePane constructor and installs primary/secondary/tertiary ChattingPane vptrs at `+0/+0xa0/+0xa4`, matching inherited ScrollablePane/Pane interface views. No evidence supports an unrelated direct base; the source declaration should use `ChattingPane : public ScrollablePane`.
11. **Class surface.** Because `[[CHILDREN]]` must follow the class declaration, Destination 8 declares every currently emitted or sufficiently resolved ChattingPane method plus the two proven fields. This avoids the source-incomplete class defect seen when child definitions exist without declarations.
12. **Split choice.** Retaining one source-bearing aggregate is rejected. Six exact method starts, six consecutive vtable slots, five internal alignment spans, independent ABIs, and a clean relative nesting plan make exact children validator- and source-correct.
13. **Slot `+0x5c` name.** `GetScrollDelta` is the highest-probability inherited spelling. MCP proves the base `0x005655c0` and direct-family overrides ChattingPane `0x0047f6b0`, FolderTreePane `0x004b2b50`, ListPane `0x004f4140`, SystemMessagePane `0x00585890`, OldSystemMessagePane `0x00589630`, and TextEditPane `0x0058ed80` all return an output pair derived from old-minus-new positions. The FolderTree/SystemMessage/OldSystemMessage/TextEdit docs expose only role descriptions or unresolved inherited names; none supports `ConvertScrollDelta`. The current ListPane inventory alone records a concrete recovered source-facing spelling, `ListPane::GetScrollDelta`, and the same inventory already supplies the accepted `+0x4c/+0x54` corrections. Historical B002 `ConvertScrollDelta` was a behavioral inference without a symbol or surviving source declaration, so it ranks second and is superseded.
