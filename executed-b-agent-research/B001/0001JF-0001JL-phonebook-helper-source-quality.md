## Function Findings

### [UID:0001JF] Selected-Entry Helper

Observed behavior:

- Exact IDA function: `sub_58CFA0`, size `0x3c`, half-open range `0x0058cfa0-0x0058cfdc`; `0x0058cfdc-0x0058cfe0` is `0xcc` padding.
- Direct caller: `PhoneBookDialog::OnCommand` at `0x0058cd8c`, edit command path.
- The caller passes two stack output buffers and two capacities, both `0x40` wide characters.
- Body obtains the selected row through the shared `ListPane` selected-entry accessor path, copies two wide strings with `_wcscpy_s`, and returns the leading byte from the row.
- Row reads are exactly:
  - `entry + 0x002` as contact display/name string
  - `entry + 0x082` as phone-number string
  - `entry + 0x000` as returned byte

Best source-facing route:

- Direct class method on [UID:0000AE] `PhoneBookListPane`, not a `PhoneBookDialog` file-local helper and not a chat/article list method.
- Keep source file context under [UID:0000MJ] `PhoneBookDialog.cpp`, because the class belongs to that login/terminal phone-book source file.
- Recommended source name remains `PhoneBookListPane::GetSelectedEntryData`.

Best row type:

```cpp
struct PhoneBookContactEntry
{
    unsigned char entryFlags;
    wchar_t name[64];
    wchar_t phoneNumber[64];
};
```

`entryFlags` is the best defensible name. `status`, `type`, and `favorite` were rejected because every producer checked in this scope initializes the byte to zero and no checked consumer branches on nonzero flag values. The byte is still real source-visible storage because `GetSelectedEntryData` returns it, so do not collapse it to padding.

Producer/consumer validation:

- `PhoneBookDialog` constructor/load path reads `PHONE.CFG`, builds rows with byte `0`, copies alternating name/number lines into the two 64-wide-character fields, and appends through the shared list insert/append helper.
- `PhoneEntryDialog::OnDialogAction` add and edit paths also set the byte to `0`, copy name/number into the same two fields, and append or replace the row.
- `PhoneBookListPane::RenderEntry` draws the two row fields as columns, truncating display text to the name and number column widths.
- `PhoneBookDialog::SavePhoneBook` writes the same two row fields back to `PHONE.CFG`.

struct PhoneBookContactEntry
{
    unsigned char entryFlags;
    wchar_t name[64];

unsigned char PhoneBookListPane::GetSelectedEntryData(
    wchar_t *nameOut,
    size_t nameCapacity,
    wchar_t *numberOut,
    size_t numberCapacity)
