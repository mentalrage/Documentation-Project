## Heuristic / Inference Reanalysis And Validation

### Callback purpose and parameter names

- `pixels`: direct consumers pass the active 16-bit surface buffer; every nonzero/nonclear case mutates it in place.
- `pixelCount`: direct consumers pass active width times active height; entry computes `pixelCount >> 1` for packed pairs and checks the low bit for one final 16-bit pixel.
- `fadeStep`: entry clamps the signed third argument into `[0,24]`; ScreenPane field `+0x5ac` is already documented as `m_fadeStep`; transition setup writes endpoint 24 for one direction and 0 for the other.
- `SoftwareRenderCompatBlockTransferCallback`: preserves the established source-family name, distinguishes RGB555 compatibility behavior from the RGB565 peer, and describes the slot's whole-buffer transfer operation without an IDA address.

### Exact 25-step channel semantics

For one 5-bit channel `x`, define `s1=x>>4`, `s2=x>>3`, `s4=x>>2`, and `s8=x>>1`. Each RGB555 channel is transformed independently with the following exact integer expression:

| Fade step | Exact channel result | Meaning |
| --- | --- | --- |
| 0 | `x` | full intensity / no write |
| 1 | `x-s1` | first attenuation step |
| 2 | `x+s1-s2` | exact compiler-observed approximation |
| 3 | `x-s2` | exact attenuation |
| 4 | `x-s1-s2` | exact attenuation |
| 5 | `x+s1-s4` | exact approximation |
| 6 | `x-s4` | exact attenuation |
| 7 | `x-s1-s4` | exact attenuation |
| 8 | `x-s2-s4` | exact attenuation |
| 9 | `x-s1-s2-s4` | exact attenuation |
| 10 | `x+s1-2*s4` | exact approximation |
| 11 | `x+s1-s8` | exact approximation |
| 12 | `s1+s8` | exact reduced intensity |
| 13 | `s8` | half intensity |
| 14 | `s8-s1` | exact reduced intensity |
| 15 | `2*s4-s1` | exact reduced intensity |
| 16 | `s1+s2+s4` | exact reduced intensity |
| 17 | `s2+s4` | exact reduced intensity |
| 18 | `s1+s4` | exact reduced intensity |
| 19 | `s4` | quarter intensity |
| 20 | `s4-s1` | exact reduced intensity |
| 21 | `s1+s2` | exact reduced intensity |
| 22 | `s2` | eighth intensity |
| 23 | `s1` | sixteenth intensity |
| 24 | `0` | black / clear |

- Exhaustive arithmetic comparison over all 32 possible channel values confirms that the output at step `n+1` is never brighter than step `n`.
- The formulas are exact bit-shift approximations, not generic `x*(24-step)/24`. Replacing them with multiplication/division changes boundary rounding and is rejected.
- The source should retain numeric case labels because they are ordinal steps. Only the endpoint meanings need semantic names; fabricating 24 independent effect names would misrepresent the caller contract.

### Packed and scalar equivalence

- For two RGB555 pixels packed in one dword, the shift components are `s1=(value>>4)&0x04210421`, `s2=(value>>3)&0x0c630c63`, `s4=(value>>2)&0x1ce71ce7`, and `s8=(value>>1)&0x3def3def`.
- Optimized exact forms include `(value&0x7bde7bde)>>1` for step 13, `(value&0x739c739c)>>2` for step 19, `(value&0x63186318)>>3` for step 22, and `(value&0x42104210)>>4` for step 23.
- Lower 16-bit halves of the same constants implement the odd-pixel tail. The dword-pair and 16-bit-tail formulas produce the same result for both pixels and every channel.
- SIMD blocks are compiler lowering of the same expressions. The constants at `0x0061a950`, `0x0061a960`, `0x0061a980`, `0x0061a9a0`, `0x0061a9b0`, `0x0061a9c0`, `0x0061a9d0`, and `0x0061a9e0` are splatted RGB555 masks/deltas, not source arrays indexed by `fadeStep`.
- The observed large per-case bodies, vectorized bulk prefixes, dword remainder loops, and scalar odd tails are consistent with one macro-expanded scalar case loop optimized by 32-bit MSVC.

### Rejected alternatives

- `__m128i *` return and buffer type: rejected as decompiler residue; the callback contract is void and 16-bit-pixel based.
- 25 unrelated render modes: rejected by endpoint initialization, one `m_fadeStep` field, monotone case ordering, and identical callers.
- Generic alpha blend or linear multiply: rejected because exact shifts and rounding differ.
- Standalone jump table or SIMD constant arrays in source: rejected because no source-level indexed table route exists.
- SoftwareBlend16 owner: rejected because this is stateful callback registration/dispatch code, not a reusable leaf blend helper.
- ScreenPane owner: rejected because ScreenPane consumes the callback but does not install, pair, or emit the providers.
