## ObjectStatusBlob consumer inventory

- ObjectStatusBlob byte `+34` decimal (`+0x22`) is composition/render mode. Riding fields at decimal `+44/+46/+48` (`+0x2c/+0x2e/+0x30`) are definition index, packed palette/render flags, and signed Y offset from `RidableAnimals` columns 1-3. ## File Role

`NewHumanImageLib` is the updated human sprite composition library. It owns the newer table-driven character composition system: motion records, layer records, part records, per-part sprite descriptors, accessory-to-draw mapping, hair-color indices, composition draw commands, bounds calculation, and render dispatch.

This is a separate source module from [UID:0000JY][HumanImageLib](by-file/HumanImageLib.md). Both are human character image libraries, but `NewHumanImageLib` has its own data model around `Motion.tbl`, `Layer.tbl`, `Part.tbl`, `acc2drw.tbl`, and part-specific descriptor tables.

[UID:00050M][HumanImageRenderParams](by-type/by-struct/HumanImageRenderParams.md) is the shared packed `0x40` render-input declaration emitted through this file's H at position 5. It names every byte from status kind through the final invisible flag, includes the context unions used by face/shape and gender/direction consumers, and supplies a period-compatible size guard. It must precede the NewHumanImageLib declarations so callers can stack-allocate the complete type; an incomplete forward declaration is not sufficient.

The type is the exact first `0x40` bytes of [UID:00009S][ObjectStatusBlob](by-class/ObjectStatusBlob.md). ObjectStatusBlob alone extends it with `m_faceShape` at `+0x40` and padding through size `0x44`. This is an ABI-prefix relationship, not inheritance and not permission to duplicate the packed declaration inside ObjectStatusBlob CPP.

[UID:0000M3][ObjectImageControlPane](by-file/ObjectImageControlPane.md) is a concrete UI preview consumer of this module's base human path: the object-image control's status-kind `0` branch calls [UID:0000RT][g_pNewHumanImageLib](by-global/g_pNewHumanImageLib.md), uses `0x004e09e0` as `CalculateBounds` / `CalculateHumanBounds`, and uses `0x004e06a0` as `Draw` / `RenderHuman` with a preview/render-mode constant. This is consumer evidence only; it does not move human image-library ownership into the UI control file.
